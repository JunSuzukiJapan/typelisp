# 型チェッカーの作り直し — 洗い出しと設計方針（案、2026-11-08）

## 1. 目的

継ぎはぎの修正が重なった型チェッカーを、小さい機能ごとに分かれた、見通しのいい設計に作り直す。
最初の作業量より、その後の追加・修正にかかる時間を短くすることを優先する（ユーザー決定）。

## 2. 今のチェッカーの境界

作り直しの間、外との境界は変えない。境界を固定すれば、評価器・コンパイラ・島・LSP には手を入れずに済む。

| 方向 | 中身 |
|---|---|
| 入力 | リーダーが読んだフォーム（`Value`）。最上位フォームを1つずつ受け取る |
| 出力 | core IR（`TopLevelForm = Value`、cons セルの木）。`Interp::exec` と島がこれを読む |
| 公開の入口 | `check_form` / `check_form_at`、`publish_names`、`finish_unit`、モジュールの出入り（`enter_module` など）、REPL とダンプ用の `signature` / `capture_delta` / `apply_delta`、LSP 用の `take_type_uses` / `take_errors` / `expr_type` / `registry` |
| 内部の流れ | フォーム → 解析（`Node` の木、`Checked`）→ 変換（`lower.rs`、`Node` → core IR） |

`Node` と `lower.rs` はチェッカーの内側にある。作り直しの対象に含めるかは 6 節で決める。

core IR のほかに、登録表と型もチェッカーの外から読まれている（2026-11-08 に確認）。

| 読む側 | 読むもの |
|---|---|
| ダンプ（`dump.rs`） | `Registry` 全体（`AdtDef`・`FnSig`・`TraitDef` など、serde で書き出す） |
| LSP（`src/bin/lsp.rs`） | `registry()` の `def_locs` と `docs`、補完の候補 |
| コンパイラ（`abi_signature.rs`・`llvm_builtins.rs`・`externs.rs`） | `Registry::with_builtins()`、組み込みの `AdtDef`・`FnSig` |
| 評価器（`interp.rs`） | 組み込みの型定義（`builtin_sum_defs`、`task_of` など） |
| 実行時の型の識別（`type_key.rs`） | `Type`（型変数は位置 `TypeShape::Param(i)` に直して扱う） |

`Type::Var` を直接書いている場所は、チェッカーの外では `type_key.rs`・`types.rs`（表示）・`interp.rs:766` の 3 ファイルだけである。

## 3. チェッカーが受け持つ機能

規模は `check/` 全体で約 3 万行。そのうち `analyze.rs` 1 ファイルが約 1.8 万行で、メソッドが約 430 個ある。

### 3.1 最上位フォーム

`defun` `defsignature` `defffi` `defvar` `defparameter` `defconstant` `defmacro` `module` `defmethod`
`defstruct` `defenum` `deftrait` `deftype` `impl`（`impl<T>` を含む）`use` `pub` `unsafe`（`def-c-struct`）。

### 3.2 式の特殊形

`if` `let` `let*` `progn` `unsafe` `c-alloc` `c-ref` `c-deref` `setf` `incf` `decf` `rotatef` `shiftf`
`loop` `block` `return-from` `catch` `throw` `unwind-protect` `break` `return` `list` `format`
`print` `println` `eprint` `eprintln` `pprint` 系 `pprint-logical-block` `lambda` `labels` `macrolet`

`compile` `documentation` `ed` `trace` `untrace` `step` `disassemble` `source-file` `quote` `quasiquote` `:dyn`。

### 3.3 横断する仕組み

- 名前解決（モジュールの木、`use`、パス、メソッドの受け手）
- 型の構文解析と正規化（別名の展開、未定義の型名を断る）
- 登録表（`Registry`：関数・型・トレイト・impl・別名・ドキュメント・定義位置）
- ジェネリック（単型化の要求・テンプレート・特殊化名）
- トレイト（境界の検査、関連型、ブランケット impl、デフォルト本体、`:dyn` の表）
- マクロ展開（`defmacro`、`macrolet`、コアマクロ）
- 表現の分類（`Repr`、Option のニッチ、`Sexpr` への包み方）
- LSP 向けの記録（型の使用位置、ローカル参照、式の型、エラー回復）
- REPL・ダンプ向けの差分
- `#[test]` の収集、FFI コールバックの持ち上げ、`format` の書式エンジン、`loop` の DSL

## 4. 見つかった設計上の問題

### 4.1 型変数を名前で扱っている

`AdtDef.params` は名前の列で、フィールドやメソッドのシグネチャは `Type::Var("T")` の形で保存される。
ほかの定義は、受け手や対象に書かれた名前を宣言側の名前に書き直してから登録される
（`check_defmethod_in_form` の `owner_rename`、`check_impl_form` の `rename`）。

呼び出し側では、型の側のパラメータとメソッド自身のパラメータを、名前をキーにした 1 つの置換表に入れている。
名前がぶつからないようにするための検査が、誤って正しいコードを断っている。

```lisp
(defstruct Pair<T, U> (first T) (second U))
(impl Pair<A,B> (defmethod mk<T> (self (x T)) T x))
;; error: the method's own type parameter `T` has the name of a type parameter of `Pair`
```

実行時の型の識別（`type_key.rs`）は、すでに位置（`TypeShape::Param(i)`）で扱っている。
名前に頼っているのはチェッカーだけである。

### 4.2 書いただけで型変数が宣言されたことになる

`written_type_vars` が、`impl` の対象や `defmethod` の受け手に書かれた未知の名前を、すべて型変数として宣言扱いにする。
`(impl<T> ...)` の頭に書いた宣言は、ブランケット impl のとき以外は使われていない。
型変数は宣言した場所でだけ生まれる、に直す（ユーザー決定）。

```lisp
(impl<T,U> Pair<T,U> ...)
(defmethod pair-first<T,U> ((p Pair<T,U>)) T (first p))
```

### 4.3 ジェネリックな本体を 2 回、別の規則でチェックしている

ジェネリックな本体は、まず型変数を抽象のままチェックし、インスタンス化のたびに元のフォームを具体型でチェックし直す。
2 回のチェックは規則が食い違う。

- 抽象のチェックは Rust と同じく境界を要求する（`(+ x 1)` は「`T` に `+` が無い」でエラー）。
- 具体型でのチェックは、境界が無くても具体型で通れば通る。
- 抽象のチェックがエラーを出しても、テンプレートは登録に残る。そのため REPL では、エラーになった定義がそのまま呼べる（4.4）。
- 抽象のチェックだけが断る書き方があった。ジェネリックな本体の中の `(format false "~a" x)` がそれで、`x : T` を `Sexpr` に包めないとして断っていた（2026-11-08 に、型変数のときは包み方を具体型のチェックへ回すよう修正済み）。

### 4.4 チェックに失敗した定義が登録に残る

`check_defun` などは、自己再帰のためにシグネチャとテンプレートを本体のチェックより先に登録する。
本体のチェックが失敗しても登録を取り消さない。ファイル実行は最初のエラーで止まるので表に出ないが、REPL と LSP では、エラーになった定義が残って呼べてしまう。

```lisp
(defun inc<T> ((x T)) T (+ x 1))   ; error: no method `+` for type variable `T`
(inc 41)                           ; => 42
```

今のチェッカーでは直さず、新しいチェッカーで 5.3 の仕組みにより直す（ユーザー決定）。

### 4.5 ファイルと状態が大きすぎる

- `analyze.rs` 1 ファイルに、最上位フォーム・式・パターン・ジェネリック・トレイトがすべて入っている。
- `Checker` は 35 個、`Info` は 7 個の状態を持つ。その多くが `Cell` / `RefCell` で、チェックの途中で書き換わる
  （ループの段、ブロックの段、`unsafe` の深さ、推論の試し打ち `infer_probe` と穴の数 `probe_holes`、特殊化の待ち行列、型変数の束縛 `type_var_bindings` など）。
- 最上位フォームの振り分け表が、`pub` 付きと無しで 2 つある（`check_one_form` 内と `check_pub`）。

### 4.6 `Self` と関連型をソースの字面で置き換えている

`impl` の項目は、チェックの前に、読んだフォームの中のシンボル `Self` と関連型の名前を、対象の型の書かれた形に置き換えて作り直される（`subst_value`、`subst_method_item`）。
型の置き換えを、型ではなく構文の上でしている。トレイトのシグネチャも `Type::Var("Self")` と関連型の名前で保存され、名前で突き合わされる。

## 5. 設計方針（案）

### 5.1 小さい機能ごとにモジュールを分ける

1 つのモジュールは 1 つの機能だけを受け持ち、ほかのモジュールとは決まった型（`Type`、`Checked`、登録表の読み書き API）だけでやりとりする。
分け方の案を示す。

| モジュール | 受け持ち |
|---|---|
| `types` | `Type` の定義、構文解析、正規化、置換、単一化 |
| `scope` | 型変数の宣言とローカル変数の環境（親フレームを共有する連鎖） |
| `resolve` | 名前解決（モジュールの木、`use`、パス） |
| `registry` | 登録表。書き込みは 1 つの最上位フォームの単位でまとめて確定する |
| `toplevel/*` | 最上位フォーム 1 種類につき 1 ファイル（`defun.rs`、`defstruct.rs`、`impl.rs` …）。振り分け表は 1 つ |
| `expr/*` | 特殊形をまとまりごとに 1 ファイル（制御、束縛、代入、脱出、出力、関数、`match` …） |
| `generic` | インスタンス化と特殊化 |
| `traits` | 境界の検査、関連型、ブランケット impl、`:dyn` の表 |
| `macros` | マクロ展開 |
| `repr` | 表現の分類、`Sexpr` への包み方 |
| `ide` | LSP 向けの記録 |
| `lower` | `Node` → core IR |

### 5.2 型の表し方

- 型の側のパラメータは位置で持つ。登録表のシグネチャには、利用者が書けない位置の印で保存する。
- 型変数は宣言（`defun f<T>`、`defstruct Pair<T,U>`、`impl<T,U>`、`defmethod m<T,U>`、`deftrait` の `(:type ...)`）からだけ生まれる。
- メソッドの型パラメータは、宣言の頭に書いたものだけになる。受け手の型 `Pair<T,U>` は、ほかの引数と同じ「パラメータの型」として扱う。
  型の側のパラメータとメソッド自身のパラメータという 2 種類の区別が無くなり、名前がぶつかる検査も要らなくなる。

### 5.3 登録は成功してから確定する

1 つの最上位フォームの登録は、まとめて仮に書き込み、チェックが成功したときだけ確定する。失敗したら全部捨てる（4.4 の解消）。
自己再帰は、仮の書き込みが同じフォームの中から見えることで支える。

### 5.4 ジェネリックのチェック（ユーザー決定）

本体を 1 回だけ、境界にもとづいてチェックする（Rust と同じ）。インスタンス化は、チェック済みの木の型を置き換えて作る。
表現によって変わる選択（`Sexpr` への包み方など）は、置き換えた後に決まる節点として残す。

これを採ると、今「具体型では通る」だけで境界を書いていないジェネリックな定義は、エラーになる（4.3）。

## 6. 進め方（ユーザー決定）

1. この文書で設計を決める。
2. 新しいチェッカーを今のものの隣に置く。prelude を読み込まないテストから順に、新しいチェッカーでも通るようにしていく。
   環境変数 `TYPELISP_TYPECK` を空でない値にすると、今のチェッカーの `check_form_at` が、すべてのフォームを新しいチェッカー（`crate::typeck`）に渡す。
   新しいチェッカーがまだ扱えない形は `unimplemented!()` で止まる。prelude はダンプから読み込まれ、チェッカーを通らないので、スイッチを立てても REPL は起動する。
   prelude はほぼすべての機能を使うため、prelude を読み込むテストを新しいチェッカーで回せるのは、移植の終盤になる。
3. `Node` と `lower.rs` は、最初は今のものを使い回す。直すべき点が見つかったら、切り替えのあとの次の段階で扱う。
4. 全テストが新しいチェッカーで通ったら切り替え、古いチェッカーを丸ごと消す。

## 7. `types` と `scope` の設計（案）

### 7.1 型パラメータは「どの定義の何番目か」で表す

`Type::Var(String)` をやめ、次の 2 つに置き換える。

```rust
/// 宣言された型パラメータ。どの定義の何番目かで識別する。
pub struct TypeParam {
    pub owner: ParamOwner,
    pub index: u32,
    /// エラーメッセージに出すための、宣言に書かれた名前。比較とハッシュには使わない。
    pub name: SymRef,
}

pub enum ParamOwner {
    /// 関数・型・型の別名・トレイト。定義の Path で識別する。
    Def(Path),
    /// メソッド。型の Path とメンバーのシンボルで識別する。
    Method(Path, SymRef),
}

enum Type {
    ...
    Param(TypeParam),
    /// 呼び出しの推論で使う穴。チェッカーの中だけで使い、登録表と出力には出さない。
    Infer(u32),
}
```

- 定義ごとに持ち主が違うので、別の定義の型パラメータとは名前が同じでもぶつからない。
  `Pair<T,U>` の `T`（`Param{Def(Pair), 0}`）と、メソッド `mk<T>` の `T`（`Param{Method(Pair, mk), 0}`）は別物になる。
- 型の定義のフィールドは、その型の `Param{Def(型), i}` で書く。`p : Pair<A,B>` のフィールドの型は、`i` 番目を `A`・`B` に位置で置き換えて求める。
- 置き換えは「持ち主と番号 → 型」の表で、1 回だけ同時に行う。置き換えた結果をもう一度置き換えることはしない。

### 7.2 呼び出しの推論は穴で行う

ジェネリックな関数やメソッドを呼ぶときは、呼ばれる側のシグネチャの型パラメータを、新しい穴 `Infer(n)` に置き換えてから引数と突き合わせる。
呼ぶ側の型パラメータは、決まった型（中身の分からない定数）として扱う。

自己再帰（`f<T>` の中で `f` を呼ぶ）でも、呼ばれる側は穴に置き換わるので、呼ぶ側の `T` と混ざらない。
ラムダの引数のように、期待する型を先に渡したい場所にも、穴を含んだ型をそのまま渡せる。

穴は 1 つの呼び出しの中で解き終える。解けない穴が残ったら「型パラメータを推論できない」エラーにする。

### 7.3 メソッドと impl の型パラメータ

- `(impl<T,U> Pair<T,U> ...)` の頭の `T,U` は、中の各メソッドの型パラメータの先頭に並ぶ。
  `(defmethod m<V> ...)` なら、`m` の型パラメータは `[T, U, V]`（持ち主は `Method(Pair, m)`）になる。
- 受け手の型 `Pair<T,U>` は、ほかの引数と同じ「パラメータの型」である。メソッドを呼ぶときは、受け手も含めて 7.2 の推論で型パラメータを決める。
- `impl` の外の `(defmethod m<T,U> ((p Pair<T,U>)) ...)` も同じ形になる。

### 7.4 トレイトの `Self` と関連型

トレイトのシグネチャの中では、`Self` を `Param{Def(トレイト), 0}`、`k` 番目の関連型を `Param{Def(トレイト), 1 + k}` として扱う。
`impl` は、ソースの字面を置き換えるのではなく（4.6）、登録済みの型の上で `Self` を対象の型に、関連型を `(:type ...)` で決めた型に、位置で置き換える。

### 7.5 型変数の環境

- 型変数は、宣言（`defun f<T>`、`defstruct Pair<T,U>`、`defenum`、`deftype`、`impl<T,U>`、`defmethod m<T>`、`deftrait` の `Self` と `(:type ...)`）からだけ生まれる。
- 型を構文解析するときは、裸の名前をまず型変数の環境で探し、無ければ型として名前解決する。どちらにも無ければ「未定義の型」エラーにする。書いただけで宣言扱いになる経路（`written_type_vars`）は作らない。
- 環境は、親の枠を参照で共有する連鎖にする。枠を書き換えたり、複製したりしない。
- `:where` の境界は、型変数の名前ではなく `TypeParam` をキーにする。

### 7.6 境界

- `:where` の境界は、型パラメータを宣言した枠の内側の枠（`TypeScope::bound`）に置く。型パラメータが見えるところでは、その境界も見える。
- ジェネリックな本体で、受け手の型が型パラメータ `T` のメソッド呼び出しは、`T` の境界のトレイトとそのスーパートレイトからメソッドを探す。型は、トレイトのシグネチャの `Self` を `T` に、関連型を境界が固定した型に、位置で置き換えたもの。固定していない関連型が要るなら、まだ扱わない。
- そのような呼び出しは `TraitCall` ノードにする。特殊化した木を下ろすとき、受け手の型は具体型になっているので、その型の `impl` のメソッドの呼び出しにする。
- 呼び出しの位置では、型引数が境界を満たすかを確かめる。型引数がまだ穴なら、フォームをチェックし終えたところで確かめる。境界が固定した関連型は、`impl` が決めた型（`TraitImpl::assoc`）と単一化する。固定から型引数が決まるので、フォームの終わりの確認は、型引数が決まらないエラーより先に、進まなくなるまで繰り返す。型引数が呼び出し側の型パラメータなら、その境界（かそのサブトレイトの境界）が要る。具体型なら、その型へのトレイトの `impl` が要る。

### 7.7 並べて置く期間の扱い

`Type` は古いチェッカーと新しいチェッカーで共有する。

- `Type` に `Param` と `Infer` を足す。古いチェッカーは `Var` を使い続け、新しいチェッカーは `Var` を使わない。切り替えのときに `Var` を消す。
- 登録表は新しいチェッカー専用のものを別に作る。組み込みの型と関数の定義（今は `registry.rs` に `Var` で書かれている）は、並べて置く期間だけ、古い定義を位置の表し方に直す変換で読み込む。切り替えのときに、組み込みの定義のソースを新しい表し方に書き直し、変換は消す。
- ダンプ・LSP・コンパイラ・評価器が読む登録表は、切り替えのときに新しいものへ移す。

## 8. 登録表と core IR の組み立て（案）

### 8.1 登録表の形

- 定義は `Path`（モジュールとシンボル）をキーにした表に入れる。モジュールごとの入れ子の表にはしない。
  `Path` がすでに「どのモジュールの、どの名前か」を表しているからである。
- 名前空間は 2 つ。値（関数・グローバル変数・マクロ）と、型（型・型の別名・トレイト・C の構造体）。
  1 つのモジュールの 1 つの名前に結び付く値は 1 つだけ、型も 1 つだけ（`docs/dev/name-resolution.md` 1 節、`typelisp-user-error-types` の決定）。
  今の登録表のように、関数・変数・マクロを別々の表に入れて、同じ名前で両方を定義できる形にはしない。
- `use` の取り込みは「どのモジュールで、どの名前が、どの定義を指すか」の表にする。
- 型のメソッドは、型の定義の中ではなく「型の `Path` とメンバーのシンボル」をキーにした表に入れる。
  型の定義を書き換えずにメソッドを足せる（`impl` が型の定義を後から書き換えている今の形をやめる）。
- 表は、新しいチェッカーが必要とする種類だけを、必要になった段階で足す。

### 8.2 成功したときだけ確定する

登録表への書き込みは、すべて取り消し用の記録（書き込む前の値）を残す。
1 つの最上位フォームのチェックが成功したら記録を捨て、失敗したら記録をさかのぼって元に戻す（5.3 の実装）。
自己再帰は、記録を残しながら書き込んだ定義が、同じフォームの中から見えることで支える。

### 8.3 並べて置く期間の組み込みと prelude

prelude と組み込みの定義は、今の登録表に入っている（prelude はダンプから読み込まれる）。
新しいチェッカーは、最初のフォームをチェックする前に、今の登録表の中身を新しい登録表へ写す。
写すときに、名前の型変数（`Type::Var`）を位置（`Type::Param`）に直す。

- 関数：`FnSig::type_params` の `i` 番目を `Param{Def(関数), i}` にする。
- 型：`AdtDef::params` の `i` 番目を `Param{Def(型), i}` にする。
- メソッド：今の登録表は、型の側のパラメータを型の宣言名で書いている。型の側の `i` 番目を `Param{Method(型, m), i}`、
  メソッド自身の `j` 番目を `Param{Method(型, m), 型の数 + j}` にする（7.3 の形）。
- トレイト：`Self` を 0 番目、関連型を 1 番目から並べる（7.4）。
- `:where` の境界：名前のキーを `TypeParam` に直す。

この写しは並べて置く期間だけのもので、切り替えのときに、ダンプと組み込みの定義を新しい登録表の形に直して消す。

prelude のジェネリックな定義の本体（特殊化の元になるチェック済みの木）は写さない。新しいチェッカーが prelude のソースを自分でチェックして持つ（ユーザー決定、2026-11-09）。今のチェッカーに特殊化を頼む一時的な橋は作らない。そのため、新しいチェッカーが prelude の使うすべての機能を扱えるようになるまで、prelude のジェネリックな定義の呼び出し（「specializing」）は未対応のまま残る。切り替えのときに、ダンプを新しいチェッカーの形で作り直す。

prelude のソースは、型変数を宣言する形で書く（`impl<T> Option<T>`）。今のチェッカーもこの形を受け入れる。コアマクロの層と prelude の先頭からの 260 個のフォームは、新しいチェッカーでチェックできる（2026-11-09）。次に止まるのは `:dyn`（261 個目のフォーム）。

### 8.4 core IR の組み立て

core IR の形（`(call ...)`、`(let ...)`、`(defun ...)` など）を組み立てる関数は、今のチェッカーと共有する。
組み立てが型の情報として尋ねるのは、次の 3 つだけである。

- 型の種類（構造体か直和型か）：値の表現（`Repr`）を決める。
- 組み込み関数の宣言上の引数と戻り値の型：境界で `int` を生のワードとして渡すかを決める。
- 組み込みメソッドについての同じ問い。

この 3 つを必須メソッドにしたトレイト `check::lower::CoreForms` を置き、組み立て関数をその既定メソッドにした（2026-11-08）。
今のチェッカーの `Info` と新しいチェッカーの登録表が、それぞれこのトレイトを実装する。
今のチェッカーの木を自分で lower する組み立て（`pattern_form`、`labels_form`）と、名前の型変数を読むもの（`variant_field_tys`、`definition_form`、`method_definition_form`）は、今のチェッカーの側に残した。
新しいチェッカーで `match` と `labels` を扱うときに、lower 済みの形を受け取る組み立てに分け直す。

### 8.5 次の一本

ジェネリックでない関数の定義と呼び出し、ローカル変数、`let`、`if`。

```lisp
(defun pick ((c bool) (a int) (b int)) int (let ((x a)) (if c x b)))
(pick true 1 2)
```

登録表は関数の表と取り消しの記録だけを持つ。名前解決は、ローカル、今のモジュールの関数の順に探す（`use` と祖先は、それらを扱う段階で足す）。

## 9. 進み具合

### 9.1 新しいチェッカーで扱えるもの（2026-11-08）

- リテラル（整数・bignum・ratio・浮動小数・文字列・文字・真偽値・`()`・キーワード）。規則は `typeck::literal` にあり、今のチェッカーもそれを使う。
- ローカル変数、`let`、`progn`、`if`。
- `defun` と呼び出し。ジェネリックな `defun f<T>` を含む。本体は型パラメータを抽象のまま 1 回だけチェックし、呼び出しごとに型パラメータを穴にして解く。
  特殊化は、呼び出したフォームの束（`(module <monomorph specializations> ...)`）の中に、保存したチェック済みの木の型を置き換えて作る。
- 型引数が決まったかどうかは、フォームをチェックし終えたところで 1 回だけ確かめる。後ろの引数や外側の期待する型で決まってよい。
- 今のチェッカーの登録表の写し（8.3）。組み込みと prelude の関数・メソッド・型を呼べる。組み込みのジェネリックな関数とメソッド（`Vector::new` など）は特殊化せず、1 つの入口をすべての型引数で使う。型引数は結果の型が運ぶ。
- `defstruct`（既定値なし）、アクセサ、`make-instance`、フィールドの読み出し `p::x`。
- `defmethod`（`impl` の外）と固有の `impl<T...>`。静的メソッドの呼び出し `(Type::name ...)`、`use` で入った静的メソッド。
- `defenum`、変種の値 `(Name::Variant ...)` と `use` で入った裸の構築子、`module::f` の呼び出し。
- `match`：変種・束縛・`_` のパターン。網羅性は入れ子のパターンまで見る（行列による判定）。`Option` をニッチで表すかどうかは lower で決める。
- `Sexpr` の `match`：`Sexpr` の変種の名前（`cons`・`sym`・`int` など）のパターン。`Option<Sexpr>` には、`some` をはがしたものとして `Sexpr` の変種を書き、同じ腕の並びに `none` を書ける。網羅性は `none` と `Sexpr` の変種（退いた `nil` と `bignum` を除く）を合わせたもので見る。`(nil)` と `(bignum ..)` は今のチェッカーと同じ文で断る。
- 型がすでに持つメソッドを、トレイトの `impl` がメソッドを書かずに使うこと。種類（インスタンスメソッドか）、`&optional`・`&key`・`&rest` がないこと、シグネチャがトレイトのものと一致することを確かめる。トレイトに既定の本体があれば、そちらを使う（今のチェッカーと同じ）。
- 1 つの具体化のための `impl`（`(impl cons-cell<int,int> ...)`）。メソッドはその具体化のもので、コードは具体化の名前で作る。型引数がまだ決まっていない受け手での呼び出しは、まだ扱わない。
- `use`（`import`・`shadowing-import`・`pub use` を含む）。値・型・トレイト・別名・型の変種と静的メソッド・モジュールを名指しできる。
- `defvar`・`defparameter`・`defconstant`（型の宣言が必須）とグローバル変数の読み出し。`the`。
- `format`（宛先が真偽値のとき）・`print`・`println`。引数は、それぞれの型のまま `Sexpr` のリストにして渡す。どう `Sexpr` にするかは lower で、決まった型から選ぶ（`typeck::sexpr_value`）。制御文字列の指令と引数の型は、フォームをチェックし終えたところで照らし合わせる。
- `module`（`typeck::module`）と `pub`。`module` の本文の各フォームは子のモジュールで最上位のフォームとしてチェックし、すぐ効く必要のあるもの（`defmacro` など）はその場で評価器に入れる。`pub` は定義の印（`Definer::public`）。ほかのモジュールの `pub` でない関数・変数・マクロは、パスからは無いものとして扱う（「unresolved path」）。パスでグローバル変数を読める。
- 型の書き方：関数の型 `(fn (A &rest B) R)`、`::` のパス、リストの形 `(Name A)`、タプルの型 `#{A B}`。
- `deftrait`（`typeck::deftrait`）と、型へのトレイトの `impl`（`typeck::trait_impl`）。`Self` と関連型はトレイトの型パラメータで、`Self` が 0 番、`k` 番目の関連型が `1 + k` 番。`impl` の各メソッドは型のメソッドとして登録し、シグネチャはトレイトのものの `Self` と関連型を位置で置き換えたものと一致させる。`impl` のメソッドの型の中では、関連型の名前はその `impl` が決めた型を表す（`TypeScope::name_types`）。スーパートレイトの `impl` が先にあることも確かめる。
- トレイトの既定の本体。`deftrait` で 1 回だけチェックする。`Self` はそのトレイトを境界に持つ型パラメータで、関連型はトレイトのほかの型パラメータ。`impl` が省いたメソッドは型のメソッドとして登録し、本体はトレイトの既定の本体を、トレイトの型パラメータを `impl` の型に置き換えて作る（ジェネリックな `impl<T>` なら呼び出しの位置で特殊化する）。省いたメソッドを先に登録するので、書いたメソッドから呼べる。
- 期待する型への広げ方（`typeck::widen`）。`Sexpr` が期待されるところへは、`Sexpr` の符号がある値を広げる（`Symbol` と `Sexpr` はそのまま、ほかは `AsSexpr`）。`Option<Sexpr>` は `Sexpr` に狭めない。`rational` へは `int` と `ratio`。呼び出しの結果の型を先に期待と合わせるところでは、広げる先の型なら食い違いをエラーにせず、値をチェックしたところで決める。
- `quote`。記号は `Symbol`、ほかのデータは `Option<Sexpr>`。`quasiquote`：`,x` は `x` を `Option<Sexpr>` を期待してチェックし、`,@x` は prelude の `sexpr-append` でつなぐ。
- `defmacro`（`typeck::defmacro`）：引数と結果は `Option<Sexpr>`。`&optional`・`&key` の既定値は、それより前の引数を束縛してチェックする。本体は評価器が持つ。
- `list`（`typeck::list_form`）。各要素は `Option<Sexpr>` を期待してチェックし、`Sexpr` の cons 変種でつなぐ。`panic`（型は `!`）と `unwind-protect`（型は守られる式の型、後始末の値は捨てる）。
- `as`・`try-as`（`typeck::cast`）。変換は元の型のメソッドの呼び出しにする（表は旧チェッカーの `as_conversion`）。整数・浮動小数点数の族への変換は族の広い型で登録されているので、狭い型へはその後に幅の変換をつなぐ。トレイトオブジェクトへの `as` はまだ扱わない。
- `defun` の `&optional`・`&rest`・`&key`（`typeck::lambda_list`）と、それらを持つ関数・メソッドの呼び出し（`typeck::args`）。呼び出しは引数を 1 つずつそろえた呼び出しにする。省いた引数は、既定値（`defun` のときに引数を束縛せずにチェックし、core IR にして持つ）か `none`、既定値のない引数を渡したら `some` で包む。`&rest` の引数は 1 つの `Sexpr` のリストにする。既定値を持つ引数の型は、関数の型パラメータを含んではいけない。`defmethod` と型の `impl` のメソッドも同じ。トレイトの `impl` のメソッドは目印を書けない（トレイトのメソッドの引数の数は `deftrait` が決める）。
- 関数の値（`typeck::lambda`）：`lambda`、`labels`、`apply`、関数の型を持つ値の呼び出し、型パラメータと `&optional`・`&key` を持たない関数を値として取り出すこと。`lambda` と `labels` の関数の本体からは、外のループを抜けられない。`block` を扱うときは、`labels` の関数に名前の暗黙の block を付ける（旧チェッカーと同じ）。
- `let*`（入れ子の `let` にする）と、引数の数で意味が変わる呼び出し（`typeck::sugar`）：可変個の算術と比較、0 個・1 個の算術と比較、`(log x base)`、`(atan y x)`。書き換えた形をその位置でチェックする。3 つ以上の `append`・`concatenate`・`aref` はまだ扱わない。
- 1 つの本体を名指す道具（`typeck::tools`）：`compile`・`trace`・`untrace`・`disassemble`。名前は関数・マクロ・型のメソッドを指し、ジェネリックな定義は断る。1 つの具体化のためのメソッド（`Type<args>::member`）はまだ扱わない。
- `defun` の `:where` の境界（`typeck::bounds`、7.6）：境界のトレイトとスーパートレイトのメソッドをジェネリックな本体で呼ぶこと、呼び出しの位置で型引数が境界を満たすかを確かめること（境界の固定は `impl` が決めた関連型と単一化するので、固定から型引数が決まる。`impl` 自身の `:where` も確かめる）。`defmethod`・型の `impl`・トレイトの `impl` の `:where` も同じ（`impl` の `:where` は、メソッドごとに、その型パラメータの枠で読む）。トレイトの `impl` のメソッド自身の `:where`、ブランケット `impl` による実装、固定していない関連型を含むメソッドの型は、まだ扱わない。
- 単純な `loop` と `break`・`return`（`typeck::looping`）。ループの型は、出口が解く穴にする。何も出ないループは `!`。
- `setf`：変数（`defconstant` は断る）、フィールド `var::field`（構造体の `set-field`）、呼び出しの形の場所 `(accessor recv key...)`（受け手の型の `set-accessor`、`get` なら `set` も）。
- マクロの呼び出し（`typeck::macros`）。書かれたままの引数で展開し、展開したものを呼び出しの位置でチェックする。最上位では、定義のフォームとして読む前に展開する。マクロの本体は評価器が持ち（`MacroExpander`）、チェッカーは呼び出せる引数の数（`MacroShape`）だけを持つ。
- 定義の名前の規則（`typeck::define`）：予約語、std::prelude が与える名前を `(shadow ...)` なしで定義しないこと、関数・変数・マクロの名前空間と型・トレイト・別名・C 構造体の名前空間でそれぞれ名前が 1 つの意味であること、再定義の方針（`RedefPolicy`）、組み込みを置き換えないこと。
- 新しいチェッカーが定義した型とメソッドを、セッションの名前表に公開する（後のフォームでパスが読めるように）。
- 標準ライブラリの中の定義（`typeck::library`）。標準ライブラリのモジュールで定義したフォームの後に、`std` がそのモジュールたちの定義をすべて取り込み、`std::prelude` が `prelude_offers` の定義と、その関数と変数の型が名指す型を再公開する。名前は標準ライブラリのモジュールをまたいで 1 つ（型の名前はすべてのモジュールで 1 つ）。標準ライブラリの型の固有の `impl` は、標準ライブラリのどのモジュールでも書ける。
- ドキュメント文字列（`Doc` の表）：`defun`・`defmacro`・`defvar`・`defstruct`・`defenum`・`deftrait`・`defmethod`・`impl` のメソッド・既定の本体を持つトレイトのメソッド。
- `Option` が期待されるところの `()` は `none`。`Option<Sexpr>` の受け手は `Sexpr` のメソッドにも答える（`Sexpr` にないものは `Option` のもの）。
- 1 つの最上位フォームの登録は、成功したときだけ確定する。

### 9.2 まだ扱っていないもの

新しいチェッカーがこれらに出会うと `unimplemented!()` で止まる。切り替えまでに、すべてを扱えるようにする。

- 名前と型：`deftype`、`defstruct` の既定値と付属、トレイトオブジェクトの型 `:dyn`、C のポインタ `(ptr ...)` と C のワード（`ptr`・`c-long`・`c-ulong`）と `unsafe`。
- 定義：prelude のトレイトの既定の本体（チェック済みの木が無い）、トレイトのメソッドの `:where`・`:where` を付けた `impl`・1 つの具体化のための `impl`・関連型を固定したスーパートレイト・ブランケット `impl`・`:where` の境界のある呼び出しとジェネリックな本体での境界のメソッド・`:dyn`、`defsignature`、`defffi`、`def-c-struct`、`pub` を付けた `defsignature`・`defffi`・`deftype`。
- `match`：`Sexpr` からのダウンキャストと `(the T x)`、値のパターン、`:when`、`:or`、`Sexpr` の形とダウンキャスト、構造体のパターン、トレイトオブジェクトの match。
- 式：拡張した `loop`（`:for`・`:collect` など）、`setf` の C のポインタ越しのフィールド・タプルの要素・`aref`・`c-deref`、関数を値として使うこと、ローカルな関数値の呼び出し、式の値を関数として呼ぶこと、`macrolet`、メソッド呼び出し、組み込みの関数とメソッド（8.3 の写しが要る）、残りの特殊形（3.2 の一覧）。
- `format` の宛先がストリームのとき（`CharOutput` を実装しているかを問う）、`~/name/` 指令、`eprint`・`eprintln`。
- `:dyn` への暗黙の変換（トレイトオブジェクトを作る）と、トレイトオブジェクトを `Sexpr` に入れること。
- 定数の畳み込み（今のチェッカーは、条件がリテラルの `if` などを lower のときに畳む）。
- LSP 向けの記録（定義位置、ドキュメント、ローカル参照、式の型）、エラー回復モード、`#[test]` の収集。

### 9.3 今のチェッカーと振る舞いが変わる点

切り替えのとき、これらに合わせてテストの期待を直す。

- 型引数の推論がフォーム全体で行われる。`(Tree::Node (Tree::Leaf) "a" (Tree::Leaf))` は今のチェッカーでは `T` を推論できずに断られるが、新しいチェッカーでは通る。
- 網羅性を入れ子のパターンまで見る。`((Full (Circle r)) ..) (Empty ..)` は今のチェッカーでは通り、実行時に `no matching match arm` で止まる。新しいチェッカーは `(Full (Rect _ _))` が漏れているとして断る。
- 網羅していないときのメッセージは、漏れている値を 1 つ示す（「`(Rect _ _)` is not covered」）。
- `Option<Sexpr>` の `match` で、裸の `none` を変種として受け入れる（裸の名前は変種という規則のまま）。今のチェッカーは `(none)` と書くことを求める。
- `:where` の境界は、定義が宣言した型パラメータにしか付けられない。今のチェッカーは `(defun f<T> ... (:where (shape U)) ...)` を黙って受け入れる。
- 宣言していない型変数を使うテスト（`(impl Box<T> ...)`、`(defmethod m ((v Vector<T>)) ...)`）は断られる。宣言を足す（`impl<T>`、`m<T>`）。
- 型引数も、呼び出しの位置で決まらなければフォームの残りで決まる。`(let ((v (Vector::new))) (push v "a") v)` は今のチェッカーでは「`T` を推論できない」と断られるが、新しいチェッカーでは `v` が `Vector<string>` になって通る。
- 数値リテラルの型は、書かれた位置で決まらなければフォームの残りで決まる（Rust と同じ）。`(let ((x 1)) (id8 x))` は今のチェッカーでは型の不一致だが、新しいチェッカーでは `x` が `u8` になって通る。何も決めなければ `int`（浮動小数は `f64`）。
- 呼び出し `(name x ...)` の第 1 引数は 1 回だけチェックする。今のチェッカーは、`x` を試しにチェックし、メソッドがなければもう一度チェックするので、関数名がどこかの型のメソッド名でもあると、第 1 引数に入れ子にした呼び出しに深さの指数の時間がかかる（深さ 20 で 26 秒）。
- `impl` が既定の本体のないメソッドを省いたとき、新しいチェッカーは「missing method」と断る。今のチェッカーは既定の本体をその型でチェックし直すので、省いたメソッドの呼び出しの位置で「no method `n` for type `D`」と断ることがある。
- ジェネリックな本体の `format` で、型パラメータの引数は「どんな値でも印字する指令」しか受けない（`~c` や `~{` は断る）。本体は 1 回だけチェックするので、すべての型について成り立つことだけを認める。今のチェッカーは特殊化ごとに照らし合わせ直していた。

### 9.4 1 回の走査でチェックする

木の各ノードは 1 回だけチェックする。推論の状態（穴とその解）は 1 つの表で、走査に沿って育つだけで、写しを取ることも巻き戻すこともない。

- 呼び出しの第 1 引数は期待する型なしでチェックし、その型でメソッド表、なければ関数表を引く。関数なら、チェック済みの引数をパラメータの型と単一化する（rustc の `check_expr_method_call` と同じ形）。
- 期待する型でしか決まらないものは、期待する型がないときに推論変数にする。数値リテラルは整数（浮動小数）にしかなれない穴になり、フォームの終わりで決まっていなければ既定の型にして、そこで範囲を確かめる（rustc の `next_int_var` と数値の fallback）。
- 型をその場で見なければならないところ（受け手のメソッドを引く）では、決まっていない数値の穴を既定の型として見る。メソッドが見つかったときだけその型に決める。`(+ 1 x)` は `int` の `+` で、`(id8 1)` の `1` は `u8`。
- `()` を `Option::none` とする規則と、`Sexpr`・`:dyn` への広げは、まだ扱っていない（9.2）。扱うときも、チェック済みの木に後から変換を足す形にし、チェックし直さない。
