# 値を型の幅で運ぶ（設計）

2026-11-24 ユーザー指示: 「Lチカぐらいの小さなプログラムだと、これは大きな問題になるので、必要なビット幅だけで運ぶ計画を、部分だけみるのではなく全体的な設計を考えて」。同日の決定: 語の幅はターゲットのポインタの幅に合わせる。直接の関数は AOT だけ（組み込みで REPL は要らない。REPL を含まない実行ファイルを作れることが条件）。AVR 用のランタイムは今は持たない。前提は `docs/dev/numeric-widths-design.md`（演算は型の幅で計算するようになった）。その測り直しで、`(+ a b)`（`i8`）の関数全体が AVR で 165 命令のままだと分かった。演算は 2 命令で、残りは値を運ぶ仕組みである。

## 今の形

コンパイル済みコードのあらゆる値は 64bit の語で運ばれる。運ばれる場所と仕組み:

| 場所 | 仕組み |
|---|---|
| 式の中 | LLVM の `i64` の SSA 値。演算は型の幅で計算するが、結果は語に戻す |
| ローカル・引数 | 関数ごとにヒープに確保するフレーム（`rt_frame_open`、`BoxedObj::Frame`、`Vec<i64>` とコレクタ用のマスク）のスロット |
| 呼び出し | 全ての関数がコルーチンの ABI（`i64 f(i64 frame)`、戻り値は状態語、値はスロット 0）。引数はスレッドローカルに置いて呼び先が `rt_pending_arg` で受け取る。呼び出しは駆動する側（`FrameStack`）を通る |
| ランタイムの関数 | 全て `i64 rt_x(ptr args, i32 argc)`。島は引数の配列を確保して 64bit ずつ書く（島の中に `alloca-args` 107 か所、`store-arg` 210 か所） |
| 大域変数 | ランタイムの表（`rt_global_get`/`rt_global_set`） |
| ヒープのオブジェクト（構造体・列挙・クロージャの環境・`Sexpr`） | タグ付きの語（固定幅の整数は fixnum、浮動小数は箱） |
| 実行時エラー | ランタイムが旗（`typelisp_abi::raise`）を立てて戻り、コンパイル済みコードが状態語 `STATUS_UNWIND` で返る |

コルーチンの ABI は、タスク・チャネル・`sleep`・ループの safepoint で関数が途中で止まれるように作ったもの（`docs/dev/compiled-cps-design.md`）。止まらないプログラムも、全ての関数がこの形で運ばれる。

結果:

- 8bit・32bit の機械では、どの値も 64bit で運ばれる。AVR では 1 つの値の受け渡しが 8 レジスタになる。
- 止まらない関数も、呼ぶたびにヒープにフレームを作り、引数をスレッドローカル経由で渡す。Lチカの実行ファイル（Cortex-M、約 6 万 9 千バイト）のかなりの部分が、この駆動（`FrameStack`）とヒープである。
- ランタイムを呼ぶたびに、引数の配列をメモリに作る。

## 原則

1. **値はその型の LLVM の型で運ぶ。** 語（タグ付き、ターゲットのポインタの幅）で運ぶのは、ヒープを指しうる値と、語でしか置けない場所（下の「語の運び手」）だけ。
2. **止まらない関数は、普通の関数にする。** 引数と戻り値は型のとおり、ローカルは関数の中。止まりうる関数だけがコルーチンの ABI を使う。
3. **語との変換は、語の運び手に入る・出るところの 1 か所だけ。** 数値の設計で「計算の型と語」の変換を命令を作る関数に置いたのと同じ形を、値を運ぶ全体に広げる。
4. **使わないものはリンクしない**（組み込みの段階 8）を最後まで通す。ヒープも、駆動も、ランタイムそのものも、要らないプログラムには入れない。

## 型と運ぶ型

| 型 | LLVM の型 |
|---|---|
| `i8` `u8` | `i8` |
| `i16` `u16` | `i16` |
| `i32` `u32` | `i32` |
| `f32` | `float` |
| `f64` | `double` |
| `bool` | `i1`（メモリ上は `i8`） |
| `char` | `i32` |
| `()` | 運ばない（`void`、引数からは外す） |
| `c-long` `c-ulong` | ターゲットの C の `long` の幅（LP64 は `i64`、Cortex-M と AVR は `i32`） |
| `ptr`、`(ptr T)` | `ptr` |
| ヒープを指しうる値（`int`、`string`、`Sexpr`、構造体、列挙、クロージャ、`Vector` など） | 語（タグ付き、ターゲットのポインタの幅） |

この表は Rust の 1 か所（`Repr` から LLVM の型）に置き、島はそれを問う。今の `Repr` と `field_kind`/`binding_kind` の番号がそのまま使える。

`c-long` は今 `i64` に決め打ちしていて、Cortex-M（C の `long` は 32bit）で C の関数に渡す値の幅が誤っている。この表に入れることで直る。C の構造体のメモリを読み書きするランタイム（`typelisp-rt/src/c_mem.rs` の `KIND_C_LONG`/`KIND_C_ULONG`/`KIND_PTR`）も 8 バイトとして読み書きしていて、32bit の機械では C の構造体の配置と合わない。チェッカーが読み書きの種類を幅で決める（`KIND_RAW_I32`/`KIND_RAW_U32`/`KIND_RAW_64`）ことで直す。ランタイムは C の `long` の幅を問わない。

### 語の幅はターゲットのポインタの幅

語（タグ付きの値）の幅は、ターゲットのポインタの幅にする。ホスト（64bit）は今と同じ、Cortex-M と wasm32 は 32bit、AVR は 16bit。語はヒープを指すので、ポインタと同じ幅であるのが本来の形である。

- タグの表（`typelisp-mem/src/tagged.rs`）を語の幅に依らない形にする。語は `isize`、fixnum は語の幅 − 1 bit（64bit で 63bit、32bit で 31bit、16bit で 15bit）。`int` の意味は変わらない（多倍長）。変わるのは fixnum と多倍長の境目だけ。
- 境目はターゲットで決まる。コンパイラはホストで動くので、`int` のリテラルや畳み込んだ定数をコンパイル済みコードに書くときは、ターゲットの fixnum の範囲で、fixnum の語か多倍長の箱かを選ぶ。ホストの `Value::Int` が fixnum かどうかとは別に問う。
- 小さな値のタグ（`TAG_SMALL` の下の文字・文字列・パスの番号）は、語の幅 − 6 bit に入る番号だけを持てる。32bit では約 6700 万、16bit では 1024 で、AVR でヒープを使うプログラムを動かす日が来たら制約になる。
- ヒープのフィールド（構造体・列挙の値）は、ランタイムの関数を通してだけ読み書きしている（`rt_struct_field_get`、`rt_data_field` など）。下の「ランタイムの関数の呼び出し規約」で型のとおりに渡すので、フィールドの値を語に詰める必要が無くなる。語の幅が 32bit でも `i32` のフィールドは `i32` のまま渡る。
- クロージャの環境は、コンパイル済みコードが語の配列を直接読んでいる（`load-env`）。コルーチンのフレームのスロットも語である。語が 32bit になると `f64` も 64bit の `c-long` も 1 つの語に入らないので、環境もフレームも、型ごとの大きさと揃えで並べる（コレクタには語のスロットの位置だけを渡す）。
- prelude: 今は、ホスト向けにコンパイルしたビットコード（`prelude.typld`）を AOT がそのままリンクしている。語の幅がターゲットで変わるので、AOT はプログラムから届く prelude の関数を、ダンプの検査済みの状態からターゲット向けにコンパイルする。JIT は今のビットコードを使う。届く関数だけをコンパイルするので、実行ファイルも小さくなる。
- インタプリタとの境界（JIT）とダンプはホストだけのもので、64bit のまま変わらない。

## 関数の 2 つの形

### 直接の関数とコルーチン

- **直接の関数**: `define <戻りの型> @f(<引数の型>...)`。ローカルは `alloca`（LLVM が SSA にする）。呼び出しは LLVM の `call`。
- **コルーチン**: 今のコルーチンの ABI。

ある関数がコルーチンになるのは、その関数が止まりうるときだけ。止まりうるとは、呼び出しの木をたどって次のどれかに届くこと。

- 止まる操作（`rt_suspend_*`。`yield` も含む）。
- ループの safepoint。ただし、プログラムにスケジューラがあるときだけ（`externs::needs_scheduler` と同じ問い）。スケジューラの無いプログラムでは、safepoint はもともと何もしない。
- `eval` などインタプリタに入る呼び出し。
- 自分自身に戻ってくる呼び出し（再帰）。直接の関数は機械のスタックを使うので、直接にすると「再帰の深さの上限はヒープ」という性質が壊れる（2026-11-24 ユーザー決定）。
- 間接呼び出し（クロージャ、`:dyn` のメソッド、`apply`、関数値の呼び出し）。ただし、プログラムの中に止まりうる関数値が 1 つも無ければ、間接呼び出しも止まらない。関数値の呼び出し規約は 1 つにする必要があるので、間接呼び出しの扱いはプログラム全体で 1 つに決める。

コルーチンから直接の関数は普通に呼べる。直接の関数はコルーチンを呼ばない（呼ぶなら、その関数自身が止まりうるので、コルーチンになる）。だから 2 つの形は混ざっても矛盾しない。

スケジューラの無いプログラムでは、`eval` も再帰も `catch` も間接呼び出しも使わない限り、全ての関数が直接の関数になる。そのときは駆動（`FrameStack`）も、フレームのヒープへの確保もリンクされない。

### どこで決めるか

- AOT（`typl -c`）: プログラム全体が見えるので、関数ごとに決める。
- JIT と REPL: 後から定義される関数がどう呼ぶかが分からないので、今のまま全てコルーチンにする。実行ファイルの大きさの問題はここには無い。

島は両方を出せるようにする。どちらで出すかは関数ごとに Rust 側が決めて島に渡す。フレームの扱いは今も命令を作る関数（`frame-slot`、`coroutine-begin`、`coroutine-call`、`coroutine-end` など、島の中で数か所ずつ）に隠れているので、直接の関数でもそれらが別の命令を出す形にできる。

### 実行時エラーと `catch`

実行時エラーの旗（`typelisp_abi::raise`）は今のまま使う。直接の関数は、エラーを起こしうる呼び出し（ランタイムのエラーを起こす関数と、そういう関数を呼ぶ関数）のあとで旗を見て、立っていれば自分の後始末（`unwind-protect`、`catch` の受け口）へ行くか、そのまま戻る。旗を見る必要があるかは、呼び出しの木で決める（エラーを起こしえない呼び出しのあとでは見ない）。

プログラムのどこにも受け取る側が無ければ（`catch` もハンドラも無い）、エラーは起きた所でプログラムを終える。そのときは旗を見る命令も要らない。Lチカはこれに当たる。

### コレクタの根

直接の関数のローカルのうち、ヒープを指しうる値（語）で、メモリを確保しうる呼び出しをまたいで生きるものは、コレクタに見えなければならない。そういう関数だけ、スタック上の語の配列を根の鎖につなぐ（shadow stack）。関数の入口でつなぎ、出口で外す。どのローカルが語かは型で決まっているので、マスクは要らない。ヒープを使わない関数は何もしない。

## 運ぶ場所ごとの形

| 場所 | 直接の関数 | コルーチン |
|---|---|---|
| 式の中 | 型の LLVM の型 | 型の LLVM の型 |
| ローカル | 型の `alloca` | フレームの、型の大きさのスロット |
| 引数・戻り値 | 型のとおり（`()` は外す） | フレームの、型の大きさのスロット |
| ランタイムの関数 | 型のとおりの C の関数 | 同左 |
| 大域変数 | 型の LLVM の大域変数。語の大域変数はコレクタの根の表に載せる | 同左 |
| ヒープのフィールド | ランタイムの関数に型のとおり | 同左 |
| クロージャの環境 | 型の大きさで並べる | 同左 |
| `Sexpr` | 語 | 語 |
| 割り込みのハンドラ | 直接の関数（止まる操作は今も断っている） | — |
| インタプリタとの境界（JIT の `call_compiled`） | — | 語 |

語で運ぶのは、ヒープを指しうる値そのものと、`Sexpr` の中、インタプリタとの境界（JIT）だけになる。`Sexpr` に入るところでの直し方は今の `field_kind` が決めているものと同じ（固定幅の整数と浮動小数は箱）。

コルーチンのフレームとクロージャの環境は、語の幅が 64bit 未満のターゲットのために、型ごとの大きさと揃えで並べる（上の「語の幅はターゲットのポインタの幅」）。

### ランタイムの関数の呼び出し規約

`i64 rt_x(ptr args, i32 argc)` をやめて、型のとおりの C の関数にする（`extern "C" fn rt_u8_box(v: u8) -> u64`）。引数の配列を作る命令が無くなり、AVR でも Cortex-M でもレジスタで渡る。

- 関数の型は `externs.rs` の表に、Rust の関数そのものから持たせる（表が関数ポインタを持っているのと同じ所）。島は名前と引数を渡し、Rust 側が型を見て `call` を作る（`build-call` を `call-runtime` に置き換える）。
- 全てのランタイムの関数を一度に移す。2 つの呼び出し規約を並べて残さない。

## 要らないランタイムを外す

スケジューラも `eval` も無く、ヒープを使わない（`cons`、文字列、構造体、多倍長を作らない）プログラムは、ランタイムの関数を 1 つも呼ばない。そういうプログラムには、ヒープの初期化もリンクしない。

- 入口（`main` の前の初期化）は、使う機能から組み立てる。ヒープを使わないなら、ヒープを用意しない。
- エラーでプログラムを終えるのに要るもの（ボードの `exit`、または止める命令）だけが残る。

AVR では、これが前提になる。今のランタイムは Rust で書かれていて、AVR は Rust では tier 3 のターゲット（安定版ではビルドできず、nightly と `build-std` が要る）。ランタイムを使わないプログラムなら、コンパイル済みコードと小さな入口だけで動く。

## 確かめ方

- 命令の形: 直接の関数の IR に `rt_frame_open` と `rt_pending_arg` が無く、`i8` の引数が `i8` で渡ること。コルーチンになるべき関数（`sleep` を呼ぶ関数）がコルーチンのままであること。
- 意味の一致: 今の全体テストを、AOT の直接の関数で通す。`numeric_agreement_test` のような 3 経路の一致のテストに、AOT の実行ファイルの答えを加える（JIT はコルーチン、AOT は直接の関数なので、2 つの形の一致がそのまま確かめられる）。
- コレクタ: 直接の関数が語のローカルを持ったまま確保する呼び出しを、GC を毎回走らせる設定で回す。
- リンク: Lチカに `FrameStack`、`rt_frame_open`、ヒープの初期化の記号が無いこと（`what_a_program_does_not_use_is_left_out` に足す）。`eval` を使わないプログラムにインタプリタ（`typelisp_front`）の記号が無いこと（今も無いことは確かめた。番人のテストが無いので足す）。
- 語の幅: Cortex-M（32bit）で、fixnum の境目をまたぐ `int` の演算、`f64` と `c-long` を持つクロージャとコルーチン、構造体の `i32` のフィールドが、ホストと同じ答えになること。
- 大きさ: Cortex-M の Lチカと `(+ a b)`（`i8`）の関数の命令数。AVR に移ってからは、AVR の実行ファイルの大きさ。

## 進め方

1. 型から LLVM の型への表を Rust の 1 か所に置く。語の型もこの表から引く（まだ 64bit）。`c-long` をターゲットの C の `long` の幅にする。
   実装: C の幅は `typelisp_mem::target::DataModel`（AOT のドライバがビルドの間だけターゲットのものにする）。チェッカー（構造体の配置、リテラルの範囲、畳み込み）、インタプリタ、FFI の thunk、島（`c-long-bits`）がこれを問う。語と整数の LLVM の型は `src/compile/carriers.rs`。ホスト以外へのビルドでは、コンパイル中に C の関数を呼ばない。
2. ランタイムの関数を型のとおりの C の関数に移す（`call-runtime`、全ての関数を一度に）。島を 2 回再生成、prelude、ABI。
   実装: ランタイムの関数は全て固定の引数の C の関数（値は語、`i64`）。引数が任意の長さのもの（`rt_struct_new`、`rt_frame_call`、`format` の部品など）だけが配列と長さ（`*const i64, u32`）を取る。表（`externs.rs`）は各関数をその型の関数ポインタへのキャストで持つので、定義と食い違うとコンパイルが通らない（`runtime_abi.rs`）。島の `build-call` は呼び先がランタイムの関数なら、島が配列に書いた語を読み戻して型どおりに呼ぶ。配列は `-O1` 以上で LLVM が消す。島の書き方（`alloca-args`/`store-arg`）を変えるのは、値が型を持つ段階 3 にまとめた。古い規約の島で新しい島を作るために、1 回目の再生成だけ古い呼び出しを書き換える一時的なコードを使い、消してから再生成して不動点を確かめた。
3. 島の値を型のとおりにする。段階 6 にまとめた（2026-11-24 ユーザー決定）。島は式の値を 1 つずつフレームのスロット（語）に置くので（途中で止まっても残るように）、スロットが語である間は、値に型を持たせても演算のたびに語に戻る。型どおりのスロットが要るのは、語が 64bit より狭くなる段階 6 である。島の `alloca-args`/`store-arg` の書き換えも段階 6 で行う。
4. 直接の関数（AOT）: 止まりうるかの判定、直接の関数の入口・呼び出し・戻り、実行時エラーの旗、コレクタの根。JIT は今のまま。
   実装: 型から LLVM の型への表は `carriers::Carrier`（`Repr` の固定幅の整数は幅を持つ）。判定は `src/compile/aot/direct.rs` で、島の中間表現から読む。直接の関数の表（`src/compile/direct.rs`）はビルドの間だけあり、島は何も知らず、コルーチンを組み立てる関数（`coroutine-begin`、`coroutine-call`、`coroutine-end`、`frame-slot` など）が表を見て形を選ぶ。引数と戻り値は型どおり、スロットは語のままでスタックの配列に置く。コレクタの根になるスロットがある関数は、スロット全部をタスクの根の積みに開いた局所のフレーム（`rt_local_frame_open`）に置き、戻りと巻き戻しの両方の出口で閉じる。`catch`、`unwind-protect`、`labels`、間接呼び出し、再帰を含む関数と、スケジューラのあるプログラムのループは、コルーチンのまま。実行環境に番地を渡す関数（入口、vtable、`print-object`、割り込みのハンドラ、C のコールバック）と、`eval` に届くプログラムの全ての関数も、コルーチンのまま。prelude の関数は、止まらないものを `名前$direct` として写し、プログラムからはそれを呼ぶ。
5. 要らないランタイムを外す（ヒープの初期化、駆動）。Cortex-M で Lチカを測る。
   実装: 直接の関数は出し終えたあと、最適化のレベルに依らず整える（`src/compile/aot/settle.rs`。スロットを値にする、番地が定数の `volatile` を命令にする、エラーを起こしえない呼び出しの後の旗の確認を消す）。プログラムの入口にも直接の写しを作る。そこからランタイムの関数に届かず、自分の `defvar`・C のコールバック・割り込みのハンドラ・`eval` も無ければ、生成する `main` は写しを呼ぶだけで、ヒープも作らない。ランタイムは使うが、待つものも初期化する大域変数も無ければ、駆動を通さず写しを呼び、答えを `rt_main_answered`/`rt_main_returned` に渡す。ボードのヒープと割り込みの用意は、ランタイムを使うプログラムだけが呼ぶ（`typelisp_board_start`）。番地が変数の `volatile` は今もランタイムの関数を呼ぶ。大きさ（Cortex-M4、Lチカ、release のランタイム）: `-O2` で text 2060 バイト（ベクタ表 960 バイトを含む）、`-O0` で 2292 バイト。
6. 語の幅をターゲットのポインタの幅にする: 島の値とスロットを型のとおりにする（段階 3）、タグの表、fixnum の境目をターゲットで選ぶ、コルーチンのフレームとクロージャの環境を型ごとの配置にする、AOT で prelude をターゲット向けにコンパイルする。Cortex-M と wasm32 で確かめる。全体テストを通せる 5 段に分ける。
   1. ランタイムの語を `Word` にし、語でない値（浮動小数、固定幅の整数、`char`、`bool`）を型のとおりの署名で渡す。実装済み。`Word` は 64bit のホストでは `isize` で、署名の表が `i64` と区別できる。32bit のターゲットでは、生成コードの語が 64bit の間は `i64`。呼び出しの答えは 64bit の値で受け渡し、幅の広い値は複数の語に分ける（`value_words`/`raw_value`）。C の整数は、ランタイムの署名ではどのターゲットでも 64bit。
   2. 島の値とスロットを型のとおりにする。`alloca-args`/`store-arg` を無くし、タグの付け外しは Rust の 1 か所に置く。実装済み。値は `Carrier` の LLVM の型で組み立てから使用まで運ぶ（`bool` は `i1`、`char` は `i32`、`()` は語の 0）。置き場は 3 種類（`src/compile/llvm_builtins/slots.rs`）: 呼び出しの引数の並び（記録だけで、記憶域は無い）、一時置き場、フレームのスロット。置き場の型は最初に入れた値の型で決まるので、島は幅を知らない。戻ってこないコード（`panic` など）の値は「値が無い」という印で、置いても何も起きず、何も置かれなかった置き場を読むとそれが返る。呼び出しの答えは語で戻るので、中間表現の呼び出しの節（`call`、`apply`、`dyn-call`、`assoc`、`fnref`、`methodref`）は答えの表現を持ち、`int-any-width` は型を持つ。固定幅の整数の欄の番号は幅ごとに分けた（`field_kind::FIXED`）。語に入れた狭い値の残りのビットに意味は無く、読む側が型の幅だけを読む。島の新しい本体は、1 つ前の版のコンパイラで組み立ててから、不動点まで作り直した。
   3. コルーチンのフレームと引数を、幅の広い値が複数の語を使う配置にする。クロージャの環境は全部セル（タグ付きの語）なので変えない。
   4. AOT で prelude をターゲット向けにコンパイルし、fixnum の境目をターゲットで選ぶ。
   5. 語の幅をターゲットのポインタの幅に切り替える。`volatile` の番地は `int` の語で渡っていて、32bit では fixnum に入らない番地があるので、番地として渡す。
7. AVR: ターゲットの追加、入口、ボードの記述、Lチカを動かす。

1〜3 は JIT にも効く変更で、今の全体テストがそのまま番人になる。4 から AOT と JIT の形が分かれる。Lチカはヒープを使わないので、AVR で動かすのに 6 は要らない。6 は、ヒープを使うプログラムを 32bit の機械で小さく正しく動かすための段階である。
