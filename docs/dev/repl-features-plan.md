# REPL の機能を増やす計画

2026-11-26 決定。SBCL・CCL・CLISP・Allegro・SLIME の REPL を参考に、`typl` の REPL に次の 5 つを足す。

1. 実行中の計算を Ctrl-C で止める、エラー時のバックトレースとフレームの局所変数
2. 入力の支援(補完、引数一覧の表示、括弧の対応、継続行の字下げ)
3. 調べる道具(describe、apropos、inspect、ソース表示、who-calls)
4. 前の結果の参照(`:*` `:**` `:***`)
5. セッションと環境(プロンプトにモジュール、初期化ファイル、`--eval`/`--load`、`:help`、`:cd`/`:pwd`)

## 前提: 今あるもの

- `src/main.rs` の `repl`: rustyline の `DefaultEditor`、履歴 `~/.typl_history`、複数行入力(`is_incomplete`)、`:type`/`:t`、`:quit`/`:exit`
- 道具: `trace`/`untrace`/`step`/`disassemble`/`room`/`ed`/`dribble`/`time`/`documentation`/`macroexpand`
- モジュールの切り替えは `(in-module ...)` が既にある。REPL は `user` から始まる
- エディタ向けの表はチェッカーが既に持っている: `Checker::completion_candidates`、`docs`、`definitions`、`def_locs`(`typeck/editor.rs`、LSP が使う)

## REPL コマンドの決まり

- REPL コマンドは行頭の `:名前`。今の `:type`/`:quit` と同じ
- コマンドの一覧は 1 つの表に置き、`:help` もディスパッチもその表を読む。表に無い `:名前` が行頭に来たときは、フォームとして読む(キーワードの評価)
- 例外は `:*` `:**` `:***`(段階 6)。これはコマンドではなく式で、式の中のどこにでも書ける

## 段階

影響の大きいものから、後の段階が使う土台を先に作る順に並べる。

### 段階 1: コマンドの土台とセッション(項目 5)

- コマンド表 `REPL_COMMANDS`(名前、短い名前、説明)を作り、`:type`/`:quit`/`:exit` をそこへ移す。番人テストで「表にある名前はすべてディスパッチされる」を確かめる
- `:help`: 表を一覧にする
- プロンプトに今のモジュールを出す(Allegro の `CL-USER(1):` に当たる)。`(in-module ...)` で変わる
- 初期化ファイル `~/.typlrc`(SBCL の `.sbclrc`)。REPL を始める前に読む。`--no-init` で読まない
- `--eval FORM` と `--load FILE`(SBCL)。書いた順に実行してから REPL に入る。`-c` やスクリプト名とは組み合わせない
- `:cd DIR`/`:pwd`。`use` の解決元(`Loader` の src_root)は移さない。読み込み済みのモジュールはそこから見つけたものなので、途中で移すと同じモジュールを別のファイルとして読み直しうる。`(load ...)` はプロセスのカレントフォルダから解決するので `:cd` に従う
- 実装: `src/repl/`(`mod.rs` が読む・評価する、`commands.rs` がコマンド表)。`main.rs` は環境を読み込んで `typelisp::repl::run` に渡すだけ。プロンプトは `user` では `typl> `、それ以外では `typl user::foo> `(文書の例は `user` なので変わらない)

### 段階 2: Ctrl-C で計算を止める(項目 1 の前半)

- SIGINT のハンドラは、プロセス全体で 1 つの `AtomicBool` を立てるだけにする。`readline` の最中は rustyline が端末を raw にしているので、今までどおり入力の破棄として届く
- フラグを見る場所
  - インタプリタ: `step_task` の 1 歩ごと(`core_cps.rs`)。立っていたら `EvalError::Interrupted` で巻き戻す。`unwind-protect` の後始末は走る
  - コンパイル済みコード: ループの safepoint(C7)は 256 回に 1 回ドライバへ番を渡すので、ドライバ側で見れば足りる。番を渡さない経路(関数入口の `rt_safepoint`、古い呼び出し規約の本体)で止まらない形が残るかを確かめ、残るなら塞ぐ
  - 待ち(`recv`、`sleep`、I/O)で止まっている間も止められること
- 止まったら `interrupted` と場所を出してトップレベルへ戻る。セッションの定義は残る
- `catch` や `Result` で握りつぶせない(CL の `interactive-interrupt` も普通の `handler-case` では拾わない慣習)
- REPL の外(`typl file.typl`、AOT 実行ファイル)は今までどおり既定の動作で終わる
- テスト: 子プロセスに無限ループを送り、SIGINT を送って、次の入力が評価されることを確かめる
- 実装: フラグは `typelisp_abi::interrupt`。答えるのはドライブの主タスク(`Task::drive_main`)だけで、インタプリタの 1 歩の前(状態が解釈中のときだけ)と、待ちから覚めて答えを受け取るとき(`Task::deliver`、safepoint の番もここを通る)に `EvalError::Interrupted` へ替える。待っている主タスクはスケジューラが `SchedError::Interrupted` で起こす(`interrupt_waiting`)。そのためにメインのスレッドの待ちは `LOOK_EVERY`(50ms)で区切る
- コンパイル済みフレームへは既存の `InterpretedUnwind` の経路で渡るので、種類を保ったまま届き、フレームの中の `unwind-protect` も走る
- `recv` で相手のいないチャネルを待つのは、今までどおりデッドロックとして即座にエラーになる(割り込みの前に答えが出る)

### 段階 3: バックトレースと局所変数(項目 1 の後半)

- リスタートは採らない方針なので、選択式のデバッガは作らない。エラーで止まったら「場所の一覧を出してトップレベルへ戻る」
- 関数の本体はこれまでフレームを積まなかった(本体の式の列は `Seq` が持つ)。名前のある関数の本体に入るとき `Frame::Call` を積む。これは `Seq` の代わりも兼ねる(本体の残りの式と環境を持つ)ので、呼び出しごとのフレームの数は増えない
- 末尾呼び出し: 最後の式を評価している `Frame::Call`(残りの式が無い)の上に次の `Frame::Call` を積むときは置き換える(`CpsStack::push`)。末尾再帰のループはフレーム 1 つのまま走る。末尾で呼ばれた関数の呼び出し元はバックトレースに出ない(SBCL と同じ)
- 失敗が `Frame::Call` を通り過ぎるとき、まだルートされているうちに名前・引数・呼び出し位置を文字列に描いて写し取る。描いたものは値を持たないので、REPL が持ち続けてもルートは要らない。ドライブの主タスクが失敗すると `Interp::take_backtrace` で REPL へ渡る
- 表示は `:backtrace`(`:bt`)。エラー時に自動では出さない(エラーの 1 行は今のまま)
- `:locals N`: バックトレースの N 番目の呼び出しの引数を、シグネチャの型で描いて出す。`:frame` は作らない(`:locals N` で足りる)
- 写し取りは次の行で捨てる
- 見えないもの: コンパイル済み本体の中の呼び出し(`trace` と同じ)、`trace` 中の関数と標準ライブラリへの入口(それぞれ自分のフレームで本体を包む)、名前の無いクロージャ
- `let` で束縛した局所変数は出していない。環境の束縛は名前と値だけで型を持たず、型が無いと niche の `Option` を描けない。出すには環境の束縛に表現を持たせる必要があり、インタプリタの環境の形を変えることになる。残作業
- コンパイル済み本体の中の呼び出しは見えない(`trace` と同じ制限)。見えるのはインタプリタのフレームと、コンパイル済み本体への入口
- テスト: 3 段の呼び出しの奥で `panic` し、`:bt` に 3 つの場所が順に出ること、`:locals` に引数が型どおりに出ること

### 段階 4: 調べる道具(項目 3)

いずれも REPL コマンド。名前はモジュールのパスで書けて、裸の名前は今のモジュールから解決する(名前解決は 1 か所、新しい表を作らない)。

- `:describe NAME`: 種類(関数・変数・マクロ・型・トレイト)、シグネチャ、docstring、定義した場所。型ならフィールドと実装しているトレイト、トレイトならメソッドと実装している型。LSP の hover と同じ情報源を読む
- `:apropos TEXT`: 全モジュールの定義から名前に TEXT を含むものを、パスと種類つきで出す(`Checker::definitions`)
- `:src NAME`: 定義のソースを出す。場所は `def_locs`、本文はファイルから。REPL で打った定義は REPL が入力を覚えておいて出す
- `:who-calls NAME`: NAME を呼んでいる定義の一覧。チェッカーは今これを記録していないので、大域の名前を解決する 1 か所で「どの定義の中から何を参照したか」を記録する
- `:inspect FORM`: FORM を評価し、値を型に沿って開く。構造体・enum はフィールド、`Vector`/リスト/`HashTable` は要素。番号で中へ、`u` で上へ、`q` で抜ける(SBCL・CCL の inspector)
- テスト: 各コマンドの出力を REPL 経由で比べる

### 段階 5: 入力の支援(項目 2)

`DefaultEditor` を `Editor<ReplHelper>` に替え、rustyline の `Helper`(`Completer`/`Hinter`/`Highlighter`/`Validator`)を実装する。`ReplHelper` はチェッカーの共有ハンドルを持ち、`readline` の間だけ借りる(その間に評価は走らない)。

- 補完(`Completer`)
  - 裸の名前: `completion_candidates(今のモジュール)`
  - `a::b::` の続き: そのモジュールの公開されている名前
  - `:` の続き: 行頭なら REPL コマンド、それ以外はキーワード
  - `use`/`load` の文字列の中: ファイル名
- 引数一覧(`Hinter`): カーソルが `(name ` の中にあるとき、行末に灰色で `name : (int String) -> bool` を出す。段階 4 の `:describe` と同じ文面を使う
- 括弧の対応(`Highlighter`): カーソルの隣の括弧と対になる括弧を強調する
- 複数行の判定(`Validator`): `is_incomplete` の判定を移す。判定はリーダーの結果だけで決め、2 つ目の判定を書かない
- 継続行の字下げ: 開いている括弧の深さで字下げを入れる
- 端末でないとき(パイプ、テスト)は今と同じく何も飾らない
- テスト: 補完の候補を返す関数を直接呼ぶ単体テスト。端末操作そのものは pty を使う 1 本だけ

### 段階 6: 前の結果の参照(項目 4)

- 名前は `:*`(直前の結果)、`:**`(2 つ前)、`:***`(3 つ前)。2026-11-26 にユーザーが決めた
- `:*` は今はただのキーワードとして読まれ、評価すると自分自身になる。REPL では、**評価される位置にある** `:*` `:**` `:***` だけを前の結果として扱う。クォートの中(`':*`、`(list ':*)`)はキーワードのまま。マクロに渡った引数は展開後に評価される位置へ来たら前の結果になる
- この読み替えは REPL だけ。ファイルやスクリプトでは `:*` はキーワードのまま
- 型の問題: 結果ごとに型が違うので、「直前の結果」という 1 つの変数にはできない。結果ごとに隠しモジュールの大域変数(`%repl::result-17` のような名前)をその型で作り、`:*` はチェックの時点で直前の結果の変数に解決する
  - その帰結として、関数の本体に書いた `:*` は定義した時点の結果に固定される(CL の `*` は呼んだ時点の値)。静的型と両立させるにはこの形しかない
  - 3 つより古い結果は、定義から参照されていなければ消す。参照されていれば残す
- 値を返さなかった入力(定義など)は履歴を進めない(CL と同じ)
- CL の `+`(直前の入力)と `/`(多値)は入れない。typelisp に多値は無く、入力の履歴は rustyline にある
- テスト: `1`、`"a"`、`(+ :*** 1)` が `2` になる、`':*` がキーワードのまま、定義が無い入力で履歴が進まない

## 決めていないこと

- 3 つより古い結果を消す具体的な方法(段階 6)
- `let` の局所変数を `:locals` に出すための環境の形(段階 3 の残作業)
