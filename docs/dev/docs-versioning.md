# ドキュメントのバージョン管理と公開

利用者向けドキュメント（`docs/<言語>/`）を、typelisp のバージョンごとに読めるようにして
GitHub Pages で公開する仕組み。決めたのは 2026-10-07。

公開先: https://junsuzukijapan.github.io/typelisp/

## 方針

1. **ソースにはバージョン別のディレクトリを作らない。** `docs/<言語>/` は常に「次にリリースする
   版」の文書が1世代だけある。`docs/v0.1/ja/...` のようなコピーは、言語数 × 版数でファイルが増え
   （1世代で約 590 ファイル）、修正のバックポートと翻訳の追従が版ごとに要るので採らない。
2. **古い版の正本は git タグ。** 公開する版はタグ `vMAJOR.MINOR.PATCH` の時点の `docs/` から作る。
3. **公開する単位は MAJOR.MINOR。** 同じ MINOR の中では最新のパッチのタグから作る
   （`v0.1.0` と `v0.1.1` は `0.1` という1版で、`v0.1.1` から作る）。パッチで直した誤字は、その
   MINOR の文書に反映される。ABI の版（[api_version/](api_version/)）が MAJOR.MINOR を互換性の
   単位にしているのと同じ。
4. **`v0.0.x` は公開しない。** 最初に公開する版は 0.1（`build-site.py` の `FIRST_VERSION`）。
5. **作業ツリーの `docs/` はタグを打つまで公開されない。** main に入れただけでは、公開サイトは
   変わらない。

## 公開されるサイトの構造

```
/                         en/latest/ へのリダイレクト
/<言語>/<MAJOR.MINOR>/    その版のその言語のドキュメント
/<言語>/latest/           その言語を持つ最新の版のコピー
/<言語>/versions.json     版セレクタが読む一覧（その言語を持つ版だけ）
```

- 版セレクタは Material の `extra.version.provider: mike` が `../versions.json` を読む仕組みを
  使っている（mike というツール自体は使っていない。`versions.json` は `build-site.py` が書く）。
  `versions.json` を `/<言語>/` の直下に置くのは、サイトの根が `/<言語>/<版>/` だから。
- 言語セレクタはその版が持つ言語だけを並べる。最初の版（0.1）は日本語しか無く、タグ `v0.1.0` と
  `v0.1.1` の `docs/` には日本語（28 ファイル）しか無い。多言語版が入ったのはその後。
  版によって言語の集合が違うのは仕様で、足りない言語を別の版や英語で埋めない。

## 仕組み

| ファイル | 役割 |
|---|---|
| [scripts/docs/build-site.py](../../scripts/docs/build-site.py) | タグから全版・全言語のサイトを作る |
| [scripts/docs/requirements.txt](../../scripts/docs/requirements.txt) | MkDocs と Material のバージョン固定 |
| [.github/workflows/docs.yml](../../.github/workflows/docs.yml) | Pages へのデプロイ（`workflow_call` と `workflow_dispatch`） |
| [.github/workflows/release.yml](../../.github/workflows/release.yml) | リリースの公開後に `docs.yml` を呼ぶ（`docs` ジョブ） |

`build-site.py` の規則:

- タグは `git archive` で読み、チェックアウトしない。版ごとにその版のファイルと、このスクリプトの
  規則でビルドする。`docs/dev` は利用者向けでないので除く。
- 言語は、そのタグの `docs/<言語>/README.md` がある言語。`LANGUAGES` に無い言語のディレクトリが
  あれば、黙って飛ばさずエラーで止まる。
- **目次はどこにも書かない。** 各版の `docs/<言語>/README.md` のリンクを、`##` の見出しでまとめて
  出現順に並べる。`.../README.md` へのリンクは、そのディレクトリの他のページを子にした節になる
  （組み込み関数の節）。したがって README の索引を直すと目次が変わり、旧版の目次は旧版の
  README のまま崩れない。
- ページの題は各 Markdown の見出し。目次の題は README のリンクのテキスト。
- `docs/<言語>/` の外へ出るリンク（リポジトリ直下の README、`editor/` の README）は、同じタグの
  GitHub の URL（`https://github.com/JunSuzukiJapan/typelisp/blob/<タグ>/...`）に書き換える。
  サイトに無いファイルへの相対リンクが 404 になるのを防ぐ。
- 出力はいつも作り直す。サイトの状態を保持するブランチは無く、`docs.yml` は毎回全タグから全体を
  ビルドする（21 言語で約 35 秒）。見落とした版は次の実行で現れる。

## リリース手順への組み込み

何もしなくてよい。タグ `v*` を push すると `release.yml` が走り、テストと配布物の作成を通って
リリースが公開された後に `docs` ジョブがサイトを作り直す。テストが落ちた版のドキュメントは
公開されない。

- 手で公開し直したいとき（スクリプトの修正を反映する、後からタグを足した、など）は、Actions の
  Docs ワークフローを `workflow_dispatch` で走らせる。そのときタグにあるものがそのまま公開される。
- `release.yml` を `workflow_dispatch` で走らせた場合は `release` ジョブが飛ぶので、`docs` も飛ぶ。
- リポジトリの設定で、Settings > Pages > Source を「GitHub Actions」にしてある（一度きり）。

## 書き手が守ること

- 利用者向けドキュメントの中に、版数もバージョン切替のリンクも書かない。それはサイトの生成側が
  付ける。ソースの Markdown は GitHub 上でそのまま読めることも保つ（相対リンクはそのまま）。
- 文書の構成（ファイルの追加・改名・削除）を変えたら、その言語の README の索引を直す。目次は
  README から作るので、索引に無いページはサイドバーに出ない（ページ自体はビルドされる）。
- 新しい言語を足すときは、`build-site.py` の `LANGUAGES` に、ディレクトリ名・言語セレクタに出す
  名前・Material の表示言語を足す。足さないとビルドが止まる。
- 次のリリースまで公開されないので、「公開サイトを今すぐ直したい」ときは、直す版のタグが
  最新パッチになるようにパッチリリースを切るか、その MINOR の最新タグの内容が公開されることを
  受け入れる。タグを打ち直さない。

## 採らなかった案

| 案 | 採らなかった理由 |
|---|---|
| `docs/v0.1/`, `docs/v0.2/` を作る | ファイル数が版数倍になる。修正を複数の版へ入れ直す手間と、翻訳の追従が版ごとに要る |
| タグだけを正本にして公開物を作らない | 検索も言語切替もできず、利用者向けとして弱い |
| 最新版だけを公開する | 古い版のドキュメントを読めるようにするという要件を満たさない |
| mike で gh-pages ブランチに版を積む | 版 × 言語の2軸があり、mike は1つの MkDocs プロジェクトの版管理なので合わない。状態を持つブランチも要る |
| パッチ単位で公開する | 版が増えるだけで、利用者が選ぶ単位（互換性の単位）は MAJOR.MINOR |

## 既知の制限

- **Material for MkDocs は MkDocs 2.0 への非互換を公表している。** 本実装は MkDocs 1.6.1 と
  Material 9.7.7 に固定してあり（`requirements.txt`）、当面は影響を受けない。固定を外す、または
  別の生成器へ移るときは、`build-site.py` の `mkdocs_config` とビルド呼び出しだけを差し替えれば
  よい（版と言語の並べ方、目次の作り方、リンクの書き換えは生成器に依存しない）。
  警告の表示は環境変数 `NO_MKDOCS_2_WARNING` で止めている。
- 検索は Material 既定の検索プラグインで、言語ごとの分かち書きの設定はしていない。日本語・中国語・
  韓国語などの検索精度は未調整。
- 公開サイトの見た目（版セレクタ・言語セレクタ）は、ブラウザで目視した範囲でしか確かめていない。
  自動の検査は無い。
