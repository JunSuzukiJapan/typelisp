# 数値計算を型の幅で行う（設計）

2026-11-24 ユーザー指示: 「`i8` を使っても 64bit の語で計算するのはバグ。組み込みとは関係なく直す。行き当たりばったりではなく、数値計算全体をきちんと設計する」「別のブランチで」「ビット幅ごとにライブラリを分け、使わない幅はリンクしない」。ブランチは `feature/numeric-widths`（`feature/cross-compile-embedded` の先頭から。使わないものをリンクしない仕組みと大きさの測り方がそちらにあるため）。

## 今の形

固定幅の整数（`i8` `i16` `i32` `u8` `u16` `u32`）と `f32` は、どの層でも「64bit で計算して、型の幅に丸める」で実装されている。

- 島（`compiler.rs`）: `+` `-` `*` は `add i64` などのあと `build-normalize-int`（`shl` と `ashr`/`lshr` の 2 回）。比較は `i64` の符号付き比較。`/` `mod` `ash` `logbitp` `logcount` `integer-length` はランタイムの関数（`rt_int_div` など、幅は `wsig` の引数）。幅の変換も `build-normalize-int`。
- 浮動小数: 命令を作る関数（`llvm_builtins.rs` の `build-fadd` など）が語を `double` に直して計算する。`f32` は `double` で計算したあと `round-f32-if` で binary32 に丸める。
- ランタイム: 割り算・剰余・シフト・ビット数え・`int` との変換・箱詰め（`rt_narrow_new`/`rt_narrow_value`）は、幅を `wsig` で受け取る 1 つの関数がすべての幅を扱う。`typelisp_mem::NarrowInt` は幅と符号を値と一緒に持つ。
- インタプリタ（`eval_int_builtin`）と定数の畳み込み: `i64` で計算して `normalize_int` で丸める。

結果:

- 型の幅で計算していない。`(+ a b)`（`i8`）は AVR で 168 命令、`i8` のままなら 2 命令（`add r24, r22` と `ret`）。LLVM の最適化でも 8bit に縮まない。
- 幅の扱いが層ごとに書かれていて、同じ意味を 3 か所（島、ランタイム、インタプリタ）が別々に実装している。
- ランタイムは幅を実行時の引数で受け取るので、1 つの幅しか使わないプログラムにも全ての幅の処理が入る。

## 意味（変えない）

言語の意味は今のまま（`docs/ja/reference/functions/numbers.md` の 1 章）。

- `+` `-` `*` `lognot` は 2 の補数で巻き戻る。
- `/` はゼロ方向に切り捨て。ゼロ除算は panic（`divide by zero`）、符号付きの最小値 ÷ -1 は panic（`arithmetic overflow: A / B`）。
- `mod` は床除算（ゼロで `mod by zero`）、`rem` は切り捨て除算。
- `ash` は型の幅以上のシフト量で飽和する（左は 0、右は 0 か、負の符号付きなら -1）。
- 幅の変換は切り詰め（Rust の `as`）。`try-` は入らなければ `None`。
- `f32` は binary32 の演算。

## 設計

### 1. 2 つの層: 語と計算の型

- **語**: 値がコンパイル済みコードの中を運ばれる形。フレームのスロット、引数、戻り値、クロージャの環境、構造体のフィールド。今は 64bit の語で、固定幅の整数はその型の幅から符号拡張（符号なしはゼロ拡張）した値を持つ（今と同じ不変条件）。語の幅はフレームの ABI が決めることで、この作業では変えない（組み込みの話の続き）。
- **計算の型**: 演算が計算する LLVM の型。

| 型 | 計算の型 |
|---|---|
| `i8` `u8` | `i8` |
| `i16` `u16` | `i16` |
| `i32` `u32` | `i32` |
| `f32` | `float` |
| `f64` | `double` |
| `int` | タグ付きの語（fixnum の速い道と多倍長の関数。今のまま） |
| `char` `bool` | 数値ではないので対象外（今のまま） |

演算は「語を計算の型に直す → 計算の型で演算する → 語に戻す」の 3 つで書く。直すのは `trunc`（浮動小数は `bitcast` と `fptrunc`）、戻すのは `sext`/`zext`（`fpext` と `bitcast`）。入れ子の演算の間の「戻す・直す」の組は LLVM が消すので、式の中は計算の型のまま進む。符号は演算が選ぶ（`sdiv`/`udiv`、`srem`/`urem`、`icmp slt`/`ult`、`ashr`/`lshr`、`sitofp`/`uitofp`）。

### 2. 命令を作る関数（Rust、`llvm_builtins.rs`）が型を受け取る

語と計算の型の変換は、命令を作る関数の中の 1 か所だけに置く。島は型（`wsig`、浮動小数は幅）を渡すだけで、幅を丸める命令を自分では出さない（`build-normalize-int` と `round-f32-if` は無くなる）。

- 整数: 二項演算（`add` `sub` `mul` `and` `or` `xor`）、比較、単項（`not`、`ctpop`、`integer-length`）、割り算と剰余（検査の済んだ値で `sdiv`/`udiv`/`srem`/`urem`）、シフト（飽和を `select` で）、`logbitp`、幅の変換（`trunc`/`sext`/`zext`）、浮動小数への変換。
- 浮動小数: 二項演算、比較、単項の組み込み関数（`sqrt` など）を、幅（32 か 64）を受け取って `float`/`double` で。幅の変換（`fptrunc`/`fpext`）。

割り算の検査（ゼロ、最小値 ÷ -1）は島が分岐で書き、失敗の側だけでランタイムの関数を呼んで panic を上げる（文言はランタイムの 1 か所）。成功の側はその場の命令。

### 3. 幅ごとのライブラリ

固定幅の意味を Rust で 1 回だけ書き、幅ごとに実体化する。

- `typelisp_mem` に固定幅の整数の trait（`i8` `i16` `i32` `u8` `u16` `u32` の Rust の型そのものに実装する）と、意味の関数（割り算・剰余・シフト・変換・`int` からの切り詰めと入るかの問い、など）を総称関数で置く。インタプリタ、定数の畳み込み、ランタイムは全てこれを呼ぶ。インタプリタは型から幅を選んでその幅の実体を呼ぶ。
- ランタイムの関数は幅ごとの記号にする（`rt_i8_div` のように、マクロで幅ごとに作る）。中身は総称関数の実体なので、実装は 1 つ。生成コードは幅ごとの記号を呼ぶので、使わない幅の関数はリンクされない。`wsig` を実行時に受け取る関数は無くなる。
- 箱詰め（`Sexpr` の中の固定幅の値）も幅ごとの関数にする。`NarrowInt` は幅ごとの値を持つ形（`enum`）にする。
- `f32` と `f64` は既に別々の関数なので、同じ形に揃えるだけ。

### 4. 確かめ方

- 命令の形: 幅ごとに `(+ a b)` などをコンパイルした IR に、計算の型の命令（`add i8` など）があり、64bit の丸め（`shl` と `ashr` の組）が無いこと。
- 意味の一致: 6 つの幅と `f32` の全ての演算について、端の値（最小値、最大値、-1、0、1 など）の組で、コンパイル済みコード・インタプリタ・定数の畳み込みの答えが一致すること（表で回す）。
- リンク: `u8` だけを使うプログラムの実行ファイルに、ほかの幅のランタイム関数が無いこと（記号を読む）。

## 進め方

1. 意味の層: `typelisp_mem` の trait と総称関数。インタプリタと定数の畳み込みをこれに乗せ替える。意味の一致のテストを先に書く（今の実装で通ることを確かめてから乗せ替える）。
2. ランタイム: 幅ごとの関数（マクロ）と箱詰め。`wsig` の関数を消す。
3. 命令を作る関数: 型を受け取る整数・浮動小数の関数を足す（チェッカーの登録 `typeck/builtins/llvm.rs` と well-known 記号も）。
4. 島: 数値の分岐を新しい関数と幅ごとのランタイム関数に乗せ替え、`build-normalize-int` と `round-f32-if` を消す。島を 2 回再生成、prelude を再生成、ABI。
5. 命令の形とリンクのテスト、AVR での命令数の測り直し。
