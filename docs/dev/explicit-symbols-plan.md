# 外のシンボルは明示的に取り込む — 実装計画

作成: 2026-10-17

## 1. 決まったこと（2026-10-17、ユーザー決定）

- シンボルの比較はポインタの比較だけで行う。名前の文字列は比べない。特殊形の頭の振り分け、
  関数名の解決、ローカル変数、チェッカーより後ろの core IR の変数も含む。
- モジュールの中で書いた名前は、そのモジュールのシンボルである。外のシンボルになるのは、
  明示的に取り込んだときだけ。
- 標準ライブラリ専用のモジュール `std` を置く。`std` に定義して公開（`pub`）したものは、
  取り込まずにどのモジュールからでも使える。
- 公開されていない定義は、ほかのモジュールからは見えない。祖先のモジュールも同じ。
- `std` が公開している名前と同じ名前をモジュールで定義するには、モジュールの先頭で
  明示的に宣言する（CL の `shadow`）。宣言せずに定義するとエラー。
- `use` は、取り込む側のモジュールの定義の表に「このモジュールのシンボル → 取り込む定義」を
  登録する。シンボル表は書き換えない。
- 語彙表を、予約語・内部用・`std` の名前の 3 つに分ける。

## 2. 今の仕組み（2026-10-17 時点）

- シンボル表はモジュールごと。`intern_in(m, name)` は `m` の表だけを引き、無ければ `m` に作る。
  語彙表（SYSTEM、約 380 個）だけは、モジュールを作るときに全部ポインタで写す。
- prelude、Rust の組み込み関数、コアマクロ、島はルートに読み込む。
- 名前の解決（`Checker::resolve_module_entry`）は、名前の文字列で「今のモジュール →
  `use` の別名 → 祖先 → ルート」と引く。`m` で書いた `car` は `m` のシンボルだが、
  文字列でルートの `car` に解決される。
- レジストリの表（`Namespace::fns` など）のキーは `String`。定義を指す `Path` は `Vec<String>`。
- チェッカーのローカル変数（`Env::lookup`）は文字列で比べる。
- core IR の `(var SYM)` は、bridge が文字列に変えて島へ渡す。島の `compile-value` などは
  `sexpr-sym-name` で頭を文字列にして `case` で振り分ける。

## 3. 新しい規則

### 3.1 読むとき（シンボル表）

モジュール `m` で名前 `n` を読むと、次の順に決まる。名前のハッシュは 1 回だけ計算する。

1. `m` の表にあれば、それ（`m` のシンボル、または `shadow` で作ったもの）
2. 予約語なら、その予約語（全モジュール共通）
3. `std` が公開している名前なら、`std` のシンボル
4. どれでもなければ、`m` に作る

予約語は 2 を表の写しで済ませる（今の SYSTEM の写しと同じ）。3 は `std` の公開表を 1 回引く。
`std` の公開表は prelude を読み込み終えた時点で固まるので、利用者のコードを読む間に変わらない。

キーワードは keyword モジュール、`(intern NAME NS)` は `NS` で同じ手順を踏む。ダンプ・fasl・
コンパイル済みコードからシンボルを作り直すときは、所属モジュールにそのまま作る入口を使う
（たどると読み込み時点の公開表で別物にすり替わる）。

### 3.2 定義と解決（レジストリ）

- 1 つのシンボルは 1 つのモジュールに属し、そのモジュールでしか定義できない。定義の名前の
  シンボルの所属が今のモジュールでなければエラー（`std` の名前なら「`(shadow NAME)` を先に
  書く」と知らせる）。予約語・キーワードは今までどおりエラー。
- 定義の表のキーは `SymRef`。素の名前の解決は、シンボルの所属モジュールの表をポインタで
  1 回引くだけ。祖先はたどらない。
- `use` は、今のモジュールのシンボル（`intern_in(m, 最後のセグメント)`）をキーに、
  取り込む定義を今のモジュールの表へ登録する。そのシンボルが `std` のものなら、
  `shadow` していない限りエラー（`std` の名前を `use` で隠すのは、定義で隠すのと同じ扱い）。
- パス `a::b::foo` は、チェッカーがモジュール `a::b` を決めてから、そのモジュールの表に
  ある名前 `foo` のシンボルを引く（作らない、`std` もたどらない）。定義が `pub` でなければエラー。
  リーダーには `a` が今のモジュールの子かルート直下かが決められないので、ここだけ検査のときに引く。
- マクロの展開が持ち込んだシンボルは、展開した側のモジュールのシンボルのまま。解決は
  そのシンボルの所属モジュールの表を引くので、`std` のマクロが `std` の非公開の補助関数を
  呼ぶことができる。利用者が書いたコードからは、非公開のシンボルは作れない（読めば自分の
  モジュールのシンボルになる）ので、見えないという規則は崩れない。

### 3.3 `shadow`

- `(shadow NAME...)` は、今のモジュールに `NAME` のシンボルを作り、以後そのモジュールで
  `NAME` を読むと `std` のものではなくそれになる。
- ファイルのトップレベルでは、フォームを 1 つずつ読んで検査するので、使う前に書けばよい。
- `(module m ...)` の中では、フォーム全体を読み終えてから検査するので、リーダーが読みながら
  処理する。`(module m (shadow NAME...) ...)` のように、本体の最初に書く決まりにする。
- `shadowing-import` は `shadow` と `use` を 1 つにしたもの。

### 3.4 ローカル変数と IR

- チェッカーの `Env` のキーは `SymRef`。比べるのはポインタ。
- core IR の `(var SYM)` は利用者が書いたシンボルを運ぶ。インタプリタと島の環境は `eq` で比べる。
  bridge は文字列に変えない。LLVM の値の名前は表示のために `name()` から付けるだけ。
- チェッカーが作る一時変数は gensym したシンボルを束縛と参照の両方に渡す。
- 島の IR タグの振り分けは `sexpr-sym-name` + 文字列の `case` をやめ、タグのシンボルと `eq` で比べる。

### 3.5 語彙表の 3 分割

| 分類 | 中身 | 所属 |
|---|---|---|
| 予約語 | 特殊形・定義形の頭、`&rest` などの構文の語、`pub` `where` `fn` `quote` `_` | SYSTEM。全モジュールに写す。定義名・束縛名に使えない |
| 内部用 | core IR のタグ（`var` `call` `assoc` `int` `str` `pat-bind` ...） | 内部用モジュール。利用者のモジュールには写さない |
| `std` の名前 | `cond` `and` `or` `when` `dolist` などのマクロ、`not` `intern` `self` `test` `ptr` `recv` `send` | `std`。公開表に載る |

キーワードは今までどおり keyword モジュール。語彙表は位置で番号が決まるので、分割しても
番号は変えない（所属だけ変える）。

## 4. 性能

- 読むとき: 名前のハッシュ 1 回、表の参照は多くて 2 回（自分の表、`std` の公開表）。
  予約語は自分の表の写しで 1 回。
- 解決: ポインタをキーにした表を 1 回引く。`use` の別名も同じ表にある。祖先をたどらない。
- ローカル変数: ポインタの比較。
- コンパイル済みコードはリンク名で呼ぶので、実行時に名前を引くことはない。

## 5. 段階

各段階で全テストを通してからコミットする。

1. 語彙表の 3 分割と、モジュール `std`・内部用モジュールの追加。島の振り分けを `eq` に。
2. prelude・組み込み関数・コアマクロを `std` へ移し、公開するものに `pub` を付ける。
   リーダーの 3.1 の手順、`shadow`、ダンプのシンボル復元。
3. レジストリの値の表（関数・変数・マクロ）と `use` の別名を `SymRef` キーにし、祖先を
   たどる解決と文字列による解決を消す。パスは 3.2 の手順で引く。例・テストを新しい規則に直す。
4. `Env` と IR の変数を `SymRef` にし、インタプリタと島を `eq` に（島の再生成は 2 回）。
5. 利用者向け文書（日本語の原本、翻訳）。

残すもの: 型の表（`types`）とモジュールの木のキー、定義を指す `Path(Vec<String>)` は文字列の
まま。シンボルどうしの比較ではなく、定義の識別に使っているため。段階 3 のあとで改めて扱いを決める。
