# REPL

引数を付けずに `typl` を起動すると REPL（対話モード）になります。この文書では、式の評価の
ほかに REPL でできること、つまり REPL のコマンド、入力の支援、直前の結果の参照、計算の中断、
エラーのあとの調べ方を説明します。

## 起動と終了

```
$ typl
typl> (+ 1 2)
3
typl> :quit
```

`:quit`（短く `:q`）か `Ctrl+D` で終了します。入力の履歴は `~/.typl_history` に残り、次に起動した
ときも `Ctrl+P` / `Ctrl+N` や `Ctrl+R`（履歴の検索）で呼び出せます。

起動すると、最初のプロンプトの前に次のものを順に実行します。どれも、実行した値は表示しません。

1. `~/.typlrc` があれば、その中身。`--no-init` を付けると読みません。
2. コマンドラインの `--eval FORM` と `--load FILE`。書いた順に実行します。どちらも何度でも書けます。

```
$ typl --load util.typl --eval '(println "ready")'
ready
typl>
```

`--eval`、`--load`、`--no-init` は REPL を起動するときだけのものです。ファイルを実行するときに
付けるとエラーになります。

起動したときのモジュールは `user` です。`(in-module foo)` で別のモジュールに移ると、プロンプトに
そのモジュールが表示されます。

```
typl> (in-module foo)
typl user::foo>
```

## REPL のコマンド

行の先頭に書いた `:名前` は REPL のコマンドです。`:help` で一覧を表示します。一覧に無い `:名前` は
コマンドではなく、ふつうのキーワードとして評価します。

| コマンド | 意味 |
|---|---|
| `:help`（`:h`、`:?`） | コマンドの一覧を表示する |
| `:type FORM`（`:t`） | FORM を評価せずに、その型を表示する |
| `:describe NAME`（`:d`） | 定義の種類、型、フィールドや変種、メソッド、実装しているトレイト、定義した場所、ドキュメント文字列を表示する |
| `:apropos TEXT` | 名前に TEXT を含む定義を、すべてのモジュールから探す（大文字小文字は区別しない） |
| `:src NAME` | 定義のソースを表示する |
| `:who-calls NAME` | 関数かメソッド NAME を呼んでいる関数とメソッドを表示する |
| `:inspect FORM`（`:i`） | FORM を評価し、値を型に沿って開く |
| `:backtrace`（`:bt`） | 直前の行が失敗したときに途中だった呼び出しを、内側から順に表示する |
| `:locals [N]` | `:backtrace` の N 番目（省略すると 0 番目）の呼び出しの引数を表示する |
| `:cd [DIR]` | カレントフォルダを DIR に移す（省略するとホームフォルダ） |
| `:pwd` | カレントフォルダを表示する |
| `:quit`（`:exit`、`:q`） | REPL を終了する |

NAME には、`inner` のような名前のほかに `std::seq::reverse` や `Option::unwrap` のようなパスも
書けます。

```
typl> (defun inner ((x int) (s string)) int "x に 1 を足す。" (+ x 1))
typl> :describe inner
user::inner is a function
  type: (fn (int string) int)
  parameters: x s
  defined at <stdin>:1:1

x に 1 を足す。
typl> :src inner
(defun inner ((x int) (s string)) int "x に 1 を足す。" (+ x 1))
```

`:src` は、ファイルから読み込んだ定義ならファイルから、REPL で入力した定義なら入力した文字列から
表示します。標準ライブラリの定義にはソースの位置が記録されていないので表示できません。

`:who-calls` が探すのは、今のセッションにある関数の本体です。ジェネリックな関数は、型を決めて
使われた分だけが対象です。

`:cd` は `(load ...)` が探すフォルダを変えますが、`use` がファイルを探すフォルダは起動したときの
ままです。

## 値を開く（`:inspect`）

`:inspect` は値を型に沿って開きます。構造体はフィールドに、列挙型（`Option` を含む）はその変種の
フィールドに、`Vector` は要素に、`HashTable` はキーと値に開きます。番号を入力するとその部分に入り、
`u` で一つ上に戻り、`q` で終わります。

```
typl> (defstruct point (x int) (y Option<int>))
typl> :inspect (make-instance 'point :x 1 :y (Some 2))
(make-instance 'point :x 1 :y (Some 2)) = #<point x: 1 y: (Some 2)>
  type: point
  0. x = 1
  1. y = (Some 2)
inspect> 1
y = (Some 2)
  type: Option<int>
  0. Some 0 = 2
inspect> q
```

リストと `Sexpr` は開かずに、そのまま表示します。

## 入力の支援

端末から入力しているときは、次のものが使えます。

- `Tab` で補完します。補完するのは、名前（定義と、`if` や `defun` のような構文）、`::` を含むパス、
  行の先頭の REPL コマンド、文字列の中ではファイル名です。
- 関数の名前の後に空白を入力すると、その関数の型を行の末尾に薄く表示します。
- カーソルの隣の括弧と対になる括弧を強調します。
- フォームが終わらないまま改行すると、次の行は開いている括弧の数だけ字下げして始まります。

## 直前の結果（`:*`、`:**`、`:***`）

REPL では、`:*` が直前に表示した値、`:**` がその一つ前、`:***` がさらに一つ前の値になります。
それぞれ、その値の型を持ちます。

```
typl> 1
1
typl> "a"
"a"
typl> 2
2
typl> (+ :*** :*)
3
```

- 値を表示しなかった入力（定義など）とエラーになった入力は、結果を進めません。
- まだその数だけ結果が無いときに `:**` や `:***` を書くとエラーです。
- クォートした `':*` は、ふつうのキーワードです。
- 関数の本体に書いた `:*` は、定義したときの結果を指したままです。Common Lisp の `*` は関数を
  呼んだときの値を読みますが、typelisp では型を決めるために、定義したときに決めます。
- REPL の外（ファイルの実行や、`~/.typlrc`・`--load`・`--eval`）では、`:*` はふつうのキーワードです。

## 計算を止める（`Ctrl+C`）

評価の途中で `Ctrl+C` を押すと、その計算を止めてプロンプトに戻ります。それまでに定義したものは
残ります。止まるのは、インタプリタで動いているループ、コンパイルしたコードのループ、`sleep` や
`wait` で待っている途中のどれでもかまいません。途中の `unwind-protect` の後始末は実行します。

```
typl> (loop)
^Cerror: interrupted
typl>
```

入力の途中で押した `Ctrl+C` は、入力中の行を捨てるだけです。

## エラーのあとに調べる（`:backtrace`、`:locals`）

エラーで止まったあと、`:backtrace`（`:bt`）で、そのとき途中だった関数の呼び出しを、内側から
順に表示します。`:locals N` は N 番目の呼び出しの引数を、宣言した型に沿って表示します。

```
typl> (defun inner ((x int)) int (if (= x 0) (panic "boom") x))
typl> (defun outer ((n int)) int (* 2 (inner n)))
typl> (outer 0)
error: <stdin>:1:40: panic: boom
typl> :bt
  0: (user::inner 0)  called at <stdin>:1:33
  1: (user::outer 0)  called at <stdin>:1:1
typl> :locals 1
  n = 0
```

- 関数の最後の式での呼び出し（末尾呼び出し）では、呼んだ側の関数は表示しません。そのおかげで、
  末尾再帰のループは何回まわっても呼び出し 1 つ分の場所しか使いません。
- コンパイルした関数の中での呼び出しと、名前の無い関数（`lambda`）は表示しません。
- `:locals` が表示するのは引数だけで、`let` で束縛した変数は表示しません。
- 次の行を評価すると、前のエラーの記録は消えます。
