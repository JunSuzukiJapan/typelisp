# คำสั่งรูปแบบ (Format Directives)

คำสั่ง (directive) ที่เขียนในสตริงควบคุมของ `print`/`println`/`format` ครอบคลุมคำสั่ง `format` ของ CL
เกือบทั้งหมด ตัวฟังก์ชันเองอธิบายใน
[การพิมพ์](printing.md#1-print--println--format)

## 1. วิธีเขียนคำสั่ง

แต่ละคำสั่งคือ `~` ตามด้วย **พารามิเตอร์นำหน้า (prefix parameter)** ที่ไม่บังคับ (คั่นด้วยจุลภาค: จำนวนเต็ม / `'c` (อักขระ) / `v` (นำจากอาร์กิวเมนต์ถัดไป) / `#` (จำนวนอาร์กิวเมนต์ที่เหลือ)) จากนั้นเป็น
**ตัวปรับแต่ง (modifier)** `:` และ `@` ที่ไม่บังคับ แล้วจึงเป็นอักขระของคำสั่ง ตามลำดับนี้ อักขระของ
คำสั่งไม่แยกตัวพิมพ์ใหญ่และเล็ก

สตริงควบคุมต้องเป็น literal ([การพิมพ์](printing.md#1-print--println--format)) นอกจากนั้น
สิ่งต่อไปนี้ถูกตรวจสอบตอนตรวจสอบ

- **จำนวนและชนิดของอาร์กิวเมนต์** สำหรับแต่ละคำสั่งที่ใช้อาร์กิวเมนต์: ยังเหลืออาร์กิวเมนต์หรือไม่ และ
  ชนิดของมันได้รับการยอมรับหรือไม่ (หมายเหตุ "อาร์กิวเมนต์" ในตารางด้านล่าง) ในกรณีที่เส้นทาง
  ขึ้นกับค่าตอนรัน เช่น การเลื่อนด้วย `~*` กิ่งใดของ `~[` ที่ถูกเลือก
  `~^` ทำงานหรือไม่ หรือ `~@{` ทำซ้ำกี่ครั้ง **ทุกเส้นทาง** จะถูกตรวจสอบ อาร์กิวเมนต์ที่เหลือ
  ไม่เป็นไร (เหมือนใน CL)
- **พารามิเตอร์และตัวปรับแต่ง** ตัวปรับแต่งที่ไม่ได้รับการยอมรับ พารามิเตอร์มากเกินไป และค่าที่เกินช่วง
  (ความกว้างติดลบ ฐานที่ไม่ใช่ 2 ถึง 36 จำนวนเต็มในที่ที่คาดหวังอักขระ และอื่น ๆ) เป็นข้อผิดพลาด สิ่งเหล่านี้ไม่ถูกละเลยหรือปัดเศษโดยไม่แจ้ง

**สมาชิก** ของอาร์กิวเมนต์ที่เป็นลิสต์ (`~{`, `~:{`, `~<...~:>`) เป็น `Sexpr` และทั้งจำนวนและ
ชนิดของแต่ละสมาชิกไม่อาจทราบได้จากชนิด ข้อกำหนดต่อสมาชิก (จำนวนเต็มสำหรับ `~d`
และอื่น ๆ) และสมาชิกที่ขาดหายถูกตรวจสอบเมื่อค่ามาถึง และเป็นข้อผิดพลาดตอนรัน (จะไม่
สลับไปใช้การแสดงผลแบบอื่นแทน)

กฎที่ผ่อนปรนของ CL ไม่ถูกนำมาใช้ การส่งสิ่งที่ไม่ใช่จำนวนเต็มให้ `~d` แล้วพิมพ์เป็น `~a` หรือ
`~:[` ที่ถือว่าค่าใดก็เป็นบูลีน ไม่ถูกตีความใหม่แบบนั้น แต่เป็นข้อผิดพลาดของชนิด

## 2. เอาต์พุต (ใช้หนึ่งอาร์กิวเมนต์)

| คำสั่ง | พารามิเตอร์ / ตัวปรับแต่ง | ความหมาย |
|---|---|---|
| `~a` | `~mincol,colinc,minpad,padchar` / `@`=ชิดขวา | Aesthetic (`princ` ของ CL; สตริงไม่มีเครื่องหมายคำพูด) อาร์กิวเมนต์เป็นชนิดใดก็ได้ |
| `~s` | เหมือนข้างบน | Standard (`prin1` ของ CL; รูปแบบที่อ่านกลับได้) อาร์กิวเมนต์เป็นชนิดใดก็ได้ |
| `~w` | — | `write` ของ CL pretty-print ถ้า `*print-pretty*` เป็นจริง มิฉะนั้นเหมือน `~s` |
| `~d` `~b` `~o` `~x` | `~mincol,padchar,commachar,interval` / `:`=จัดกลุ่มหลัก, `@`=แสดงเครื่องหมายเสมอ | จำนวนเต็มฐานสิบ/สอง/แปด/สิบหก อาร์กิวเมนต์เป็นจำนวนเต็ม |
| `~r` | `~radix,mincol,padchar,commachar,interval` (มี radix) หรือไม่มี | เมื่อมี radix ใช้ฐานนั้น (2 ถึง 36) เมื่อไม่มี: `~r`=จำนวนนับภาษาอังกฤษ, `~:r`=ลำดับที่ภาษาอังกฤษ, `~@r`=เลขโรมัน, `~:@r`=เลขโรมันแบบเก่า อาร์กิวเมนต์เป็นจำนวนเต็ม |
| `~p` | `:`=ถอยหนึ่งตัว, `@`=y/ies | พหูพจน์ (`~p`→"s", `~@p`→"y"/"ies") อาร์กิวเมนต์เป็นจำนวนเต็ม |
| `~c` | `:`=ชื่อ, `@`=ไวยากรณ์ `#\` | อักขระ อาร์กิวเมนต์เป็น `char` |
| `~f` | `~w,d,k,overflowchar,padchar` / `@`=เครื่องหมาย | จุดตรึง (fixed-point) อาร์กิวเมนต์เป็นตัวเลข |
| `~e` | `~w,d,,,,padchar,exptchar` / `@`=เครื่องหมาย | สัญกรณ์เลขชี้กำลัง อาร์กิวเมนต์เป็นตัวเลข พารามิเตอร์ exponent-digits, scale และ overflowchar ของ CL ไม่รองรับ (การให้พารามิเตอร์เหล่านี้เป็นข้อผิดพลาด) |
| `~g` | `@`=เครื่องหมาย | จุดลอยตัวทั่วไป อาร์กิวเมนต์เป็นตัวเลข ไม่รับพารามิเตอร์ |
| `~$` | `~d,n,w,padchar` / `:`,`@` | สัญกรณ์เงิน อาร์กิวเมนต์เป็นตัวเลข |

## 3. เอาต์พุต (ไม่ใช้อาร์กิวเมนต์)

| คำสั่ง | ความหมาย |
|---|---|
| `~%` | ขึ้นบรรทัดใหม่ (`~n%` สำหรับ n ครั้ง) |
| `~&` | fresh-line (ขึ้นบรรทัดใหม่เว้นแต่อยู่ต้นบรรทัด; `~n&`) |
| `~\|` | ขึ้นหน้าใหม่ (form feed) |
| `~~` | `~` ตามตัวอักษร (`~n~` สำหรับ n ตัว) |
| `~t` | แท็บ (`~colnum,colincT` หากอยู่ที่คอลัมน์ colnum หรือเลยไปแล้ว จะเลื่อนต่อเป็นทวีคูณของ colinc ไม่เลื่อนหาก colinc เป็น 0 `@`=สัมพัทธ์ `:`=แท็บสัมพัทธ์กับจุดเริ่มต้นของ logical block ซึ่งใช้ได้เฉพาะตอน pretty-print) |
| `~_` | ขึ้นบรรทัดใหม่แบบมีเงื่อนไข (pretty; ปกติ=`:linear` / `~:_`=`:fill` / `~@_`=`:miser` / `~:@_`=`:mandatory`) |
| `~i` | การเยื้อง (pretty; `~ni`=จุดเริ่มต้นของ block + n / `~n:i`=คอลัมน์ปัจจุบัน + n) |
| `~<newline>` | ละเลยการขึ้นบรรทัดใหม่ (`:`=เก็บช่องว่าง, `@`=เก็บการขึ้นบรรทัดใหม่) |

เช่นเดียวกับใน CL คำสั่งของ pretty-printer (`~_` `~i` `~:t` `~<...~:>` และเส้นทาง pretty-print ของ
`~a`/`~s`/`~w`) ไม่ทำอะไรเลยเมื่อ `*print-pretty*` เป็นเท็จ ค่าเริ่มต้นเป็นเท็จ

## 4. โครงสร้างควบคุม

| คำสั่ง | ความหมาย |
|---|---|
| `~(...~)` | การแปลงตัวพิมพ์ (`~(` ตัวพิมพ์เล็ก, `~:(` ขึ้นต้นแต่ละคำด้วยตัวพิมพ์ใหญ่, `~@(` ขึ้นต้นคำแรกคำเดียวด้วยตัวพิมพ์ใหญ่, `~:@(` ตัวพิมพ์ใหญ่ทั้งหมด) |
| `~[...~;...~]` | การเลือกแบบมีเงื่อนไข (แตกกิ่งตามอาร์กิวเมนต์จำนวนเต็ม เมื่อใช้ `~n[`, `~v[` หรือ `~#[` จะแตกกิ่งตามค่านั้นและไม่ใช้อาร์กิวเมนต์ `~:;`=อนุประโยคเริ่มต้น เฉพาะเป็นอนุประโยคสุดท้าย) `~:[false~;true~]` แตกกิ่งตามอาร์กิวเมนต์ `bool` และมีสองอนุประโยคพอดี |
| `~{...~}` | การวนซ้ำ (เดินผ่านอาร์กิวเมนต์ที่เป็นลิสต์ `~:{`=ต่อลิสต์ย่อย, `~@{`=ตามอาร์กิวเมนต์ที่เหลือ, `~:@{`=ตามแต่ละลิสต์ในอาร์กิวเมนต์ที่เหลือ, `~^`=ออก, `~:}`=รันหนึ่งครั้งแม้ว่าง) ตัวเนื้อหาที่ไม่ใช้อาร์กิวเมนต์ในหนึ่งรอบเป็นข้อผิดพลาด (จะไม่มีวันจบ) |
| `~<...~;...~>` | การจัดชิด (กระจายส่วนต่าง ๆ ไปบน `~mincol` คอลัมน์ `:`/`@`=การเว้นที่ปลาย) |
| `~<...~;...~:>` | **Logical block** (ปิดด้วย `~:>`; เป็นคนละสิ่งกับการจัดชิดข้างบน) ส่วนแรกคือ prefix และส่วนสุดท้ายคือ suffix (ทั้งสองเป็นสตริง literal เท่านั้น) เมื่อใช้ตัวคั่น `~@;` prefix จะเป็น **prefix ต่อบรรทัด** `~:<` ตั้ง prefix/suffix เริ่มต้นเป็น `(`/`)` อาร์กิวเมนต์เป็นลิสต์หนึ่งตัว (`~@<` ใช้อาร์กิวเมนต์ที่เหลือแทน) |
| `~*` | การข้ามอาร์กิวเมนต์ (`~n*`=ไปข้างหน้า n, `~:*`=ย้อนกลับ, `~@*`=ไปยังตำแหน่งสัมบูรณ์) |
| `~/name/` | การเรียกเมทอด (หัวข้อ 5 แฟล็ก `:`/`@` ถูกส่งให้เมทอด ไม่รับพารามิเตอร์) |

คำสั่ง CL ต่อไปนี้ไม่รองรับ (เป็นข้อผิดพลาดตอนตรวจสอบ)

- `~?` และ `~@?`: คำสั่งเหล่านี้รับสตริงควบคุมเป็นอาร์กิวเมนต์ตอนรัน จึงไม่อาจตรวจสอบอาร์กิวเมนต์ที่
  คำสั่งของมันใช้ได้ ให้เขียนคำสั่งเหล่านั้นลงในสตริงควบคุมโดยตรง
- `~@[...~]`: ทดสอบว่าอาร์กิวเมนต์ไม่ใช่ nil แต่ภาษานี้ไม่มี nil ให้ใช้ `~:[false~;true~]`
  ซึ่งแตกกิ่งตาม `bool`
- `~{~}` ที่ตัวเนื้อหาว่าง: รับตัวเนื้อหาจากอาร์กิวเมนต์ตอนรัน ให้เขียนคำสั่งไว้ภายใน
  วงเล็บปีกกา

## 5. `~/name/`

**ข้อแตกต่างหนึ่งจาก CL: ชื่อไม่ได้ถูกค้นหาเป็นฟังก์ชันโกลบอล แต่เป็นเมทอดของชนิดของ
อาร์กิวเมนต์เอง** เมทอดมีรูปร่าง `((self Self) (colon bool) (at bool)) → string` และ
`:`/`@` ของคำสั่งถูกส่งผ่านตามที่เป็น

วิธีของ CL ที่ค้นหาเป็นฟังก์ชันโกลบอลไม่สามารถ implement อย่างปลอดภัยในภาษานี้ แม้
สตริงควบคุมเป็น literal ชนิดของสมาชิกของอาร์กิวเมนต์ลิสต์ (ภายใน `~{`) ก็ไม่ทราบ
ตอนตรวจสอบ และการค้นหาฟังก์ชันด้วยชื่ออย่างเดียวอาจเรียกฟังก์ชันที่ตั้งใจไว้สำหรับชนิดอื่น
การเลือกตามชนิดของค่าหมายถึงเมทอดถูกตรวจสอบชนิดสำหรับชนิดนั้นพอดี ซึ่งปลอดภัย
(กลไกเดียวกับ `print-object`) และใช้ได้กับค่าอย่าง `string`/`bool`/`char`/
`symbol`/ลิสต์ด้วย เฉพาะจำนวนเต็มที่ไม่อาจแยกความกว้างจากค่า จึงเป็นข้อผิดพลาด **เมื่อ
มีชนิดจำนวนเต็มมากกว่าหนึ่งชนิดนิยามเมทอดชื่อนั้น**

ไม่ทราบว่าใช้กับอาร์กิวเมนต์ใด แต่ทราบว่าอาจเรียกเมทอดใดได้ ตัวตรวจสอบรวบรวม
`~/name/` ทุกตัวจากสตริงควบคุมที่เป็น literal และบันทึกชนิดของอาร์กิวเมนต์ที่จุดเรียกนั้น
ที่มีเมทอดรูปร่างข้างต้น ดังนั้น **หากไม่มีชนิดของอาร์กิวเมนต์ใดมีเมทอดนั้น
จะเป็นข้อผิดพลาดตอนตรวจสอบ** (ไม่ใช่ตอนรัน) และใช้ได้ในไฟล์ปฏิบัติการ AOT ด้วย

```lisp
(defstruct point (x i32) (y i32))
(defmethod brief ((self point) (colon bool) (at bool)) string
  (if colon (format false "<~a,~a>" self::x self::y) (format false "~a/~a" self::x self::y)))
(println "~a" (format false "~/brief/"  (point::new 3 4)))   ; => 3/4
(println "~a" (format false "~:/brief/" (point::new 3 4)))   ; => <3,4>
```
