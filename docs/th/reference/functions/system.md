# เวลา สภาพแวดล้อม และการ implement

ฟังก์ชันสำหรับเวลา การสอบถามสภาพแวดล้อมขณะรัน เครื่องมือของการ implement การแยกวิเคราะห์และ
การประเมินค่าข้อความ docstring และแมโคร

## 1. เวลา

| ชื่อ | รูปแบบ | ชนิด | คำอธิบาย |
|---|---|---|---|
| `universal-time` | — | `defstruct` | สองฟิลด์: `day` (จำนวนวันนับจาก 1900-01-01) และ `second` (วินาทีภายในวันนั้น 0..86399) |
| `internal-time` | — | `defstruct` | สองฟิลด์: `second` และ `microsecond` (ภายในวินาทีนั้น 0..999999) |
| `get-universal-time` | `(get-universal-time)` | `()→universal-time` | เวลาตั้งแต่ epoch ของ CL (1900-01-01 UTC) |
| `get-internal-real-time` | `(get-internal-real-time)` | `()→internal-time` | เวลาที่ผ่านไปเทียบกับโพรเซส |
| `get-internal-run-time` | `(get-internal-run-time)` | `()→internal-time` | **เวลา CPU** ที่โพรเซสนี้ใช้ไป (ผู้ใช้บวกระบบ) |
| `internal-time-seconds` | `(internal-time-seconds it)` | `internal-time→f64` | เป็นจำนวนวินาที รูปแบบสำหรับรายงานความต่างระหว่างการอ่านสองครั้ง |
| `internal-time-units-per-second` | — | `int` | `1000000` (ไมโครวินาที) หน่วยของฟิลด์ `microsecond` เหมือนใน CL ค่านี้เป็นตัวเลือกของ implementation |
| `time` | `(time form)` | แมโคร | รัน `form` พิมพ์เวลาจริงและเวลา CPU บรรทัดละอย่าง และคืนค่าของ `form` ตามที่เป็น |

เวลาจริงและเวลา CPU บอกสิ่งที่ต่างกัน สำหรับงานที่ส่วนใหญ่รอ I/O ทั้งสองต่างกัน
มาก และความต่างนั้นคือสิ่งที่คุณต้องการรู้พอดี ดังนั้น `time` แสดงทั้งสอง

`sleep` ที่หยุด task อยู่ใน[Task และ channel](concurrency.md#3-yield--sleep--การยอมให้ผู้อื่นทำงาน)

## 2. การถอดรหัสและการเข้ารหัสวันที่

| ชื่อ | รูปแบบ | ชนิด | คำอธิบาย |
|---|---|---|---|
| `decoded-time` | — | `defstruct` | **เก้าฟิลด์**: `second` / `minute` / `hour` / `date` / `month` / `year` / `day-of-week` / `daylight-p` / `zone` ค่าที่คืนเก้าค่าของ CL เป็น struct เดียว (ไม่มีค่าหลายค่า) |
| `decode-universal-time` | `(decode-universal-time ut &optional zone)` | `(universal-time,int)→decoded-time` | universal time เป็นส่วนประกอบของปฏิทิน `zone` คือชั่วโมงทางตะวันตกของกรีนิช (ทิศทางเดียวกับ CL) **หากละ จะเป็นเวลาท้องถิ่น** (เหมือนใน CL) |
| `encode-universal-time` | `(encode-universal-time sec min hour date month year &optional zone)` | `(int×6,int)→universal-time` | ทิศตรงข้าม หากไม่มี `zone` อาร์กิวเมนต์ถูกอ่านเป็น **เวลาท้องถิ่น** |
| `get-decoded-time` | `(get-decoded-time)` | `()→decoded-time` | ขณะนี้ ถอดรหัสเป็นเวลาท้องถิ่น |
| `timezone-offset-seconds` | `(timezone-offset-seconds day second)` | `(int,int)→Option<int>` | ค่าชดเชยของเวลาท้องถิ่นทางตะวันตกของกรีนิช เป็น **วินาที** ที่ universal time นั้น |
| `timezone-daylight-p` | `(timezone-daylight-p day second)` | `(int,int)→Option<bool>` | เวลาออมแสงมีผลหรือไม่ที่ universal time นั้น |

เหมือนใน CL สำหรับ `day-of-week` **0 คือวันจันทร์ และ 6 คือวันอาทิตย์**

**หากไม่มี `zone` จะใช้เวลาท้องถิ่น** เหมือนใน CL ค่าชดเชยท้องถิ่นถูกถาม OS ดังนั้นผลลัพธ์
ขึ้นกับที่ที่เครื่องอยู่ **การให้ zone อย่างชัดเจนทำให้ผลลัพธ์แน่นอน** และ `0` คือ UTC

หน่วยของ `zone` คือ "ชั่วโมงทางตะวันตกของกรีนิช" เหมือนใน CL ดังนั้น UTC+9 อ่านเป็น `-9` อย่างไรก็ตาม **อาร์กิวเมนต์
เป็นจำนวนเต็มและฟิลด์ `zone` ของผลลัพธ์เป็น `f64`** ค่าชดเชยจริงไม่ได้เป็นชั่วโมงเต็มเสมอ (อินเดียคือ +5:30 เนปาล +5:45)
และการปัดค่าที่รายงานจะบอกความเท็จโดยไม่แจ้ง
zone ที่คุณเขียนด้วยมือเป็นจำนวนชั่วโมงเต็ม ดังนั้นอาร์กิวเมนต์จึงเป็น `int`

เมื่อให้ `zone` `daylight-p` เป็น `false` และ `zone` เป็นค่าที่ให้พอดี ตามที่ CL กำหนด
(*If a time-zone is supplied, daylight saving time information is ignored*)

เวลาท้องถิ่นที่ตกในช่วงเปลี่ยนเวลาออมแสงไม่ซ้ำกันตั้งแต่แรก และ CL
ไม่ได้บอกว่าจะเลือกอันไหน `encode-universal-time` คืนหนึ่งในสองคำตอบสำหรับเวลาเช่นนั้น

## 3. สภาพแวดล้อมขณะรัน

| ชื่อ | รูปแบบ | ชนิด | คำอธิบาย |
|---|---|---|---|
| `command-line-args` | `(command-line-args)` | `()→Vector<string>` | บรรทัดคำสั่ง **สมาชิกตัวที่ 0 คือชื่อโปรแกรม** |
| `getenv` | `(getenv name)` | `string→Option<string>` | ตัวแปรสภาพแวดล้อม `none` หากไม่ได้ตั้งหรือไม่ใช่ UTF-8 |
| `home-directory` | `(home-directory)` | `()→Option<string>` | `$HOME` พื้นฐานของ `user-homedir-pathname` ([Pathname](streams-files.md#92-ฟังก์ชัน)) |
| `lisp-implementation-type` | `(lisp-implementation-type)` | `()→string` | `"typelisp"` |
| `lisp-implementation-version` | `(lisp-implementation-version)` | `()→string` | เวอร์ชันของ implementation |
| `machine-type` | `(machine-type)` | `()→string` | สถาปัตยกรรม CPU (`x86_64` / `aarch64` …) ค่าของ **เป้าหมายการบิลด์** |
| `machine-instance` | `(machine-instance)` | `()→Option<string>` | ชื่อโฮสต์ |
| `machine-version` | `(machine-version)` | `()→Option<string>` | ชื่อของฮาร์ดแวร์ที่ **กำลังรันอยู่ตอนนี้** (`Apple M1` / `Intel(R) Xeon(R) …`) `none` ในที่ที่ระบุไม่ได้ |
| `software-type` | `(software-type)` | `()→string` | OS (`macos` / `linux` …) |
| `software-version` | `(software-version)` | `()→Option<string>` | รุ่นของ OS (`uname -r` เช่น `24.6.0`) |
| `short-site-name` | `(short-site-name)` | `()→Option<string>` | ชื่อสั้นของไซต์ที่ติดตั้ง **เป็น `none` เสมอ** |
| `long-site-name` | `(long-site-name)` | `()→Option<string>` | ในทำนองเดียวกัน ชื่อยาว **เป็น `none` เสมอ** |

ตัวที่คืน `Option` เป็นรายการที่ CL ยอมให้เป็น `NIL` (*or nil if no such name can be
determined*) POSIX ไม่มีที่บันทึกชื่อไซต์ ดังนั้นจึงเป็น `none` เสมอ SBCL คืน
เหมือนกัน สังเกตความต่างระหว่าง `machine-type` และ `machine-version`: อย่างแรกคือสถาปัตยกรรม
ที่ไบนารีนี้ **ถูกบิลด์** สำหรับมัน อย่างหลังคือชิปที่ **กำลังรัน** มันตอนนี้

สมาชิกตัวที่ 0 ของ `command-line-args` คือพาธของสคริปต์สำหรับ `typl script.typl a b` และตัว
ไฟล์ปฏิบัติการเองสำหรับไฟล์ปฏิบัติการ AOT ที่รันเป็น `./prog a b` **ไม่ว่ารันแบบใดก็อ่านอาร์กิวเมนต์เดียวกัน
ที่ดัชนีเดียวกัน** (`typl` ตัดชื่อของตัวเองและตัวเลือกอย่าง `--heap-cells` ออกก่อนส่ง
ต่อ)

| `yes-or-no-p` | `(yes-or-no-p question)` | `string→bool` | ให้ผู้ใช้สะกด `yes` / `no` ออกมา สำหรับคำถามที่ความผิดพลาดมีราคาแพง |

`false`

## 5. เครื่องมือของการ implement (CLHS 25.2)

ชั้นที่ implementation ตอบคำถามเกี่ยวกับตัวมันเอง `heap-info` / `room` / `dribble`
เป็นฟังก์ชันธรรมดา `trace` / `untrace` / `step` / `disassemble` / `ed` เป็น **ฟอร์มพิเศษ**
(`trace` / `untrace` / `disassemble` / `ed` รับ *ชื่อ* ของการนิยาม และ `step` รับ *ฟอร์ม* ทั้งหมดไม่ถูกประเมินค่า)

| ชื่อ | รูปแบบ | ชนิด | คำอธิบาย |
|---|---|---|---|
| `heap-info` | `(heap-info)` | `()→heap-info` | สถานะปัจจุบันของฮีปเป็น struct ตัวเลขเดียวกับที่ `room` พิมพ์ |
| `room` | `(room &optional verbose)` | `(bool)→()` | รายงาน `heap-info` ไปยัง `*standard-output*` `(room true)` ให้รายละเอียดมากขึ้น |
| `dribble` | `(dribble &optional path)` | `(string)→Result<(),FileError>` | เริ่มบันทึกเอาต์พุตของเซสชันไปยัง `path` / หยุดบันทึกเมื่อเรียกโดยไม่มีอาร์กิวเมนต์ |
| `trace` | `(trace name...)` | `Sexpr` | รายงานการเรียกการนิยามที่ระบุชื่อไปยัง `*trace-output*` คืนรายการชื่อที่กำลัง trace อยู่ตอนนี้ |
| `untrace` | `(untrace name...)` | `Sexpr` | หยุดรายงาน **เมื่อไม่มีอาร์กิวเมนต์ จะลบทั้งหมด** |
| `step` | `(step form)` | ชนิดของ `form` | ประเมิน `form` โดยหยุดถามที่ทุกการเรียก |
| `disassemble` | `(disassemble name [llvm])` | `()` | พิมพ์สิ่งที่การนิยามนั้นกลายเป็น โดยค่าเริ่มต้นคือโค้ดเครื่องของโฮสต์ LLVM IR เมื่อใช้ `true` |
| `ed` | `(ed)` / `(ed name)` / `(ed "path")` | `Result<(),FileError>` | เริ่ม `$VISUAL` / `$EDITOR` เมื่อให้ชื่อ จะเปิดที่บรรทัดที่เขียนการนิยามนั้น |

`trace`/`untrace`/`step`/`disassemble` ใช้ได้เฉพาะในอินเทอร์พรีเตอร์ และฟังก์ชันที่เรียกสิ่งเหล่านี้คอมไพล์ไม่ได้
([เอกสารอ้างอิงไวยากรณ์ บทที่ 10](../syntax.md#10-การคอมไพล์))

### 5.1 ฟิลด์ของ `heap-info`

| ฟิลด์ | ชนิด | เนื้อหา |
|---|---|---|
| `capacity` / `live` / `free` | `int` | arena ของ cons ทั้งหมดและการแบ่งย่อย `live + free = capacity` เสมอ |
| `symbols` / `strings` / `boxes` | `int` | จำนวนปัจจุบันของออบเจ็กต์อีกสามประเภทของฮีป |
| `gc-count` | `int` | จำนวนการเก็บขยะตั้งแต่ implementation เริ่มทำงาน |
| `growable` | `bool` | arena ยังขยายได้หรือไม่ |

ฟิลด์ทั้งหมดเป็น `int` (ยกเว้น `growable`) ขีดจำกัดการเติบโต (ดูคำอธิบายของ
`typl --heap-cells`) ไม่ถูกรายงาน เพราะสิ่งที่ผู้อ่านต้องการรู้คือยังขยายได้หรือไม่
(`growable`)

### 5.2 สิ่งที่ `trace` / `step` มองเห็นและมองไม่เห็น

- **การนิยามที่ตัวเนื้อหาคอมไพล์แล้วก็มองเห็น จากจุดเรียกที่กำลังอินเทอร์พรีต**
- **จุดเรียก *ภายใน* โค้ดที่คอมไพล์แล้วมองไม่เห็น** การ trace ชื่อที่มีตัวเนื้อหาที่คอมไพล์แล้วจะเพิ่ม
  หมายเหตุหนึ่งบรรทัดบอกเรื่องนี้ ข้อจำกัดเดียวกับที่ SBCL อธิบายสำหรับการเรียกในเครื่อง
- **การเรียกผ่านค่า closure (`funcall`/`apply`) มองไม่เห็น** closure ไม่มีชื่อ
- **การนิยามแบบ generic ไม่ครอบคลุม** มีการสร้างสำเนาสำหรับแต่ละชนิดในแต่ละจุดที่ใช้ จึง
  ไม่มีตัวเนื้อหาเดียวให้ระบุชื่อ (เหตุผลเดียวกัน และถ้อยคำเดียวกัน กับตอนที่ `compile` ปฏิเสธ)

คำสั่งของ `step` คือ `s` (ก้าวเข้าสู่การเรียกนี้ บรรทัดว่างทำเหมือนกัน), `n` (ข้ามการเรียกนี้),
`c` (หยุดถามตั้งแต่ตรงนี้) และ `q` (ยกเลิก) **หากอินพุตมาตรฐานไม่ใช่เทอร์มินัล `step`
เพียงประเมิน `form`**: พฤติกรรมเสื่อมที่ CLHS อนุญาตอย่างชัดเจน เพื่อให้สคริปต์และการทดสอบไม่
ค้างที่ prompt ที่ไม่มีใครตอบได้

`$VISUAL` / `$EDITOR` ของ `ed` ถูกแยกที่ช่องว่าง ดังนั้น `EDITOR="code -w"` ใช้ได้ หากไม่ได้ตั้งทั้งสอง
ผลลัพธ์คือ `Err`: ไม่เดา `vi` หมายเลขบรรทัดถูกส่งก่อน ในรูป `+N`

`dribble` บันทึกทั้งสามทางที่เอาต์พุตของเซสชันออกจากโพรเซส: สิ่งที่
`print`/`println`/`format` เขียน สิ่งที่เขียนไปยังสตรีมที่เชื่อมกับเอาต์พุตมาตรฐาน และ
บรรทัดที่พิมพ์ใน REPL พร้อมกับค่าที่ REPL พิมพ์กลับ

ต่อการดำเนินการ ([ชนิดข้อผิดพลาด](option-result.md#3-ชนิดข้อผิดพลาดและ-trait-error))

| ชื่อ | รูปแบบ | ชนิด | คำอธิบาย |
|---|---|---|---|
| `parse-int` | `(parse-int s &key radix junk-allowed)` | `string→Result<int,ParseIntError>` | `parse-integer` ของ CL ข้ามช่องว่างนำหน้าและตามหลัง (ชุดเดียวกับ `trim`) อ่านเครื่องหมาย `+`/`-` อย่างมากหนึ่งตัว แล้วเป็นหลักในฐาน `radix` (ค่าเริ่มต้น 10, 2 ถึง 36; หลักที่เกิน 10 ใช้ตัวพิมพ์ใหญ่หรือเล็กก็ได้) ไม่มีขีดจำกัดจำนวนหลัก (`int`) อักขระอื่นที่เหลือให้ `Err` เมื่อใช้ `:junk-allowed true` จะหยุดที่ตัวที่ไม่ใช่หลักตัวแรกและเพิกเฉยส่วนที่เหลือ แต่ให้ `Err` หากไม่มีหลักเลยสักตัว (สอดคล้องกับ `nil` ของ CL) ไม่คืนค่าที่สองของ CL (ตำแหน่งที่การอ่านจบ) `radix` ที่เกินช่วงจะ panic (เป็นความผิดพลาดของผู้เรียก ไม่ใช่ของข้อความ) |
| `parse-float` | `(parse-float s)` | `string→Result<f64,ParseFloatError>` | จำนวนทศนิยม รับ `inf`/`nan` ด้วย |
| `read` | `(read s)` | `string→Result<Option<Sexpr>,ReadError>` | อ่านหนึ่ง `Sexpr` จาก `s` (ด้วยตัวอ่านเดียวกับที่อ่านซอร์สโค้ด) วงเล็บไม่สมดุล สตริงที่ไม่ปิด และทำนองเดียวกันให้ `Err` การอ่านจากสตรีมคือ `read-sexpr` ([สตรีม](streams-files.md#6-ฟังก์ชัน-generic-และการดำเนินการกับไฟล์)) |
| `read-from-string` | `(read-from-string s [start])` | `(string,int)→Result<cons-cell<Option<Sexpr>,int>,ReadError>` | `read` บวก **ตำแหน่งที่การอ่านจบ** `(car r)` คือค่าและ `(cdr r)` คือตำแหน่งของอักขระถัดไปที่จะอ่าน `start` ค่าเริ่มต้นเป็น 0 |
| `read-from-string-preserving-whitespace` | เหมือนข้างบน | เหมือนข้างบน | เหมือนกัน แต่ไม่ใช้ช่องว่างที่จบ datum ความต่างเห็นได้ในตำแหน่งที่คืน |
| `eval` | `(eval form)` | `Option<Sexpr>→Result<Option<Sexpr>,EvalError>` | ตรวจสอบชนิดของ `form` ตอนรันและประเมินค่า ตาม `eval` ของ CL |

CL คืน **สองค่า** (ค่าและตำแหน่ง) จาก `read-from-string` แต่ภาษานี้ไม่มี
ค่าหลายค่า จึงคืน `cons-cell` หนึ่งตัว การมีตำแหน่งทำให้การอ่านสตริงทีละ datum เป็นลูป
แทนการสแกนใหม่:

```lisp
(let ((s "1 2 3") (i 0) (going true))
  (while going
    (match (read-from-string s i)
      ((ok p) (progn (println "~s" (car p)) (setf i (cdr p))
                     (if (>= i (length s)) (progn (setf going false) ()) ()) ()))
      ((err e) (progn (setf going false) ())))))
```

ความต่างที่ `preserving-whitespace` สร้างคือ **ช่องว่างหนึ่งตัว**: `read` ของ CL ใช้
ช่องว่างที่จบ datum และ `read-preserving-whitespace` ทิ้งไว้ `(read-from-string "12 34")`
คืนตำแหน่ง 3 และเวอร์ชัน preserving คืน 2

ไวยากรณ์ตัวเลขที่ตัวอ่านรับอยู่ใน[เอกสารอ้างอิงไวยากรณ์ บทที่ 1](../syntax.md#1-องค์ประกอบทางศัพท์)
สิ่งที่ `*print-radix*` ([การพิมพ์](printing.md#62-ฐาน-ตัวพิมพ์-และการอ่านกลับได้)) พิมพ์อ่านกลับได้ตามที่
เป็น ไม่มี `*read-base*` ของ CL

### 6.1 ความหมายของ `eval`

ตาม `eval` ของ CLHS: ประเมินค่าใน **สภาพแวดล้อมโกลบอลปัจจุบัน** (ฟังก์ชัน ตัวแปร ชนิด
และแมโครโกลบอล รวมถึงการนิยามที่เพิ่มตอนรัน) และใน **สภาพแวดล้อม lexical ว่าง** (การผูก
ท้องถิ่นของ `let`/`lambda` ของผู้เรียกมองไม่เห็น) ทั้งนิพจน์และ
การนิยาม (`defun`/`defvar`/`defstruct`/`defenum`/`defmacro`) ประเมินได้ และการนิยามถูก
ลงทะเบียนในสภาพแวดล้อมโกลบอลทันทีและถาวร

```lisp
(eval (unwrap (read "(+ 40 2)")))                 ; => (ok 42)
(defvar (x i32) 10)
(eval (unwrap (read "(+ x 5)")))                  ; => (ok 15)  ; the global x is visible
(eval (unwrap (read "(defun sq ((n i32)) i32 (* n n))")))  ; => (ok sq)  ; returns the defined name
(eval (unwrap (read "(sq 9)")))                   ; => (ok 81)  ; the definition just made is visible
```

- **ค่าที่คืน**: สำหรับนิพจน์ คือผลลัพธ์เป็น `Option<Sexpr>` สำหรับการนิยาม คือสัญลักษณ์ของ
  ชื่อที่นิยาม (เหมือนใน CL) หากต้องการใช้ผลลัพธ์ ให้แยก `Sexpr` ด้วย `match`
  (`(int n)`/`(str s)`/…)
- **ความแตกต่างเนื่องจากชนิดสถิต (สำคัญ)**: CL คืนค่าจริงของผลลัพธ์ แต่ในภาษา
  นี้ชนิดที่คืนทำได้เพียง `Result<Option<Sexpr>,EvalError>` แบบเดียวกันหมด และ **โค้ด
  ที่เขียนแบบสถิตอ้างอิงล่วงหน้าไปยังชื่อที่ `eval` นิยามตอนรันไม่ได้**: `(sq 9)` ที่เขียน
  ตรง ๆ ในไฟล์ถูกตรวจสอบก่อนที่ `eval` ที่นิยาม `sq` จะรัน และ "ไม่ได้นิยาม" อย่างไรก็ตาม
  **`eval` ที่ตามมามองเห็นมัน** (การตรวจสอบชนิดของมันรันตอนรัน หลังการนิยาม) REPL ตรวจสอบ
  และรันทีละบรรทัด ดังนั้นชื่อที่นิยามด้วย `eval` เรียกตรง ๆ ได้จากบรรทัดถัดไป
- **ข้อผิดพลาด**: ข้อผิดพลาดของชนิดและของไวยากรณ์คืน `Err` (ไม่ panic) **panic ตอนรัน** ใน
  โค้ดที่ประเมิน (การหารด้วยศูนย์และอื่น ๆ) แพร่ออกไปเหมือนจากโค้ดที่เขียนตรง ๆ การล้างทรัพยากร
  ของ `unwind-protect` ที่คั่นอยู่จะรัน
  ([เอกสารอ้างอิงไวยากรณ์ บทที่ 8](../syntax.md#8-การออกจากการทำงานแบบไม่เป็นเส้นตรง-catch--throw--unwind-protect))
- **เนมสเปซ**: เมื่อรันด้วย `typl file.typl` และภายในไฟล์ปฏิบัติการ AOT `eval` ประเมินใน
  เนมสเปซของโมดูลของสคริปต์ (โกลบอลของสคริปต์เองมองเห็น) REPL ประเมินใน
  เนมสเปซราก
- **การคอมไพล์**: ทั้ง `read` และ `eval` คอมไพล์ได้ วิธีที่จัดการในไฟล์ปฏิบัติการ AOT และ
  ผลที่ตามมา (ฟอร์มที่ส่งให้ eval ถูกอินเทอร์พรีต) อยู่ใน
  [เอกสารอ้างอิงไวยากรณ์ 10.2](../syntax.md#102-eval-ในไฟล์ปฏิบัติการ-aot)

## 7. Docstring / `documentation`

`defun`/`defmethod` (รวมภายใน `impl`)/`defmacro`/`defvar`/`defconstant`/`defstruct`/`defenum`/
`deftype`/`deftrait` มี docstring ได้ ตำแหน่งตามกฎของ CL สำหรับแต่ละตัว:

| ฟอร์ม | ตำแหน่งของ docstring |
|---|---|
| `defun` / `defmethod` / `defmacro` | ที่จุดเริ่มต้นของตัวเนื้อหา (หลังชนิดที่คืนและอนุประโยค `where`) เฉพาะเมื่อมีอย่างน้อยหนึ่งฟอร์มของตัวเนื้อหาตามมา สตริงเดี่ยวยังคงเป็นค่าที่คืน |
| `defvar` / `defconstant` | **หลัง** ค่าเริ่มต้น: `(defvar (name Type) value "doc")` |
| `defstruct` / `defenum` | **ทันทีหลัง** ชื่อ ก่อนฟิลด์/variant |
| `deftype` | **ทันทีหลัง** ชื่อ ก่อนชนิด: `(deftype meters "doc" i32)` |
| `deftrait` | ทันทีหลังรายการ supertrait ก่อนรายการต่าง ๆ หนึ่งอันสำหรับทั้ง trait **เมทอดที่มี implementation เริ่มต้น** ใส่ docstring ของตัวเองก่อนตัวเนื้อหาได้ |

| ชื่อ | รูปแบบ | ชนิด | คำอธิบาย |
|---|---|---|---|
| `documentation` | `(documentation name)` | (ฟอร์มพิเศษ; `name` เป็นสัญลักษณ์เปล่าหรือ `Type::method`)→`Option<string>` | คืน docstring ของ `name` |

เหมือน `quote`/`compile` `documentation` เป็นฟอร์มพิเศษ (อ่าน `name` เป็นชื่อที่ไม่ถูกประเมินค่า)
ต่างจาก `(documentation 'name 'function)` ของ CL ตรงที่ไม่รับอาร์กิวเมนต์ชนิด แต่จะแก้ไขชื่อ
เปล่าตามลำดับ **ตัวแปร → ฟังก์ชัน → ชนิด → trait → แมโคร** (ลำดับความสำคัญเดียวกับตัวระบุ
เปล่าที่ประเมินเป็นนิพจน์) รูปแบบ `Type::method` ค้นหา docstring ของเมทอด
ที่เกี่ยวข้องหรือเมทอดสถิต

```lisp
(defun square ((n i32)) i32
  "Returns n squared."
  (* n n))

(unwrap-or (documentation square) "no docs")   ; => "Returns n squared."

(defstruct point
  "A 2D point."
  (x i32)
  (y i32))

(unwrap-or (documentation point) "no docs")    ; => "A 2D point."
```

**ค่าถูกตัดสินตอนตรวจสอบ**: หากชื่อไม่แก้ไขไปยังการนิยามใด จะเป็นข้อผิดพลาด
ตอนตรวจสอบ (เหมือนการอ้างอิงตัวแปรที่ไม่ได้นิยาม) หากแก้ไขได้แต่ไม่มี docstring
ผลลัพธ์คือ `Option::none`

**ไม่ครอบคลุม**:

- `(setf documentation)` (การเปลี่ยน docstring ตอนรัน) ไม่มี
- ชื่ออิสระที่มี module กำกับ (`mod::name`; `Type::method` รองรับ) ไม่รองรับ
- การประกาศเมทอดใน `deftrait` **ที่ไม่มีตัวเนื้อหา** มี docstring ไม่ได้ สตริง literal
  ที่ตามมาท้ายจะเป็นตัวเนื้อหา (ค่าที่คืน) ของ implementation เริ่มต้นเอง จึงไม่มีทางแยก
  ทั้งสอง

hover ของ language server (`typl-lsp`) แสดง docstring ด้วย

## 8. แมโคร

วิธีนิยามแมโครอยู่ใน[เอกสารอ้างอิงไวยากรณ์ 3.14](../syntax.md#314-defmacro--การนิยามแมโคร)

| ชื่อ | รูปแบบ | ชนิด | คำอธิบาย |
|---|---|---|---|
| `gensym` | `(gensym)` / `(gensym prefix)` | `(&optional string)→symbol` | สัญลักษณ์ใหม่ ชื่อของมันคือ `" <prefix><n>"` โดย `n` คือ `*gensym-counter*` ช่องว่างนำหน้าเขียนในซอร์สไม่ได้ ดังนั้นการผูกที่สร้างขึ้นจะไม่ชนกับชื่อที่เขียน |
| `*gensym-counter*` | ตัวแปร | `int` | หมายเลขที่ `gensym` ใช้ครั้งถัดไป เหมือนใน CL อ่านและตั้งค่าได้ |
| `macroexpand-1` | `(macroexpand-1 form)` | `Option<Sexpr>→Result<Option<Sexpr>,EvalError>` | ขยายการเรียกแมโครหนึ่งขั้น `none` หมายถึง "ไม่ใช่การเรียกแมโคร" |
| `macroexpand` | `(macroexpand form)` | `Option<Sexpr>→Result<Option<Sexpr>,EvalError>` | ทำซ้ำจนไม่ใช่แมโครอีก |

`macroexpand-1` คืน `Option` CL รายงาน "ขยายหรือไม่" เป็นค่าที่คืนค่าที่สอง แต่
ไม่มีค่าหลายค่า จึงให้ `none` ทำหน้าที่นั้น **แมโครที่ขยายเป็นการเรียกตัวเอง
ไม่มีวันสับสนกับสิ่งที่ไม่ใช่แมโคร** การขยายหนึ่งขั้นเป็นอันเดียวกับที่ตัวตรวจสอบชนิดใช้
ดังนั้นสิ่งที่โปรแกรมเห็นและสิ่งที่ตัวตรวจสอบเห็นไม่เคยต่างกัน

```lisp
(defmacro twice (x) `(+ ,x ,x))
(macroexpand-1 '(twice 5))   ; => (ok (+ 5 5))
(macroexpand-1 '(+ 1 2))     ; => (ok ())      ; none shows as the empty list (Option<Sexpr> is transparent)
(macroexpand '(when true 1)) ; => (ok (if true (progn 1 ()) ()))
```

สิ่งที่ CL มีแต่ภาษานี้ไม่มี: `eval-when` (`:compile-toplevel`/`:load-toplevel`/`:execute`
ตรงกันเสมอ จึงไม่มีความแตกต่างให้เลือก), `define-compiler-macro`, `load-time-value`,
`make-symbol`/`copy-symbol`/`gentemp` (สัญลักษณ์ที่ไม่ได้ intern การผูกถูกค้นหาด้วยชื่อ จึง
ไม่ได้อะไรเพิ่ม)

## 9. การผูกแมโครท้องถิ่น (`macrolet` / `symbol-macrolet`)

ทั้งสองเป็นฟอร์มพิเศษที่ผูก **ชื่อที่ไม่ใช่ค่า** แบบ lexical ไม่มีอะไรเหลือตอนรัน:
สิ่งที่ถูกคอมไพล์คือรูปที่ขยายแล้วของตัวเนื้อหา

```lisp
(macrolet ((twice (x) `(+ ,x ,x)))
  (twice 21))                       ; => 42

(let ((v (the Vector<i32> (Vector::new))))
  (progn (push v 7)
    (symbol-macrolet ((head (get v 0)))
      (progn (setf head 42) head))))  ; => 42
```

- การผูก `macrolet` ซ่อนแมโครโกลบอลชื่อเดียวกัน **เฉพาะระหว่างตัวเนื้อหา** รายการพารามิเตอร์
  เหมือน `defmacro` (`&optional`/`&rest`/`&key`)
- **พี่น้องของ `macrolet` เดียวกันมองเห็นกันจาก *ตัวเนื้อหา* ของตัวเองไม่ได้** (เหมือนใน CL; นี่คือ
  ความต่างจาก `labels`) การขยายถูกตรวจสอบที่จุดใช้งาน ดังนั้น `earlier` ที่ขยายเป็น
  `(later ...)` ใช้ได้: ทั้งสองมองเห็นที่จุดนั้น
- ชื่อของ `symbol-macrolet` เข้าสู่สภาพแวดล้อมเป็นการผูกธรรมดา ดังนั้น `let` ด้านในซ่อน
  ชื่อเดียวกัน และตัวแปรภายนอกถูกซ่อน: กฎของ CL ออกมาตามที่เป็น
- **`setf` เขียนไปยังการขยาย** `(setf head 42)` คือ `(setf (get v 0) 42)`
- การขยายถูกตรวจสอบใน **สภาพแวดล้อมของจุดใช้งาน** (ไม่ใช่จุดผูก)

| `dlet` | `(dlet ((*var* val)...) body...)` | — | แทนที่โกลบอลเฉพาะระหว่าง `body` และคืนค่าเดิมตอนออก CL เขียนสิ่งนี้เป็น `let` แต่ `let` ในภาษานี้ผูกแบบ lexical เสมอ จึงมีชื่อแยก (บทบาทเดียวกับแมโครชื่อเดียวกันของ Emacs Lisp) คืนค่าเดิมไม่ว่าจะออกจากตัวเนื้อหาด้วยวิธีใด: จบตามปกติ, `throw`, `panic`, `break`/`return` **ไม่ใช่การผูกต่อ task** |
| `with-standard-io-syntax` | `(with-standard-io-syntax body...)` | — | รัน `body` โดยให้ตัวแปรควบคุมตัวพิมพ์ทุกตัวอยู่ที่ค่ามาตรฐานและ `*read-eval*` เป็น `true` ([การพิมพ์](printing.md#6-การควบคุมปริมาณที่พิมพ์)) |
| `exit` | `(exit code)` | `int→!` | จบโพรเซส |
| `dump` | `(dump path)` | `string→bool` | เขียนสภาพแวดล้อมปัจจุบัน (ข้อมูลชนิดบวกตัวเนื้อหาที่คอมไพล์แล้ว) ลงไฟล์เดียว `typl --image <path>` เริ่มใหม่จากมัน ใช้ได้เฉพาะในอินเทอร์พรีเตอร์ ([เอกสารอ้างอิงไวยากรณ์ 10.1](../syntax.md#101-dump)) |
