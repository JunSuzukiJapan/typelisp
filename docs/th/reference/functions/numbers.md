# ตัวเลข

การดำเนินการกับจำนวนเต็ม จำนวนทศนิยม จำนวนตรรกยะ จำนวนเชิงซ้อน และบูลีน รวมถึงฟังก์ชันอื่นที่เกี่ยวกับ
ตัวเลข สำหรับวิธีอ่านรูปแบบการเรียก ดู[ฟังก์ชันที่มีให้ในตัว](README.md)

## 1. จำนวนเต็มความกว้างคงที่

มีชนิดจำนวนเต็มเจ็ดชนิด: **`int`** (`integer` ของ CL: ความแม่นยำไม่จำกัด และเป็นชนิดเริ่มต้นของ
literal จำนวนเต็มที่ไม่มีคำอธิบายชนิด; บทที่ 3) และชนิดความกว้างคงที่ `i8` `i16` `i32` `u8` `u16` `u32`
การดำเนินการจะแก้ไขไปยังชนิดใดถูกกำหนดโดยชนิดของอาร์กิวเมนต์แรก (แต่ละชนิดเป็นอิสระต่อกัน
ไม่มีการแปลงโดยปริยาย) **ไม่มีชนิดจำนวนเต็ม 64 บิต** ค่าตอนรันคือหนึ่ง word ที่บิตต่ำเป็นแท็ก ดังนั้นเหลือเพียง 63 บิตสำหรับ
จำนวนเต็ม immediate และชนิดที่อ้างว่ามี 64 บิตจะต้องทิ้งบิตบนสุดไปที่ใดที่หนึ่ง `int` กลายเป็น bignum
เมื่อเกิน 63 บิตนั้น ดังนั้นหากความกว้างไม่สำคัญ ให้ใช้ `int` ตารางด้านล่างสำหรับ
ชนิดความกว้างคงที่ทั้งหก (ตารางของ `int` อยู่ในบทที่ 3)

| ชื่อ | รูปแบบ | ชนิด | คำอธิบาย |
|---|---|---|---|
| `+` `-` `*` `/` | `(op a b)` | `(T,T)→T` | การคำนวณสี่ประการ `/` ตัดไปทางศูนย์และ panic เมื่อหารด้วยศูนย์ |
| `mod` | `(mod a b)` | `(T,T)→T` | เศษที่เหลือ (`mod` ของ CL, **การหารแบบปัดลง (floor)**: เครื่องหมายตามตัวหาร `(mod -7 3)`→`2`) panic เมื่อหารด้วยศูนย์ |
| `rem` | `(rem a b)` | `(T,T)→T` | เศษที่เหลือ (`rem` ของ CL, **การหารแบบตัดทอน (truncating)**: เครื่องหมายตามตัวตั้ง `(rem -7 3)`→`-1`) panic เมื่อหารด้วยศูนย์ |
| `floor-div` `ceiling-div` `round-div` `truncate-div` | `(op a b)` | `(T,T)→cons-cell<T,T>` | สอดคล้องกับ `floor`/`ceiling`/`round`/`truncate` สองอาร์กิวเมนต์ของ CL (`(floor 7 2)`→ผลหาร 3 เศษ 1) แทนที่จะเป็นค่าหลายค่า จะคืนผลหารและเศษใน `cons-cell` (`car`=ผลหาร, `cdr`=เศษ) `round-div` ปัดกรณีกึ่งกลางไปหาเลขคู่ เหมือนที่ CL ทำ |
| `abs` | `(abs x)` | `T→T` | ค่าสัมบูรณ์ |
| `signum` | `(signum x)` | `T→T` | เครื่องหมาย (`1`/`-1`/`0`) |
| `gcd` | `(gcd a b)` | `(T,T)→T` | ตัวหารร่วมมาก |
| `lcm` | `(lcm a b)` | `(T,T)→T` | ตัวคูณร่วมน้อย (0 หากตัวใดตัวหนึ่งเป็น 0) |
| `max` `min` | `(op a b)` | `(T,T)→T` | ตัวที่มากกว่า / น้อยกว่า (สามอาร์กิวเมนต์ขึ้นไปถูกขยายด้วยน้ำตาลไวยากรณ์ variadic ของบทที่ 8) |
| `1+` `1-` | `(op x)` | `T→T` | `x±1` |
| `<` `<=` `>` `>=` `=` `/=` | `(op a b)` | `(T,T)→bool` | การเปรียบเทียบ |
| `eq` `eql` `equal` `equalp` | `(op a b)` | `(T,T)→bool` | เหมือน `=` ทั้งหมด (ไม่มีความแตกต่างสำหรับตัวเลขชนิดเดียวกัน) |
| `int->float` | `(int->float x)` | `T→f64` | การแปลงขยายเป็น `f64` |
| `int->int` | `(int->int x)` | `T→int` | การแปลงขยายเป็น `int` (ถูกต้องแม่นยำเสมอ) สิ่งที่ `(as int x)` ทำ |
| `int->ratio` | `(int->ratio x)` | `T→ratio` | การแปลงขยายเป็น `ratio` (ถูกต้องแม่นยำเสมอ) |
| `int->char` | `(int->char x)` | `T→char` | ตีความค่าเป็น Unicode scalar value panic เมื่อค่าไม่ถูกต้อง |
| `try-int->char` | `(try-int->char x)` | `T→Option<char>` | เวอร์ชันของ `int->char` ที่คืน `None` เมื่อล้มเหลว |
| `int->i8` `int->i16` `int->i32` `int->u8` `int->u16` `int->u32` | `(int->W x)` | `T→W` | การแปลงความกว้าง ค่าที่ไม่พอดีถูกตัดทอน (เหมือน `as` ของ Rust) |
| `try-int->i8` … `try-int->u32` | `(try-int->W x)` | `T→Option<W>` | การแปลงเดียวกันในรูปของคำถาม `None` หากค่าไม่พอดีกับความกว้างนั้น |

การแปลงเหล่านี้คือสิ่งที่ฟอร์มพิเศษ `(as Type x)`/`(try-as Type x)`
([เอกสารอ้างอิงไวยากรณ์](../syntax.md#7-ฟอร์มพิเศษอื่น-ๆ)) ทำ การดำเนินการระดับบิต (`logand`/`ash`/`ldb` และ
อื่น ๆ) และ predicate (`zerop`/`evenp` และอื่น ๆ) มีรูปร่างเดียวกันข้ามชนิด จึงรวมไว้
ในบทที่ 11 และ 9

`i8` `i16` `u8` `u16` `u32` มีตารางของบทนี้ทุกประการ และ `f32` มีตาราง `f64`
ของบทที่ 4 ทุกประการ

**ชื่อชนิดหมายถึงความกว้างและเครื่องหมายของมัน ไม่มีอะไรมากกว่านั้น** `i32` หมายถึง "ถือ 32 บิตเป็นมีเครื่องหมาย"
และ `u32` หมายถึง "ถือ 32 บิตเป็นไม่มีเครื่องหมาย" `(+ (the u8 200) (the u8 100))` คือ `44`,
`(+ 2147483647 1)` (เป็น `i32`) คือ `-2147483648` และ `(lognot (the u32 0))` คือ `4294967295` `f32` ก็
เหมือนกัน: binary32 จริง ๆ `(/ (the f32 1.0) (the f32 3.0))` พิมพ์เป็น `0.33333334` ซึ่งเป็นคนละ
ค่ากับผลลัพธ์ `f64` `0.3333333333333333`

แค็ตตาล็อก CL ที่สืบเนื่อง (`abs`/`signum`/`gcd`/`lcm`/`isqrt`/`expt` และ predicate ของบทที่ 9)
มีสำหรับ `int`/`i32`/`f64`/`ratio` หากต้องการสำหรับความกว้างอื่น ให้ย้ายด้วย `(as int x)` /
`(as i32 x)` (มีการแปลงความกว้างสำหรับทุกคู่)

## 2. word ดิบที่ขอบเขตกับ C (`ptr` / `c-long` / `c-ulong`)

สามชนิดที่ใช้เฉพาะสำหรับส่งค่าไปและกลับจากฟังก์ชัน C ที่ประกาศด้วย
[`defffi`](../syntax.md#33-defffi--การประกาศฟังก์ชัน-c-ffi) `ptr` เป็นตัวชี้ทึบ และ
`c-long` / `c-ulong` คือ `long` / `unsigned long` ของ C การทำให้เป็นค่าต้องอยู่ภายใน
`(unsafe ...)`

**ไม่มีการคำนวณ** ไม่มีสิ่งใดในตารางของบทที่ 1 ใช้ได้: ทั้ง `(+ p 1)` และ `(< n m)`
เขียนไม่ได้ สิ่งเหล่านี้เป็น word ที่ส่งให้ C ไม่ใช่ชนิดที่ใช้คำนวณ ดังนั้นหากต้องการคำนวณ ให้ย้ายไปยัง
ชนิดที่มีความกว้าง `c-long` / `c-ulong` มีเฉพาะการแปลง:

| ชื่อ | รูปแบบ | ชนิด | คำอธิบาย |
|---|---|---|---|
| `int->i8` … `int->u32` | `(int->W x)` | `T→W` | การแปลงความกว้างเดียวกับบทที่ 1 ค่าที่ไม่พอดีถูกตัดทอน |
| `try-int->i8` … `try-int->u32` | `(try-int->W x)` | `T→Option<W>` | การแปลงเดียวกันในรูปของคำถาม |
| `int->c-long` `int->c-ulong` | `(int->W x)` | `T→W` | ทางเข้า จาก word ดิบอีกชนิดและจากชนิดจำนวนเต็มของบทที่ 1 |
| `try-int->c-long` `try-int->c-ulong` | `(try-int->W x)` | `T→Option<W>` | เหมือนข้างบน |
| `int->int` | `(int->int x)` | `T→int` | **ถูกต้องแม่นยำเสมอ** วิธีที่ซื่อตรงในการอ่าน `size_t` ที่ไม่พอดีใน `i32` |

`(as i32 x)` / `(try-as i32 x)` / `(as int x)` / `(as c-ulong n)` คือสิ่งที่สิ่งเหล่านี้ทำ และ
มีการแปลงสำหรับทุกคู่กับชนิดจำนวนเต็มของบทที่ 1 `ptr` ไม่มีแม้แต่ตารางนี้:
ไม่มีวิธีอ่านตัวชี้เป็นตัวเลข มันเป็นค่าที่ส่ง รับ และส่งต่อให้ฟังก์ชัน C อื่นเท่านั้น

**พิมพ์ก็ไม่ได้เช่นกัน** `(println "~a" x)` ไม่รับ word ดิบ (ไม่มีการแสดงผลเป็น `Sexpr`)
ดังนั้นให้ย้ายไปยังชนิดที่มีความกว้างก่อน เช่น `(println "~a" (as int n))`

"ไม่มีชนิดจำนวนเต็ม 64 บิต" จากต้นบทที่ 1 ใช้กับสามชนิดนี้ด้วย ที่เป็นเช่นนั้น
**เพราะเก็บไม่ได้**: เป็นฟิลด์ `defstruct` `defvar` ภายในอาร์กิวเมนต์ชนิด หรือภายใน `Sexpr` ไม่ได้ จึงเป็น word ที่เพียงผ่านฟังก์ชันในฐานะอาร์กิวเมนต์
ค่าที่คืน และตัวแปรท้องถิ่น สำหรับรายละเอียด ดู
[เอกสารอ้างอิงไวยากรณ์](../syntax.md#ptr--c-long--c-ulong--word-ดิบของเครื่อง)

## 3. จำนวนเต็มความแม่นยำไม่จำกัด `int`

`integer` ของ CL และ **จำนวนเต็ม** ของภาษานี้: literal จำนวนเต็มที่ไม่มีคำอธิบายชนิดมีชนิดนี้ และ
ฟังก์ชันที่มีให้ในตัวซึ่งคืนตัวเลข เช่น `length` และ `char->int` คืนชนิดนี้ ค่าถูกเก็บ
เป็นค่า immediate 63 บิต (fixnum) ตราบที่พอดี ถูกเลื่อนขั้นเป็น bignum โดยอัตโนมัติเมื่อผลลัพธ์ของการดำเนินการ
ไม่พอดีอีกต่อไป และกลับเป็นค่า immediate เมื่อพอดีอีกครั้ง `eq`
เป็นเอกลักษณ์ของค่าเสมอภายในช่วง fixnum และ `eql`/`=` เป็นเอกลักษณ์เชิงตัวเลขตลอดทั้งช่วง
เป็นคนละชนิดกับชนิดจำนวนเต็มความกว้างคงที่ (บทที่ 1) โดยไม่มีการแปลงโดยปริยาย: `(as int x)` คือการขยายที่ถูกต้องแม่นยำจากความกว้างคงที่ และ `(as i32 n)` /
`(try-as i32 n)` คือการตัดทอน / การตรวจสอบจาก `int` (ความหมายเดียวกับ `int->W` / `try-int->W`
ในบทที่ 1)

variant จำนวนเต็มของ `Sexpr` ก็เป็นเพียง `int` (`(int n)` รับทั้ง fixnum และ bignum)

ฟังก์ชันที่มีให้ในตัวที่รับดัชนีหรือจำนวนนับ (`substring`, `get` ของ `Vector`, จำนวนการเลื่อนของ `ash` และ
อื่น ๆ) รับ `int` แต่การส่งค่าที่ไม่พอดี fixnum เป็นข้อผิดพลาดตอนรัน ("an integer
argument does not fit a fixnum")

| ชื่อ | รูปแบบ | ชนิด | คำอธิบาย |
|---|---|---|---|
| `+` `-` `*` | `(op a b)` | `(int,int)→int` | ไม่เคยล้น (เลื่อนขั้น) |
| `/` | `(/ a b)` | `(int,int)→int` | ตัดไปทางศูนย์ panic เมื่อหารด้วยศูนย์ |
| `mod` | `(mod a b)` | `(int,int)→int` | เศษที่เหลือของการหารแบบปัดลง (เครื่องหมายตามตัวหาร) |
| `max` `min` | `(op a b)` | `(int,int)→int` | |
| `<` `<=` `>` `>=` `=` `/=` | `(op a b)` | `(int,int)→bool` | |
| `eq` `eql` `equal` `equalp` | `(op a b)` | `(int,int)→bool` | ทั้งหมดคือ `=` |
| `logand` `logior` `logxor` `lognot` `logtest` `logcount` `integer-length` `logbitp` `ash` | | | เหมือนบทที่ 11 (two's complement ที่มีบิตไม่จำกัด) |
| `int->float` `int->ratio` `int->char` `try-int->char` | | | เหมือนบทที่ 1 |
| `int->W` `try-int->W` | `(int->W x)` | `int→W` | การตัดทอน / การตรวจสอบ `W` เป็นหนึ่งในความกว้างทั้งหกหรือ `c-long`/`c-ulong` |
| `int->int` | | `int→int` | เอกลักษณ์ (ฝั่งชนิดความกว้างคงที่และ word ของ C `int->int` ขยาย; บทที่ 1) |
| `abs` `signum` `rem` `gcd` `lcm` `expt` `1+` `1-` | | | รูปร่างเดียวกับบทที่ 1 `expt` รับเฉพาะเลขชี้กำลังที่ไม่เป็นลบ |

## 4. จำนวนทศนิยม (`f64` / `f32`)

`f32` มีตารางเดียวกัน

| ชื่อ | รูปแบบ | ชนิด | คำอธิบาย |
|---|---|---|---|
| `+` `-` `*` `/` | `(op a b)` | `(f64,f64)→f64` | IEEE-754 การหารด้วยศูนย์ไม่ panic แต่ให้ `inf`/`NaN` |
| `mod` | `(mod a b)` | `(f64,f64)→f64` | เศษที่เหลือของการหารแบบปัดลง (เหมือนใน CL; เครื่องหมายตามตัวหาร `a - b*floor(a/b)`) |
| `rem` | `(rem a b)` | `(f64,f64)→f64` | เศษที่เหลือของการหารแบบตัดทอน (เหมือนใน CL; เครื่องหมายตามตัวตั้ง `a - b*truncate(a/b)`) |
| `<` `<=` `>` `>=` `=` `/=` | `(op a b)` | `(f64,f64)→bool` | การเปรียบเทียบ |
| `eq` `eql` `equal` `equalp` | `(op a b)` | `(f64,f64)→bool` | เหมือน `=` ทั้งหมด |
| `expt` | `(expt a b)` | `(f64,f64)→f64` | เลขยกกำลัง |
| `abs` | `(abs x)` | `f64→f64` | ค่าสัมบูรณ์ |
| `signum` | `(signum x)` | `f64→f64` | เครื่องหมาย (`1.0`/`-1.0`; `±0.0`/`NaN` ถูกคืนตามที่เป็น เหมือนใน CL ต่างจาก `signum` ของ Rust) |
| `max` `min` | `(op a b)` | `(f64,f64)→f64` | ตัวที่มากกว่า / น้อยกว่า (สามอาร์กิวเมนต์ขึ้นไปถูกขยายด้วยน้ำตาลไวยากรณ์ variadic ของบทที่ 8) |
| `1+` `1-` | `(op x)` | `f64→f64` | `x±1.0` |
| `sqrt` `floor` `ceiling` `round` `truncate` | `(op x)` | `f64→f64` | การดำเนินการเอกภาค |
| `exp` `log` `sin` `cos` `tan` `asin` `acos` `atan` `sinh` `cosh` `tanh` `asinh` `acosh` `atanh` | `(op x)` | `f64→f64` | ฟังก์ชันอดิศัย `log` คือลอการิทึมธรรมชาติ |
| `log` (สองอาร์กิวเมนต์) | `(log x base)` | `(f64,f64)→f64` | ลอการิทึมที่ฐานที่กำหนด ขยายเป็น `(/ (log x) (log base))` (บทที่ 8) |

| `try-float->f32` `try-float->f64` | `(op x)` | `f64→Option<f32>` / `→Option<f64>` | การแปลงเดียวกันในรูปของคำถาม `none` หากการปัดเปลี่ยนค่า (การขยายเป็น `f64` เป็น `some` เสมอ) สิ่งที่ `(try-as f32 x)` ทำ |
| `ffloor` `fceiling` `fround` `ftruncate` | `(op x)` | `f64→f64` | ฟังก์ชันชื่อเดียวกันของ CL เป็นชื่อแทนของ `floor`/`ceiling`/`round`/`truncate` ข้างบน: ใน CL ตัวที่ไม่มี prefix คืนจำนวนเต็ม ดังนั้นตัวที่มี prefix `f` ตรงกับพฤติกรรมของภาษานี้ |
| `float-radix` `float-digits` `float-precision` | `(op x)` | `f64→int` | 2 / 53 / 53 ตามลำดับ (เฉพาะความแม่นยำของ `0.0` เป็น 0) `f64` เป็น IEEE-754 binary64 เสมอ จึงเป็นค่าคงที่ |
| `float-sign` | `(float-sign x)` | `f64→f64` | `1.0` หรือ `-1.0` |
| `scale-float` | `(scale-float x n)` | `(f64,int)→f64` | `x * 2^n` |
| `decode-float` | `(decode-float x)` | `f64→cons-cell<f64,int>` | แมนทิสซา (ใน `[1/2,1)` ไม่มีเครื่องหมาย) และเลขชี้กำลัง CL คืนสามค่า แต่ไม่มีค่าหลายค่า จึงปล่อยเครื่องหมายให้ `float-sign` |

**ความแตกต่างจาก CL: `round` ปัดอย่างไร** `round` (และ `fround`/`round-div` ด้วย) ปัด **ออกจาก
ศูนย์** (`(round 2.5)` = `3.0`) CL ปัด **ไปหาเลขคู่** ให้ `2`

## 5. จำนวนตรรกยะ `ratio`

จำนวนตรรกยะความแม่นยำไม่จำกัดที่เข้ากันได้กับ CL ถูกเก็บในรูปต่ำสุดที่ตัวส่วนเป็นบวกเสมอ
และจัดสรรบนฮีป ไม่มีการแปลงโดยปริยายกับชนิดจำนวนเต็มหรือ
`f64` (ใช้เมทอดแปลงอย่างชัดเจนหรือ `as`/`try-as`) สำหรับไวยากรณ์ literal ของ ratio ดู
[เอกสารอ้างอิงไวยากรณ์](../syntax.md#1-องค์ประกอบทางศัพท์)

| ชื่อ | รูปแบบ | ชนิด | คำอธิบาย |
|---|---|---|---|
| `+` `-` `*` `/` | `(op a b)` | `(ratio,ratio)→ratio` | การดำเนินการสี่ประการ (ผลลัพธ์อยู่ในรูปต่ำสุดเสมอ) `/` panic เมื่อหารด้วยศูนย์ |
| `mod` | `(mod a b)` | `(ratio,ratio)→ratio` | เศษที่เหลือของการหารแบบปัดลง (เหมือนใน CL; เครื่องหมายตามตัวหาร) |
| `rem` | `(rem a b)` | `(ratio,ratio)→ratio` | เศษที่เหลือของการหารแบบตัดทอน (เหมือนใน CL; เครื่องหมายตามตัวตั้ง) |
| `abs` | `(abs x)` | `ratio→ratio` | ค่าสัมบูรณ์ |
| `signum` | `(signum x)` | `ratio→ratio` | เครื่องหมาย (คืน `1`/`-1`/`0` เป็น `ratio`) |
| `expt` | `(expt a b)` | `(ratio,ratio)→ratio` | เลขยกกำลัง เลขชี้กำลังต้องเป็น `ratio` ที่มีค่าเป็นจำนวนเต็ม (มิฉะนั้น panic) เลขชี้กำลังติดลบให้ส่วนกลับ |
| `max` `min` | `(op a b)` | `(ratio,ratio)→ratio` | ตัวที่มากกว่า / น้อยกว่า |
| `1+` `1-` | `(op x)` | `ratio→ratio` | `x±1` `ratio` ไม่มีการดำเนินการระดับบิต (ใน CL ใช้กับจำนวนเต็มเท่านั้น) |
| `<` `<=` `>` `>=` `=` `/=` | `(op a b)` | `(ratio,ratio)→bool` | การเปรียบเทียบ |
| `eq` `eql` `equal` `equalp` | `(op a b)` | `(ratio,ratio)→bool` | เหมือน `=` ทั้งหมด |
| `numerator` | `(numerator x)` | `ratio→int` | ตัวเศษในรูปต่ำสุด (ชื่อเดียวกับใน CL) |
| `denominator` | `(denominator x)` | `ratio→int` | ตัวส่วนในรูปต่ำสุด (เป็นบวกเสมอ) |
| `ratio->int` | `(ratio->int x)` | `ratio→int` | ส่วนจำนวนเต็ม (ตัดไปทางศูนย์) |
| `ratio->float` | `(ratio->float x)` | `ratio→f64` | แปลงเป็น `f64` |

ทางเข้าจากจำนวนเต็มความกว้างคงที่และ `f64` คือ `int->int`/`int->ratio` (บทที่ 1) และ
`float->int`/`float->ratio` (บทที่ 4) `int`/`ratio` เป็นชนิดแยกที่อิสระจาก `i32` และ
ชนิดอื่น และการคำนวณแบบผสมต้องมีการแปลงอย่างชัดเจน

## 6. จำนวนเชิงซ้อน `complex`

struct (`defstruct`) ในไลบรารีมาตรฐาน

**ความแตกต่างสองข้อจาก CL** (ทั้งสองเป็นผลจากระบบชนิดแบบสถิต):

1. **ส่วนประกอบเป็น `f64` เสมอ** จำนวนเชิงซ้อนของ CL เก็บจำนวนตรรกยะได้ด้วย และ `(complex 1 2)` กับ
   `(complex 1.0 2.0)` เป็นคนละชนิด ชนิดสถิตต้องเลือกหนึ่งอย่าง และฟังก์ชันอดิศัย
   คืนชนิดจำนวนทศนิยม
2. **`(sqrt -1.0)` เป็น `sqrt` ของจำนวนจริง (NaN)** ใน CL `sqrt` คืนจำนวนเชิงซ้อนจาก
   จำนวนจริงได้ แต่ `sqrt` ของ `f64` ต้องคืน `f64` ผลลัพธ์ที่เป็นจำนวนเชิงซ้อนมาจากอาร์กิวเมนต์ที่เป็น
   จำนวนเชิงซ้อน: `(sqrt (complex -1.0 0.0))` คือ `i`

|---|---|---|---|

## 8. ตัวช่วยเชิงตัวเลขและน้ำตาลไวยากรณ์ของการเรียก

`abs`/`signum` (ชนิดตัวเลขทั้งหมด), `gcd`/`lcm` (เฉพาะชนิดจำนวนเต็ม), `rem` (ชนิดจำนวนจริงทั้งหมดรวม
`f64`) และ `expt` (`int`/`f64`/`ratio`) นิยามเป็นเมทอดของแต่ละชนิดตัวเลข (แก้ไขโดย
ชนิดของตัวรับ: `(abs x)` คือเมทอดของชนิดของ `x`) รายละเอียดของแต่ละชนิดอยู่ใน
บทที่ 1, 3, 4 และ 5 จำนวนเต็มความกว้างคงที่ไม่มี `expt` (ไม่มีการเลื่อนขั้นและจะ
ล้น; ย้ายไป `int` ด้วย `(as int x)` และใช้ `expt` ของมัน)

### 8.1 รูปแบบ variadic และ 0/1 อาร์กิวเมนต์

การคำนวณและการเปรียบเทียบของ CL เป็น variadic แต่เมทอดถูกแก้ไขโดยชนิดของตัวรับเท่านั้น
ไม่ใช่โดยจำนวนอาร์กิวเมนต์ ดังนั้น **ตัวตรวจสอบขยายรูปแบบต่อไปนี้เป็นการเรียกสองอาร์กิวเมนต์**

| รูปแบบที่เขียนได้ | การขยาย | ใช้กับ |
|---|---|---|
| `(op a b c ...)` | การพับซ้าย `(op (op a b) c)` | `+` `-` `*` `/` `max` `min` `logand` `logior` `logxor` `gcd` `lcm` |
| `(cmp a b c ...)` | `(and (cmp a b) (cmp b c) ...)` โดยผูกแต่ละพจน์กับตัวแปรชั่วคราว | `<` `<=` `>` `>=` `=` `/=` |
| `(op)` | `(+)`=0 / `(*)`=1 / `(logior)`=`(logxor)`=0 / `(logand)`=-1 / `(gcd)`=0 / `(lcm)`=1 | ตัวข้างบนที่มีสมาชิกเอกลักษณ์ |
| `(op x)` | สำหรับ `+ * max min logand logior logxor` คือ `x` เอง `(- x)` ทำนิเสธ `(/ x)` ให้ส่วนกลับ `(gcd x)`/`(lcm x)` ให้ `(abs x)` (เหมือนใน CL) | เหมือนข้างบน |
| `(cmp x)` | ประเมิน `x` และให้ `true` | `<` `<=` `>` `>=` `=` `/=` |
| `(log x base)` | `(/ (log x) (log base))` | `f64` |

แต่ละพจน์ถูกประเมินค่าเพียงครั้งเดียวพอดี จากซ้ายไปขวา (นี่คือเหตุผลที่การเปรียบเทียบ variadic
ผ่านตัวแปรชั่วคราว) รูปแบบ variadic ของ `/=` เปรียบเทียบ **คู่ที่อยู่ติดกัน** ต่างจาก CL ที่ถามว่า
ทุกคู่ต่างกันหรือไม่

### 8.2 `isqrt` และ `expt` ของจำนวนเต็ม

| ชื่อ | รูปแบบ | ชนิด | คำอธิบาย |

| `isqrt` | `(isqrt n)` | `T→T` | จำนวนเต็มที่ใหญ่ที่สุดที่ไม่เกินรากที่สอง panic เมื่อเป็นค่าติดลบ |
| `expt` | `(expt n e)` | `(T,T)→T` | เลขยกกำลัง (ด้วยการยกกำลังสอง) CL คืนจำนวนตรรกยะสำหรับเลขชี้กำลังติดลบ แต่ชนิดจำนวนเต็มแสดงไม่ได้ จึง panic ให้แปลงเป็น `ratio` ก่อน |

| `most-positive-double-float` / `most-negative-double-float` | `f64` | ค่าจำกัดที่ใหญ่ที่สุด / เล็กที่สุด |
| `least-positive-double-float` / `least-negative-double-float` | `f64` | ขนาดที่ไม่เป็นศูนย์ที่เล็กที่สุด รวม subnormal |
| `least-positive-normalized-double-float` / `least-negative-normalized-double-float` | `f64` | เหมือนกัน แต่จำกัดเฉพาะจำนวนที่ normalized |
| `double-float-epsilon` / `double-float-negative-epsilon` | `f64` | เป็นไปตามนิยามของ CL (`e` บวกที่เล็กที่สุดที่ `(/= (+ 1 e) 1)`) จึง **ใหญ่กว่า** 2^-53 **หนึ่ง ULP**: 2^-53 เองถูกปัดกลับเป็น `1.0` ภายใต้ round-to-nearest-even |

## 11. การดำเนินการระดับบิต

นิยามบน two's complement ที่มีบิตไม่จำกัด (CL 12.10) ถูก implement สำหรับ
ชนิดจำนวนเต็มความกว้างคงที่และ `int` ไม่ใช่สำหรับ `ratio` (CL ก็มีการดำเนินการระดับบิตสำหรับจำนวนเต็มเท่านั้น)

| ชื่อ | รูปแบบ | ชนิด | คำอธิบาย |
|---|---|---|---|
| `logand` `logior` `logxor` | `(op a b)` | `(T,T)→T` | and, or, exclusive or ระดับบิต (รูปแบบ variadic และศูนย์อาร์กิวเมนต์ใน 8.1) |
| `lognot` | `(lognot x)` | `T→T` | ส่วนเติมเต็มระดับบิต |
| `ash` | `(ash x count)` | `(T,int)→T` | การเลื่อนแบบเลขคณิต ซ้ายหาก `count` เป็นบวก ขวาหากเป็นลบ |
| `logbitp` | `(logbitp x index)` | `(T,int)→bool` | บิต `index` ถูกตั้งหรือไม่ (**ลำดับอาร์กิวเมนต์ตรงข้ามกับ CL**; ดูด้านล่าง) |
| `logtest` | `(logtest a b)` | `(T,T)→bool` | `(/= (logand a b) 0)` |
| `logcount` | `(logcount x)` | `T→T` | จำนวนบิตที่ถูกตั้ง (สำหรับจำนวนลบ คือจำนวนบิต 0) |
| `integer-length` | `(integer-length x)` | `T→T` | จำนวนบิตที่ต้องใช้แสดง ไม่นับเครื่องหมาย |
| `logeqv` `lognand` `lognor` `logandc1` `logandc2` `logorc1` `logorc2` | `(op a b)` | `(T,T)→T` | อีกเจ็ดตัวที่เหลือ ประกอบจากข้างบน |

**มีเพียงอาร์กิวเมนต์ที่สองของ `ash` ที่เป็น `int` แทนที่จะเป็น `T`** มันคือ **ระยะทาง** เป็นบิต ไม่ใช่
ค่าของชนิดของตัวรับ ดังนั้นความกว้างและเครื่องหมายของตัวรับไม่ได้บอกอะไรเกี่ยวกับระยะทาง
(ด้วยเหตุผลเดียวกับที่ `count` ใน `(ash integer count)` ของ CL เป็นจำนวนเต็มใดก็ได้) การเลื่อนค่าที่ไม่มีเครื่องหมาย
ไปทางขวาเป็นการเลื่อนแบบตรรกะ (`(ash (the u8 200) -3)` = `25`) และค่าที่มีเครื่องหมายเป็นการเลื่อนแบบ
เลขคณิตที่ปัดไปทางอนันต์ลบ (`(ash (the i32 -100) -4)` = `-7`) `index` ของ `logbitp`
เป็น `int` ด้วยเหตุผลเดียวกัน

**Byte specifier** แทนที่จะเป็นออบเจ็กต์ทึบที่ `byte` ของ CL คืน จะใช้ `cons-cell<int,int>`
(`car`=ขนาด, `cdr`=ตำแหน่ง) ทั้งขนาดและตำแหน่งเป็นจำนวนบิต จึงเป็น `int`
ไม่ว่าจำนวนเต็มที่ถูกแยกส่วนจะมีความกว้างเท่าใด

**จำนวนเต็มเป็นอาร์กิวเมนต์แรก ลำดับต่างจาก CL** CL เขียน
`(ldb bytespec integer)` แต่ภาษานี้เลือกเมทอดตามชนิดของตัวรับ (อาร์กิวเมนต์
แรก) และถ้า specifier มาก่อนก็เลือกตามชนิดของจำนวนเต็มไม่ได้ การดำเนินการระดับบิตอื่นทั้งหมด
มีรูปแบบ `(op integer ...)` (`(logand a b)`, `(ash x count)`, `(lognot x)`) และ
มีเพียงตระกูล `ldb` และ `logbitp` ที่กลับกัน จึงปรับให้สอดคล้อง
อาร์กิวเมนต์ที่เหลือคงลำดับสัมพัทธ์ของ CL ดังนั้น `(dpb newbyte spec n)` กลายเป็น `(dpb n newbyte spec)`

| ชื่อ | รูปแบบ | ชนิด | คำอธิบาย |
|---|---|---|---|
| `byte` | `(byte size position)` | `(int,int)→cons-cell<int,int>` | สร้าง byte specifier |
| `byte-size` / `byte-position` | `(byte-size b)` | `cons-cell<int,int>→int` | ดึงส่วนประกอบออกมา |
| `ldb` | `(ldb x b)` | `(T,cons-cell<int,int>)→T` | ดึงไบต์ที่ระบุจาก `x` โดยจัดชิดขวา |
| `ldb-test` | `(ldb-test x b)` | `(T,cons-cell<int,int>)→bool` | มีบิตใดในไบต์ที่ระบุถูกตั้งหรือไม่ |
| `mask-field` | `(mask-field x b)` | `(T,cons-cell<int,int>)→T` | ล้างทุกอย่างนอกไบต์ที่ระบุ (คงตำแหน่ง) |
| `dpb` | `(dpb x newbyte b)` | `(T,T,cons-cell<int,int>)→T` | ฝาก `newbyte` ที่จัดชิดขวาลงในไบต์ที่ระบุของ `x` |
| `deposit-field` | `(deposit-field x newbyte b)` | `(T,T,cons-cell<int,int>)→T` | เวอร์ชันของ `dpb` ที่คงตำแหน่ง |
| `boole` | `(boole op a b)` | `(int,T,T)→T` | หนึ่งในการดำเนินการตรรกะสองตัวถูกดำเนินการ 16 แบบ เลือกโดย `op` (ค่าคงที่ `boole-*` จากบทที่ 10) |

`T` คือชนิดที่ implement trait `Bits` ได้แก่ `i8`/`i16`/`i32`/`u8`/`u16`/`u32`/`int` มีเพียง
`boole` ที่คง `op` ไว้ก่อน เพราะไม่มีเหตุผลที่จะเปลี่ยนลำดับของ CL ตรงนั้น

## 12. จำนวนสุ่ม

| ชื่อ | รูปแบบ | ชนิด | คำอธิบาย |
|---|---|---|---|
| `random` | `(random n [state])` | `int &optional random-state → int` | จำนวนสุ่มตั้งแต่ `0` จนถึงแต่ไม่รวม `n` หากละ state จะสุ่มจาก `*random-state*` และเลื่อนมันไปข้างหน้า |
| `make-random-state` | `(make-random-state [state])` | `&optional random-state → random-state` | หากไม่มีอาร์กิวเมนต์ จะได้ state ใหม่ หากให้ จะได้สำเนาของมัน (สำเนาเล่นลำดับเดียวกันซ้ำ) |
| `random-state-p` | `(random-state-p x)` | `random-state→bool` | `true` เสมอ (ชนิดสถิตตัดชนิดอื่นออกไปแล้ว มีไว้เพียงเพื่อสอดคล้องกับ CL) |
| `*random-state*` | — | `random-state` | state เริ่มต้นของ `random` ตัวแปรโกลบอลที่กำหนดค่าได้ (แทนที่ด้วย `setf`) |
| `seed-random-state` | `(seed-random-state n)` | `int→random-state` | state ที่จำนวนเต็มนั้นระบุ seed เดียวกันเล่นลำดับเดียวกันซ้ำเสมอ |

ตัวสร้างคือ xorshift64 และคืนลำดับเดียวกันไม่ว่าจะอินเทอร์พรีตหรือคอมไพล์

state ใหม่จาก `make-random-state` ถูก seed จากนาฬิกาจริง จึงทำซ้ำข้ามการรันไม่ได้
หากต้องการทำซ้ำ ให้ใช้ `seed-random-state`:

```lisp
(let ((s (seed-random-state 12345)))
  (println "~a ~a ~a" (random 100 s) (random 100 s) (random 100 s)))
;; prints the same three numbers on every run
```

**CL ไม่มีวิธีที่พกพาได้ในการให้ seed** (`make-random-state` รับเพียง `nil`/`t`/state) ดังนั้นชื่อ
นี้ตาม `sb-ext:seed-random-state` ของ SBCL ไม่ใช่ CL

seed ต่างกันให้ลำดับต่างกัน `(seed-random-state 0)` และ `(seed-random-state 1)` ให้
ลำดับต่างกัน เช่นเดียวกับ `-7` และ `7`
