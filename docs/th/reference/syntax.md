# เอกสารอ้างอิงไวยากรณ์ typelisp

typelisp เป็น Lisp ที่มีระบบชนิดแบบสถิต เขียนด้วย S-expression สำหรับรายการฟังก์ชันและเมทอดที่มีให้ในตัว
ดู[ฟังก์ชันที่มีให้ในตัว](functions/README.md) สำหรับรายการชนิด ดู [types.md](types.md)
และสำหรับการอ่านข้อความแสดงข้อผิดพลาด ดู [errors.md](errors.md)

## 1. องค์ประกอบทางศัพท์

- **ไม่แยกตัวพิมพ์ใหญ่และเล็ก** สัญลักษณ์ทั้งหมดถูกทำให้เป็นตัวพิมพ์เล็กเมื่ออ่าน
- **คอมเมนต์**: จาก `;` ถึงท้ายบรรทัด (คอมเมนต์บรรทัด) `#| ... |#` (คอมเมนต์แบบบล็อก ซ้อนกันได้)
- **การประเมินค่าตอนอ่าน**: `#.(expr)` **รันฟอร์มที่ตามมาขณะอ่าน** และถือค่าของมันเป็นสิ่งที่อ่านได้ นี่เป็นที่เดียว
  ที่ตัวอ่านเป็นมากกว่าฟังก์ชันของข้อความ ขอบเขตที่เข้าถึงได้ขึ้นกับเส้นทางการอ่าน เหมือนใน CL:
  - `(load ...)` และ REPL ประเมินทีละฟอร์ม จึงเรียก **ฟังก์ชันที่นิยามไว้ก่อนหน้าใน
    ข้อความเดียวกัน** ได้ (`load` ของ CL)
  - ไฟล์โมดูลถูกตรวจสอบเป็นหน่วยและรันโดยผู้ที่ `use` มัน ดังนั้น `#.` เข้าถึงได้เฉพาะไลบรารีมาตรฐาน
    และสิ่งที่เซสชันรันไปแล้ว ทั้งการนิยามของไฟล์เองและของโมดูลที่มัน `use` **ยังไม่ได้รัน**
    (เหมือนที่ `compile-file` ของ CL ต้องใช้ `eval-when`)
  - `read` / `read-from-string` ภายในโปรแกรมก็ประเมิน `#.` ด้วย (เหมือนใน CL)
  - การตั้ง `*read-eval*` (ค่าเริ่มต้น `true`) เป็น `false` ทำให้ `#.` เป็นข้อผิดพลาดการอ่านทุกที่: สวิตช์เพื่อป้องกัน
    ไม่ให้ข้อความที่อ่านเป็นข้อมูลรันโค้ด (เหมือนใน CL) มันถูกตรวจสอบที่ทุก `#.` ดังนั้น `setf` มีผล
    ตั้งแต่ฟอร์มถัดไปที่อ่าน ภายใน `with-standard-io-syntax` มันเป็น `true`
- **บูลีน**: `true` / `false`
- **จำนวนเต็ม**: ฐานสิบ (`42`, `-7`) เครื่องหมาย `+`/`-` นำหน้าได้ ฐานอื่นเขียนด้วยไวยากรณ์ radix ของ CL
  `#b`/`#o`/`#x`/`#NNr` (เครื่องหมายอยู่หลังตัวระบุ: `#x-ff`) prefix `0x` ไม่มี
  ใน CL และไม่ถูกนำมาใช้: `0xff` อ่านเป็นสัญลักษณ์
  literal จำนวนเต็มที่ไม่มีคำอธิบายชนิดเป็น `int` โดยค่าเริ่มต้น (ความแม่นยำไม่จำกัด
  [ตัวเลข](functions/numbers.md#3-จำนวนเต็มความแม่นยำไม่จำกัด-int)) ไม่มีขีดจำกัดบนของขนาด
  **หากชนิดที่คาดหวังเป็นชนิดจำนวนเต็มความกว้างคงที่ literal จะมีชนิดนั้น และจะตรวจสอบว่า
  ชนิดนั้นเก็บค่าได้**: `(the u8 300)` เป็นข้อผิดพลาดของชนิด (หากต้องการให้ตัดทอน ให้เขียน
  `(as u8 300)`) `(the u32 4294967295)` และ `(the u32 #xFFFFFFFF)` เขียนได้เพราะกฎนี้
  ค่า `int` พอดีกับ immediate 63 บิตหรือกลายเป็น bignum ถูกตัดสินโดยขนาดของมัน โดยไม่มี
  ไวยากรณ์พิเศษ (เหมือนใน CL)
- **จำนวนทศนิยม**: ที่มีจุดทศนิยมหรือเลขชี้กำลัง (`e`/`E`) (`1.5`,
  `3.0e10`) `f64` โดยค่าเริ่มต้น (`f32` หากเป็นชนิดที่คาดหวัง)
- **อัตราส่วน (ratio)**: `numerator/denominator` (ฐานสิบเท่านั้น เช่น `1/3`) ถูกทำให้เป็นรูปต่ำสุดเมื่ออ่าน ตามที่ CL
  กำหนด (`2/4` คือ `1/2`) ที่มีค่าเป็นจำนวนเต็ม (`4/2` และอื่น ๆ) ถูกอ่านเป็น `int` ไม่ใช่
  `ratio` ตัวส่วนเป็นศูนย์ (`1/0`) เป็นข้อผิดพลาดการอ่าน
- **อักขระ**: `#\` ตามด้วยอักขระหนึ่งตัวหรือชื่ออักขระ ตัวอย่างเช่น `#\a` `#\Space`
  `#\Newline` `#\Tab` `#\Return` `#\Page` `#\Nul` (และ `#\Null`) `#\Backspace` ชื่อไม่แยก
  ตัวพิมพ์ใหญ่เล็ก
- **สตริง**: `"..."` escape คือ `\n` `\t` `\r` `\0` `\\` `\"` (`\x` อื่นใดเป็นเพียง `x`)
- **สัญลักษณ์**: โทเค็นใด ๆ ที่มีตัวอักษร ตัวเลข และสัญลักษณ์ (`+` `<=` `my-func` และอื่น ๆ)
  `]` และ `}` จบ token จึงเขียนไว้ในสัญลักษณ์ไม่ได้ และถ้าพบตัวใดตัวหนึ่งที่ต้นของ datum จะเป็นข้อผิดพลาดในการอ่าน ส่วน `[` และ `{` เขียนไว้ในสัญลักษณ์ได้ เช่นเดียวกับ CL ทั้งสองถูกเว้นว่างไว้ให้โปรแกรมเมอร์ใช้ใน[แมโครของตัวอ่าน](#11-ตัวอ่านแมโคร-readtable)
- **คีย์เวิร์ด**: สัญลักษณ์ที่ขึ้นต้นด้วยเครื่องหมายทวิภาค เช่น `:name` (เหมือนใน CL) ประเมินค่าเป็นตัวเอง:
  ไม่ค้นหาการผูกใด และค่าของมันคือตัวมันเอง ด้วยชนิดสถิต `symbol` คีย์เวิร์ดที่มีชื่อ
  เหมือนกันเป็นออบเจ็กต์เดียวกันเสมอ (`(eq :foo :FOO)` เป็นจริง; เหมือนสัญลักษณ์อื่นถูก
  ทำให้เป็นตัวพิมพ์เล็ก) เครื่องหมายทวิภาคเป็นส่วนของชื่อ ดังนั้น `(symbol->string :foo)` คือ `":foo"` (typelisp
  ไม่มีระบบแพ็กเกจ จึงต่างจาก `symbol-name` ของ CL) `:` เดี่ยว ๆ หรือที่มีทวิภาคเพิ่ม
  เช่น `:a:b` เป็นข้อผิดพลาดการอ่าน ทดสอบด้วย `keywordp` ที่ขึ้นต้นด้วย `::` ไม่ใช่คีย์เวิร์ด
  แต่เป็นพาธสัมบูรณ์ (ด้านล่าง)
  โปรดทราบว่า `:dyn` เป็นคีย์เวิร์ดสงวนสำหรับตำแหน่งของชนิดเท่านั้น การเขียนที่อื่นเป็นข้อผิดพลาด
  (ดู[บทที่ 2](#2-การเขียนชนิด))
- **ลิสต์**: `(a b c)` อ่านคู่แบบจุด `(a . b)` ได้ด้วย
- **เวกเตอร์**: `#(1 2 3)` (เหมือน CL) เนื้อหาเป็นลิเทอรัลทั้งหมดและไม่ถูกประเมินค่า `a` ใน `#(a b)` เป็นสัญลักษณ์ ไม่ใช่ตัวแปร ชนิดของสมาชิกมาจากบริบท (`(the Vector<i32> #(1 2))`) หรือจากสมาชิกตัวแรกเมื่อไม่มีบริบท (`#(1 2 3)` เป็น `Vector<int>`) สมาชิกทุกตัวต้องมีชนิดเดียวกัน `#(1 "a")` เป็นข้อผิดพลาดของชนิด เช่นเดียวกับ `#()` ที่ไม่มีทั้งสมาชิกและบริบท การประเมินค่าแต่ละครั้งสร้างเวกเตอร์ใหม่ ในที่ที่คาดหวังข้อมูล S-expression (`(the Option<Sexpr> #(1 x))`, `'#(..)`, สิ่งที่ `read` คืน) จะเป็น `Vector<Option<Sexpr>>` ที่สมาชิกทุกตัวเป็นข้อมูล คือ variant `vector` ของ `Sexpr`
- **อาร์เรย์**: `#2A((1 2) (3 4))` (เหมือน CL) ตัวเลขระหว่าง `#` กับ `A` คือ rank และระดับการซ้อนของลิสต์ในเนื้อหาจำนวนเท่านั้นระดับแรกคือมิติ `#0A x` คืออาร์เรย์ศูนย์มิติที่มีสมาชิกหนึ่งตัว ลิสต์ในระดับเดียวกันที่ยาวไม่เท่ากันเป็นข้อผิดพลาดในการอ่าน ชนิดถูกกำหนดแบบเดียวกับเวกเตอร์และเป็น `Array<T>` (ถ้าไม่มีสมาชิก บริบทต้องเป็นผู้ให้ชนิด เช่น `(the Array<f64> #2A(()))`) ในฐานะข้อมูล S-expression จะเป็น `Array<Option<Sexpr>>` คือ variant `array` ของ `Sexpr`
- **ลิสต์ว่าง `()`**: ขึ้นกับบริบท เป็นค่าของชนิด `Unit` หรือ `none` ของ
  `Option<Sexpr>` **`Sexpr` ไม่มี variant ลิสต์ว่าง**: `Sexpr` หมายถึง "S-expression ที่ไม่ว่าง"
  และชนิดของข้อมูล S-expression คือ `Option<Sexpr>` (ดู "รูปแบบสำหรับ `Option<Sexpr>`" ใน
  [4.3 match](#43-match--การจับคู่รูปแบบ))
- **quote/quasiquote/unquote**:
  - `'x` → `(quote x)`
  - `` `x `` → `(quasiquote x)`
  - `,x` → `(unquote x)` (มีความหมายเฉพาะภายใน quasiquote)
  - `,@x` → `(unquote-splicing x)` (ต่อเป็นสมาชิกของลิสต์ตอนขยาย)
- **พาธ `::`**: `foo::bar` ถูกอ่านเป็นพาธผ่านโมดูล ชนิด และสมาชิก (ไม่ใช่ชื่อสัญลักษณ์เดียว) ที่ขึ้นต้น
  ด้วย `::` เช่น `::foo` เป็นพาธสัมบูรณ์จากราก `::` ภายในอาร์กิวเมนต์ generic (`Vec<a::b>` และ
  ทำนองเดียวกัน) ไม่ถือเป็นตัวคั่นพาธ

## 2. การเขียนชนิด

ในซอร์ส ชนิดเขียนเป็นสัญลักษณ์หรือลิสต์ธรรมดา

- **ชนิดพื้นฐาน**: `int` `i8` `i16` `i32` `u8` `u16` `u32` `f32` `f64` `bool` `char` `string`
  `symbol` `int` คือชนิดจำนวนเต็ม (integer ของ CL เคลื่อนระหว่าง immediate 63 บิตกับ
  bignum โดยอัตโนมัติ; [ตัวเลข](functions/numbers.md#3-จำนวนเต็มความแม่นยำไม่จำกัด-int)) และชนิดความกว้างคงที่ทั้งหก
  ตั้งชื่อตามความกว้างและเครื่องหมาย (ไม่มีชนิดจำนวนเต็ม 64 บิต ดู
  [ตัวเลข](functions/numbers.md#1-จำนวนเต็มความกว้างคงที่))
- **ชนิดตรรกยะ**: `ratio` (จำนวนตรรกยะในรูปต่ำสุด) จัดสรรบนฮีปเหมือนใน CL ไม่มีการแปลงโดยปริยาย
  กับ `int`/`f64` และอื่น ๆ (แปลงอย่างชัดเจนด้วย `as`/`try-as` หรือเมทอดแปลง ดู
  [ตัวเลข](functions/numbers.md#5-จำนวนตรรกยะ-ratio))
- **word ดิบที่ขอบเขตกับ C**: `ptr` (ตัวชี้ทึบ), `c-long` / `c-ulong` สำหรับ FFI เท่านั้น:
  การทำให้เป็นค่าต้องใช้ `(unsafe ...)` และที่ที่ปรากฏได้ถูกจำกัด
  ([3.3 defffi](#ptr--c-long--c-ulong--word-ดิบของเครื่อง)) อย่าใช้สิ่งเหล่านี้ในที่ที่ต้องการจำนวนเต็ม 64 บิต:
  ไม่มีการคำนวณ
- **ชนิดทึบที่เปลี่ยนแปลงได้**: `random-state` (สถานะของตัวสร้างจำนวนสุ่ม) ใส่ใน
  `Vector<T>`/`HashTable<K,V>`/`Sexpr` ไม่ได้ (ใส่ใน `Option<T>`/`Result<T,E>` ได้)
- **ชนิด Unit**: `()`
- **ชนิด Never**: `!` (ชนิดของนิพจน์ที่ไม่จบ เช่น `panic`/`unreachable`/`todo`/ลูปที่
  ไม่คืนค่า เข้ากับชนิดที่คาดหวังใดก็ได้)
- **ชนิดฟังก์ชัน**: `(fn (ชนิดของอาร์กิวเมนต์...) ชนิดที่คืน)` ชนิดของฟังก์ชันที่มีอาร์กิวเมนต์ variadic
  คือ `(fn (ชนิดของอาร์กิวเมนต์... &rest ชนิดของสมาชิก) ชนิดที่คืน)`
- **ชนิด generic**: `Name<T1,T2,...>` (อ่านเป็นโทเค็นเดียวโดยไม่มีช่องว่าง)
  ตัวอย่างเช่น `Option<i32>` `Result<i32,ParseIntError>` `HashTable<string,i32>` `Vector<T>`
  ชนิด unit `()` เขียนเป็นอาร์กิวเมนต์ชนิดได้ด้วย (`Result<(), FileError>`) `(`/`)` โดยปกติ
  เป็นตัวคั่นที่จบโทเค็น แต่ขณะที่วงเล็บมุมเปิดอยู่ จะยอมให้อักขระคู่นี้ผ่าน
  `()` ใช้เป็นชนิดของฟิลด์หรือชนิดของอาร์กิวเมนต์ได้ด้วย
- **รูปแบบการประยุกต์ของชนิด generic**: `(Name T1 T2 ...)` การสะกดแบบลิสต์ที่ตั้งชื่อชนิดเดียวกับ
  `Name<T1,T2,...>` ตัวอย่างเช่น `(vector char)` เหมือนกับ `Vector<char>`
  รูปแบบชื่อเป็นวิธีเขียนปกติ รูปแบบนี้ **มีไว้สำหรับเมื่ออาร์กิวเมนต์ชนิดสะกดภายในชื่อไม่ได้**:
  อาร์กิวเมนต์ชนิดเองเป็นนิพจน์ชนิด แต่ภายในชื่อโทเค็นเดียว เขียนได้เฉพาะชื่อ `()` และ `:dyn` ไม่ใช่
  ชนิดฟังก์ชัน (ไม่มีการสะกดอย่าง `Vector<(fn (i32) i32)>`) อาจปรากฏในรูปแบบนี้เมื่อ implementation
  แสดงชนิด เช่น ผลของการแทนชนิดที่เกี่ยวข้อง (associated type) ของ trait ลงใน signature
- **ชื่อชนิดที่มีตัวกำกับ**: กำกับด้วย `::` ได้ เช่น `module::Type`
- **ชนิด trait object**: `:dyn Trait` (สองคำที่คั่นด้วยช่องว่างเป็นชนิดเดียว) แทนค่า
  ที่ชนิดจริงถูกตัดสินตอนรัน การเรียกเมทอดของ trait ผ่าน vtable (dynamic dispatch)
  สำหรับ trait ที่มี associated type จะกำหนดตามตำแหน่งตามลำดับการประกาศ (`:dyn Iter<i32>`
  กำหนด `Item` เป็น `i32`) เขียนภายในอาร์กิวเมนต์ generic ได้ด้วย: `Vector<:dyn Drawable>`
  `HashTable<string, :dyn Drawable>` ค่าที่เป็นรูปธรรมถูกห่อเป็นกล่อง (box) อัตโนมัติในตำแหน่งที่คาดหวัง
  รูปแบบชัดเจนคือ `(as :dyn Trait expr)`
  ค่า `:dyn Sub` ส่งตามที่เป็นได้ในที่ที่ต้องการ `:dyn Super` ของ supertrait ใด ๆ (ทุกอย่าง
  ที่มันสืบทอดแบบถ่ายทอด) (upcasting) ส่งให้ trait ที่ไม่เกี่ยวข้องไม่ได้
  สำหรับเงื่อนไขที่ trait ต้องมีจึงใช้กับ `:dyn` ได้ ดู
  [3.9 deftrait / impl](#39-deftrait--impl--trait) การเขียน `:dyn` นอกตำแหน่งของชนิดเป็นข้อผิดพลาด
- ชนิด generic ที่มีให้ในตัว: `Option<T>` (`Some(T)` / `None`), `Result<T,E>` (`Ok(T)` / `Err(E)`),
  `HashTable<K,V>`, `Vector<T>` และชนิดการทำงานพร้อมกัน `Task<T>` / `Thread<T>` / `Chan<T>`
  ([บทที่ 12](#12-การทำงานพร้อมกัน-task)) ยังมี `Sexpr` ชนิดของข้อมูล S-expression
  ชนิดข้อผิดพลาดที่เป็นรูปธรรมที่มีให้ในตัวคือ `ParseIntError` / `ParseFloatError` / `ReadError` / `EvalError` /
  `FileError` / `NetError` และไลบรารีมาตรฐานมี struct `SimpleError` / `WrappedError`
  (`Error` ไม่ใช่ชนิดแต่เป็น trait: ใช้เป็น `:dyn Error`) รายการอยู่ใน [types.md](types.md)
- **ชนิดและ trait ใช้เนมสเปซเดียวกัน** (เหมือนใน Rust): ภายในโมดูลเดียว ชนิด
  (`defstruct`/`defenum`) และ trait (`deftrait`) ใช้ชื่อเดียวกันไม่ได้

## 3. การนิยามระดับบนสุด

### 3.1 defun — การนิยามฟังก์ชัน

```lisp
(defun name ((arg1 Type1) (arg2 Type2) ...) RetType
  body...)
```

- ชนิดของอาร์กิวเมนต์และชนิดที่คืนเป็นสิ่งจำเป็น
- ฟังก์ชัน generic เขียนพารามิเตอร์ชนิดในวงเล็บมุมหลังชื่อ:
  `(defun name<T1,T2...> (params) Ret body...)` (ไวยากรณ์วงเล็บมุมเดียวกับ `Vector<T>` ในตำแหน่ง
  ของชนิด)
- `defun`/`lambda`/`defmethod` รับอาร์กิวเมนต์ variadic เมื่อเขียน `&rest (name Type)` ที่ท้าย:
  `(defun name ((a Type1) &rest (xs Type2)) Ret body...)` (ในตัวเนื้อหา `xs` ถูกผูกเป็น
  `Option<Sexpr>` เสมอ ซึ่งเป็นลิสต์ S-expression อาร์กิวเมนต์จริงแต่ละตัวที่จุดเรียกถูกตรวจสอบชนิดเป็น `Type2`
  ทีละตัวแล้วห่อเป็น `Sexpr`)
  `defmacro` มี `&rest` ของตัวเองด้วย แต่ต่างตรงที่เป็น `Sexpr` ที่ไม่มีชนิดเสมอ (`defun`/
  `lambda` ระบุชนิดของสมาชิก) ชนิดฟังก์ชันอธิบายฟังก์ชัน variadic ได้ด้วย เป็น
  `(fn (T1... &rest Te) Ret)`
- **`&optional` / `&key`** (สำหรับ `defun` และ `defmethod` ไม่ใช่สำหรับ `lambda`/`labels` ด้วยเหตุผลด้านล่าง
  และ `defmacro` มี implementation แยก ด้านล่างเช่นกัน) ลำดับเป็นของ CL:
  `required &optional &rest &key` แต่ละพารามิเตอร์เขียนเป็น `(name Type)` หรือ
  `(name Type default-expr)`:

  ```lisp
  (defun greet ((name string) &optional (suffix string)) string      ; no default
    (match suffix ((some s) (append name s)) ((none) name)))         ; Option<string> in the body

  (defun pow ((b i32) &optional (n i32 2)) i32 ...)                  ; with a default
  (pow 3)      ; n = 2
  (pow 3 5)    ; n = 5

  (defun mk (&key (a i32 0) (b string "z")) string ...)
  (mk :b "q")  ; the caller writes `:name value`, in any order; omitted ones take their defaults
  ```

  - **พารามิเตอร์ที่ไม่มีนิพจน์ค่าเริ่มต้นมีชนิด `Option<Type>`** เมื่อละ จะเป็น `none` เมื่อส่ง
    ค่าเปล่าที่ผู้เรียกเขียนจะถูกห่อด้วย `some` โดยอัตโนมัติ สิ่งที่ CL ทำด้วยตัวแปร supplied-p
    ("ถูกส่งมาหรือไม่?") ปรากฏทางฝั่งของชนิดสถิตแทน
  - เมื่อมีนิพจน์ค่าเริ่มต้น ชนิดยังคงเป็น `Type` ตามที่ประกาศ เมื่อละ **นิพจน์ที่ตรวจสอบแล้ว**
    นั้นถูกฝังที่จุดเรียกตามที่เป็น (ประเมินค่าทุกครั้งที่เรียก)
  - **`&key` ผสมกับ `&optional`/`&rest` ในรายการอาร์กิวเมนต์เดียวไม่ได้** วิธีนี้หลีกเลี่ยงความกำกวมที่ CL
    เองมี (อาร์กิวเมนต์จริงที่ตามท้ายถูกรับโดย `&optional` ตามตำแหน่งหรือจับคู่ตามป้าย
    เป็น `&key` ขึ้นกับ *ค่า*) โดยห้ามการรวมกัน `&optional` และ `&rest`
    ใช้ร่วมกันได้
  - ใช้ในฟังก์ชัน generic ได้ แต่ **พารามิเตอร์ชนิดที่ปรากฏเฉพาะในอาร์กิวเมนต์ที่ละไว้
    อนุมานไม่ได้และเป็นข้อผิดพลาด** (ไม่มีค่าให้จับคู่)
  - **`defmethod` มีสามส่วนเดียวกันได้** (ทั้งเมทอดของอินสแตนซ์และฟังก์ชันสถิต)
    ให้ระบุ `&optional`/`&rest`/`&key` หลังตัวรับ:

    ```lisp
    (defstruct box (w i32) (h i32))
    (defmethod grow ((self box) &key (dw i32 0) (dh i32 0)) i32 ...)
    (grow (box::new 1 2) :dh 10)

    (defmethod origin (point &key (x i32 0) (y i32 0)) point (point::new x y))   ; static function
    (point::origin :y 7)
    ```

    ใช้ในเมทอดของชนิด generic ได้ด้วย แต่ **ชนิดของพารามิเตอร์ที่มีนิพจน์ค่าเริ่มต้น
    กล่าวถึงพารามิเตอร์ชนิดของเจ้าของไม่ได้** (ข้อจำกัดเดียวกับที่ `defun` มีสำหรับ
    พารามิเตอร์ชนิดของตัวเอง: สิ่งที่ถูกฝังเมื่อละอาร์กิวเมนต์คือนิพจน์ที่ *ตรวจสอบแล้ว* จึง
    ปล่อยให้ชนิดของมันเป็นตัวแปรนามธรรมไม่ได้)
  - **ใช้ในเมทอดของ trait ไม่ได้** `deftrait` ไม่มีไวยากรณ์สำหรับสิ่งเหล่านี้ และหากมีเพียงฝั่ง `impl`
    ที่ประกาศส่วนได้ การเรียกที่มีตัวรับ `:dyn` (เติมอาร์กิวเมนต์จากการประกาศของ trait) และ
    การเรียกที่มีตัวรับเป็นรูปธรรม (เติมจากการประกาศของ `impl`) จะกลายเป็นคนละสิ่ง
    arity ของช่อง vtable ถูกกำหนดแน่นอน
  - **ใช้ใน `lambda` / `labels` ไม่ได้** (`&rest` ใช้ได้) เพื่อเติมอาร์กิวเมนต์ที่ละ
    ผู้เรียกต้องอ่าน **นิพจน์ค่าเริ่มต้นที่ตรวจสอบแล้วของผู้ถูกเรียก** ซึ่งมีได้เฉพาะจาก
    signature ที่แก้ไขด้วยชื่อ `lambda` ถูกส่งไปมาเป็นค่า และสิ่งเดียวที่อธิบายค่านั้น
    คือชนิดฟังก์ชัน `(fn ...)` ของมัน: ในนั้นไม่มีที่สำหรับนิพจน์ และหากมี
    "สอง lambda ที่มี signature เดียวกันแต่ค่าเริ่มต้นต่างกัน" จะกลายเป็นคนละชนิด
    `&rest` อยู่ภายในเรื่องของชนิด จึงเขียนในชนิดฟังก์ชันได้
- **การอ้างอิงล่วงหน้าประกาศด้วย `defsignature`** (ด้านล่าง) ชื่อที่ยังไม่ได้ประกาศ
  เรียกก่อนการนิยามไม่ได้ เพราะระดับบนสุดถูกตรวจสอบและรันทีละฟอร์ม
  ตามลำดับซอร์ส
- หากต้องการกำหนด trait bound ให้เขียนอนุประโยค `where` ก่อนตัวเนื้อหาทันที:
  `(defun name<T> (params) Ret (where (Trait T (AssocName ConcreteType)...)) body...)`
  (การกำหนด associated type ด้วย `(AssocName ConcreteType)` ไม่บังคับ)
- **Docstring**: สตริง literal ที่ต้นตัวเนื้อหา หลังอนุประโยค `where` ทันที (หากมี)
  จะเป็น docstring (เหมือนใน CL) เฉพาะเมื่อมีอย่างน้อยหนึ่งฟอร์มของตัวเนื้อหาตามมา: สตริงเดี่ยว
  ยังคงเป็นค่าที่คืนและไม่ถูกถือเป็น docstring: `(defun f () string "doc" "value")` มี
  docstring และคืน `"value"` ส่วน `(defun f () string "value")` ไม่มี docstring และคืน
  `"value"` ดึงได้ด้วย `(documentation name)`
  ([docstring](functions/system.md#7-docstring--documentation))

### 3.2 defsignature — การประกาศล่วงหน้า

```lisp
(defsignature name (argument-types...) return-type)
(pub defsignature name (argument-types...) return-type)
```

หากต้องการเรียก `defun` ที่นิยาม **หลัง** ตัวเอง ให้ประกาศก่อนแบบนี้ การเรียกกันเองแบบวนกลับ
เขียนได้ด้วยวิธีนี้เท่านั้น:

```lisp
(defsignature odd2 (i32) bool)
(defun even2 ((n i32)) bool (if (= n 0) true  (odd2 (- n 1))))
(defun odd2  ((n i32)) bool (if (= n 0) false (even2 (- n 1))))
```

อาร์กิวเมนต์ระบุ **เฉพาะชนิด** ไม่มีตัวเนื้อหา จึงไม่มีอะไรให้ตั้งชื่อ
`&rest` เขียนท้ายสุดได้ เป็น `&rest ชนิดของสมาชิก`

การประกาศ **ถูกตรวจสอบ**:

- การนิยามที่ตามมาต้องตรงกับการประกาศ (จำนวนและชนิดของอาร์กิวเมนต์ ชนิดที่
  คืน `&rest` และมี `pub` หรือไม่) ความไม่ตรงกันเป็นข้อผิดพลาดที่การนิยาม
- การประกาศโดยไม่นิยามเป็นข้อผิดพลาด (รายงานเมื่อไฟล์ / โมดูลโหลดเสร็จ) REPL
  ไม่รายงานหลังแต่ละอินพุต เพราะการประกาศและการนิยามควรพิมพ์แยกบรรทัดกันได้
- การประกาศที่วาง **หลัง** การนิยามเป็นข้อผิดพลาด เพราะการประกาศเช่นนั้นไม่ทำอะไรได้

สามอย่างที่ประกาศไม่ได้:

- **ฟังก์ชัน generic** การสร้างสำเนาสำหรับแต่ละชนิดต้องใช้ตัวเนื้อหา และการประกาศไม่มี
  การเรียกล่วงหน้าอาจแก้ไขได้แต่การสร้างอินสแตนซ์จะล้มเหลว จึงปฏิเสธการประกาศตั้งแต่ต้น
- **`&optional`/`&key`** signature ของมันรวม **นิพจน์ที่ตรวจสอบแล้ว** ของแต่ละค่าเริ่มต้น
  (ฝังที่จุดเรียกเมื่อละอาร์กิวเมนต์) และการประกาศไม่มีที่ให้มัน
- **อะไรก็ตามที่ไม่ใช่ `defun`** `defmacro` ต้องการให้ตัวเนื้อหาแมโคร **รันไปแล้ว** เพื่อ
  ขยาย ซึ่งการลงทะเบียน signature ทดแทนไม่ได้ สำหรับชนิด (`defstruct`/`defenum`/`deftrait`)
  การลงทะเบียนคือ "สิ่งที่โค้ดที่ลงทะเบียนชนิดนั้นเองต้องการ" ซึ่งไม่ครบในตัวเอง
  เหมือน signature `defmethod` ถูกลงทะเบียนบนชนิดที่เป็นเจ้าของ จึงตามชนิดไป

สิ่งที่สอดคล้องใน CL คือ `(declaim (ftype (function (i32) bool) even2))` แต่นั่นมาพร้อมระบบ
การประกาศทั้งระบบและเป็นเพียง **คำแนะนำ** ที่นี่ ด้วยระบบชนิดแบบสถิต การประกาศถูกตรวจสอบ

### 3.3 defffi — การประกาศฟังก์ชัน C (FFI)

```lisp
(defffi (name "c_symbol") (argument-types...) return-type)
(defffi (name "c_symbol") (argument-types...) return-type :library "name")
(defffi name (argument-types...) return-type)              ; name = the C symbol name
(pub defffi ...)
```

ประกาศฟังก์ชัน C เพื่อให้เรียกได้ รูปแบบเดียวกับ `defsignature` (ชื่อ ชนิดของอาร์กิวเมนต์ ชนิดที่
คืน และไม่มีตัวเนื้อหา) แต่การไม่มีตัวเนื้อหามีความหมายต่างกัน `defsignature` เป็น
คำมั่นว่า "ฉันจะนิยามทีหลัง" ส่วน `defffi` ประกาศว่า "ผู้อื่นเขียนและคอมไพล์ตัวเนื้อหาไว้แล้ว"

```lisp
(defffi (c-abs "abs") (i32) i32)
(defffi (c-sqrt "sqrt") (f64) f64)
(defffi (c-getpid "getpid") () i32)

(unsafe (c-abs -5))                          ; => 5
```

ชื่อ typelisp และชื่อสัญลักษณ์ C เขียนแยกกันได้ เพราะตัวระบุของ typelisp มักมี `-` และตัวระบุของ C
ไม่มีได้ หากละชื่อ C จะใช้ชื่อนั้นเป็นชื่อสัญลักษณ์ C
ตามที่เป็น

**การเรียกต้องใช้ `(unsafe ...)`** (แม้สำหรับฟังก์ชันที่ใช้เฉพาะสเกลาร์) คอมไพเลอร์ไม่มีทาง
ยืนยันว่า signature ของ C ที่ประกาศตรงกับของจริง และทำได้เพียงเชื่อการประกาศ
`unsafe` คือเครื่องหมายว่าคุณรับผิดชอบเรื่องนั้น วิธีที่ตั้งใจคือห่อหนึ่งครั้งและ
สร้าง wrapper ที่ปลอดภัย:

```lisp
(defun abs-i32 ((n i32)) i32 (unsafe (c-abs n)))
(abs-i32 -3)                                 ; no unsafe needed from here on
```

ชนิดที่เขียนได้คือ `i8` `i16` `i32` `u8` `u16` `u32` `f32` `f64` `bool` `()` (void)
`string` `ptr` `c-long` `c-ulong` และตัวชี้ที่มีชนิด `(ptr T)`
([ด้านล่าง](#def-c-struct-และตัวชี้ที่มีชนิด--การจัดสรร-struct-ของ-c))

`string` คือ `const char *` สตริง typelisp ไม่ได้ลงท้ายด้วย NUL และอาจมี NUL อยู่ภายใน ดังนั้น
**จึงถูกคัดลอกเป็นสตริง C เมื่อส่ง** และคืนหลังการเรียก NUL ในสตริงเป็น
ข้อผิดพลาด: C จะดูเพียงถึงมัน ดังนั้นสตริงที่ต่างออกไปจะถูกส่งโดยไม่แจ้ง

**สตริงที่คืนมาก็ถูกคัดลอกด้วย** และไม่ถูกคืนหน่วยความจำ: สิ่งที่ C คืนเป็นของ C และอาจ
ชี้ไปในตารางสถิต เหมือน `getenv` ฟังก์ชันที่คืนหน่วยความจำที่ผู้เรียกต้องคืน (`strdup` และอื่น ๆ)
ให้รับเป็น `ptr` และคืนด้วยตนเอง

ฟังก์ชันที่ผลลัพธ์ชี้ภายในอาร์กิวเมนต์ (`strchr`, `strstr`) ก็ทำงานถูกต้อง: ผลลัพธ์
ถูกคัดลอกก่อนที่อาร์กิวเมนต์จะถูกคืน

หากฟังก์ชันที่ประกาศว่าคืน `string` คืน NULL จะเป็นข้อผิดพลาด เพราะ `string` ไม่มีค่าที่
หมายถึง "ไม่มี" หากเป็นไปได้ที่จะเป็น NULL ให้รับผลลัพธ์เป็น `ptr`

```lisp
(defffi (c-strlen "strlen") (string) i32)
(defffi (c-getenv "getenv") (string) string)

(unsafe (c-strlen "hello"))                  ; => 5
(unsafe (c-getenv "PATH"))                   ; => "/usr/bin:..."
```

เมื่อใช้ `:library` ไลบรารีที่ใช้ร่วมกันนั้นจะถูกเปิดและค้นหาสัญลักษณ์ในนั้น หากไม่มี สัญลักษณ์จะถูก
ค้นหาใน **โพรเซสเอง** (ทุกอย่างที่ลิงก์แล้ว รวม libc) ชื่อสั้นอย่าง
`sqlite3` ถูกค้นหาเป็น `libsqlite3.dylib` / `libsqlite3.so` ตามลำดับ และชื่อที่มี `/`
ถือเป็นพาธ ไลบรารีที่เปิดไม่เคยถูกปิด: โค้ดที่ชี้ไปยังฟังก์ชันของมันยังทำงานต่อ
ดังนั้นอายุที่ถูกต้องเพียงอย่างเดียวคืออายุของโพรเซส

#### ptr / c-long / c-ulong — word ดิบของเครื่อง

`ptr` คือตัวชี้ทึบ (`void *`, `FILE *` หรืออะไรก็ตามที่การประกาศหมายถึง) `c-long` / `c-ulong` คือ
`long` / `unsigned long` ของ C (และ `size_t`, `int64_t` และ `intptr_t` ด้วย)

```lisp
(defffi (c-malloc "malloc") (c-ulong) ptr)
(defffi (c-free "free") (ptr) ())
(defffi (c-strlen "strlen") (string) c-ulong)

(unsafe (let ((p (c-malloc 16))) (c-free p) ()))
```

**การไม่เรียกว่า `i64` / `u64` เป็นความตั้งใจ** ภาษานี้ไม่มีชนิดจำนวนเต็ม 64 บิต เพราะ
immediate ที่มีแท็กมีเพียง 63 บิต ([บทที่ 2](#2-การเขียนชนิด)) ชื่อ `c-long` บอกว่า "นี่คือ
word ที่ข้ามขอบเขตกับ C ไม่ใช่จำนวนเต็มของภาษานี้"

**ไม่มีการคำนวณ** `(+ x 1)` เขียนไม่ได้ จะให้ก็ได้แต่ไม่ให้ เพื่อไม่ให้มีการคำนวณใดรันบนค่าที่
เก็บไว้ที่ไหนไม่ได้และมีความกว้างต่างจากตัวเลขอื่นทุกชนิด ด้วยเหตุผลเดียวกับที่ละชนิดจำนวนเต็ม
64 บิตไว้ มี **เฉพาะการแปลง**:

```lisp
(as i32 (unsafe (c-strlen "hello")))         ; read what came back
(as int (unsafe (c-strlen s)))               ; this one to read it exactly (int does not lose 64 bits)
(try-as i32 (unsafe (c-strlen s)))           ; ask whether it fits
(as c-ulong n)                               ; make one from another integer
```

**literal** จำนวนเต็มรับชนิดที่คาดหวัง จึงไม่ต้องใช้ `as` เพียงเพื่อส่งมัน:

```lisp
(unsafe (c-malloc 16))                       ; 16 is read as a c-ulong
```

literal ที่เกินช่วงถูกปฏิเสธเหมือนความกว้างอื่น (`(c-malloc -1)` ไม่พอดี `c-ulong`)

**ที่ที่ปรากฏได้ถูกจำกัด**: ชนิดของอาร์กิวเมนต์ ชนิดที่คืน และตัวแปรท้องถิ่นเท่านั้น
แต่ละสิ่งต่อไปนี้เป็นข้อผิดพลาด:

```lisp
(defstruct handle (p ptr))          ; a struct field
(defenum maybe (none) (some ptr))   ; an enum field
(defvar (block ptr) ...)            ; a global
(defffi f ((vector ptr)) i32)       ; inside a type argument
```

มีเหตุผลเดียวสำหรับทั้งหมด: **ช่องนั้นติดแท็กสิ่งที่มันเก็บ** การติดแท็กจะทิ้งบิตบนของ
ตัวชี้ ด้วยเหตุผลเดียวกับที่ละชนิดจำนวนเต็ม 64 บิตไว้ ดังนั้นจึงไม่อนุญาตแม้ใน
`unsafe` นี่ไม่ใช่เรื่องของสิทธิ์: การแสดงผลนั้นไม่มีอยู่

ด้วยเหตุผลเดียวกัน จึงเป็นตัวแปรท้องถิ่นที่ถูก **จับ (capture)** โดยฟังก์ชันซ้อนไม่ได้ (การผูกที่ถูกจับไปอยู่ใน
เซลล์ และเซลล์ติดแท็กสิ่งที่มันเก็บ) ทราบเรื่องนี้ตอนคอมไพล์และรายงานโดย
`(compile f)`

GC ไม่ติดตาม `ptr` มันชี้ออกนอกฮีป ซึ่งถูกต้องแล้ว

สี่อย่างที่ประกาศไม่ได้:

- **อาร์กิวเมนต์ variadic** (`printf`) ส่วน variadic ถูกส่งด้วยกฎที่ต่างจากอาร์กิวเมนต์คงที่
  (บนสแตกบน AArch64 Darwin) จึงเรียกอย่างถูกต้องจาก signature คงที่ไม่ได้
  `&rest` ถูกปฏิเสธ
- **การส่งหรือคืน struct แบบส่งค่า (by value)** ด้วยเหตุผลเดียวกัน (ขึ้นกับ
  calling convention ของแต่ละแพลตฟอร์ม) ชนิดที่เขียนได้ถูกจำกัดตามรายการข้างบน จึงสะกดไม่ได้
- **Generics** C ไม่มีสิ่งที่สอดคล้อง
- **ชื่อเดียวกับฟังก์ชันที่มีให้ในตัว** การเรียกที่คอมไพล์แล้วจะแก้ไขชื่อนั้นไปยังฟังก์ชันที่มีให้ในตัว จึง
  ปฏิเสธแทนที่จะผิดพลาดเงียบ ๆ

#### Callback — การให้ C เรียกกลับ

การเขียนชนิดฟังก์ชัน `(fn (types...) return-type)` เป็นชนิดของอาร์กิวเมนต์ทำให้อาร์กิวเมนต์นั้นเป็นฟังก์ชัน
ที่ C เรียกกลับ (callback)

```lisp
(defffi (c-qsort "qsort") (ptr c-ulong c-ulong (fn (ptr ptr) i32)) ())

(defun desc ((a ptr) (b ptr)) i32 ...)

(unsafe
  (c-qsort buf n 8 desc)                                 ; a top-level function
  (c-qsort buf n 8 (lambda ((a ptr) (b ptr)) i32 ...))   ; a lambda
  (labels ((cmp ((a ptr) (b ptr)) i32 ...))
    (c-qsort buf n 8 cmp)))                              ; a local function
```

ตัวชี้ฟังก์ชันของ C ไม่ใช่อะไรอื่นนอกจากที่อยู่โค้ด และ C เรียกมันโดยส่งเฉพาะอาร์กิวเมนต์ที่ประกาศ
ไม่มีที่ส่งตัวแปรที่ถูกจับ ดังนั้น **ส่งได้เฉพาะฟังก์ชันที่ไม่มีตัวแปรอิสระ**
และตรวจสอบเรื่องนี้ตอนตรวจสอบชนิด

- เขียนชื่อฟังก์ชันหรือนิพจน์ `lambda` **ตรง ๆ** เป็นอาร์กิวเมนต์จริง ตัวแปรที่เก็บ
  ฟังก์ชันส่งไม่ได้: ไม่ทราบจนกว่าจะถึงตอนรันว่ามันเก็บฟังก์ชันใด และจึงไม่ทราบว่ามีตัวแปรอิสระหรือไม่
- `lambda` เป็นข้อผิดพลาดหากอ้างถึงตัวแปรท้องถิ่นภายนอกมัน ตัวแปรโกลบอลและฟังก์ชัน
  ระดับบนสุดอ้างถึงได้
- ฟังก์ชันท้องถิ่น (`labels`) ต้องไม่มีตัวแปรอิสระ รวมถึงของฟังก์ชันพี่น้องที่มัน
  เรียก ฟังก์ชันพี่น้องใช้ที่เก็บตัวแปรที่ถูกจับร่วมกัน ดังนั้นสิ่งที่พี่น้องที่ถูกเรียกจับไว้
  ก็ถูกจับโดยฟังก์ชันนี้ด้วย
- ฟังก์ชัน generic ได้ชนิดจากชนิดฟังก์ชันที่ประกาศ
- ชนิดที่เขียนได้ในชนิดฟังก์ชันเหมือนรายการข้างบน อย่างไรก็ตาม `string`
  เป็นชนิดที่คืนของ callback ไม่ได้ (จะส่งหน่วยความจำที่ไม่มีใครคืนให้ C) อาร์กิวเมนต์ `string` คัดลอก
  สตริงที่ C ส่งมาเป็นสตริง typelisp

การเรียกฟังก์ชัน C เขียนได้เฉพาะภายใน `unsafe` ดังนั้นส่ง callback ได้เฉพาะภายใน `unsafe`

**callback เรียกได้เฉพาะขณะที่ฟังก์ชัน C ที่ typelisp เรียกกำลังทำงาน** หาก
ถูกเรียกจากที่อื่น (เธรดที่ไม่ได้รัน typelisp ตัวจัดการสัญญาณ ฟังก์ชันที่ลงทะเบียนด้วย
`atexit`) จะพิมพ์เหตุผลและหยุดโพรเซส

**ความล้มเหลวไม่แพร่ผ่าน C** `panic` หรือ `throw` ภายใน callback คลี่ผ่านเฟรมของ C ไม่ได้
(เป็นพฤติกรรมที่ไม่นิยาม) จึงคืน 0 ให้ C และความล้มเหลวถูกโยนซ้ำให้
ผู้เรียกเมื่อฟังก์ชัน C คืนค่า หาก callback ถูกเรียกอีกครั้งระหว่างความล้มเหลวและการคืนค่า
ของฟังก์ชัน C มันจะไม่ถูกรันและคืน 0

การดำเนินการที่ต้องรอภายใน callback (`recv` บน channel ว่าง และอื่น ๆ) เป็น
ข้อผิดพลาด ([12.6](#126-โค้ดที่คอมไพล์แล้วกับ-task))

เมื่อฟังก์ชันถูกนิยามใหม่ การนิยามใหม่จะถูกเรียกตั้งแต่ครั้งถัดไปที่ส่งให้ C

ทำงานแบบเดียวกันกับ AOT (`compile-file`) จุดเข้าที่ C เรียกถูกสร้างไว้ใน
ไฟล์ปฏิบัติการ

**ส่งเป็นค่าไม่ได้** การประกาศ FFI เขียนตามที่เป็นเป็น `f` ของ
`(map f xs)` ไม่ได้: ค่าฟังก์ชันคือ closure ที่ห่อตัวเนื้อหาของการนิยาม และการประกาศนี้
ไม่มีตัวเนื้อหาให้ห่อ ให้ห่อด้วย `lambda`:

```lisp
(run-it (unsafe (lambda ((n i32)) i32 (c-abs n))))
```

`(disassemble c-abs)` ก็ถูกปฏิเสธ: สิ่งที่แสดงได้คือโค้ดเครื่องของ C ซึ่งคอมไพเลอร์นี้
ไม่ได้สร้าง `(compile c-abs)` สำเร็จ (และไม่ทำอะไร เพราะคอมไพล์แล้ว)

**ใช้กับ AOT (`compile-file`) ได้ด้วย** ตัวลิงก์แก้ไขฟังก์ชัน C เอง หาก
การประกาศมี `:library` ไลบรารีนั้นถูกเพิ่มในบรรทัดลิงก์เป็น `-l` (ที่ซ้ำกันถูกรวมเป็น
หนึ่ง) ดังนั้น `compile-file` ไม่ต้องใช้อาร์กิวเมนต์เพิ่ม `compile-file` เองอ่านซอร์ส จึงรวบรวม
จากการประกาศได้

สัญลักษณ์ถูกค้นหาตอนบิลด์ด้วย หากฟังก์ชันที่ประกาศไม่มีอยู่ ข้อผิดพลาดจะระบุชื่อมัน
ก่อนข้อผิดพลาดของการลิงก์

ไลบรารีมาตรฐาน (prelude) ไม่ใช้ `defffi` ไลบรารีมาตรฐานเข้าไปในทุก
ไฟล์ปฏิบัติการทั้งก้อน ดังนั้นการประกาศที่มี `:library` ที่นั่นจะลิงก์ไลบรารีนั้นแม้กับโปรแกรม
ที่ไม่ใช้ FFI

#### def-c-struct และตัวชี้ที่มีชนิด — การจัดสรร struct ของ C

```lisp
(unsafe
  (def-c-struct name (field type)...)
  ...)
(unsafe (pub def-c-struct ...))
```

ประกาศ struct ที่มีเลย์เอาต์เดียวกับใน C เขียนได้เฉพาะภายใน `unsafe` ระดับบนสุด
(ซึ่งมีได้เฉพาะ `def-c-struct`) ใส่ docstring ทันทีหลังชื่อได้

ชนิดที่เขียนได้สำหรับฟิลด์คือ `i8` `i16` `i32` `u8` `u16` `u32` `c-long` `c-ulong` `f32`
`f64` `bool` `ptr` ตัวชี้ที่มีชนิด `(ptr T)` และ `def-c-struct` อื่น (ฝังแบบส่งค่า) เลย์เอาต์
(ออฟเซ็ตของแต่ละฟิลด์ และขนาดกับการจัดตำแหน่งของ struct) คำนวณตามกฎของ C (สมมติ LP64)
เขียนฟิลด์ที่ชี้ไปยัง struct เองได้ แต่ struct ฝังตัวเองไม่ได้

```lisp
(unsafe
  (def-c-struct point (x i32) (y f64))              ; x at 0, y at 8, size 16
  (def-c-struct seg (a point) (b point) (next (ptr seg))))
```

ชื่อของ `def-c-struct` เข้าสู่เนมสเปซของชนิด (ภายในโมดูลเดียวกันจะมี `defstruct` หรือสิ่งอื่นชื่อเดียวกันไม่ได้) แต่ **ไม่ใช่ชนิดของค่า** คุณเขียน
`(defun f ((p point)) ...)` ไม่ได้ มันปรากฏเฉพาะเป็นสิ่งที่ตัวชี้ที่มีชนิดชี้ไป

**ตัวชี้ที่มีชนิด `(ptr T)`** คือที่อยู่ที่ชี้ไปยัง `T` `T` เป็นหนึ่งในชนิดที่เขียนได้
สำหรับฟิลด์ข้างบน เป็น word ดิบของเครื่องเหมือน `ptr` ด้วยกฎเดียวกันว่าปรากฏที่ใดได้
(อาร์กิวเมนต์ ชนิดที่คืน และตัวแปรท้องถิ่นเท่านั้น เป็นค่าได้เฉพาะภายใน `unsafe`)

การจัดสรร การอ่าน และการเขียนเขียนในรูปแบบต่อไปนี้ ทั้งหมดใช้ได้เฉพาะภายใน
`unsafe`

| รูปแบบ | ความหมาย |
|---|---|
| `(c-alloc T)` / `(c-alloc T n)` | จัดสรรค่า `T` จำนวน `n` ค่า (1 หากละ) เนื้อหาถูกเติมด้วย 0 คืน `(ptr T)` |
| `(c-ref p i)` | ตัวชี้ไปยังสมาชิกตัวที่ `i` จาก `p` ข้อผิดพลาดหากอยู่นอกช่วงที่จัดสรร |
| `(c-deref p)` / `(setf (c-deref p) v)` | อ่าน / เขียนสเกลาร์ที่ `p` ชี้ไป |
| `p::field` / `(setf p::field v)` | อ่าน / เขียนฟิลด์ของ struct การอ่านฟิลด์ที่เป็น struct ที่ฝังอยู่ให้ที่อยู่ของมัน (`(ptr inner-type)`) |
| `(as ptr p)` | ลืมชนิด ทำให้เป็น `ptr` (เพื่อส่งให้สิ่งอย่าง `void *` ของ `qsort`) ไม่มีการแปลงกลับ |

```lisp
(defun sum-x ((n int)) int
  (unsafe
    (let ((ps (c-alloc point n)))
      (dotimes (i n)
        (let ((p (c-ref ps i)))
          (setf p::x (as i32 i))))
      (let ((total 0))
        (dotimes (i n)
          (let ((p (c-ref ps i)))
            (setf total (+ total (as int p::x)))))
        total))))
```

**หน่วยความจำที่จัดสรรถูกคืนเมื่อการควบคุมออกจาก `unsafe` ที่จัดสรรมัน** เจ้าของคือ
`unsafe` ชั้นนอกสุดตามตัวอักษรภายในฟังก์ชันเดียวกัน ถูกคืนไม่ว่าโค้ดจะจบตามปกติ
หรือออกด้วย `panic`, `throw` หรือ `return-from` ฟังก์ชัน `lambda` และ `labels` เป็นคนละฟังก์ชัน
ดังนั้น `c-alloc` ในนั้นต้องมี `unsafe` ของตัวเองอยู่ภายใน

ด้วยเหตุนี้ ตัวชี้ที่มีชนิดจึงออกจาก `unsafe` ที่จัดสรรมันไม่ได้ แต่ละสิ่งต่อไปนี้เป็น
ข้อผิดพลาดของชนิด:

- การทำให้เป็นค่าของนิพจน์ `unsafe` (ดังนั้นคืนจากฟังก์ชันก็ไม่ได้)
- การจับใน closure (`lambda`, `labels`)
- การส่งให้ `task` / `thread`
- การโยนด้วย `throw`

หากต้องการใช้ค่าภายนอก `unsafe` ให้คัดลอกเป็น `defstruct` หรือตัวเลขภายใน `unsafe` แล้ว
คืนสิ่งเหล่านั้น

**หน่วยความจำที่จัดสรรฝั่ง C ไม่ถูกจัดการ** ค่าที่เข้ามาจาก C เป็นตัวชี้ที่มีชนิด (`defffi`
ค่าที่คืน อาร์กิวเมนต์ของ callback ค่าที่อ่านจากฟิลด์ชนิดตัวชี้) ถูกตรวจสอบตอนรัน
ว่าชี้ไปยังค่าของชนิดนั้นภายในการจัดสรร `c-alloc` ที่ยังมีชีวิตหรือไม่ และเป็นข้อผิดพลาดหาก
ไม่ใช่ NULL ก็เป็นข้อผิดพลาด หากต้องการรับหน่วยความจำที่ C จัดสรร หรือ NULL ให้ใช้ `ptr` ที่ไม่มีชนิด (ซึ่งเนื้อหา
อ่านไม่ได้)

```lisp
(unsafe (def-c-struct item (key i32) (tag u8)))
(defffi (c-qsort "qsort") (ptr c-ulong c-ulong (fn ((ptr item) (ptr item)) i32)) ())

(unsafe
  (let ((xs (c-alloc item 4)))
    ...
    (c-qsort (as ptr xs) 4 8 (lambda ((a (ptr item)) (b (ptr item))) i32 (- a::key b::key)))
    ...))
```

เมื่ออาร์กิวเมนต์ของ callback ถูกปฏิเสธโดยการตรวจสอบ จะรายงานให้ผู้เรียกเมื่อฟังก์ชัน C
คืนค่า เหมือนความล้มเหลวภายใน callback

### 3.4 defvar / defparameter / defconstant — ตัวแปรโกลบอล

```lisp
(defvar (name Type) init-expr)        ; initializes only if not yet bound
(defparameter (name Type) init-expr)  ; assigns every time
(defconstant (name Type) init-expr)

; with a docstring (in the same order as CL's defvar/defparameter/defconstant: after the value)
(defvar (name Type) init-expr "doc")
(defconstant (name Type) init-expr "doc")
```

**ความต่างระหว่าง `defvar` และ `defparameter` ปรากฏตอนโหลดซ้ำ** (เหมือนใน CL) หากตัวแปรโกลบอล
**ผูกอยู่แล้ว `defvar` จะไม่ประเมินตัวกำหนดค่าเริ่มต้นเลย** ดังนั้นเมื่อคุณแก้ไขไฟล์การตั้งค่าและ
อ่านใหม่ ค่าที่เซสชันเปลี่ยนไว้จะคงอยู่ตามเดิม `defparameter` กำหนดค่าทุกครั้ง ดังนั้น
การอ่านใหม่ทำให้ค่ากลับเป็นสิ่งที่เขียนไว้

ต้องมีคำอธิบายชนิด (ไม่ถูกอนุมานจากตัวกำหนดค่าเริ่มต้น) `defvar` เปลี่ยนค่าได้
`defconstant` เปลี่ยนไม่ได้ (`setf` เป็นข้อผิดพลาด)

### 3.5 defmethod — การนิยามเมทอด

```lisp
; instance method: can be called as (m obj args...)
(defmethod name ((self Type) (arg Type2) ...) RetType body...)

; static / associated function: can be called as (Type::name args...)
(defmethod name (Type (arg Type2) ...) RetType body...)
```

ผู้เรียกแก้ไขเมทอดจากชนิดสถิตของ `obj` (single, static dispatch) ใส่ docstring ได้
ในตำแหน่งเดียวกันและตามกฎเดียวกับ `defun` (ทันทีหลังอนุประโยค `where`
ที่ต้นตัวเนื้อหา เฉพาะเมื่อมีฟอร์มของตัวเนื้อหาตามมา) เช่นเดียวกันกับเมทอดภายใน `impl` ดึงได้
ด้วย `(documentation Type::method)`

### 3.6 defstruct — struct (ชนิดที่ผู้ใช้นิยาม)

```lisp
(defstruct Name
  (field1 Type1)
  (pub field2 Type2)
  ...)

; generic (type parameters in angle brackets)
(defstruct Name<T1,T2...>
  (field TypeUsingT1)
  ...)
```

- แต่ละฟิลด์คือ `(name type)` หรือ `(pub name type)` (การมองเห็นต่อฟิลด์ อิสระจาก `pub` ของ
  struct เอง) นิพจน์อีกหนึ่งตัวที่ท้ายจะเป็น **ค่าเริ่มต้น** ของ slot (`(x i32 0)`) ดู
  รายการตัวเลือกด้านล่าง
- สิ่งต่อไปนี้ถูกสร้างโดยอัตโนมัติ:
  - ตัวสร้าง `Name::new` (อาร์กิวเมนต์ตามลำดับฟิลด์)
  - getter `(field-name instance)` พร้อมน้ำตาลไวยากรณ์ `instance::field-name`
  - setter `(set-field-name instance value)` พร้อมน้ำตาลไวยากรณ์ `(setf instance::field-name value)`
- หากต้องการให้ตัว struct เป็น `pub` ให้ใส่ `pub` ข้างหน้า เช่น `(pub defstruct ...)`
- **นิยามชนิดก่อนที่จะอ้างชื่อมัน** ชนิดของฟิลด์เป็นตัว struct เองได้ (`(next Option<node>)`)
  แต่ไม่ใช่ชนิดที่นิยามทีหลัง: ชนิดไม่มีการประกาศล่วงหน้าที่สอดคล้องกับ `defsignature` ชื่อ
  ที่ยังไม่ถูกนิยามให้ข้อผิดพลาด `unknown type` เดียวกันในชนิดอาร์กิวเมนต์ของ `defun` หรือใน `the` ดังนั้นสองชนิด
  ที่อ้างถึงกันเขียนไม่ได้
- **ตัวแปรชนิดมีเฉพาะที่เขียนในตำแหน่งที่ประกาศ** สำหรับ `defun`/`defstruct`/`defenum`/
  `deftype` คือ `<T>` ของชื่อ สำหรับ `defmethod` คือชนิดของตัวรับ (`(self box<T>)` หรือ `box<T>`
  สำหรับเมทอดสถิต) สำหรับ `impl` คือชนิดเป้าหมายและ `impl<T>` สำหรับ `deftrait` คือ `Self` และ
  associated type ของ `(type Item)` ชื่อที่ปรากฏครั้งแรกที่อื่น (อาร์กิวเมนต์ ค่าที่
  คืน `the`/`lambda` ในตัวเนื้อหา) ไม่กลายเป็นตัวแปรชนิด แต่เป็น `unknown type`
- **Docstring**: สตริง literal ทันทีหลังชื่อ ก่อนฟิลด์ จะเป็น docstring
  (`(defstruct Name "doc" (field Type)...)` ตำแหน่งเดียวกับ `defstruct` ของ CL) ฟิลด์เป็น
  รูปแบบ `(name Type ...)` เสมอและไม่มีทางเป็นสตริงเปล่า ดังนั้นไม่กำกวม ดึงด้วย
  `(documentation Name)`

#### รายการตัวเลือก (Option list)

การเขียนลิสต์ `(Name option...)` ในตำแหน่งชื่อระบุตัวเลือก (ตำแหน่งเดียวกับ CL)

```lisp
(defstruct (point (:constructor make-point)          ; keyword constructor
                  (:constructor at (x &optional y))  ; BOA constructor
                  (:copier copy-point))
  (x i32 0)          ; a third element is that slot's default value
  (y i32 0))

(point::make-point :y 7)   ; x is 0
(point::at 1)              ; y is 0
(point::at 1 2)
(copy-point p)             ; a shallow copy (the same as CL's copier)
```

- **`:constructor`**: สิ่งที่สร้างคือ **ฟังก์ชันสถิต** ของชนิด (`point::make-point`) ที่ตัวเนื้อหา
  เป็น `(point::new ...)` เสมอ `new` ยังคงเป็นตัวสร้างเชิงโครงสร้างตัวเดียว สิ่งที่สร้างที่นี่คือ
  *วิธีเรียก* มัน ประกาศได้หลายตัว
  - `(:constructor name)` รับทุก slot เป็น `&key` **ทุก slot ต้องมีค่าเริ่มต้น** (ภาษานี้
    ไม่มีสิ่งที่สอดคล้องกับ "unbound slot" ของ CL)
  - `(:constructor name (slot...))` รับ slot ที่ระบุชื่อเป็นอาร์กิวเมนต์ตามตำแหน่ง (ลำดับใดก็ได้) slot
    ที่ไม่ได้ระบุชื่อถูกเติมด้วยค่าเริ่มต้น ดังนั้น **ต้องมีค่าเริ่มต้น** หลัง `&optional` ที่เหลือละได้
    (และต้องมีค่าเริ่มต้นเช่นกัน)
- **`:copier`**: สร้าง **เมทอดของอินสแตนซ์** ที่คืนค่าใหม่ซึ่งมีค่า slot เดียวกัน
  แบบตื้น (shallow) เหมือน copier ของ CL
- **`:include Parent`**: ใส่ slot ของแม่ไว้ข้างหน้า (ค่าเริ่มต้นสืบทอดด้วย แม่อยู่ใน
  ไฟล์อื่นก็ได้) **ไม่สร้างความสัมพันธ์ของชนิด**: ลูกไม่ใช่ชนิดย่อยของแม่ เมทอดของแม่
  ไม่ใช้กับลูก และไม่มีการทดสอบตอนรันที่เชื่อมทั้งสอง ภาษานี้ไม่มี subtyping อินเทอร์เฟซ
  ร่วมเป็นหน้าที่ของ `deftrait` มีเพียง *รายการ* ของ slot ที่ถูกรวม
- **ค่าเริ่มต้นของ slot ถูกอ่านโดยตัวสร้างที่ถูกสร้างเท่านั้น** การเขียนค่าเริ่มต้นโดยไม่ประกาศ
  `:constructor` ใด ๆ เป็นข้อผิดพลาด เพราะจะไม่มีวันถูกใช้
- ตัวเลือกที่ละไว้ และเหตุผล:
  - **`:conc-name`**: ใน CL มันเติม prefix ให้ตัวเข้าถึงเพื่อหลีกเลี่ยงการชนกันในเนมสเปซฟังก์ชันแบบแบนเดียว ที่นี่
    ตัวเข้าถึงเป็นเมทอดที่ dispatch ตามชนิดของตัวรับ จึงไม่ชนกัน และ prefix จะ
    ทำให้ `instance::field` เสีย (ซึ่งรู้จักเฉพาะชื่อ slot)
  - **`:predicate`**: ตอบตอนรันว่า "ค่านี้เป็น `point` หรือไม่" ที่นี่ชนิดเป็นการ
    จำแนกตอนคอมไพล์ที่ไม่มีพยานตอนรัน และไม่มีตำแหน่งที่ "ค่าของชนิดที่ไม่ทราบ
    ซึ่งอาจเป็น point" มีอยู่ (`match` บน `Sexpr` ถูกปิดผนึก และ `:dyn` downcast ไม่ได้) ดังนั้น predicate
    ที่สร้างขึ้นจะคืนได้เพียง `true`
  - **`:type` / `:initial-offset` / `:named`**: สิ่งเหล่านี้แทนที่การแสดงผลของค่าด้วยลิสต์หรือ
    เวกเตอร์ การแสดงผลเป็นของคอมไพเลอร์และสังเกตจากภาษาไม่ได้

### 3.7 defenum — enum (sum type)

```lisp
(defenum Name
  (Variant1 Type1 Type2...)   ; a variant with a payload (positional fields)
  (Variant2)                  ; a variant without a payload
  ...)

; generic
(defenum Option<T>
  (Some T)
  (None))
```

- แต่ละ variant มีรูปแบบ `(VariantName FieldType...)` ฟิลด์เป็นแบบตามตำแหน่งเท่านั้น (ไม่มี
  ชื่อ) ต้องมีอย่างน้อยหนึ่ง variant และชื่อซ้ำไม่ได้
- ค่าถูกสร้าง เหมือน `Option`/`Result` ที่มีให้ในตัว โดยมีตัวกำกับหรือผ่าน `use`:
  `(Name::Variant1 a b)` หรือ `(Variant1 a b)` หลัง `(use Name)`
- แยกส่วนประกอบได้ด้วย `match` / `if-let` `match` ตรวจสอบความครอบคลุม (ต้องครอบคลุมทุก
  variant หรือมี `_`):
  ```lisp
  (match opt
    ((Some v) v)
    ((None) 0))
  ```
- เมทอดและฟังก์ชันที่เกี่ยวข้องเพิ่มทีหลังด้วย `defmethod`/`impl` เหมือน `defstruct`
- หากต้องการให้ตัว enum เป็น `pub` ให้เขียน `(pub defenum ...)`
- **Docstring**: ตำแหน่งและกฎเดียวกับ `defstruct` ทันทีหลังชื่อ ก่อน variant
  (`(defenum Name "doc" (Variant ...)...)`) ดึงด้วย `(documentation Name)`

### 3.8 deftype — ชื่อแทนของชนิด

```lisp
(deftype meters i32)
(deftype fallible<T> Result<T,string>)
(deftype pred (fn (i32) bool))

(defun double ((m meters)) meters (* m 2))
(defun parse ((s string)) fallible<i32> ...)
```

`deftype` ของ CL ที่แคบลงเหลือสิ่งที่สมเหตุสมผลในภาษาที่มีระบบชนิดแบบสถิต: **การสะกดของชนิด ไม่ใช่
ชนิด**

- ตำแหน่งชื่อเหมือน `defun` และอาร์กิวเมนต์ generic เขียนเป็น `Name<T,U>` ที่จุดใช้งาน
  ต้องมีอาร์กิวเมนต์ชนิดตามจำนวนที่ประกาศพอดี (มากไปหรือน้อยไปเป็นข้อผิดพลาดทันที)
- การขยายเกิดขึ้น **ภายในตัว parse ชนิด** ดังนั้นไม่มีสิ่งใดต่อจากนั้นรู้ว่า alias มีอยู่: คีย์ของการ
  monomorphization, dump, เส้นทางการคอมไพล์ และ **ข้อความแสดงข้อผิดพลาด** ล้วนแสดงรูปที่ขยายแล้ว หาก
  `(f "x")` ล้มเหลวกับฟังก์ชันที่ต้องการ `meters` ข้อความจะบอก `i32`
- **ไม่ใช่ชนิดใหม่** `(deftype meters i32)` ทำให้ `meters` และ `i32` เป็นชนิดเดียวกัน ดังนั้นการสับสน
  ระหว่างสองอย่างจึงไม่ถูกจับ หากต้องการแยกให้ชัดเจน ให้ใช้ `defstruct`
- **ไม่ใช่ predicate** `(deftype small () '(integer 0 9))` ของ CL อธิบาย *เซตของค่า* ที่
  `typep` ทดสอบตอนรัน แต่ที่นี่ชนิดเป็นการจำแนกตอนคอมไพล์ที่ไม่มีพยานตอนรัน
  ดังนั้น alias ที่จำกัดค่าจะไม่มีอะไรให้จำกัด
- **มีตัวเองอยู่ภายในไม่ได้** alias ถูกขยายที่ที่เขียน จึงไม่มีที่ให้มัน
  วนซ้ำ ชนิดข้อมูลแบบเวียนเกิดเขียนด้วย `defstruct`/`defenum`
- ใช้เนมสเปซร่วมกับชนิดและ trait (ภายในโมดูลเดียวใช้ชื่อเดียวกับ
  `defstruct`/`defenum`/`deftrait` ไม่ได้) ทำให้เป็นสาธารณะด้วย `(pub deftype ...)` และนำเข้าด้วย
  `(use m::meters)`
- **Docstring**: ทันทีหลังชื่อ ก่อนชนิด (`(deftype Name "doc" Type)`)

### 3.9 deftrait / impl — trait

```lisp
(deftrait TraitName (SuperTrait...)      ; the supertrait list is required; () if none
  (type AssocName)                       ; associated types (any number, optional)
  (method-name ((self Self) params...) RetType)          ; no body = must be implemented
  (method-name ((self Self) params...) RetType body...)) ; with a body = default implementation

(impl TraitName TargetType
  (where (Trait A)...)                   ; bounds applying to the whole impl (optional)
  (type AssocName ConcreteType)          ; makes an associated type concrete
  (method-name (recv params...) RetType body...))
```

ผ่าน `impl` แต่ละเมทอดถูกลงทะเบียนเป็น `defmethod` ธรรมดาของ `TargetType` trait ถูก
อ้างถึงเป็น trait bound ในอนุประโยค `where` ของฟังก์ชัน generic (ดู
[3.1 defun](#31-defun--การนิยามฟังก์ชัน)) ชื่อ trait เป็นพาธ `::` ได้ด้วย เช่น `m::Trait`

**รายการ supertrait (จำเป็น)**: เขียนทันทีหลังชื่อ trait เสมอ แต่ละสมาชิกคือชื่อ
trait เปล่า หรือ หาก trait นั้นมี associated type คือ `(Trait (Assoc Type))` โดย **กำหนด associated
type ทั้งหมดของมัน**

```lisp
(deftrait Eq () ...)                       ; no supertraits
(deftrait Ord (Eq) ...)                    ; Rust's trait Ord: Eq
(deftrait CharSource ((Iter (Item char)))  ; pinning an associated type
  (rewind ((self Self)) ()))
```

การสืบทอดมีสามผล (1) `impl Ord X` ต้องมี `impl Eq X` เขียน **ก่อน** (กฎเรื่อง
ลำดับการเขียน: รูปแบบเดียวที่ตัดสินแบบกำหนดแน่นอนได้ใน REPL และด้วย `load` ทีละขั้น
และเข้มงวดกว่า Rust) (2) `(where (Ord T))` อย่างเดียวให้คุณเรียกเมทอดของ
`Eq` ได้ด้วย (3) เมทอดของ `Eq` เรียกผ่าน `:dyn Ord` ได้ และค่า `:dyn Ord` ส่ง
ตามที่เป็นได้ในที่ที่ต้องการ `:dyn Eq` (upcasting) trait ย่อยที่ประกาศเมทอดชื่อเดียวกับ
แม่ซ้ำ และการสืบทอดเมทอดชื่อเดียวกันจากแม่สองตัว ล้วนเป็นข้อผิดพลาด (vtable มีหนึ่ง
ช่องต่อชื่อ) การสืบทอดแบบเพชรถูกรวมเป็นช่องเดียว

**การ implement เริ่มต้น**: ตัวเนื้อหาหลัง signature ถูกใช้เมื่อ `impl` ละเมทอดนั้น
ตัวเนื้อหาถูกแก้ไขใน **เนมสเปซของโมดูล** ที่เขียน trait ดังนั้นเรียกฟังก์ชัน
ที่ไม่เป็นสาธารณะของโมดูลนั้นได้ เมทอดที่มีตัวเนื้อหามีอนุประโยค `where` และ docstring ได้ด้วย
ตัวเนื้อหาถูกตรวจสอบชนิด **หนึ่งครั้ง ที่จุดประกาศ** โดยปล่อย `Self` เป็นตัวแปรชนิด
(มี bound `Self: trait เอง`) เหมือนใน Rust: ความผิดพลาดที่จะล้มเหลวกับทุก `impl` และทุก
ชนิดที่ implement แม้ในค่าเริ่มต้นที่ไม่มี `impl` ใดละ ก็ถูกจับที่นั่น การเรียกบน `self` ไปยังเมทอดของ
trait เองหรือ supertrait ผ่าน bound นี้ และ associated type ถูกกำหนดเป็น
ตัวมันเอง ดังนั้น signature ที่คืน `Item` ถูกจับคู่กับตัวเนื้อหาโดยไม่ต้องทราบชนิด
ที่เป็นรูปธรรม

**Blanket implementation**: การทำให้เป้าหมายเป็นตัวแปรชนิดจะ implement trait ในคราวเดียวสำหรับทุก
ชนิดที่ตรงตาม bound

```lisp
(deftrait Clamp (Ord)
  (clamp ((self Self) (lo Self) (hi Self)) Self
    (if (less self lo) lo (if (less hi self) hi self))))
(impl<T> Clamp T (where (Ord T)))          ; no body at all; everything is the default
```

**ไม่มีโค้ดถูกสร้างจนกว่าจะมีชนิดที่เป็นรูปธรรมใช้จริง** (หนึ่งครั้งต่อชนิด ด้วยกลไกเดียวกับ
monomorphization ธรรมดา) trait มี blanket implementation ได้อย่างมากหนึ่งตัว หากชนิดมี
`impl` ที่ชัดเจน ตัวนั้นมีลำดับความสำคัญ การตรวจสอบชนิดของตัวเนื้อหาแยกจากการสร้าง: ทำ
หนึ่งครั้งที่จุดประกาศ **โดยปล่อยเป้าหมายเป็นตัวแปรชนิด** (เหมือนใน Rust) ดังนั้นแม้
implementation ที่ไม่เคยถูกใช้ก็ถูกจับความผิดพลาดที่นั่น หากมันจะล้มเหลวกับทุกเป้าหมาย
ภายใต้ bound ที่ประกาศ การเรียกที่ bound รองรับ (`(less self other)` ภายใต้ `(where (Ord T))`
และอื่น ๆ) ผ่าน เหมือนในตัวเนื้อหาของ `defun` แบบ generic

**Docstring**: `deftrait` มี docstring ได้หนึ่งอันสำหรับทั้ง trait เป็นสตริง literal ทันทีหลัง
รายการ supertrait ก่อนรายการต่าง ๆ (`(deftrait Name () "doc" (type ...) (method ...)...)`) signature
ที่ไม่มีตัวเนื้อหามี docstring ไม่ได้: สตริงที่ตามท้ายจะเป็นค่าที่คืนของ implementation
เริ่มต้นเอง จึงแยกทั้งสองไม่ได้

trait ที่ไลบรารีมาตรฐานจัดให้: **`Iter`** (`next` / associated type `Item` พื้นฐานของ
`doiter` และฟังก์ชันของลำดับ), **`Eq`** (`equals`; `not-equals` เป็น implementation เริ่มต้น),
**`Ord`** (สืบทอด `Eq` ต้อง implement เฉพาะ `less` และ `less-equal` / `greater` /
`greater-equal` เป็น implementation เริ่มต้น), **`Error`** (`message` / `source`; `:dyn Error` สำหรับ
จัดการชนิดข้อผิดพลาดอย่างสม่ำเสมอ), **`print-object`** (การแสดงผลของแต่ละชนิด), **`Pathish`**
(ตัวกำหนด pathname: สตริงหรือ `pathname`) และลำดับชั้นของสตรีม **`Stream`** →
**`InputStream`** / **`OutputStream`** → **`CharInput`** / **`CharOutput`** → **`PeekInput`**
ชนิดใด implement trait ใดอยู่ใน [types.md](types.md) เมทอดของแต่ละ trait อยู่ใน
[Trait มาตรฐาน](functions/traits.md), [ชนิดข้อผิดพลาด](functions/option-result.md#3-ชนิดข้อผิดพลาดและ-trait-error),
[print-object](functions/printing.md#5-print-object-การแสดงผลของแต่ละชนิด) และ
[สตรีม](functions/streams-files.md) หากคุณ `impl` `Iter` ให้ชนิดคอลเลกชันของคุณเอง `doiter`
(บทที่ 5) และ `map` / `filter` / `sort` และทำนองเดียวกันใช้กับมันได้ทันที

การเรียก trait เป็นแบบ **สถิต** โดยค่าเริ่มต้น (แก้ไขโดยชนิดสถิตของตัวรับ) หากต้องการจัดการค่าที่
ชนิดจริงถูกตัดสินตอนรัน ชนิด trait object `:dyn Trait` (บทที่ 2) ให้ dynamic
dispatch ผ่าน vtable:

```lisp
(deftrait Drawable () (draw ((self Self)) string))
(defstruct circle (r i32))
(defstruct square (side i32))
(impl Drawable circle (draw ((self Self)) string "circle"))
(impl Drawable square (draw ((self Self)) string "square"))

(defun render-all ((xs Vector<:dyn Drawable>)) ()
  (doiter (d (iter xs)) (println "~a" (draw d))))   ; one call site, an answer per implementation
```

เฉพาะ trait ที่ "ทุกเมทอดมีตัวรับ `self` ไม่ใช้ `Self` ที่ใดนอกจาก
ตัวรับ และตัวเมทอดเองไม่เป็น generic หรือ variadic" เท่านั้นที่ทำให้เป็น `:dyn` ได้ (เมทอดที่สืบทอดต้องตรงตาม
เงื่อนไขเดียวกัน)

เฉพาะชนิดที่ค่ามีการแสดงผลบนฮีปเท่านั้นที่ใส่ในกล่อง `:dyn` ได้:

| ใส่ได้ | ใส่ไม่ได้ |
|---|---|
| ชนิด `defstruct` / `defenum` (รวม `Vector<T>`, `cons-cell<A,B>`, `Result<T,E>` และ struct ของไลบรารีมาตรฐาน), `HashTable<K,V>`, `Sexpr`, `int`, `ratio`, `f64`, `string`, `random-state` | จำนวนเต็มความกว้างคงที่ (`i8` ถึง `u32`), `f32`, `bool`, `char`, `symbol`, `()`, ชนิดฟังก์ชัน และ `Option<T>` ที่ไม่มีกล่อง ([การแสดงผลขณะรันของ Option](functions/option-result.md#2-การแสดงผลขณะรันของ-optiont)) |

การวางค่าของชนิดที่ใส่ไม่ได้ในที่ที่คาดหวัง `:dyn` เป็นข้อผิดพลาดของชนิด หากต้องการจัดการค่า
เหล่านั้นผ่าน `:dyn` ให้ห่อด้วย struct เช่น `(defstruct flag (v bool))`

### 3.10 module / use — เนมสเปซ

```lisp
(module path body...)      ; path is a sequence of segments such as foo or foo::bar
(in-module path)           ; from here to the end of this unit, inside path (the flat form of module)
(use path...)              ; alias functions, types and modules into the current namespace
(import path...)           ; the same as use (a CL-compatible spelling)
(shadowing-import path...) ; a use that knowingly takes a bare name already in use
```

- `module` สร้างเนมสเปซ **ชนิดไม่ใช่เนมสเปซ** (เหมือนใน Rust ชนิดมีเพียง
  ฟังก์ชันที่เกี่ยวข้องและเมทอด)
- การ `use` ชนิดทำให้ตัวสร้างและเมทอดสถิตที่เป็นสาธารณะของมันใช้ด้วยชื่อเปล่าได้ด้วย (ตัวอย่าง
  เช่น หลัง `(use option)` เรียก `some`/`none` ได้โดยไม่ต้อง `option::some`/`option::none`)
- ลำดับการแก้ไขชื่อเปล่า (ตัวระบุที่ไม่มีตัวกำกับ): ฟอร์มพิเศษ → ตัวสร้าง → ฟังก์ชัน
  อิสระ (เนมสเปซปัจจุบัน → ราก) → เมทอดของอินสแตนซ์ (แก้ไขโดยชนิดสถิตของอาร์กิวเมนต์แรก)
  ไม่ไล่ขึ้นผ่านโมดูลแม่ระหว่างกลาง
- พาธที่มีตัวกำกับ `a::b` แก้ไข `a` ตามลำดับข้างบน หากเป็นโมดูลจะเข้าไปข้างใน และหากเป็น
  ชนิด ส่วนสุดท้ายจะถูกแก้ไขเป็นรายการที่เกี่ยวข้อง
- **`use` มีผลกับฟอร์มที่อยู่หลังมัน** ไฟล์ถูกอ่านทีละฟอร์ม และการพึ่งพาถูกแก้ไข
  ก่อนตรวจสอบฟอร์มพอดี ดังนั้นการเขียน `m::f` **เหนือ** `(use m)` ให้ `unresolved path` ให้วาง
  `use` ที่ต้นไฟล์
- **`use` รับได้หลายพาธ** (`(use a::f b::g)`) `import` เป็นการสะกดที่เข้ากันได้กับ CL
  และมีพฤติกรรมเดียวกัน
- **`use` ที่ชื่อเปล่าถูกใช้ไปแล้วจะถูกรายงาน** การแก้ไขชื่อเปล่าดูการนิยามของโมดูลเอง
  ก่อน alias ดังนั้น `(use m::twice)` หลัง `(defun twice ...)` **ไม่ทำอะไร** หากตั้งใจ
  ให้เขียน `shadowing-import` (ก็ยังเอาชนะการนิยามไม่ได้ เพราะไม่มีวิธีลบ
  การนิยาม มันเอาชนะได้เฉพาะ alias ก่อนหน้า)
- **`in-module` คือรูปแบบแบนของ `(module path body...)`** การเขียน `(in-module geometry)` ทำให้
  ทุกอย่างจากตรงนั้นถึงท้ายหน่วย (ไฟล์ หรือตัวเนื้อหาของ `module` ที่ห่อหุ้ม) อยู่ภายใน
  `geometry` อยู่ **ภายใน** โมดูลของไฟล์เอง (`main::geometry` สำหรับ `main.typl`) สองตัวติดกัน
  ซ้อนกันตามลำดับ ต่างจาก `in-package` ของ CL และตั้งชื่อต่างกัน: ในระบบนี้
  ไฟล์เป็นโมดูลอยู่แล้ว จึงไม่มีอะไรให้ "เลือก" และสิ่งที่ฟอร์มทำได้มีเพียงการซ้อน

### 3.11 ไฟล์และโมดูล (โปรเจกต์หลายไฟล์)

พาธของไฟล์เทียบกับรากของซอร์สคือพาธของโมดูล:
เนื้อหาของ `<root>/geo/point.typl` ถูกห่อโดยปริยายในโมดูล `geo::point`
(ไดเรกทอรีก็เป็นหนึ่งส่วนเช่นกัน แบบ Rust / Python) `(module bar ...)` ที่ชัดเจนในไฟล์
ซ้อน **ภายใน** มัน (`geo::point::bar`) ดังนั้นพาธที่ได้มากับการประกาศที่ชัดเจนไม่ชนกัน

- **รากของซอร์ส**: วางไฟล์ manifest `typelisp.toml` ที่รากของโปรเจกต์ (ว่างก็ได้ ใส่
  บรรทัดเดียว `src = "src"` เพื่อตั้งชื่อไดเรกทอรีซอร์สได้) หาโดยไล่ขึ้นจากไดเรกทอรีของ
  ไฟล์เป้าหมาย หากไม่มี manifest ไดเรกทอรีของไฟล์จุดเข้า (ไดเรกทอรีปัจจุบันสำหรับ
  REPL) เป็นราก
- **การโหลดตามต้องการ**: เมื่อ `(use geo::point)` อ้างถึงโมดูลที่ยังไม่ได้โหลด ไฟล์ที่ตรงกัน
  (`geo/point.typl`) ถูกโหลด ตรวจสอบชนิด และลงทะเบียนโดยอัตโนมัติ `use a::b::c` ค้นหา
  prefix ที่ยาวที่สุดก่อน: `a/b/c.typl` → `a/b.typl` → `a.typl` (เพราะ `c` อาจเป็นรายการภายในโมดูล)
  การนิยามที่มองเห็นได้จากโมดูลอื่นต้องมี `pub` ([3.13 pub](#313-pub--การมองเห็น))
- **การอ้างอิงเป็นวงกลมเป็นข้อผิดพลาด**: สายถูกรายงานในรูปแบบ
  `circular module dependency: a -> b -> a`
- **การรัน**: `typl <file.typl>` รันไฟล์ (หากไม่มีอาร์กิวเมนต์ จะเป็น REPL) `use` ใน REPL แก้ไข
  ไฟล์ด้วยกฎเดียวกัน
- **ความจุ cons arena**: `typl --heap-cells N` ตั้ง **ความจุเริ่มต้น** ของ arena ของ cons cell
  (ค่าเริ่มต้น 65536; รูปแบบ `--heap-cells=N` ก็ใช้ได้ทั้งสำหรับรันไฟล์และ REPL) arena
  **เติบโตโดยการเพิ่ม** เมื่อไม่พอ ขีดจำกัดของการเติบโตคือ 256 เท่าของความจุเริ่มต้น
  และการจัดสรรเกินนั้นให้ `heap exhausted`: ความจุเริ่มต้นหมายถึง "จัดสรรเท่านี้ก่อน"
  และขีดจำกัดหมายถึง "เกินนี้ถือว่ารั่ว"

### 3.12 load — การโหลดแบบแบน

```lisp
(load "path")   ; top level only; path is a string literal
```

- **การโหลดแบบแบน** สไตล์ CL: อ่านฟอร์มของไฟล์เป้าหมาย **เข้าไปในเนมสเปซปัจจุบัน** ตามที่
  เป็น (ไม่ห่อด้วยโมดูล ต่างจาก `use`) เฉพาะระดับบนสุด (ภายในตัวเนื้อหาฟังก์ชันเป็น
  ข้อผิดพลาดของชนิด)
- `path` สัมพัทธ์กับไดเรกทอรีของไฟล์ที่โหลด (จาก REPL สัมพัทธ์กับ cwd ของโพรเซส) หาก
  ไม่มีนามสกุล จะเพิ่ม `.typl`
- `(load ...)`/`(use ...)` ในไฟล์ที่โหลดก็ถูกประมวลผลแบบเวียนเกิดด้วย
- **อ่านทีละฟอร์มและรันทันที** (เหมือน `load` ของ CL) ฟอร์ม *k* รันเสร็จก่อนที่ *k+1* ถูกอ่าน:
  แม้มีข้อผิดพลาดของไวยากรณ์หรือชนิดกลางทาง ฟอร์มก่อนหน้ามันรันไปแล้ว ไฟล์โมดูลที่โหลดด้วย `use`
  ต่างกัน: ถูกตรวจสอบเป็นหน่วยเดียว และการรันมันปล่อยให้ผู้ที่ `use` (สอดคล้องกับ `compile-file`
  ของ CL)

### 3.13 pub — การมองเห็น

```lisp
(pub defun ...)
(pub defsignature ...)
(pub defffi ...)
(pub defvar ...)
(pub defparameter ...)
(pub defconstant ...)
(pub defmacro ...)
(pub defmethod ...)
(pub defstruct ...)
(pub defenum ...)
(pub deftype ...)
```

ใส่ `pub` ได้เฉพาะสิบเอ็ดชนิดข้างบน (ไม่ใช่กับ `module`/`use`/`deftrait`/`impl`) เขียนโดยให้
คีย์เวิร์ดการนิยามอยู่หลัง `pub` ทันที ไม่ใช่ในรูป `(pub (defun ...))` ที่ห่อการนิยาม
ด้วยวงเล็บ หนึ่ง `pub` ทำให้การนิยามหนึ่งอันเป็นสาธารณะพอดี (ทำเครื่องหมายหลายการนิยามในคราวเดียวไม่ได้)

### 3.14 defmacro — การนิยามแมโคร

```lisp
(defmacro name (required... &optional opt... &rest rest-name &key key...) body...)
```

- พารามิเตอร์ทั้งหมดและค่าที่คืนเป็น `Sexpr` เสมอ จึงไม่เขียนคำอธิบายชนิด
- แมโครแบบ unhygienic สไตล์ CL (การหลีกเลี่ยงการชนกันด้วย `gensym` เป็นความรับผิดชอบของผู้เขียนแมโคร)
- รายการพารามิเตอร์เรียงตามลำดับของ CL `required &optional &rest &key` (แต่ละตัวระบุมากสุดครั้งเดียว และ
  เฉพาะตามลำดับนี้)
  - `&optional` … อาร์กิวเมนต์ทางเลือก `name` หรือ `(name default-expr)` นิพจน์ค่าเริ่มต้นถูก
    ประเมินตอนขยาย (อ้างถึงพารามิเตอร์ที่ผูกก่อนหน้าได้) และผูกเมื่อละอาร์กิวเมนต์
    (หากไม่มีค่าเริ่มต้น จะเป็นลิสต์ว่าง `()`)
  - `&rest name` … รับอาร์กิวเมนต์ตามตำแหน่งที่เหลือรวมกันเป็นลิสต์ `Sexpr` เดียว
  - `&key` … อาร์กิวเมนต์แบบคีย์เวิร์ด `name` หรือ `(name default-expr)` ผู้เรียกส่งเป็น `:name value`
    (ลำดับใดก็ได้) เมื่อละ จะเป็นนิพจน์ค่าเริ่มต้น (ลิสต์ว่าง `()` หากไม่มี) คีย์เวิร์ดที่ไม่รู้จัก
    หรือลำดับ `:key` ที่มีความยาวเป็นคี่เป็นข้อผิดพลาด
- ตัวอย่าง: `(defmacro pair (x &optional (y 1)) ...)` / `(defmacro make (&key (a 0) (b 9)) ...)`

### 3.15 macrolet / symbol-macrolet — การผูกแมโครท้องถิ่น

```lisp
(macrolet ((name (lambda-list) body...) ...) body...)   ; lexically scoped macros
(symbol-macrolet ((name expansion) ...) body...)         ; a name stands for a form
```

ทั้งสองเป็นฟอร์มพิเศษแบบ **นิพจน์** และไม่มีอะไรเหลือตอนรัน (สิ่งที่ถูกคอมไพล์คือรูปที่
ขยายแล้วของตัวเนื้อหา) รายการพารามิเตอร์เหมือน `defmacro` กฎโดยละเอียดและ
ตัวอย่างอยู่ใน
[การผูกแมโครท้องถิ่น](functions/system.md#9-การผูกแมโครท้องถิ่น-macrolet--symbol-macrolet)

## 4. การผูกค่าและเงื่อนไข

```lisp
(let ((name val) ...) body...)      ; parallel binding
(let* ((name val) ...) body...)     ; sequential binding (earlier bindings usable in later initializers)

(if cond then else)                 ; else is required (always three elements)
(when cond body...)                 ; an if without else (Unit type). defmacro
(unless cond body...)               ; the negation of when. defmacro
(cond (test1 body...) (test2 body...) ... (else body...))   ; defmacro
(case expr
  (key1 body...)
  ((key2 key3) body...)             ; a list of keys: matches if any of them does
  (else body...))                   ; expr is evaluated once. keys are compared with equal.
                                     ; keys are "literals" and are not evaluated (as in CL).
                                     ; a bare symbol a means the symbol 'a.
                                     ; writing 'a is an error (use the bare a). defmacro
(ecase expr (key body...) ...)      ; a case requiring a match. panics if nothing matches. defmacro
(ccase expr (key body...) ...)      ; CL's ccase. there are no restarts to offer, so it is the same as ecase. defmacro
(and expr...)                       ; short-circuit evaluation. true with zero arguments. defmacro
(or expr...)                        ; short-circuit evaluation. false with zero arguments. defmacro
(progn body...)                     ; runs in order and returns the last value
(unsafe body...)                    ; the same as progn, plus permission to write FFI calls
                                     ; and raw words. see 3.3 defffi
(prog1 form more...)                ; evaluates everything; the value is that of form. defmacro
(prog2 a b more...)                 ; evaluates everything; the value is that of b. defmacro
(the Type expr)                     ; a type annotation (no run-time effect)
```

### 4.1 unsafe — การรับสมมติฐานที่ตรวจสอบไม่ได้

```lisp
(unsafe body...)
```

เหมือน `progn`: ประเมินตัวเนื้อหาตามลำดับและคืนค่าสุดท้าย ไม่สร้างขอบเขตและ
ไม่ใช่ขอบเขตของฟังก์ชัน (`break` / `return-from` ผ่านตรงออกไปภายนอก) ความต่าง
คือบางสิ่งเขียนได้เฉพาะภายในมัน

ปัจจุบันมีสามอย่างที่ต้องใช้ `unsafe`: การเรียกฟังก์ชัน C ที่ประกาศด้วย
[defffi](#33-defffi--การประกาศฟังก์ชัน-c-ffi) การทำให้ word ดิบของเครื่อง (`ptr` / `c-long` / `c-ulong` /
`(ptr T)`) เป็นค่า และ [`def-c-struct` และ `c-alloc`](#def-c-struct-และตัวชี้ที่มีชนิด--การจัดสรร-struct-ของ-c)

หน่วยความจำที่จัดสรรด้วย `c-alloc` ถูกคืนเมื่อออกจาก `unsafe` ชั้นนอกสุดภายในฟังก์ชันเดียวกัน
มีเพียง `unsafe` นั้นที่ต่างจาก `progn` ตรงที่มีงานต้องทำตอนออก: การคืนหน่วยความจำ

สิ่งที่ `unsafe` รับไว้คือสมมติฐานต่อไปนี้ที่คอมไพเลอร์ตรวจสอบไม่ได้:

- **ว่าชนิดตรงกัน** ว่า signature ของ C ที่ประกาศตรงกับของจริง หากไม่ อาร์กิวเมนต์จะเข้า
  ไปในรีจิสเตอร์ผิดและค่าที่คืนถูกอ่านด้วยความกว้างผิด
- **ความปลอดภัยของหน่วยความจำ** สิ่งที่ฝั่ง C ทำกับสิ่งที่ได้รับ
- **สถานะระดับโพรเซส** ตัวแปรสภาพแวดล้อม ตัวจัดการสัญญาณ `errno` ตัวอย่างเช่น การเรียก `setenv`
  ผ่าน FFI ทำลายสมมติฐานที่ `decode-universal-time` ของ implementation นี้ใช้
  เมื่อคำนวณเวลาท้องถิ่น
- **ความปลอดภัยของเธรด**

ไม่ใช่ทางหนีจากการตรวจสอบชนิด `(unsafe (+ 1 "two"))` ไม่ผ่าน สิ่งที่อนุญาตคือการเขียน
**การดำเนินการ** บางอย่าง ไม่ใช่การเขียนเรื่องไร้สาระ

ทำงานแบบ lexical ตัวเนื้อหาของ `lambda` ที่เขียนภายใน `unsafe` สืบทอดสิทธิ์ (เหมือน
closure ภายในบล็อก `unsafe` ของ Rust) ค่านั้นอาจถูกเรียกจากภายนอก `unsafe` ภายหลัง
แต่การเขียนมันที่นั่นเองถือเป็นการยอมรับความรับผิดชอบ

### 4.2 destructuring-bind — การแยกลิสต์ตามรูปร่าง

```lisp
(destructuring-bind lambda-list form body...)
```

แยกลิสต์ที่ `form` สร้าง **ตามรูปร่างของมัน** และผูก รายการพารามิเตอร์เป็นของ `defmacro`
(required → `&optional` → `&rest`/`&body` → `&key` แต่ละตัวมีนิพจน์ค่าเริ่มต้น) ด้วยเหตุผลเดียวกับที่
CL ใช้ร่วมกันหนึ่งชุดระหว่างสองอย่าง: เป็นสองฟอร์มที่แยกสิ่งเดียวกัน

```lisp
(destructuring-bind (op a b) (quote (+ 1 2)) (format false "~a ~a ~a" op a b))  ; "+ 1 2"
(destructuring-bind (head &rest tail) xs (format false "~a | ~a" head tail))
(destructuring-bind (a &optional (b 9)) (quote (1)) b)                          ; 9
(destructuring-bind (&key (x 0) y) (quote (:y 7)) (format false "~a ~a" x y))   ; "0 7"
```

- **ตัวแปรที่ผูกทุกตัวเป็น `Option<Sexpr>`** นี่ไม่ใช่ข้อจำกัดของ implementation แต่เป็น
  ธรรมชาติของสิ่งที่ถูกผูก: ลิสต์ S-expression เป็นลิสต์เพียงชนิดเดียวในภาษานี้ จึงไม่มี
  ชนิดอื่นให้สมาชิก การถอยไปใช้ `match` ในที่ที่ต้องการสเกลาร์เหมือนกับใน
  ตัวเนื้อหาของ `defmacro`
- **รูปร่างที่ไม่ตรงกัน panic** (สอดคล้องกับข้อผิดพลาดของ CL): สมาชิกน้อยหรือมากเกินไป ลำดับ
  `&key` ที่มีความยาวเป็นคี่ หรือคีย์เวิร์ดที่ไม่รู้จัก `sexpr-car` เป็นฟังก์ชันผ่อนปรนที่คืน `()`
  สำหรับ `()` ดังนั้นหากไม่มีการตรวจสอบ ลิสต์สั้นจะถูกผูกกับลำดับว่างโดยไม่แจ้ง
- **รายการพารามิเตอร์ซ้อนไม่รองรับ** `defmacro` ก็ไม่รับ จึงมีกฎเดียว
  `(a (b c))` ไม่ผูกลิสต์ย่อยกับ `b` โดยไม่แจ้ง แต่เป็นข้อผิดพลาดที่บอกเช่นนั้น
- นิพจน์ค่าเริ่มต้นของ `&optional` / `&key` **ถูกประเมินเฉพาะเมื่อใช้** (เหมือนใน CL)
- ไม่มีสิ่งที่สอดคล้องกับ `&allow-other-keys` ของ CL (`defmacro` ก็ไม่มี)

### 4.3 match — การจับคู่รูปแบบ

```lisp
(match expr
  (pattern body...)
  ...)
```

ชนิดของรูปแบบ:
- `_` — wildcard
- ชื่อตัวแปร — รูปแบบการผูก (จับคู่เสมอ) อย่างไรก็ตาม หากชนิดของ scrutinee มี variant ชื่อ
  นั้น จะถูกแก้ไขเป็น **รูปแบบชื่อ variant เปล่าด้านล่าง**
- ชื่อ variant เปล่า — จับคู่ variant ที่ไม่รับอาร์กิวเมนต์ (`(match c (red 1) (blue 2))`) การเขียน
  variant ที่มีฟิลด์ด้วยชื่อเปล่าเป็นข้อผิดพลาด arity ดังนั้นให้เขียนในวงเล็บ เช่น `(circle r)`
- **literal แบบ immediate**: จำนวนเต็ม / `true`/`false` / อักขระ — เปรียบเทียบเป็น word
- **literal แบบค่า**: สตริง / จำนวนทศนิยม / สัญลักษณ์ (`'foo`) / จำนวนเต็ม bignum / ratio —
  เปรียบเทียบตามค่าด้วย `Eq::equals` ของชนิดนั้น ([Trait มาตรฐาน](functions/traits.md#2-eq--ord-การเปรียบเทียบ))
  สตริงเปรียบเทียบตามเนื้อหา ไม่ใช่ตามเอกลักษณ์
- `(= expr)` — ประเมินนิพจน์ใดก็ได้และเปรียบเทียบด้วย `Eq::equals` วิธีเดียวที่จะเปรียบเทียบชนิด
  ที่ไม่มีไวยากรณ์ literal (อินสแตนซ์ของ `defstruct` ตัวแปรโกลบอล ผลลัพธ์ที่คำนวณ) และ
  implementation `Eq` ที่ผู้ใช้นิยามกลายเป็นกฎการเปรียบเทียบตามที่เป็น `expr` อ้างถึงทุกอย่าง
  ที่มองเห็นได้จากตำแหน่งของกิ่ง (อาร์กิวเมนต์ การผูกภายนอก ตัวแปรโกลบอล)
- `(Ctor sub-pattern...)` — รูปแบบตัวสร้าง (`Some x` `None` `Cons a d` `Ok v` และอื่น ๆ)

การเปรียบเทียบชนิดที่ไม่ได้ implement `Eq` กับ literal แบบค่า / `(= expr)` เป็นข้อผิดพลาดของชนิด (ภาษานี้
เลือกที่จะบอกว่า "สิ่งเหล่านี้เปรียบเทียบกันไม่ได้" แทนที่จะทิ้งกิ่งที่ไม่มีวันจับคู่โดยไม่แจ้ง)

**literal แบบค่ากับ scrutinee `Sexpr`**: `Eq` ของ `sexpr` คือ `eq` (เอกลักษณ์ของ CL) ดังนั้น
immediate (`'foo` (ที่ intern) / จำนวนเต็ม / อักขระ / `true`/`false`) เขียนตามที่เป็นได้และ
จับคู่ตามเนื้อหา:

```lisp
(match s ('add 1) (42 2) (#\a 3) (_ 0))
```

literal ที่ไม่ใช่ immediate (สตริง / จำนวนทศนิยม / จำนวนเต็ม bignum / ratio) **เขียนไม่ได้**
กับ `Sexpr` `eq` ของมันเปรียบเทียบเอกลักษณ์ของออบเจ็กต์ ซึ่งจะทำให้เกิด "กิ่งที่ผ่านการตรวจสอบชนิดแต่
ไม่มีวันจับคู่" จึงเป็นข้อผิดพลาดที่ระบุรูปแบบ variant: เขียน `(str "hi")` และมันจะถูกแยก
เป็น `string` และเปรียบเทียบตามเนื้อหา `(= expr)` ขอ `equals` อย่างชัดเจน ดังนั้นข้อจำกัดนี้
ไม่ใช้กับมัน

**scrutinee ไม่จำเป็นต้องเป็น ADT** `string`/`symbol`/`i32`/`f64` และทำนองเดียวกัน จับคู่ได้
โดยตรง (ที่นั่นเป็นที่ของรูปแบบ literal สตริง) อย่างไรก็ตาม ชนิดที่ไม่มี variant ครอบคลุมด้วย
การไล่ทั้งหมดไม่ได้ ดังนั้นต้องมี `_` (หรือรูปแบบการผูกที่ทำหน้าที่ wildcard):

```lisp
(defun kind ((s string)) i32
  (match s
    ("add" 1)
    ("sub" 2)
    (_     0)))          ; a type without variants needs `_`
```

กับ scrutinee `Sexpr` นอกจากรูปแบบ variant ที่มีให้ในตัว 18 แบบข้างบนแล้ว เขียน **รูปแบบ downcast**
(ดึงอินสแตนซ์ของ ADT ที่ผู้ใช้นิยามออกมา) ได้: ไวยากรณ์สำหรับได้อินสแตนซ์ของ `defstruct`/`defenum`
(บทที่ 3) ที่ถูกแปลงโดยปริยายเป็น `Sexpr` คืนด้วย `match` เช่นใน
`(list p 42)`:

- `(TypeName sub-pattern...)` — การแยกฟิลด์โดยมี **ชื่อชนิด** นำหน้า (เฉพาะ struct:
  `defstruct` มีหนึ่ง variant เสมอ จึงเขียนด้วยชื่อชนิดแทนชื่อ variant)
  ตัวอย่างเช่น สำหรับ `(defstruct point (x f64) (y f64))` คือ `(point x y)`
- ชื่อ variant เปล่า `(VariantName sub-pattern...)` — ดึง variant ของ `defenum` ออกมา แก้ไขเป็น
  ชื่อเปล่าที่มองเห็นหลัง `(use EnumType)` (กฎการมองเห็นเดียวกับตอนเรียกตัวสร้าง)
  ตัวอย่างเช่น สำหรับ `(defenum color (red) (blue))` คือ `(red)` `(blue)` หลัง `(use color)` หากชื่อ variant
  ของหลาย enum ที่มองเห็นชนกัน จะเป็นข้อผิดพลาดความกำกวม ดังนั้นเขียนรูปแบบที่มีตัวกำกับ
  `(EnumType::VariantName ...)` ได้ด้วย (ไม่ต้อง `use`)
- `(the Type pattern)` — downcast ของทั้งชนิด (ผูกทั้งก้อน) ไม่แยก
  ฟิลด์ แต่ส่งค่าให้ `pattern` ตามที่เป็น วิธีเดียวที่จะดึง struct ที่เปลี่ยนแปลงได้ออกมาโดย
  คงเอกลักษณ์ และเป็นวิธีเดียวที่จะดึง `Vector<T>`/`HashTable<K,V>` ออกจาก `Sexpr`
  (ไม่มีรูปแบบการแยกฟิลด์) ตัวอย่างเช่น หลัง `(the point p)` `(setf p::x 9)` จะสะท้อนใน
  อินสแตนซ์เดิมในลิสต์ด้วย

**รูปแบบสำหรับ `Option<Sexpr>`**: ชนิดของข้อมูล S-expression ไม่ใช่ `Sexpr` แต่เป็น `Option<Sexpr>` และ
ลิสต์ว่างไม่ใช่ variant ของ `Sexpr` แต่เป็น `none` ของ `Option` ดังนั้นเมื่อจับคู่ `Option<Sexpr>`
เขียน 18 variant ของ `Sexpr` และ `none` **แบบแบนในรายการกิ่งเดียวกัน** ได้ (ไม่ต้องมี `match`
ชั้นนอกเพื่อลอก `Option` ออก):

```lisp
(defun tag ((s Option<Sexpr>)) i32
  (match s
    ((int _)    1)
    ((cons _ _) 2)
    ((str _)    3)
    ((none)     0)          ; the empty list
    (_          9)))
```

ความครอบคลุมถูกตรวจสอบในเอกภพแบบแบนเดียวกัน: 18 variant ของ `Sexpr` บวก `none` รวม 19
การลืม `(none)` เป็นข้อผิดพลาดเว้นแต่มี `_` เขียน `(some x)` ได้ด้วยและผูก "บางสิ่ง
ที่ไม่ว่าง"

น้ำตาลไวยากรณ์นี้ใช้กับ `Option<Sexpr>` **เท่านั้นพอดี** สำหรับ `Option<Option<Sexpr>>` จะไม่ชัดเจนว่า
`(int n)` ลอกชั้นไหน ดังนั้นให้เขียน `match` สองระดับตามปกติ

รูปแบบ downcast เดียวกันใช้ตามที่เป็นได้กับ **scrutinee ที่เป็น trait object (`:dyn Trait` บทที่ 2)**:
`match` แกะกล่องแล้วส่งให้กลไกรูปแบบ `Sexpr` ข้างบน จึงไม่มี
ไวยากรณ์เพิ่ม เซตของชนิดที่ implement เปิดอยู่ ดังนั้นไม่มีวันครอบคลุมครบ และต้องมี `_`:

```lisp
(defun area ((d :dyn Drawable)) i32
  (match d
    ((circle r) (* (* r r) 3))     ; field decomposition with the type name first
    ((the square s) (* s::side s::side))
    (_ 0)))
```

**การอนุมานชนิดข้ามกิ่ง**: ทุกกิ่งต้องมีชนิดเดียวกัน (ยกเว้นกิ่งที่ไม่จบ เช่นกับ
`panic`) ใน `match` ที่เขียนในที่ที่ไม่คาดหวังชนิด กิ่งต่าง ๆ เติมอาร์กิวเมนต์ชนิดที่ขาดของกันและกัน:
`(result::ok v)` กำหนดเฉพาะ `T` และ `(result::err e)` เฉพาะ `E` แต่รวมกันกำหนด
`Result<T,E>` อาร์กิวเมนต์ชนิดที่ไม่มีกิ่งใดกำหนดได้ภายในท้ายที่สุดเป็นข้อผิดพลาดของกิ่งนั้น
(`cannot infer type argument ...`) นอก `match` อาร์กิวเมนต์ชนิดที่กำหนดไม่ได้เป็นข้อผิดพลาด
ทันที

การตรวจสอบความครอบคลุมของ `match` ที่ใช้รูปแบบ downcast ไม่นับรูปแบบเหล่านั้นเข้ากับความครอบคลุมของ
variant ของ `Sexpr` เอง (`match` ที่ระบุเฉพาะรูปแบบ downcast ต้องปิดด้วย `_`) สำหรับ ADT แบบ generic
(`defstruct point<T> ...` และอื่น ๆ) อาร์กิวเมนต์ชนิดของรูปแบบ downcast อนุมานไม่ได้ ดังนั้น
รูปแบบการแยกฟิลด์ (`(point ...)`) และรูปแบบ variant เปล่าใช้ไม่ได้ ให้ระบุด้วย `the`
เช่น `(the point<i32> p)`

**downcast ดูการสร้างอินสแตนซ์ด้วย** อาร์กิวเมนต์ชนิดที่ชัดเจนถูกใช้จับคู่:
`(the point<i32> p)` ปล่อยผ่านเฉพาะค่า `point<i32>` และ `point<string>` ผ่านไปยัง
กิ่งถัดไป เพราะค่าจำชนิดของตัวเองรวมอาร์กิวเมนต์ชนิด (กลไกเดียวกับที่
เลือก `print-object`)

```lisp
(if-let (pattern val) then els)     ; then (with bindings) if val matches pattern, else els. defmacro
(while-let (pattern val) body...)   ; loops while val (re-evaluated each time) matches pattern. defmacro
```

## 5. การวนซ้ำ

```lisp
(loop body...)                      ; an infinite loop. leave with break/return
(while test body...)                ; loops while test is true. defmacro
(until test body...)                ; loops while test is false (the negation of while). defmacro
(dotimes (var count-expr) body...)  ; evaluates count-expr once and runs var over 0..count-1. defmacro
(do ((var init step) ...)
    (test result...)
  body...)                          ; CL-style iteration with parallel stepping. defmacro
(do* ((var init step) ...)
     (test result...)
  body...)                          ; the sequential version of do (let* binding, assigned in order). defmacro
(doiter (var coll-expr) body...)    ; iterates over a value implementing the Iter trait. defmacro

(break)                             ; leaves only the innermost loop. the value is always Unit
(return)                            ; leaves only the innermost loop
(return value)                      ; leaves the innermost loop with a value
```

ทั้ง `break`/`return` ออกจาก **เฉพาะลูปที่ห่อหุ้มในสุด** (ไม่ใช่การออกก่อนกำหนดจาก
ฟังก์ชัน และข้ามขอบเขต `lambda` ไม่ได้) ชนิดของ `loop` คือการรวมของชนิดค่าของ
`break`/`return` ที่พบภายใน (`!` หากไม่เคยออก) หากต้องการออกจากฟังก์ชัน ให้ใช้
`return-from` ด้านล่าง

### 5.1 `block` / `return-from` — ทางออกที่มีชื่อ

```lisp
(block name body...)                ; a named exit target. the value is the last form,
                                    ; or the value passed by return-from
(return-from name)                  ; leaves that block with Unit
(return-from name value)            ; leaves with a value
```

**แต่ละฟังก์ชันของ `defun` / `defmethod` / `labels` สร้าง block ด้วยชื่อของตัวเองโดยปริยาย**
(เหมือนใน CL) ดังนั้น `(return-from f v)` คือการออกก่อนกำหนดจากฟังก์ชัน:

```lisp
(defun first-even ((a i32) (b i32)) i32
  (if (= (mod a 2) 0) (return-from first-even a) ())
  (if (= (mod b 2) 0) (return-from first-even b) ())
  -1)
```

`block` เป็นทางออกแบบ **lexical** และชื่อถูก **แก้ไขที่ที่เขียน**: ตัวตรวจสอบเชื่อม
`return-from` กับ `block` ที่ห่อหุ้มและรวมชนิดของค่าเข้ากับชนิดทางออกของ block ดังนั้น:

- `return-from` ที่ไม่มี `block` ตรงกันเป็น **ข้อผิดพลาดของชนิด** (ไม่ใช่ข้อผิดพลาดตอนรัน)
- ค่าที่ชนิดไม่เข้ากับทางออกอื่นหรือชนิดของตัวเนื้อหาเป็น **ข้อผิดพลาดของชนิด** (กฎเดียวกัน
  กับกิ่งของ `match`)
- หาก block ชื่อเดียวกันซ้อนกัน **ตัวใน ชนะ** (กฎการบังของ CL)
- **ข้ามขอบเขตฟังก์ชันไม่ได้** จากภายใน `lambda` คุณออกไปยัง `block` ภายนอกไม่ได้
  (`lambda` ไม่สร้าง block: block โดยปริยายของ CL ต้องมี *ชื่อ* และฟังก์ชันนิรนามไม่มี)
  สิ่งที่ต้องข้ามคือ `catch`/`throw` (บทที่ 8 ซึ่งเป็น **dynamic**)

เหมือน `break`/`return` (บทที่ 5) เป็นทางออกแบบ **สถิต** ดังนั้นในโค้ดที่คอมไพล์แล้วเป็นการแตกกิ่งไปยัง basic
block ที่กำหนดตอนคอมไพล์ หากมี `unwind-protect` คั่นกลาง `cleanup` ของมันจะรัน (บทที่ 8)

หากคุณไม่เคยเขียน `return-from` block โดยปริยายไม่มีค่าใช้จ่าย

### 5.2 `loop` แบบขยาย (LOOP ของ CL)

**หากสมาชิกตัวแรกของ `loop` เป็นคีย์เวิร์ด** จะถูกอ่านเป็นลำดับของอนุประโยค มิฉะนั้นยังคงเป็น
ลูปธรรมดาข้างบน และความหมายของ `loop` ที่มีอยู่ไม่เปลี่ยน (เหมือนกฎลูปธรรมดาของ CL เอง)

CL เขียนคำของอนุประโยคเป็นสัญลักษณ์เปล่า (`(loop for i from 1 to 3 collect i)`) แต่ที่นี่ **ทั้งหมด
เป็นคีย์เวิร์ด**: `for` เปล่า ๆ จะเป็นเพียงการอ้างอิงตัวแปร และการเป็นคีย์เวิร์ดยังเป็นสิ่งที่แยกมัน
จากลูปธรรมดา ข้อยกเว้นคือ `=` ซึ่งคั่นตัวแปรกับค่า: ตำแหน่งของมัน
ไม่กำกวม จึงอ่านได้ทั้งแบบเปล่าหรือเป็นคีย์เวิร์ด (`:=`)

```lisp
(loop :for i :from 1 :to 3 :collect i)              ; #(1 2 3)
(loop :for x :in (iter v) :when (evenp x) :sum x)
(loop :repeat 4 :for x = 1 :then (* x 2) :collect x) ; #(1 2 4 8)
(loop :for i :from 1 :to 4 :sum i :into s :finally (return (* s 2))) ; 20
```

**อนุประโยคตัวแปร** (เขียนก่อนอนุประโยคตัวเนื้อหา นี่คือกฎของ CL: เขียนหลัง อาจอ่านเป็น
"วนซ้ำเฉพาะจากตรงนั้นไป" จึงเป็นข้อผิดพลาด):

| อนุประโยค | ความหมาย |
|---|---|
| `:with v = e` | ผูกหนึ่งครั้ง อ่านตัวแปรของอนุประโยคก่อนหน้าได้ |
| `:for v :in s` / `:for v :across s` | สมาชิกของ `Iter` ตามลำดับ ภาษานี้ไม่มีการแยกลิสต์/เวกเตอร์ของ CL ดังนั้นสองสิ่งนี้เป็นการสะกดสองแบบของอนุประโยคเดียวกัน |
| `:for v :on s` | **ส่วนต่อท้าย** ที่ต่อเนื่องกัน CL ส่งหาง cons ที่ใช้ร่วมกัน แต่ `Iter` ไม่มีหางให้ใช้ร่วม จึงแต่ละตัวเป็น `Vector` ใหม่ |
| `:for v :from a [:to b \| :below b \| :downto b \| :above b] [:by s]` | การนับ `:downfrom`/`:upfrom` ก็ใช้ได้ |
| `:for v = e [:then f]` | เริ่มด้วย `e` และตั้งแต่ครั้งที่สองใช้ `f` (หากไม่มี `:then` ใช้ `e` ทุกครั้ง) |
| `:repeat n` | วนซ้ำตามจำนวนครั้งนั้น |

เมื่อมีหลาย `:for` พวกมันก้าวหน้า **พร้อมกัน** และลูปจบทันทีที่ตัวใดตัวหนึ่งหมด

**อนุประโยคตัวเนื้อหา** (รันทุกครั้ง ตามลำดับที่เขียน):

| อนุประโยค | ความหมาย |
|---|---|
| `:do form...` | เพื่อผลข้างเคียง |
| `:collect e [:into v]` | รวบรวมเป็น `Vector<T>` |
| `:append e [:into v]` | ต่อเนื้อหาของ `Iter` |
| `:sum e` / `:count e` | ผลรวม / จำนวนครั้งที่เป็นจริง |
| `:maximize e` / `:minimize e` | ค่ามากสุด / น้อยสุด **`Option<T>`** (เหมือนที่ CL คืน nil สำหรับลำดับว่าง ชนิด `Ord` ใด ๆ ไม่มีสมาชิกที่น้อยที่สุด) |
| `:always e` / `:never e` | `true` หากทั้งหมดเป็นจริง; `false` ทันทีเมื่อมีตัวหนึ่งล้มเหลว |
| `:thereis e` | `e` เป็น **`Option<T>`** คืน `some` แรก หรือ `none` หากไม่มี (นี่คือสิ่งที่สอดคล้องกับ "ค่าที่ไม่ใช่ nil ตัวแรก" ของ CL ในการทดสอบ `bool` ให้ใช้ `:always`/`:never`) |
| `:while e` / `:until e` | **จบตามปกติ** ที่นี่ (`:finally` รัน และสิ่งที่รวบรวมไว้เป็นคำตอบ) |
| `:when e clause` / `:unless e clause` / `:if e clause [:else clause]` | ทำให้หนึ่งอนุประโยคมีเงื่อนไข |
| `:return e` | ออกทันทีด้วยค่านั้น (`:finally` ไม่รัน เหมือนใน CL) |
| `:initially form...` / `:finally form...` | ก่อนลูป / เมื่อจบตามปกติ |

**`:named name`** (ก่อนอนุประโยคอื่นใด ครั้งเดียวเท่านั้น) ห่อทั้งลูปด้วย `(block name …)`
`(return-from name e)` ออกได้ทันทีแม้จากภายในลูปซ้อน และเหมือน `:return` `:finally`
ไม่รัน หากไม่มีชื่อ จะไม่สร้าง block: `loop` ที่ไม่มีชื่อของ CL สร้าง `block nil` แต่
ที่นี่ไม่มี `nil` และ `break`/`return` (บทที่ 5) ให้ "ออกจากลูปในสุด" อยู่แล้ว

```lisp
(loop :named outer :for i :from 1 :to 3
  :do (loop :for j :from 1 :to 3 :do (if (= (* i j) 4) (return-from outer (* 100 i)) ()))
  :finally (return 0))                                  ; 200
```

การละ `:finally (return 0)` เป็น **ข้อผิดพลาดของชนิด** เป็นเพียงกฎของ `block` ที่ทำงาน (5.1): ชนิดของทางออก
`int` ไม่เข้ากับ `()` ที่ลูปออกเมื่อหมด

**ค่าของลูป** คือผลสะสมของอนุประโยคที่สะสมหากมี (ตัวแรก หากมีหลายตัว) `true` สำหรับ `:always`/`:never`, `none` สำหรับ `:thereis` และ `()` หากไม่มี หาก
สิ่งสุดท้ายใน `:finally` คือ `(return e)` นั่นคือค่า: สำนวน `finally (return …)` ของ CL วิธีเดียว
ที่ลูปซึ่งไม่สะสมจะระบุคำตอบของตัวเองได้

**ความแตกต่างจาก CL / สิ่งที่ไม่รวม**:

- **คำของอนุประโยคเป็นคีย์เวิร์ด** (ข้างบน)
- `:maximize`/`:minimize`/`:thereis` คืน `Option<T>` (ไม่มี nil)
- **การเขียนเฉพาะ `:return` โดยไม่มีทั้งการสะสมและ `:finally` เป็นข้อผิดพลาด** CL คืน nil เมื่อ
  หมด แต่ที่นี่ไม่มี ดังนั้นลูปต้องบอกว่าค่าของมันคืออะไรเมื่อหมด
- การเชื่อมอนุประโยคขนานด้วย `:and`, `:being`/การวนซ้ำเฉพาะบนตารางแฮช, `:it` และ `:nconc`
  ไม่รวมอยู่
- ชนิดสมาชิกของ `:collect` มาจากชนิดของนิพจน์ที่สะสม การพยายามรวบรวมชนิดที่
  **เขียนเป็นชื่อชนิดไม่ได้** เช่นชนิดฟังก์ชัน เป็นข้อผิดพลาดที่บอกเช่นนั้น

## 7. ฟอร์มพิเศษอื่น ๆ

```lisp
(setq var value ...)                ; CL's variable assignment. just a sequence of (setf var value). defmacro
(psetq var value ...)               ; parallel assignment. evaluates all values first, then assigns. defmacro
(psetf place value ...)             ; psetq generalized to places (the same expansion). defmacro
(setf place value)                  ; assignment to a place. a place is a variable name / var::field /
                                     ; a call of the form (accessor recv key...). valid if the
                                     ; static type of recv has an instance method named
                                     ; set-{accessor} (for the get of Vector<T> and HashTable<K,V>,
                                     ; set corresponds as an exception; otherwise set-accessor-name).
                                     ; the value is the value assigned (as in CL). so
                                     ; in (if c (setf x 1) ()), then and else do not have matching types
(incf place)  (incf place delta)    ; place += delta (delta=1 if omitted). the result is as with setf
(decf place)  (decf place delta)    ; place -= delta (delta=1 if omitted)
(rotatef place1 place2 ... placeN)  ; rotates N places (new place1=old place2, ...,
                                     ; new placeN=old place1). each place's subforms evaluated once
(shiftf place1 ... placeN newvalue) ; shifts the values of place2..N left and puts newvalue in placeN.
                                     ; the return value is the old value of place1
(list e1 e2 ... en)                 ; expands to (cons e1 (cons e2 (... ()))). () with zero arguments.
                                     ; each element is converted to Sexpr implicitly (like CL's cons, it
                                     ; can hold any value). scalars (int/i32/f64/ratio/char/bool/string/
                                     ; symbol) are wrapped in the matching Sexpr variant, and defstruct/
                                     ; defenum/Vector<T>/HashTable<K,V> and the like go in as they are
                                     ; (at no conversion cost). the same for &rest/format arguments.
(source-file)                       ; the name of the file this form was read from (string). fixed as a
                                     ; constant at check time. corresponds to CL's *load-pathname*, but is
                                     ; not a variable: module bodies run after checking, so "currently
                                     ; loading" cannot be relied on, while at check time it is always known.
                                     ; for sources that are not files, the reader's name for them (<stdin>/<input>)
(quote datum)                       ; the same as 'datum. returns it as Sexpr data without evaluating
(quasiquote template)               ; the same as `template. embeds expressions in the template with ,/,@
(documentation name)                ; returns the docstring of name (a bare name or Type::method) as Option<string>
(panic message)                     ; message: string. ends abnormally with an unrecoverable error. type !
(unreachable)                       ; expands to (panic "unreachable"). defmacro
(todo)                              ; expands to (panic "todo"). defmacro
(as Type expr)                      ; numeric/character type conversion. conversions that can fail panic on failure
(try-as Type expr)                  ; like as, but returns the result as Option<Type> (None on failure)
(print control args...)             ; expands the format and writes to standard output (no newline)
(println control args...)           ; the same (with a newline at the end)
(format dest control args...)       ; CL's format. returns the expanded string
(pprint x)                          ; pretty-prints. writes a newline first, as in CL
(pprint-fill x)                     ; fill layout
(pprint-linear x)                   ; all on one line or one element per line
(pprint-tabular x [colinc])         ; tabular layout (16 columns by default)
(pprint-logical-block (obj :prefix p :suffix s) body...)  ; build a logical block yourself
```

ตระกูล `print`/`println`/`format`/`pprint` เป็นฟอร์มพิเศษ ดังนั้นอาร์กิวเมนต์ variadic ของมัน (ออบเจ็กต์
เดียวสำหรับตระกูล `pprint`) ถูกห่อเป็น `Sexpr` ด้วยชนิดของตัวเองก่อนส่ง: นี่คือ
เหตุผลที่ `(println "~a" my-struct)` ใช้ได้เลย รายละเอียดของคำสั่งรูปแบบและ pretty printer อยู่ใน
[คำสั่งรูปแบบ](functions/format.md) และ[การพิมพ์](functions/printing.md#4-pretty-printer)

`as`/`try-as` จัดการเฉพาะแค็ตตาล็อกของตัวเลขและอักขระ (ระหว่าง `int` ชนิดจำนวนเต็มความกว้างคงที่
`f32`/`f64`/`ratio`/`char`) ชนิดเดียวกันไม่ใช่การแปลง **การแปลงระหว่างความกว้างจำนวนเต็ม
(รวม `int`) และระหว่าง `f32`↔`f64` เป็นการแปลงจริง**: `as` ตัดทอน / ปัด และ `try-as`
ตอบว่าพอดีกับความกว้าง (ความแม่นยำ) นั้นหรือไม่ `(as int x)` คือการขยายที่ถูกต้องแม่นยำจากความกว้างคงที่
และ `(as i32 n)` คือการตัดทอนจาก `int` จำนวนเต็ม → `char` ล้มเหลวได้เมื่อเกินช่วง ดังนั้น `as` panic และ
`try-as` ให้ `None` ทุกอย่างอื่น (การขยาย และการตัดทอนของ `float->int`/`ratio->int`) สำเร็จเสมอ
`float->int`/`ratio->int`/`char->int` ลงที่ `int` และหากขอความกว้างที่แคบกว่า
จะเรียก `int->W` ต่อจากนั้น นี่เป็นน้ำตาลไวยากรณ์ที่ขยายเป็นเมทอดแปลงที่สอดคล้องกัน
(`int->char`/`int->int`/`int->W` และอื่น ๆ ใน[ตัวเลข](functions/numbers.md))

`documentation` เหมือน `quote`/`compile` เป็นฟอร์มพิเศษที่อ่าน `name` โดยไม่ประเมินค่า เป็น
สัญลักษณ์เปล่าที่ไม่ถูกประเมินค่า / พาธ `::` ต่างจาก `(documentation 'name 'function)` ของ CL ตรงที่ไม่รับอาร์กิวเมนต์
ชนิด: มันแก้ไข `name` ตามลำดับ ตัวแปร → ฟังก์ชัน → ชนิด → trait → แมโคร (ลำดับความสำคัญเดียวกัน
กับตอนที่ตัวระบุเปล่าถูกประเมินเป็นนิพจน์) และคืน docstring ของการนิยามที่พบ
(`(documentation Type::method)` สำหรับเมทอด) การแก้ไขล้มเหลว (ไม่มีการนิยามชื่อนั้น) เป็น
ข้อผิดพลาดตอนตรวจสอบ การนิยามที่มีอยู่แต่ไม่มี docstring ให้ `Option::none` ทุกอย่าง
ถูกตัดสินเป็นค่าคงที่ตอนตรวจสอบ: ไม่มีการค้นหาตอนรัน ชื่ออิสระที่มี module กำกับ (`mod::name`
ยกเว้น `Type::method`) ไม่รองรับ

## 8. การออกจากการทำงานแบบไม่เป็นเส้นตรง (catch / throw / unwind-protect)

```lisp
(catch 'tag body)                   ; runs body. if (throw 'tag v) happens anywhere
                                    ; body reaches, that v becomes the value
(throw 'tag value)                  ; exits to the nearest dynamically enclosing (catch 'tag ...)
(unwind-protect protected cleanup)  ; runs cleanup however protected is left
```

ต่างจาก `break`/`return` (บทที่ 5) นี่เป็นทางออกแบบ **dynamic**: `throw` ไม่มองหา
`catch` รอบตัวเองแบบ lexical และไปถึง `catch` แท็กเดียวกันข้ามการเรียกฟังก์ชันกี่ชั้นก็ได้

```lisp
(defun find-first ((xs Option<Sexpr>)) int
  (catch 'found
    (progn
      (dolist (x xs)
        (match x ((int n) (if (> n 10) (throw 'found n) ())) (_ ())))
      -1)))                         ; if not found, the value at the end as usual
```

- **แท็กเป็นสัญลักษณ์ literal เท่านั้น** (`'done`) ต่างจาก CL ตรงที่ไม่ถูกประเมินค่า
- **แท็กพาชนิด** ชนิดถูกตัดสินเมื่อใช้ `'tag` ครั้งแรก และ `throw`/`catch` ของสัญลักษณ์เดียวกันทุก
  ครั้งต่อมาถูกตรวจสอบกับมัน การใช้กับชนิดอื่นเป็นข้อผิดพลาดของชนิด
- ชนิดของ `throw` คือ `!` (ไม่จบ) ชนิดของ `(catch 'tag expr)` คือการรวมของชนิดของ
  `expr` และชนิดของแท็ก
- ค่าของ `unwind-protect` คือค่าของ `protected` ค่าของ `cleanup` ถูกทิ้ง
  `cleanup` รันไม่ว่า `protected` จะถูกออกด้วยวิธีใด: นอกจากจบตามปกติ `throw` และ `panic` แล้ว
  ยังรันเมื่อออกด้วย `break`/`return`/`return-from` การออกจากการทำงานแบบไม่เป็นเส้นตรงโดย `cleanup` เอง
  ชนะทางออกที่กำลังดำเนินอยู่
- `unwind-protect` ที่ซ้อนกันรันจากข้างในออกมา `break` ที่ออกจากลูป **ภายใน** `protected` ไม่ได้
  ออกจาก `protected` ดังนั้น `cleanup` ของมันไม่รัน

condition ของ CL (`define-condition`/`handler-bind`/`invoke-restart`) ไม่ถูกนำมาใช้ มันไม่เข้ากับ
ระบบชนิดแบบสถิต ดังนั้นความล้มเหลวที่กู้คืนได้แสดงด้วย `Result` (บทที่ 9)

## 9. นโยบายการจัดการข้อผิดพลาด

- ความล้มเหลวที่กู้คืนได้: `Result<T,E>` + `match` ความล้มเหลวที่กู้คืนไม่ได้ (บั๊ก ค่าคงที่ที่ถูกทำลาย):
  `panic`
- ไม่มีไวยากรณ์ที่สอดคล้องกับ `?`/try การแตกกิ่งเขียนอย่างชัดเจนด้วย `match`
- ชื่อฟังก์ชันและฟอร์มพิเศษไม่ใช้ `!` (การดำเนินการแบบทำลาย) หรือ `?` (predicate) เป็น
  ส่วนท้าย predicate ตั้งชื่อด้วยส่วนท้าย `-p`/`p` (`zerop`, `consp` และอื่น ๆ) หรือส่วนนำหน้า `is-`
  (`is-some`, `is-ok` และอื่น ๆ)

## 10. การคอมไพล์

```lisp
(compile name)                      ; JIT-compiles an already defined defun/method into native code
(compile-file src-path out-path)    ; AOT-compiles a source file into a native executable (skips the final `(main)`)
(dump path)                         ; writes the current environment (type information + compiled bodies) to one file
(disassemble name)                  ; prints what that definition becomes (host machine code by default, LLVM IR with true as the second argument)
```

`compile` เป็นฟอร์มพิเศษ `name` ไม่ถูกประเมินค่าและถูกอ่านเป็นสัญลักษณ์เปล่าที่ไม่ถูกประเมินค่า / พาธ `::`
(สตริงเป็นข้อผิดพลาดของชนิด) ฟังก์ชัน generic เป็นเป้าหมายไม่ได้: มีการสร้างสำเนาสำหรับแต่ละชนิดในแต่ละ
จุดใช้งาน จึงไม่มีตัวเนื้อหาที่คอมไพล์แล้วเพียงตัวเดียว **ชื่อที่แก้ไขไม่ได้เป็นข้อผิดพลาด
ตอนตรวจสอบ** และไม่ถูกส่งต่อไปถึงตอนรัน (มีข้อความแยกสำหรับ: มีชนิดแต่ไม่มีเมทอดนั้น /
ไม่มีทั้งชนิดและฟังก์ชัน / ชื่อเปล่าที่ไม่ได้นิยาม) การมองเห็นในที่นี้ถูกปฏิบัติเหมือนการอ้างอิงอื่น: "มีอยู่แต่มองไม่เห็นจากที่นี่" ล้มเหลวตอนตรวจสอบ เหมือน
"แก้ไขไม่ได้"

ผู้ถูกเรียกก็ถูกคอมไพล์แบบถ่ายทอด ดังนั้น **ฟังก์ชันที่ (แม้ทางอ้อม) เรียกสิ่งที่คอมไพล์ไม่ได้
คอมไพล์ไม่ได้** โพรเซสไม่ล่ม แต่ปฏิเสธด้วยข้อผิดพลาดที่บอกเช่นนั้น
ฟังก์ชันที่มีให้ในตัวทุกตัวคอมไพล์ได้ ดังนั้นฟังก์ชันที่ถูกปฏิเสธด้วยวิธีนี้มีเพียงตัวที่เรียก
การดำเนินการที่ใช้ได้เฉพาะในอินเทอร์พรีเตอร์ต่อไปนี้:

```lisp
(defun g () int 1)
(defun f () () (progn (trace g) ()))
(compile f)
; => trace: `(trace ...)` is an interpreter-only action and cannot itself be compiled
```

ตัวที่ใช้ได้เฉพาะในอินเทอร์พรีเตอร์คือ `compile`/`compile-file`/`dump` และ `trace`/`untrace`/`step`/`disassemble`
([เครื่องมือของการ implement](functions/system.md#5-เครื่องมือของการ-implement-clhs-252)) สิ่งเหล่านี้ไม่ใช่สิ่งที่
คอมไพล์ไม่ได้ แต่เป็นการดำเนินการของฝั่งที่คอมไพล์ (สิ่งที่ `dump` เขียนออกมาคือสภาพแวดล้อมของ
อินเทอร์พรีเตอร์เอง ซึ่งไฟล์ปฏิบัติการ AOT ไม่มี สิ่งที่ `trace` เฝ้าดูและที่ที่
`step` หยุดคือเส้นทางการเรียกของอินเทอร์พรีเตอร์ที่กำลังรัน และ `disassemble` ใช้คอมไพเลอร์เอง)
`room`/`dribble`/`ed` ไม่อยู่ในกลุ่มนี้และคอมไพล์ได้ตามปกติ

สิ่งที่ **คอมไพล์ได้**: I/O ของสตรีมและไฟล์, `random`, `gensym`, `symbol->string`/`string->symbol`,
`parse-int`/`parse-float`, `get-universal-time`/`get-internal-real-time`, `exit`, ฟังก์ชัน
อดิศัย การดำเนินการระดับบิต `catch`/`throw`/`unwind-protect` ทั้งสี่ตัวของ `eq`/`eql`/`equal`/`equalp`
(ซึ่งทำให้ `case` คอมไพล์ได้สำหรับทุกชนิด) ตระกูลการพิมพ์ทั้งหมดรวม `print`/`println`/
`format`/`pprint` และ `pprint-logical-block`, `read` และ `eval` ไลบรารีมาตรฐานมาพร้อมกับ
ที่คอมไพล์แล้ว

ไฟล์ปฏิบัติการ AOT มีเฉพาะความสามารถที่โปรแกรมใช้ โปรแกรมที่ไม่พิมพ์ไม่ได้เอนจินจัดรูปแบบ
โปรแกรมที่ไม่เรียก `read` ไม่ได้ตัวอ่าน และโปรแกรมที่ไม่เรียก `eval` ไม่ได้
ตัวตรวจสอบและอินเทอร์พรีเตอร์

จากบรรทัดคำสั่ง `typl -c src-path [-o out-path]` (`-c` เขียนเป็น `--compile` ได้ด้วย) ทำเหมือน
`compile-file` หากไม่มี `-o` ผลลัพธ์คือ `src-path` ที่ตัดนามสกุล `.typl` ออก โดย
ค่าเริ่มต้น ไลบรารีสถิต `libtypelisp_front.a` ที่ลิงก์เข้ากับไฟล์ปฏิบัติการ สำหรับ `typl` ที่บิลด์แบบ release
คืออันที่ `typl` พกอยู่ภายในตัว เขียนออกไปตอนลิงก์ครั้งแรกที่
`$TYPELISP_HOME/lib/<build ID>/` (หรือ `~/.typelisp/lib/<build ID>/` หากไม่มี `TYPELISP_HOME`) และใช้จาก
ที่นั่น สำหรับ `typl` ที่บิลด์แบบ debug คืออันที่ `typl` ถูกบิลด์ `typl --remove-lib` ลบสิ่งที่ `typl` นั้น
เขียนออกไป เมื่อมี `--others` จะลบของ build ID อื่น เมื่อมี `--all` จะลบของทุก build ID
เมื่อใช้ `typl --lib-dir DIR` จะใช้อันใน `DIR` (ทั้งสำหรับ `-c` และ `compile-file`) และหากไม่มี
อยู่ที่นั่น จะเป็นข้อผิดพลาดตอนเริ่มต้น

### 10.1 Dump

```lisp
(dump "session.typld")     ; write one out
```
```sh
typl --image session.typld prog.typl   # start from it
typl --image session.typld             # the REPL too
```

dump เก็บข้อมูลชนิดและตัวเนื้อหาที่คอมไพล์แล้วไว้ในไฟล์เดียว สิ่งที่ `(dump path)` เขียนคือสิ่งที่
เซสชันปัจจุบันโหลด (ไลบรารีมาตรฐาน หรือ dump ที่ส่งด้วย `--image`) บวก **สิ่งที่เซสชัน
นิยามเอง** ดังนั้นผลลัพธ์ครบในตัวเอง และ `typl --image` เปิดสภาพแวดล้อมเดียวกันขึ้นมา
สิ่งที่เซสชัน `(compile f)` ไว้ถูกเขียนในรูปที่คอมไพล์แล้ว

สิ่งที่ถูกบันทึกคือ **การนิยาม ไม่ใช่ประวัติ**:

- นิพจน์ระดับบนสุดของเซสชัน (`(println ...)` และอื่น ๆ) ไม่รวมอยู่ จะมีปัญหาหาก
  การโหลดรันมันซ้ำ
- ตัวแปรโกลบอลกลับมาพร้อม **ค่าที่ได้จากการรันตัวกำหนดค่าเริ่มต้นอีกครั้ง** ไม่ใช่ค่าตอน
  dump นี่เป็นความต่างโดยเจตนาจาก `save-lisp-and-die` ของ SBCL (ที่เขียนฮีปออกไปตามที่
  เป็น) และการเลือกนี้ทำให้ปัญหาทั้งตระกูลหายไป: "ค่าที่บันทึกไม่ได้" เช่น
  สตรีมที่เปิดอยู่ ตัวชี้ฟังก์ชันของ closure และหน่วยความจำภายนอก
- ต่างจาก `save-lisp-and-die` **โพรเซสไม่ตาย** เพราะการเขียนไม่ทำให้ image เสียหาย

dump บันทึกเวอร์ชันของไลบรารีมาตรฐานและคอมไพเลอร์ของ implementation ที่เขียนมัน
การโหลดด้วย `typl` คนละเวอร์ชันเป็นข้อผิดพลาด ไม่เคยยอมรับโดยไม่แจ้ง

### 10.2 `eval` ในไฟล์ปฏิบัติการ AOT

`eval` ตรวจสอบชนิดกับ "สภาพแวดล้อมโกลบอลปัจจุบัน" แล้วจึงประเมินค่า
([การแยกวิเคราะห์และการประเมินค่า](functions/system.md#6-การแยกวิเคราะห์และการประเมินค่า)) สภาพแวดล้อมนั้น (ตารางของ
signature ชนิด และแมโครที่ตัวตรวจสอบค้นหา และตัวเนื้อหาที่อินเทอร์พรีเตอร์รันได้) **ไม่ได้อยู่ใน
โค้ดเครื่อง** ฟังก์ชันที่คอมไพล์แล้วเป็นเพียงสัญลักษณ์ที่วางไว้ที่ที่อยู่ มันไม่มีทั้งชนิดของ
อาร์กิวเมนต์และตารางสำหรับค้นหาตัวเนื้อหาด้วยชื่อ

ดังนั้น เฉพาะโปรแกรมที่เรียก `eval` เท่านั้น `compile-file` **สร้างสภาพแวดล้อมนั้นตอนคอมไพล์
และเขียนลงในไฟล์ปฏิบัติการ** รูปแบบเดียวกับ dump ซึ่งมีส่วนของไลบรารีมาตรฐาน
และส่วนของโปรแกรมเอง สิ่งเดียวที่เกิดตอนเริ่มต้นคือการกู้คืนมัน: ไม่อ่านซอร์สซ้ำ และ
ไม่ตรวจสอบชนิดซ้ำ โปรแกรมที่ไม่เรียก `eval` ไม่ได้อะไรเพิ่ม

ผลที่ตามมา:

- **การเริ่มต้นใช้เวลานานขึ้นและไฟล์ปฏิบัติการใหญ่ขึ้น** เพราะโค้ดของตัวตรวจสอบและ
  อินเทอร์พรีเตอร์และ snapshot ของสภาพแวดล้อมเข้าไปอยู่ด้วย ฮีปก็ถูกทำให้ใหญ่ขึ้นเล็กน้อย
- **ฟอร์มที่ส่งให้ eval ถูกอินเทอร์พรีต** แม้ฟอร์มที่ส่งให้ eval เรียกฟังก์ชันของโปรแกรมเอง
  สิ่งที่รันคือตัวเนื้อหาที่อินเทอร์พรีตได้ซึ่ง snapshot เก็บไว้ ผลลัพธ์เหมือนกัน มีเพียง
  ความเร็วที่ต่างกัน

ที่เก็บของตัวแปรโกลบอล **ใช้ร่วม** กับโค้ดที่คอมไพล์แล้ว (ช่องเดียวกัน) ตัวกำหนดค่าเริ่มต้นของ `defvar`
รันหนึ่งครั้งโดยการเริ่มต้นที่คอมไพล์แล้ว และการกู้คืนข้ามมัน ดังนั้นตัวกำหนดค่าเริ่มต้นที่มีผลข้างเคียง
ไม่รันสองครั้ง

`compile-file` อ่านไลบรารีมาตรฐานด้วย (และฝังตัวเนื้อหาของมันลงในไฟล์ปฏิบัติการ) ดังนั้นฟังก์ชันของ
ไลบรารีมาตรฐานอย่าง `abs`/`gcd` และ `(impl print-object ...)` รวมถึง
`(defmethod print-object ...)` ใช้กับ AOT ได้

`compile-file` รับ `use` ด้วย (และ `import`/`shadowing-import`) `(use m)` ของไฟล์จุดเข้าค้นหาไฟล์
ด้วยกฎเดียวกับ `typl file.typl` และไฟล์ที่พึ่งพาที่พบก็ถูกคอมไพล์และลิงก์เข้ากับ
ไฟล์ปฏิบัติการด้วย: เลย์เอาต์ที่ `main.typl` อ่าน `http.typl` ผ่าน `(use http)` คอมไพล์ AOT ได้
ตามที่เป็น การนิยามของไฟล์จุดเข้าเองก็เข้าไปในโมดูลที่ตั้งชื่อตามไฟล์ เหมือนกับ
`typl file.typl` (`point` ใน `p.typl` คือ `p::point`) ดังนั้นการแสดงผลของค่า
(`#<p::point x: 1 y: 2>`) เหมือนกันไม่ว่ารันด้วยวิธีใด

## 11. ตัวอ่านแมโคร (readtable)

สิ่งที่ตัวอ่าน **ทำเมื่อพบอักขระหนึ่ง ๆ** แทนที่ได้จากโปรแกรม (CLHS 23.1)

```lisp
(set-macro-character c f)             ; f reads the character c
(get-macro-character c)               ; Option<f>
(set-dispatch-macro-character d s f)  ; f reads the two-character sequence d s
(get-dispatch-macro-character d s)    ; Option<f>
```

ชนิดของ `f` คือ `(fn (string-input-stream char) Option<Sexpr>)` อาร์กิวเมนต์แรกคือ **สตรีมบน
ข้อความที่ยังไม่ได้อ่าน** และอาร์กิวเมนต์ที่สองคือ **อักขระที่เป็นตัวกระตุ้น** (อักขระตัวที่สองสำหรับ
dispatch) ค่าที่คืนกลายเป็นข้อมูลที่อ่านได้ ณ จุดนั้น สตรีมเป็นชนิดที่เป็นรูปธรรมแทนที่จะเป็น
`:dyn PeekInput` เพราะตัวอ่านส่งชนิดนี้ชนิดเดียวเสมอ: `read-sexpr` / `read-char` / `peek-char` /
`unread-char` / `read-delimited-list` ล้วนรับ `(where (PeekInput S))` ดังนั้นทั้งหมดใช้กับชนิด
ที่เป็นรูปธรรมได้ตามที่เป็น

```lisp
(set-macro-character #\!
  (lambda ((s string-input-stream) (c char)) Option<Sexpr>
    (match (read-sexpr s)
      ((ok o) (match o
                ((datum d) (sexpr-cons (quote not) (sexpr-cons d (quote ()))))
                ((eof) (quote ()))))
      ((err e) (quote ())))))

!(equal 1 2)   ; => read as (not (equal 1 2)), that is, true
```

ตัวอ่าน **ดูอักขระแมโครก่อนไวยากรณ์ที่มีให้ในตัว** จึงยึด `(` และ `'` ได้ด้วย อักขระย่อยของ `#` ที่ลงทะเบียนด้วยวิธีนี้มีลำดับความสำคัญเหนือ `#b`/`#x`/`#.` ที่มีให้ในตัว อักขระอื่นนอกจาก
`#` กลายเป็นอักขระ dispatch ทันทีเมื่อส่งให้ `set-dispatch-macro-character`: **ไม่มี**
สิ่งที่สอดคล้องกับ `make-dispatch-macro-character` ของ CL การลงทะเบียนทำหน้าที่นั้นอยู่แล้ว ดังนั้น
ขั้นตอนแยกจะไม่มีอะไรให้ทำ

**เวลาที่มีผล** ขึ้นกับเส้นทางการอ่าน เหมือนกับ `#.` (บทที่ 1):

- REPL และ `(load ...)` รันทีละฟอร์ม ดังนั้น **ฟังก์ชันที่นิยามในฟอร์มก่อนหน้า** ลงทะเบียนได้
  ตามที่เป็น
- ไฟล์โมดูลถูกตรวจสอบเป็นหน่วยและรันทีหลัง ดังนั้น **เฉพาะการเรียก `set-macro-character` /
  `set-dispatch-macro-character` ที่รันทันที** (บทบาทของ `(eval-when (:compile-toplevel) ...)` ของ CL)
  เมื่อรันทันที **ฟังก์ชันที่ส่งต้องมีอยู่แล้ว ณ จุดนั้น** `defun` ใน
  ไฟล์เดียวกันยังไม่ได้รัน ดังนั้นให้เขียน `lambda` หรือใช้ไลบรารีมาตรฐานหรือสิ่งที่
  รันไปแล้ว ครอบคลุมเฉพาะการเรียกระดับบนสุด ไม่ดูภายใน `progn` หรือ `let`

`read` / `read-from-string` ที่มีให้ในตัวก็ปรึกษา readtable ด้วย (เหมือนใน CL)

**สิ่งที่ไม่มี**: `*readtable*` และ `copy-readtable` และ `readtable-case` สองอย่างแรกเพราะ
readtable **ไม่ใช่ค่า**: ค่าต้องเป็น "สิ่งที่ส่งให้ตัวอ่านได้" แต่
ตัวอ่านที่อ่านซอร์สอยู่นอกโปรแกรม ไม่มีที่ให้ส่ง `readtable-case` เพราะ
บทที่ 1 ตัดสินว่าตัวอ่านของภาษานี้ทำเป็นตัวพิมพ์เล็กเสมอ (`:downcase` ของ CL)


## 12. การทำงานพร้อมกัน (task)

**task คือเธรดน้ำหนักเบา** (ในภาษาของ Go คือสิ่งที่คำสั่ง `go` เริ่ม) และรันแบบร่วมมือ
(ไม่มี preemption) การสลับไม่ผ่านเคอร์เนล และสถานะการทำงานอยู่บนฮีปแทนสแตกของเครื่อง
ดังนั้นสร้าง task จำนวนมากได้ในราคาถูก

**task รันพร้อมกันบนเธรด OS หลายตัว** (ความขนานแบบหลายคอร์) จำนวนเธรดคือ
ตัวแปรสภาพแวดล้อม `TYPELISP_THREADS` (ผลรวม รวมเธรดที่รัน `main` ค่าเริ่มต้น
คือความขนานของเครื่อง) ใน `typl` **เฉพาะ task ที่คอมไพล์แล้ว** รันบนเธรดอื่น และ task ที่อินเทอร์พรีตรันบนเธรดของอินเทอร์พรีเตอร์ (12.7) ข้อมูลที่ใช้ร่วมกันผ่าน `Mutex<T>` หรือ `Chan<T>`
การอ่านและเขียนพร้อมกันที่ไม่ผ่านสิ่งเหล่านี้ไม่นิยาม เหมือนใน Go (12.7)

ในคำศัพท์ **มีเพียง `task` / `thread` / `select` ที่เป็นฟอร์มพิเศษ** ที่เหลือเป็นฟังก์ชันธรรมดา
เมทอดและแมโคร ([Task และ channel](functions/concurrency.md))

### 12.1 `task` — การเริ่ม task

```lisp
(task (f arg...))                   ; returns Task<T>, where T is the return type of f
```

**รับเฉพาะรูปแบบของการเรียก** `f` และแต่ละ `arg` ถูกประเมินค่าที่ที่เขียน `task` ตาม
ลำดับที่เขียน และมีเพียง **ตัวการเรียก** ที่เกิดใน task ใหม่ กฎเดียวกับ `go f(x)` ของ Go
และเป็นเหตุผลที่มันรับรูปแบบการเรียกแทน thunk: thunk จะจับอาร์กิวเมนต์ไว้โดยไม่
ประเมินค่า

```lisp
(dotimes (i 10)
  (task (worker i ch)))             ; i is evaluated on the spot each time; no capture trap

(task ((lambda () ()                ; to run an arbitrary body, call a lambda
         (println "start")
         (send ch 1))))
```

ฟอร์มพิเศษ (`if` / `let` / `progn` …) เขียนตรง ๆ ใต้ `task` ไม่ได้

**ทำไมจึงเป็นฟังก์ชันไม่ได้**: การเขียน `(spawn (lambda () T body...))` จะต้องสะกด `T` ออกมา
เพราะ `lambda` ต้องมีคำอธิบายชนิดที่คืน และแมโครไม่ทราบชนิดที่คืนของ `(f a b)`
มีเพียงตัวตรวจสอบที่ทราบ

### 12.2 `thread` — การเริ่ม task บนเธรด OS เฉพาะ

```lisp
(thread (f arg...))                 ; returns Thread<T>, where T is the return type of f
(join th)                           ; waits for completion and returns its value (any number of times)
```

รูปแบบและกฎการประเมินค่าเหมือน `task` (รับเฉพาะรูปแบบการเรียก และ `f` กับ `arg` ถูก
ประเมินค่าที่ที่เขียน) ความต่างคือที่ที่รัน: **มันเริ่มเธรด OS เฉพาะสำหรับ
task นั้นและรันบนมันเท่านั้น** ไม่ถูก multiplex กับ task อื่น ดังนั้นการเรียกฟังก์ชัน C ที่บล็อก
(`defffi`) ภายในหยุดเฉพาะเธรดนั้น และ task อื่นก้าวหน้าต่อ ภายใน `task` `send` `recv`
และที่เหลือใช้ได้ตามที่เป็น

- `Thread<T>` คือคู่เทียบของ `Task<T>` เหมือน `wait` `join` หยุด **task ที่เรียก** และค่า
  ถูกแคช เมื่อ task จบ เธรดก็จบด้วย
- กฎของ panic เหมือน `task` (ทั้งโพรเซสล่ม) เมื่อ `main` คืนค่า
  โพรเซสก็จบ
- หากต้องการเขียนเป็นฟังก์ชัน ให้ใช้ `(Thread::spawn (lambda () T body...))` (`std::thread::spawn` ของ Rust)
  ส่งฟังก์ชันที่มีชื่อก็ได้
- **เฉพาะโค้ดที่คอมไพล์แล้วที่รันบนเธรดเฉพาะ** เมื่อ `typl` ประเมิน `(thread (f ...))` หรือ
  `Thread::spawn` ขณะอินเทอร์พรีต จะคอมไพล์ฟังก์ชันที่จะรัน (และสิ่งที่มันเรียก) ทันที
  ก่อนรัน สิ่งที่คอมไพล์ไม่ได้ (`lambda` ที่อ้างถึงตัวแปรท้องถิ่นภายนอกมัน
  การสร้าง struct และอื่น ๆ) ก่อนที่เธรดจะเริ่ม คือ panic ที่ถูกปฏิบัติเหมือน
  `(panic ...)` `lambda` ที่อ้างถึงตัวแปรท้องถิ่นส่งได้หากสร้างขึ้นภายใน
  ฟังก์ชันที่คอมไพล์แล้ว

### 12.3 `select` — การรอการดำเนินการ channel หลายตัวพร้อมกัน

```lisp
(select
  ((v (recv ch1)) body...)          ; a receive arm. v is bound to an Option<T>
  ((send ch2 x) body...)            ; a send arm
  (else body...))                   ; optional. **if written, it goes last**
```

- **เมื่อมี `else` จะไม่บล็อก** (`default` ของ Go) หากไม่มี จะรอจนมีอย่างหนึ่งเป็นไปได้
- **หากเป็นไปได้หลายอย่างพร้อมกัน จะเลือกหนึ่งอย่างแบบสุ่ม** (ตามลำดับที่เขียน กิ่งหลัง ๆ จะ
  อดอยาก)
- `v` ของกิ่งรับเป็น **`Option<T>`** channel ที่ปิดเป็น "คำตอบ" ไม่ใช่เหตุผลที่จะข้าม
  กิ่ง ดังนั้นให้ `match` กับมันภายในกิ่ง
- ชนิดคือ **การรวมของชนิดของตัวเนื้อหาของทุกกิ่ง** (กฎเดียวกับกิ่งของ `match`)
- `(select)` ที่มีศูนย์กิ่งเป็นข้อผิดพลาดของชนิด (`select{}` ของ Go ที่บล็อกตลอดไปไม่ถูกนำมาใช้) `select`
  ที่มีเฉพาะ `else` ก็เช่นกัน เพราะเหมือนเขียนตัวเนื้อหาโดยตรง

**นิพจน์ channel และค่าที่จะส่งถูกประเมินค่าอย่างละครั้ง จากซ้ายไปขวา ไม่ว่าจะเลือก
กิ่งใด** (วินัยเดียวกับที่ `case` มีสำหรับคีย์ของมัน)

```lisp
(select                             ; receiving with a timeout
  ((v (recv ch))          (println "~a" (unwrap v)))
  ((z (recv (after 0.5))) (println "timeout")))
```

`after` ([channel ที่ส่งค่าหลังผ่านเวลาหนึ่ง](functions/concurrency.md#5-after--channel-ที่ส่งค่าหลังผ่านเวลาหนึ่ง))
คือ "channel ที่ส่งค่าหนึ่งค่าหลังจาก `sec` วินาที" สอดคล้องกับ `time.After` ของ Go

### 12.4 ปฏิสัมพันธ์กับความสามารถอื่น

| ความสามารถ | ความสัมพันธ์กับ task |
|---|---|
| `catch` / `throw` | **ไม่ข้ามขอบเขต task** `throw` ที่พยายามออกจากตัวเนื้อหาของ task เป็น panic |
| `unwind-protect` | cleanup รันเมื่อ task จบตามธรรมชาติ **ไม่รันเมื่อโพรเซสจบเพราะ task หลักจบ** |
| `block` / `return-from` | เป็น lexical จึงไม่ข้ามขอบเขต `lambda` |
| `panic` | เหมือนใน Go ทั้งโพรเซสล่ม `wait` ไม่สังเกต panic เป็นค่า |
| `dlet` | **ไม่ใช่การผูกต่อ task** ยังคง "ยืมและคืนโกลบอล" ดังนั้น task รบกวนกันเอง |
| เอาต์พุตมาตรฐาน | ใช้ร่วมกันโดยทุก task เอาต์พุตของ `println` หนึ่งครั้งไม่เคยปนกับของอื่นกลางบรรทัด |
| `compile` / `eval` | ไม่มีข้อจำกัด `(compile f)` ภายใน task ใช้ได้ |

### 12.5 จุดที่ task สลับกัน

การจัดตารางเวลาเป็นแบบร่วมมือ ดังนั้น **task สลับเฉพาะที่ที่คุณเขียน**: `(yield)`, `(sleep ...)`,
`(wait ...)`, **การดำเนินการ channel ที่ต้องรอ** (`send`/`recv`/`select`) และ **การดำเนินการซ็อกเก็ต
ที่ต้องรอ** (`accept` / `tcp-connect` (รวมการแปลงชื่อ) / การอ่านและเขียนซ็อกเก็ต /
`recv-from`; [เครือข่าย](functions/network.md)) ซ็อกเก็ตทั้งหมดไม่บล็อก: หากตัวหนึ่งไม่พร้อม เฉพาะ
task นั้นหยุด และกลับมาทำงานเมื่อ OS บอกว่าพร้อม รูปแบบเดียวกับ netpoller ของ Go เฉพาะเมื่อไม่มี
task ใดรันได้ implementation จึงรอ OS จนถึงกำหนดเวลา `sleep` ที่ใกล้ที่สุด

การดำเนินการ channel ที่ตอบได้ทันที (`send` ที่บัฟเฟอร์มีที่ว่าง `recv` ที่มีค่ารออยู่
`(len ch)`/`(cap ch)`/`(close ch)`/`(Chan::new n)`) **ไม่ใช้คิวหมด** นั่นหมายความว่าคุณ
ไม่ถูกขัดจังหวะโดยไม่คาดคิดจากการอ่าน และถูกปฏิบัติต่างจาก `(sleep 0.0)` ซึ่งเป็น
"ยอมให้ผู้อื่น 0 วินาที" ของ CL

**ไม่มี preemption** ลูปแน่นที่ไม่เรียกอะไรทำให้ task อื่นอดอยาก อย่างไรก็ตาม ลูปที่คอมไพล์แล้ว
ส่งการควบคุมให้ตัวตั้งเวลา (scheduler) เป็นระยะ ดังนั้นลูปแน่นที่คอมไพล์แล้วไม่ทำให้พวกมันอดอยาก

### 12.6 โค้ดที่คอมไพล์แล้วกับ task

โค้ดที่คอมไพล์แล้วระงับ task ได้ด้วย เช่นเดียวกับไฟล์ปฏิบัติการที่สร้างด้วย `compile-file`: `main` รันเป็น
task หลักของตัวตั้งเวลา และ `task`, `sleep`, `wait`, channel และการรอซ็อกเก็ตทั้งหมดทำงานด้วยความหมาย
เดียวกับใน `typl` เมื่อ `main` คืนค่า โพรเซสจบและ task ที่เหลือถูกตัดทิ้ง (เหมือนใน Go)
อินเทอร์พรีเตอร์ไม่เคยถูกใส่ในไฟล์ปฏิบัติการเพื่อประโยชน์ของตัวตั้งเวลา

ข้อยกเว้นอย่างเดียวคือ "ภายใน callback ของ C FFI" ที่การดำเนินการซึ่ง **ต้องรอ** เป็นข้อผิดพลาด
(เป็นมิตรกว่า deadlock เงียบ ๆ): ขณะที่ฟังก์ชันที่ส่งด้วย `defffi` ถูกเรียกจาก C สแตกของ C
อยู่บนสุด และไม่มีทางระงับ task แล้วกลับมาทำต่อทีหลัง

ที่ต่อไปนี้ก็เป็นฟังก์ชันที่ถูกเรียกกลาง task เช่นกัน แต่ระงับไม่ได้:
เมทอด `print-object`, `~/name/` ใน `format`, ตัวอ่านแมโคร, ภายใน `eval` และตัวกำหนดค่าเริ่มต้นของ `defvar` ใน
ไฟล์ปฏิบัติการ AOT ที่นี่ **การดำเนินการที่ตอบได้โดยไม่ต้องรอผ่านไปได้** (`(recv ch)` ที่มีค่าใน
บัฟเฟอร์ `read-line` บนซ็อกเก็ตที่ได้รับข้อมูลแล้ว `(task ...)`, `(yield)` และอื่น ๆ) และ
**การดำเนินการที่ต้องรอจริง ๆ เป็นข้อผิดพลาด** (ไม่หยุดโพรเซสทันที แต่เป็น
panic อย่าง `` `recv` cannot block: ... `` ที่ถูกปฏิบัติเหมือน `(panic ...)`)

### 12.7 ความแตกต่างจาก Go

- **ใน `typl` เฉพาะ task ที่คอมไพล์แล้วที่ออกไปยังเธรดอื่น** สถานะของอินเทอร์พรีเตอร์ใช้ร่วม
  ระหว่างเธรดไม่ได้ ดังนั้น task จาก `task` ที่อินเทอร์พรีตรันบนเธรดของอินเทอร์พรีเตอร์ task ที่คอมไพล์แล้ว
  ก็ **ย้ายไปยังเธรดของอินเทอร์พรีเตอร์และอยู่ที่นั่น** (ไม่กลับ) ณ จุดที่มัน
  เรียกค่าฟังก์ชันที่อินเทอร์พรีต เรียกเมทอด `:dyn` ที่ไม่มีใครคอมไพล์ หรือเรียก
  `eval`/`macroexpand`/`read` หากการคำนวณยาว ๆ แตะโค้ดที่อินเทอร์พรีตแม้ครั้งเดียวระหว่างทาง
  ส่วนที่เหลือจะรันบนเธรดของอินเทอร์พรีเตอร์
- **ใน `typl` worker มีชีวิตเฉพาะหนึ่งการประเมินระดับบนสุด** ขณะที่ REPL รออินพุต และ
  ระหว่างฟอร์มระดับบนสุด เธรดอื่นไม่ทำให้ task ก้าวหน้า (task ที่เหลือทำต่อจากที่
  ค้างไว้ในการประเมินครั้งถัดไป) เมื่อจบการประเมิน จะรอให้แต่ละเธรดจบ
  ขั้นปัจจุบัน ดังนั้นหากฟังก์ชัน C (`defffi`) บล็อกต่อไปภายใน `thread` การประเมินจะไม่จบ
  จนกว่ามันจะคืนค่า
- **การพิมพ์บน worker**: เมทอด `print-object` / `~/name/` ที่อินเทอร์พรีตรันบนเธรดอื่นไม่ได้ ดังนั้น
  การพิมพ์ค่าเช่นนั้นบนเธรดอื่นเป็น panic ที่ถูกปฏิบัติเหมือน `(panic ...)` (`(compile
  T::print-object)` หรือพิมพ์จาก task หลัก)
- **data race ไม่นิยาม** (จุดยืนเดียวกับ Go) ผลลัพธ์ของหลาย task ที่เปลี่ยนค่าเดียวกัน
  โดยไม่ผ่าน `Mutex<T>` / `Chan<T>` ไม่รับประกัน
- **`task` คืนค่า** ต่างจากคำสั่ง `go` ของ Go ตรงที่คืน `Task<T>` และ `(wait t)` ได้
  ผลลัพธ์
- **ไม่มี nil channel** สำนวน fan-in ของ Go (ตั้ง channel ที่ปิดเป็น `nil` เพื่อทิ้งมันจาก
  กิ่งของ `select`) เขียนไม่ได้ ดังนั้นให้เริ่มหนึ่ง task ต่ออินพุตและรวมด้วย `WaitGroup`
  ([WaitGroup](functions/concurrency.md#4-waitgroup--การรอให้-n-สิ่งเสร็จ)) นั่นเป็นวิธีที่แนะนำใน Go ด้วย
  แต่เป็น **ความแตกต่างแรกที่ผู้มาจาก Go พบ**
