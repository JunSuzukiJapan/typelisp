# โมดูลและการจัดวางไฟล์

คู่มือนี้อธิบายวิธีประกอบโปรแกรมที่ประกอบด้วยหลายไฟล์ กฎโดยละเอียดอยู่ในหัวข้อ 3.10 ถึง 3.13 ของ
[เอกสารอ้างอิงไวยากรณ์](../reference/syntax.md#310-module--use--เนมสเปซ)

## 1. หนึ่งไฟล์คือหนึ่งโมดูล

ใน typelisp **ไฟล์หนึ่งไฟล์เป็นโมดูลในตัวมันเอง** พาธของไฟล์เทียบกับรากของซอร์สคือพาธของ
โมดูล

| ไฟล์ | โมดูล |
|---|---|
| `<root>/geometry.typl` | `geometry` |
| `<root>/geo/shapes.typl` | `geo::shapes` |
| `<root>/net/http/client.typl` | `net::http::client` |

ไม่จำเป็นต้องเขียนการประกาศโมดูลไว้ที่ต้นไฟล์

## 2. การตั้งค่าโปรเจกต์

วางไฟล์ชื่อ `typelisp.toml` ไว้ที่รากของโปรเจกต์ ไฟล์นี้จะว่างเปล่าก็ได้

```
myapp/
├── typelisp.toml
├── main.typl
└── geometry.typl
```

หากต้องการเก็บซอร์สไว้ใต้ `src/` ให้เขียนบรรทัดเดียวนี้ใน `typelisp.toml`:

```toml
src = "src"
```

`typl` ค้นหา `typelisp.toml` โดยเริ่มจากไดเรกทอรีของไฟล์ที่รันและไล่ขึ้นไปทางไดเรกทอรีแม่ และ
ใช้ตำแหน่งที่พบเป็นรากของซอร์ส หากไม่พบ ไดเรกทอรีของไฟล์ที่กำลังรันจะเป็นราก (ใน REPL คือ
ไดเรกทอรีปัจจุบัน)

## 3. การทำให้การนิยามเป็นสาธารณะและการใช้งาน

`geometry.typl`:

```lisp
(pub defstruct point
  (pub x i32)
  (pub y i32)
  (tag string))                        ; ฟิลด์ที่ไม่มี pub อ่านและเขียนจากภายนอกไม่ได้

(defun square ((n i32)) i32 (* n n))   ; ฟังก์ชันที่ไม่มี pub ก็เรียกจากภายนอกไม่ได้

(pub defun dist2 ((a point) (b point)) i32
  (+ (square (- a::x b::x)) (square (- a::y b::y))))

(impl point
  (pub new ((x i32) (y i32) (tag string)) point
    (make-instance 'point :x x :y y :tag tag))
  (pub origin () point (point::new 0 0 "o")))
```

`main.typl`:

```lisp
(use geometry)

(let ((a (geometry::point::origin))
      (b (geometry::point::new 3 4 "b")))
  (println "~a" (geometry::dist2 a b)))
```

```sh
typl main.typl        # => 25
```

`geometry.typl` จะถูกโหลดที่ตำแหน่งที่เขียน `(use geometry)` ไม่จำเป็นต้องโหลดล่วงหน้า

### สิ่งที่ถูกทำให้เป็นสาธารณะ

- ฟังก์ชัน struct enum trait ตัวแปรโกลบอล และแมโคร มองเห็นได้จากโมดูลอื่นเฉพาะที่ใส่ `pub` ให้วาง `pub` ไว้หน้า
  การนิยามทันที เช่น `(pub defun ...)`
- จากเมทอดที่เขียนใน `impl` จะใช้จากภายนอกได้เฉพาะที่เขียนเป็น `(pub new ...)` ทีละรายการ
- สำหรับ struct **การเปิดเผยชนิดกับการเปิดเผยฟิลด์แยกกัน** `(pub defstruct point ...)` ทำให้มองเห็นชนิด และ
  อ่านเขียนจากภายนอกได้เฉพาะฟิลด์ที่เขียน `(pub x i32)`
- ทำนองเดียวกัน ในโมดูลอื่นให้ฟิลด์แก่ `make-instance` ได้เฉพาะฟิลด์ที่เป็น `pub` `point` ข้างบนมี `tag` ที่ไม่ใช่
  `pub` โมดูลอื่นจึงสร้างด้วย `make-instance` ไม่ได้ และใช้ `point::new` แทน
- การใช้ชื่อที่ไม่เป็นสาธารณะจากภายนอกจะเกิดข้อผิดพลาด "cannot resolve" เช่น
  `unresolved path: geometry::square` ข้อความนี้เหมือนกับกรณีสะกดชื่อผิด ดังนั้นหากสะกดถูกต้อง
  แต่ชื่อยังแก้ไขไม่ได้ ให้สงสัยว่าลืมใส่ `pub`

รายการการนิยามที่ใส่ `pub` ได้อยู่ใน
[เอกสารอ้างอิงไวยากรณ์ 3.13](../reference/syntax.md#313-pub--การมองเห็น)

## 4. วิธีเขียน `use`

```lisp
(use geometry)              ; bring in a module; write geometry::dist2 to use it
(use geometry::dist2)       ; bring in a function; use it by the bare name dist2
(use geometry::point)       ; bring in a type; write point::new, point::origin, and point in type annotations
(use a::f b::g)             ; several can be written together
```

- **`use` มีผลเฉพาะกับฟอร์มที่อยู่หลังมัน** ให้วางไว้ที่ต้นไฟล์ หากเขียน
  `geometry::dist2` ไว้เหนือ `use` จะเกิด `unresolved path`
- การเขียนพาธเต็ม `geometry::dist2` โดยไม่ได้ `use` โมดูลก็แก้ไขไม่ได้เช่นกัน มีเพียง
  `use` เท่านั้นที่ทำให้ไฟล์ถูกโหลด
- การ `use` ชื่อที่ชื่อเปล่าของมันถูกใช้ไปแล้วจะให้คำเตือน หากตั้งใจนำเข้ามาอยู่ดี
  ให้ใช้ `shadowing-import`
- โมดูลที่อยู่ในไดเรกทอรีเขียนเป็น `(use geo::shapes)` และหลังจากนั้นอ้างถึงด้วยส่วนสุดท้ายของชื่อ
  (`shapes::...`)

### การเรียกเมทอดของ trait

เมทอดที่ implement ใน `impl` **เป็นของชนิด** ไม่ใช่ของฟังก์ชันของโมดูล จึง
เรียกได้โดยไม่ต้องใส่ชื่อโมดูล

```lisp
(use shapes::core)
(println "~a" (area (make-instance 'core::square :side 4)))    ; area, not core::area
```

เมทอดใน `impl` ของ trait เปิดเผยเสมอแม้ไม่ใส่ `pub` ส่วนเมทอดของ inherent `impl` (`(impl point ...)`)
เปิดเผยเฉพาะที่ใส่ `pub`

trait ก็เช่นกัน มองเห็นได้จากโมดูลอื่นเฉพาะที่เขียนเป็น `(pub deftrait ...)` ในโมดูลอื่นให้เขียน trait เป็นพาธเช่น `shapes::Shape` หรือนำเข้าด้วย `use` แล้วเขียนใน `impl`

## 5. การแบ่งเนมสเปซภายในไฟล์

หากต้องการแบ่งเนมสเปซภายในไฟล์เดียว ให้ใช้ `module` โมดูลนี้ซ้อนอยู่ภายในโมดูลของไฟล์นั้นเอง

```lisp
;; inside main.typl
(module util
  (pub defun clamp ((x i32) (lo i32) (hi i32)) i32
    (if (< x lo) lo (if (> x hi) hi x))))

(println "~a" (util::clamp 15 0 10))    ; main::util::clamp
```

หากต้องการนำส่วนที่เหลือทั้งหมดของไฟล์ไปไว้ในเนมสเปซเดียว สามารถเขียน `(in-module util)` แทน
การครอบด้วยวงเล็บได้

## 6. ข้อจำกัดของการพึ่งพา

- **ห้ามมีวัฏจักร** หาก `a.typl` ทำ `(use b)` และ `b.typl` ทำ `(use a)` จะเกิด
  ข้อผิดพลาด `circular module dependency: a -> b -> a` ให้ย้ายการนิยามที่ทั้งสองต้องใช้ไปไว้ใน
  โมดูลที่สาม
- **ทั้งชนิดและฟังก์ชันไม่สามารถถูกอ้างถึงก่อนที่จะนิยาม** แม้ภายในไฟล์เดียวกัน สำหรับ
  ฟังก์ชันที่เรียกกันเองแบบวนกลับ ให้ประกาศตัวหนึ่งไว้ก่อนด้วย `defsignature`
  ([เอกสารอ้างอิงไวยากรณ์ 3.2](../reference/syntax.md#32-defsignature--การประกาศล่วงหน้า))

## 7. ลำดับการทำงาน

การรัน `typl main.typl` ดำเนินไปตามลำดับนี้

1. `main.typl` และทุกไฟล์ที่ `use` จากมันจะถูกอ่านและตรวจสอบชนิด **หากมีข้อผิดพลาดของชนิด
   ที่ใดที่หนึ่ง จะไม่มีอะไรรันเลย**
2. นิพจน์ระดับบนสุดของโมดูลที่ถูก `use` จะรันก่อนนิพจน์ของโมดูลที่ใช้มัน
3. นิพจน์ระดับบนสุดของ `main.typl` รันจากบนลงล่าง

หากรวมจุดเริ่มต้นของโปรแกรมไว้ในฟังก์ชัน `main` และเรียก `(main)` ที่ท้ายไฟล์ ไฟล์เดียวกัน
ก็ใช้กับ
[การคอมไพล์แบบ AOT](compile.md#3-การสร้างไฟล์ปฏิบัติการด้วยการคอมไพล์แบบ-aot) ได้ด้วย

## 8. ความแตกต่างจาก `load`

`(load "path")` เหมือน `load` ของ Common Lisp คืออ่านเนื้อหาของไฟล์ **เข้าไปในเนมสเปซปัจจุบัน
ตามที่เป็น** ไม่ได้ครอบด้วยโมดูล และ `pub` ไม่มีบทบาท ใช้สำหรับงานอย่างการอ่านไฟล์
การตั้งค่า หรือการโหลดไฟล์ในเครื่องใหม่ใน REPL หากต้องการแบ่งโปรแกรมเป็นส่วน ๆ
ให้ใช้ `use`
