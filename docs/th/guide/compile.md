# การคอมไพล์

หากไม่ทำอะไรเพิ่ม โปรแกรม typelisp จะรันในอินเทอร์พรีเตอร์ นอกจากนี้ยังมีวิธีคอมไพล์เป็นโค้ดเนทีฟ
สองวิธี และวิธีบันทึกสภาพแวดล้อมอีกหนึ่งวิธี รายละเอียดของข้อกำหนดอยู่ใน
[เอกสารอ้างอิงไวยากรณ์ บทที่ 10](../reference/syntax.md#10-การคอมไพล์)

| วิธี | ทำอย่างไร | ผลลัพธ์ |
|---|---|---|
| การคอมไพล์แบบ JIT | `(compile name)` | ฟังก์ชันในเซสชันที่กำลังรันถูกแทนที่ด้วยโค้ดเนทีฟ |
| การคอมไพล์แบบ AOT | `typl -c src.typl` หรือ `(compile-file "src.typl" "out")` | ไฟล์ปฏิบัติการที่ทำงานได้ด้วยตัวเอง |
| Dump | `(dump "file.typld")` | บันทึกการนิยาม; `typl --image` เริ่มใหม่จากสภาพแวดล้อมเดิม |

## 1. การเตรียมการ

การคอมไพล์ใช้ LLVM 22 หากคุณบิลด์ `typl` ตาม [README.md](../../../README.md) ก็ไม่ต้อง
เตรียมอะไรเพิ่ม

ไฟล์ปฏิบัติการที่สร้างด้วยการคอมไพล์แบบ AOT ถูกลิงก์กับไลบรารีสถิต `libtypelisp_front.a` `typl`
ที่บิลด์แบบ release (รวมถึงที่ติดตั้งด้วย `cargo install`) มีไลบรารีนี้อยู่ภายในตัว จึงไม่ต้อง
เตรียมอะไร ครั้งแรกที่คอมไพล์ มันจะเขียนไลบรารีออกไปที่
`~/.typelisp/lib/<build ID>/` (หรือ `$TYPELISP_HOME/lib/<build ID>/` หากตั้งตัวแปรสภาพแวดล้อม
`TYPELISP_HOME` ไว้) และใช้สำเนานั้นต่อไป `typl --remove-lib` จะลบสำเนานั้น (ถ้าใส่ `--others`
จะลบสำเนาที่เขียนโดย `typl` รุ่นอื่น ถ้าใส่ `--all` จะลบทั้งหมด) `typl` ที่บิลด์แบบ debug
ใช้ไลบรารีใน `target/debug/` ของรีโพซิทอรีที่บิลด์มา หากต้องการใช้ไลบรารีที่วางไว้ที่อื่น
ให้ระบุโฟลเดอร์ของมันด้วย `--lib-dir` ตอนเริ่ม `typl` (หัวข้อ 3.2)
บน macOS การลิงก์ใช้ Xcode Command Line Tools

## 2. การคอมไพล์แบบ JIT

วิธีนี้เปลี่ยนฟังก์ชันที่นิยามไว้แล้วให้เป็นโค้ดเนทีฟทันที

```lisp
(defun fib ((n int)) int
  (if (< n 2) n (+ (fib (- n 1)) (fib (- n 2)))))

(compile fib)
(fib 30)           ; from here on, calls run the compiled code
```

- `name` ไม่ถูกประเมินค่า ให้เขียนชื่อฟังก์ชันตามที่เป็น (ไม่ใช่สตริง) สำหรับเมทอด ให้เขียนพร้อม
  ชื่อชนิด เช่น `(compile point::norm)`
- ฟังก์ชันที่มันเรียกจะถูกคอมไพล์ไปด้วย
- **ฟังก์ชัน generic คอมไพล์ไม่ได้** เพราะมีการสร้างสำเนาสำหรับแต่ละชนิดในแต่ละจุดที่ใช้
  ให้คอมไพล์ฟังก์ชันที่เรียกมันด้วยชนิดที่เจาะจงแทน
- `trace`, `step`, `disassemble`, `compile`, `compile-file` และ `dump` เป็นการดำเนินการของ
  อินเทอร์พรีเตอร์ ดังนั้นฟังก์ชันที่เรียกสิ่งเหล่านี้จึงคอมไพล์ไม่ได้ การพยายามคอมไพล์จะเกิด
  ข้อผิดพลาดที่ระบุเหตุผล

หากต้องการดูผลการคอมไพล์ ให้ใช้ `disassemble`

```lisp
(disassemble fib)          ; the host machine code
(disassemble fib true)     ; LLVM IR
```

## 3. การสร้างไฟล์ปฏิบัติการด้วยการคอมไพล์แบบ AOT

### 3.1 การเขียนโปรแกรม

เป็นจุดเริ่มต้น ให้นิยาม **ฟังก์ชัน `main` ที่ไม่รับอาร์กิวเมนต์**

```lisp
;; hello.typl
(defun fib ((n int)) int
  (if (< n 2) n (+ (fib (- n 1)) (fib (- n 2)))))

(defun main () ()
  (println "args: ~a" (command-line-args))
  (println "fib(25) = ~a" (fib 25)))

(main)
```

`(main)` ที่ท้ายไฟล์มีไว้เพื่อให้ `main` ถูกเรียกเมื่อคุณรัน
`typl hello.typl` `compile-file` ข้าม `(main)` ตัวสุดท้ายนี้ ดังนั้นไฟล์เดียวกัน
ใช้ได้ทั้งในอินเทอร์พรีเตอร์และกับการคอมไพล์แบบ AOT

### 3.2 การคอมไพล์

จากบรรทัดคำสั่ง ให้ใช้ `typl -c` (`typl --compile` ก็เหมือนกัน)

```sh
$ typl -c hello.typl            # makes hello
$ typl -c hello.typl -o fib     # names the executable fib
$ ./hello a b
args: #(./hello a b)
fib(25) = 75025
```

หากไม่ใส่ `-o` ไฟล์ปฏิบัติการจะตั้งชื่อตามไฟล์ซอร์สโดยตัด `.typl` ออก และวางไว้ในโฟลเดอร์
เดียวกับไฟล์ซอร์ส หากชื่อไฟล์ซอร์สไม่ลงท้ายด้วย `.typl` จำเป็นต้องใส่ `-o` เมื่อใช้ `-c`
(`--compile`) จะระบุ `--image`, `--heap-cells` และ `--feature` ไม่ได้

คุณทำสิ่งเดียวกันได้โดยเรียก `compile-file` จาก REPL หรือจากโปรแกรม

```sh
$ typl
typl> (compile-file "hello.typl" "hello")
typl> :quit
$ ./hello a b
args: #(./hello a b)
fib(25) = 75025
```

หากต้องบิลด์ซ้ำ ๆ คุณสามารถใส่บรรทัดเดียวนี้ในไฟล์แล้วรันด้วย `typl build.typl`

```lisp
;; build.typl
(compile-file "hello.typl" "hello")
```

ชื่อไฟล์ถูกแก้ไขจาก **ไดเรกทอรีปัจจุบันที่เริ่ม `typl`** ไม่ใช่จากตำแหน่งของ `build.typl`

หากต้องการลิงก์ `libtypelisp_front.a` ที่วางไว้ที่อื่นนอกจากที่ `typl` ค้นหา ให้ระบุโฟลเดอร์ของมันด้วย
`--lib-dir` ใช้ได้ทั้งกับ `typl -c` และ `compile-file`

```sh
$ typl --lib-dir ~/lib/typelisp -c hello.typl
$ typl --lib-dir ~/lib/typelisp build.typl
```

หากโฟลเดอร์ที่ระบุไม่มี `libtypelisp_front.a` `typl` จะหยุดพร้อมข้อผิดพลาด ไฟล์นี้ใช้ได้เฉพาะ
กับ `typl` ที่บิลด์มาพร้อมกันเท่านั้น หลังจากบิลด์ `typl` ใหม่ ให้คัดลอกอีกครั้ง

### 3.3 สิ่งที่ไฟล์ที่คอมไพล์แบบ AOT มีได้

- ระดับบนสุดของไฟล์จุดเริ่มต้นมีได้เฉพาะการนิยาม (`defun` `defmethod` `defvar`
  `defparameter` `defconstant` `defmacro` `defsignature` `defstruct` `defenum` `deftype` `deftrait`
  `impl` `defffi`, `(unsafe (def-c-struct ...))`) และ `use` `module` นิพจน์ระดับบนสุด
  เช่น `(println ...)` ไม่อนุญาต ยกเว้น `(main)` ตัวสุดท้าย ให้ใส่งานไว้ใน `main`
- หากไม่มี `main` ที่ไม่รับอาร์กิวเมนต์ การคอมไพล์จะล้มเหลวพร้อมข้อผิดพลาด
- ไฟล์ของโมดูลที่ถูก `use` ก็ถูกคอมไพล์และรวมเป็นไฟล์ปฏิบัติการเดียว
- ไลบรารีที่ระบุด้วย `:library` ใน `defffi` ถูกลิงก์โดยอัตโนมัติ ([FFI สำหรับ C](ffi.md))
- ฟังก์ชันของไลบรารีมาตรฐานทุกตัวใช้กับการคอมไพล์แบบ AOT ได้ `eval` ก็ใช้ได้เช่นกัน แต่
  ตัวตรวจสอบชนิดและอินเทอร์พรีเตอร์จะเข้าไปอยู่ในไฟล์ปฏิบัติการ ทำให้ไฟล์ใหญ่ขึ้นและเริ่มทำงานช้าลง
  โปรแกรมที่ไม่เรียก `eval` จะไม่รวมสิ่งเหล่านี้

### 3.4 พฤติกรรมของไฟล์ปฏิบัติการ

- `(command-line-args)` คืนค่า `Vector<string>` รูปแบบเดียวกัน ไม่ว่าจะรันเป็น
  `typl hello.typl a b` หรือ `./hello a b` สมาชิกตัวแรกคือชื่อโปรแกรม
- กำหนด exit code ด้วย `(exit n)` หาก `main` คืนค่าตามปกติ จะเป็น 0
- เมื่อเกิด `panic` โปรแกรมจะพิมพ์ข้อความและจบด้วยรหัสที่ไม่ใช่ศูนย์

## 4. Dump

คุณบันทึกการนิยามของเซสชันปัจจุบันลงในไฟล์เดียวและเริ่มจากไฟล์นั้นในครั้งถัดไปได้

```sh
$ typl
typl> (defun sq ((n i32)) i32 (* n n))
typl> (compile sq)
true
typl> (dump "session.typld")
true
typl> :quit
$ typl --image session.typld
typl> (sq 9)
81
```

ใช้ได้กับการรันไฟล์เช่นกัน เช่น `typl --image session.typld prog.typl`

- สิ่งที่ถูกบันทึกคือ **การนิยาม** นิพจน์ที่ประเมินค่าในเซสชันไม่ถูกบันทึก
- ฟังก์ชันที่คุณ `compile` ไว้จะถูกบันทึกในรูปที่คอมไพล์แล้ว
- ตัวแปรโกลบอลถูกกู้คืนโดย **รันตัวกำหนดค่าเริ่มต้นของมันอีกครั้ง** ไม่ใช่ด้วยค่าที่มันมี
  ตอนเขียน dump
- dump ไม่สามารถโหลดด้วย `typl` คนละรุ่นกับรุ่นที่เขียนมัน (เป็นข้อผิดพลาด)

หากคุณรันไฟล์และ `(dump ...)` จากไฟล์นั้น การนิยามของไฟล์นั้นจะอยู่ในโมดูลที่ตั้งชื่อตาม
ไฟล์ ฟังก์ชันที่นิยามใน `dp.typl` มีชื่อ `dp::sq` และการเรียกจากไฟล์อื่นต้องใช้
`pub` ([โมดูลและการจัดวางไฟล์](modules.md))

## 5. เกี่ยวกับไฟล์โมดูลที่คอมไพล์แล้ว

ไม่มีรูปแบบอย่าง `.fasl` ของ Common Lisp สำหรับเขียนผลการคอมไพล์ของแต่ละโมดูลออกเป็น
ไฟล์ `compile-file` สร้างไฟล์ปฏิบัติการโดยตรงจากซอร์ส ไม่มีไฟล์ระหว่างทางหลงเหลือ
