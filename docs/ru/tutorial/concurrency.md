# Конкурентность

В typelisp работа выполняется конкурентно путём запуска **задач** (лёгких потоков), а задачи передают друг другу
значения через **каналы**. Модель близка к горутинам и каналам Go. Эта глава по порядку рассматривает запуск задачи
и получение её результата, каналы, `select`, защиту общих данных и отдельные потоки ОС. Предполагается, что вы
прочитали [Основы типов](types.md).

## 1. Запуск задачи и ожидание результата

`(task (функция аргументы...))` запускает вызов функции как новую задачу. Запускающая сторона не ждёт и продолжает
работу. Значение — дескриптор типа `Task<T>`; `(wait дескриптор)` ждёт завершения задачи и возвращает её результат.

```lisp
(defun slow-square ((n int)) int
  (sleep 0.1)                  ; подождать 0,1 секунды (останавливается только эта задача)
  (* n n))

(let ((a (task (slow-square 3)))
      (b (task (slow-square 4))))
  (println "~a" (+ (wait a) (wait b))))    ; 25
```

- `task` принимает только форму вызова функции. Аргументы вычисляются там, где написан `task`; в новой задаче
  выполняется лишь сам вызов.
- Чтобы выполнить несколько выражений, создайте `lambda` и вызовите его на месте:
  `(task ((lambda () () (println "start") (work))))`
- `wait` можно вызывать сколько угодно раз. Результат запоминается.
- Задача выполняется, даже если её никогда не ждать через `wait`.
- **Когда основная работа заканчивается, программа завершается.** Ещё работающие задачи обрываются.

## 2. Передача значений через каналы

Канал `Chan<T>` — путь, по которому задачи передают значения типа `T`. Аргумент `Chan::new` — ёмкость (сколько
значений он может хранить). На канале ёмкости 0 отправитель и получатель оба ждут, пока появится другая сторона.

```lisp
(defun produce ((ch Chan<int>) (n int)) ()
  (dotimes (i n)
    (send ch (* i 10)))        ; отправить
  (close ch))                  ; больше отправок не будет

(let ((ch (the Chan<int> (Chan::new 0))))
  (task (produce ch 4))
  (doiter (v ch)               ; получать до закрытия
    (println "got ~a" v)))
```

```
got 0
got 10
got 20
got 30
```

- `(send ch v)` отправляет. Если канал полон, ждёт, пока освободится место.
- `(recv ch)` получает. Ждёт, пока придёт значение. Результат — `Option<T>`; когда канал закрыт и пуст, возвращает
  `none`.
- Обход канала через `doiter` получает значения до его закрытия. Канал можно также передать прямо в `map` или
  `filter`.
- `send` в закрытый канал вызывает panic.

### Распределение работы между несколькими задачами

Частый приём — завести один канал с работой и дать нескольким исполнителям (задачам, обрабатывающим работу) брать
из него задания. Свободный исполнитель берёт следующее задание, так что даже при смеси медленных и быстрых заданий
работа естественно распределяется.

```lisp
(defstruct job
  (id int)
  (seconds f64))                  ; сколько длится это задание

(defun worker ((name string) (jobs Chan<job>)) int
  (let ((count 0))
    (doiter (j jobs)              ; брать по одному заданию, пока jobs не закрыт
      (println "~a: start  job ~a (~as)" name j::id j::seconds)
      (sleep j::seconds)          ; работа; тем временем другие исполнители берут следующие задания
      (println "~a: finish job ~a" name j::id)
      (setf count (+ count 1)))
    count))                       ; сколько заданий выполнил этот исполнитель

(let* ((jobs (the Chan<job> (Chan::new 0)))
       (a (task (worker "A" jobs)))
       (b (task (worker "B" jobs)))
       (c (task (worker "C" jobs))))
  (send jobs (job::new 1 0.3))
  (send jobs (job::new 2 0.1))
  (send jobs (job::new 3 0.1))
  (send jobs (job::new 4 0.2))
  (send jobs (job::new 5 0.1))
  (send jobs (job::new 6 0.1))
  (close jobs)                    ; это вся работа
  (println "A: ~a jobs, B: ~a jobs, C: ~a jobs" (wait a) (wait b) (wait c)))
```

```
A: start  job 1 (0.3s)
B: start  job 2 (0.1s)
C: start  job 3 (0.1s)
B: finish job 2
B: start  job 4 (0.2s)
C: finish job 3
C: start  job 5 (0.1s)
C: finish job 5
C: start  job 6 (0.1s)
A: finish job 1
B: finish job 4
C: finish job 6
A: 1 jobs, B: 2 jobs, C: 3 jobs
```

- A, B и C берут по одному из первых трёх заданий.
- Через 0,1 секунды B и C освобождаются и берут оставшиеся задания. Пока A занят медленным заданием 1, он не берёт
  новой работы.
- В итоге A выполнил одно задание, B — два, C — три. Нигде в программе не сказано, какой исполнитель берёт какое
  задание.
- Закрытие `jobs` завершает `doiter` каждого исполнителя, задачи заканчиваются, и каждый `wait` возвращает свой
  счёт.

`jobs` — канал ёмкости 0, поэтому `send` ждёт, пока какой-нибудь исполнитель не возьмёт задание. При большей ёмкости
основная задача могла бы ставить работу в очередь, не дожидаясь исполнителей.

## 3. `select`: ожидание нескольких каналов сразу

`select` выполняет ту из нескольких операций с каналами, которая станет возможной первой. `(after секунды)` — канал,
выдающий одно значение по прошествии заданного времени. В сочетании с `select` он даёт тайм-аут.

```lisp
(defun late-send ((ch Chan<string>) (sec f64)) ()
  (sleep sec)
  (send ch "done"))

(let ((ch (the Chan<string> (Chan::new 1))))
  (task (late-send ch 1.0))
  (select
    ((v (recv ch)) (println "~a" (unwrap v)))
    ((z (recv (after 0.2))) (println "timeout"))))
;; timeout
```

- `((v (recv ch)) body...)` — ветвь приёма. `v` получает `Option<T>`.
- `((send ch x) body...)` — ветвь отправки.
- Когда несколько ветвей могут выполниться одновременно, одна из них выбирается случайно.
- С `(else body...)` в конце `else` выполняется, когда ни одна ветвь не может выполниться сразу, и `select` не ждёт.

```lisp
(let ((ch (the Chan<int> (Chan::new 0))))
  (select
    ((v (recv ch)) (println "~a" v))
    (else (println "nothing ready"))))
;; nothing ready
```

## 4. Защита общих данных

Когда несколько задач изменяют одно и то же значение, защищайте его с помощью `Mutex<T>`. `with-lock` берёт
блокировку, связывает содержимое с переменной, выполняет тело и всегда освобождает блокировку, как бы ни было
покинуто тело. Присваивание переменной через `setf` внутри тела изменяет содержимое `Mutex`.

`WaitGroup` — средство дождаться завершения заданного числа задач. Увеличьте счётчик через `add`, пусть каждая задача
вызывает `done` по завершении, и ждите через `wait`, пока счётчик не дойдёт до 0.

```lisp
(defun add-many ((counter Mutex<int>) (n int)) ()
  (dotimes (i n)
    (with-lock (c counter)
      (setf c (+ c 1)))))

(let ((counter (the Mutex<int> (Mutex::make 0)))
      (wg (the WaitGroup (WaitGroup::make))))
  (dotimes (i 4)
    (add wg 1)
    (task ((lambda () ()
             (add-many counter 1000)
             (done wg)))))
  (wait wg)
  (println "count = ~a" (with-lock (c counter) c)))    ; count = 4000
```

Если несколько задач одновременно изменяют одно значение не через `Mutex` или канал, результат не гарантирован.
Передавайте данные между задачами через каналы, где это возможно, и делайте данные общими, только когда это нужно.

## 5. Где переключаются задачи

Задачи переключаются кооперативно. Задача уступает место другим только в таких точках:

- `(yield)`, `(sleep секунды)`, `(wait дескриптор)`
- Операция с каналом, которой приходится ждать (`send`, `recv`, `select`)
- Операция с сокетом, которой приходится ждать (подключение, чтение, запись и т. д.)

Аргумент `sleep` — число секунд типа `f64`. Пишите `(sleep 1.0)`, а не `(sleep 1)`.

Задачи выполняются одновременно на нескольких потоках ОС. Однако когда `typl` выполняет программу напрямую, на другие
потоки уходят только задачи, выполняющие [скомпилированные](../guide/compile.md) функции. Остальные задачи
выполняются на одном потоке, переключаясь в указанных выше точках.

## 6. `thread`: выполнение в отдельном потоке ОС

Работа, которая не должна задерживать другие задачи, например вызов медленной функции C ([FFI для C](../guide/ffi.md)),
запускается через `thread`. Он пишется так же, как `task`, и получает собственный поток ОС. Дождитесь его завершения
через `join`.

```lisp
(defun fib ((n int)) int
  (if (< n 2) n (+ (fib (- n 1)) (fib (- n 2)))))

(let ((th (thread (fib 25))))
  (println "fib(25) = ~a" (join th)))     ; fib(25) = 75025
```

- Дескриптор от `thread` имеет тип `Thread<T>`. Как и `wait`, `join` можно вызывать сколько угодно раз.
- `thread` может выполнять только функции, которые можно скомпилировать. При запуске в `typl` вызываемая им функция
  компилируется на месте перед выполнением.

## 7. Задачи и другие возможности

- `panic` внутри задачи останавливает всю программу.
- `throw` не выходит за пределы задачи. `throw`, который вышел бы из тела задачи, становится `panic`.
- Вывод одного `println` никогда не смешивается посреди строки с выводом других задач.
