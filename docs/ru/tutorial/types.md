# Основы типов

typelisp — язык со статической типизацией. Эта глава объясняет, что делает для вас проверка типов, какие типы вы
будете использовать чаще всего (`Option`, `Result`, структуры и перечисления), и обобщённые типы. Предполагается,
что вы прочитали [Первые шаги](intro.md).

## 1. Что означает статическая типизация

В typelisp тип каждого выражения определяется до запуска программы. Выражение с несовместимыми типами — ошибка ещё
до того, как что-либо выполнится.

```lisp
(defun square ((n int)) int (* n n))

(defun main () ()
  (println "start")
  (println "~a" (square "3")))    ; ошибка типа

(main)
```

Запуск этого файла останавливается на ошибке типа, даже не выведя `start`.

```
error: main.typl:5:25: type error: type mismatch: expected `int`, found `string`
```

Типы нужно писать для аргументов и результатов функций, глобальных переменных и полей структур. Тип переменной
`let` берётся из её начального значения.

Основные типы:

| Тип | Примеры значений |
|---|---|
| `int` | `42`, `-7` (целые произвольной точности) |
| `i8` `i16` `i32` `u8` `u16` `u32` | Целые фиксированной ширины |
| `f64` `f32` | `1.5` |
| `bool` | `true`, `false` |
| `char` | `#\a` |
| `string` | `"hello"` |
| `symbol` | `'foo`, `:key` |
| `()` | Тип результата функции, которая не возвращает значения |

Узнать тип значения во время выполнения нельзя (нет `typep` или `type-of`, как в Common Lisp), потому что каждый тип
известен ещё до запуска программы.

## 2. `Option<T>`: значение, которого может не быть

В typelisp нет `nil`. «Значения может не быть» выражается типом `Option<T>`. Значение `Option<T>` — это либо `some`,
содержащее одно значение `T`, либо `none`, не содержащее ничего.

```lisp
(defun safe-div ((a int) (b int)) Option<int>
  (if (= b 0)
      (Option::none)
      (Option::some (/ a b))))
```

```
typl> (safe-div 10 2)
(some 5)
typl> (safe-div 1 0)
none
```

`Option<int>` — это не `int`, поэтому в арифметике его как есть использовать нельзя. `(+ (safe-div 10 2) 1)` —
ошибка типа. Чтобы использовать содержимое, разделите `some` и `none` с помощью `match`.

```lisp
(defun show-div ((a int) (b int)) string
  (match (safe-div a b)
    ((some q) (format false "~a" q))
    ((none) "undefined")))
```

- В ветви `(some q)` содержимое связывается с переменной `q`.
- `match` проверяет, что его ветви **покрывают все случаи**. Забытая ветвь `(none)` — ошибка типа.

### Почему нет nil

Во многих языках `nil` (`null`) может заменять значение любого типа. В результате забытая обработка случая «нет
значения» остаётся незамеченной до запуска программы. В typelisp место, где значения может не быть, имеет тип
`Option<T>`, и код не пройдёт проверку типов, пока `match` не обработает случай `none`. Забытый случай находится до
запуска программы.

Условия следуют той же идее: условием `if` может быть только `bool`. Правила вроде «всё, кроме `nil`, истинно» из
Common Lisp нет.

### Частые операции

| Форма | Смысл |
|---|---|
| `(unwrap-or opt default)` | Содержимое для `some`; значение по умолчанию для `none` |
| `(unwrap opt)` | Извлекает содержимое. На `none` останавливает программу |
| `(is-some opt)` / `(is-none opt)` | Проверяет, какой это случай |

Многие функции стандартной библиотеки возвращают `Option`. Например, `position` возвращает позицию в `some`, если
элемент найден, и `none`, если нет.

```lisp
(defvar (fruits Vector<string>) (Vector::new))
(push fruits "apple")
(push fruits "banana")

(match (position "banana" (iter fruits))
  ((some i) (println "found at ~a" i))
  ((none) (println "not found")))
```

## 3. `Result<T,E>`: операция, которая может не удаться

Операция, которая может не удаться, возвращает `Result<T,E>`: `ok` со значением `T` при успехе или `err` с ошибкой
`E` при неудаче.

```lisp
(match (parse-int "42")
  ((ok n) (println "n = ~a" (+ n 1)))
  ((err e) (println "error: ~a" (message e))))
;; n = 43

(match (parse-int "4x2")
  ((ok n) (println "n = ~a" (+ n 1)))
  ((err e) (println "error: ~a" (message e))))
;; error: parse-int: invalid integer literal: "4x2"
```

Ваши собственные функции тоже могут возвращать `Result`.

```lisp
(defun checked-age ((n int)) Result<int,string>
  (if (< n 0)
      (Result::err "age must not be negative")
      (Result::ok n)))
```

Используйте `Option`, когда отсутствие значения не требует объяснений, и `Result`, когда нужно сказать, почему
что-то не удалось. Подробнее об обработке ошибок — в [Обработке ошибок](errors.md).

## 4. `defstruct`: структуры

Тип с именованными полями определяется с помощью `defstruct`.

```lisp
(defstruct point
  (x int)
  (y int))
```

Определение даёт вам следующее:

```lisp
(let ((p (point::new 3 4)))     ; создать (аргументы в порядке полей)
  (println "~a" p::x)           ; прочитать поле; (x p) тоже работает
  (setf p::x 10)                ; изменить его
  (println "~a" p))             ; #<point x: 10 y: 4>
```

Чтобы дать структуре собственные функции, используйте `defmethod`. Тип первого аргумента (`self`) определяет, какому
типу принадлежит метод.

```lisp
(defmethod norm2 ((self point)) int
  (+ (* self::x self::x) (* self::y self::y)))

(norm2 (point::new 3 4))        ; => 25
```

Если вместо аргумента `self` написать только имя типа, получится функция, вызываемая как `point::origin`.

```lisp
(defmethod origin (point) point
  (point::new 0 0))

(point::origin)                 ; => #<point x: 0 y: 0>
```

## 5. `defenum`: одна из нескольких форм

Значение, принимающее одну из нескольких форм, например «круг, прямоугольник или точка», определяется с помощью
`defenum`. Каждая форма называется **вариантом**. Каждый вариант может содержать разное число значений разных типов.

```lisp
(defenum shape
  (circle int)        ; радиус
  (rect int int)      ; ширина и высота
  (dot))              ; не содержит значений
```

Значения создаются с именем типа впереди, как `shape::circle`. В `match` они разбираются по имени варианта.

```lisp
(defun area ((s shape)) int
  (match s
    ((circle r) (* 3 r r))
    ((rect w h) (* w h))
    ((dot) 0)))

(area (shape::circle 2))        ; => 12
(area (shape::rect 3 4))        ; => 12
```

И здесь `match` проверяет, что все случаи покрыты. Если позже добавить в `shape` вариант, каждый `match`, который его
не обрабатывает, станет ошибкой типа, так что ни одно место, требующее исправления, не будет пропущено.

После `(use shape)` можно писать `(rect 5 6)` без имени типа.

`Option` и `Result` — перечисления, построенные тем же механизмом.

## 6. Обобщённые типы

Функция, работающая для любого типа, определяется с **параметром типа** `<T>` после имени.

```lisp
(defun first-or<T> ((v Vector<T>) (default T)) T
  (if (= (len v) 0)
      default
      (get v 0)))
```

При вызове тип не указывают. `T` выводится из аргументов.

```lisp
(defvar (ints Vector<int>) (Vector::new))
(defvar (names Vector<string>) (Vector::new))
(push names "Ann")

(first-or ints 7)          ; T — это int
(first-or names "none")    ; T — это string
(first-or ints "none")     ; ошибка типа: ints — это Vector<int>, значит T — это int
```

Структуры и перечисления тоже могут быть обобщёнными. `Vector<T>`, `Option<T>` и `Result<T,E>` — типы такого рода.

```lisp
(defstruct pair<A,B>
  (left A)
  (right B))

(pair::new 1 "one")        ; pair<int,string>
```

Внутри обобщённой функции о `T` ничего не известно, поэтому значения `T` нельзя ни сравнивать, ни складывать. Чтобы
потребовать что-то вроде «любой тип, который можно сравнивать», используйте трейты ([Трейты](traits.md)).

## 7. Другое имя для типа

`deftype` даёт типу другое имя.

```lisp
(deftype meters int)
(defun double ((m meters)) meters (* m 2))
```

`meters` — это просто другое написание `int`, а не новый тип. Передать обычный `int` туда, где ожидается `meters`, —
не ошибка. Если нужно их различать, создайте структуру, например `(defstruct meters (value int))`.
