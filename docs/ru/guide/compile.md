# Компиляция

Если ничего специально не делать, программы typelisp выполняются интерпретатором. Кроме того, есть два способа
компиляции в машинный код и один способ сохранить окружение. Подробности спецификации — в
[главе 10 справочника по синтаксису](../reference/syntax.md#10-компиляция).

| Способ | Как | Результат |
|---|---|---|
| JIT-компиляция | `(compile name)` | Функция в текущем сеансе заменяется машинным кодом |
| AOT-компиляция | `typl -c src.typl` или `(compile-file "src.typl" "out")` | Самостоятельный исполняемый файл |
| Дамп | `(dump "file.typld")` | Сохраняет определения; `typl --image` запускается снова с тем же окружением |

## 1. Подготовка

Компиляция использует LLVM 22. Если вы собрали `typl` по [README.md](../../../README.md), никакой дополнительной
подготовки не нужно.

Исполняемые файлы, получаемые AOT-компиляцией, компонуются со статической библиотекой `libtypelisp_front.a`.
Релизная сборка `typl` (включая установленную через `cargo install`) несёт эту библиотеку внутри себя, поэтому
подготовка не нужна. При первой компиляции она записывает библиотеку в `~/.typelisp/lib/<идентификатор сборки>/` (или
в `$TYPELISP_HOME/lib/<идентификатор сборки>/`, если задана переменная окружения `TYPELISP_HOME`) и дальше использует
эту копию. `typl --remove-lib` удаляет её (с `--others` — записанные другими версиями `typl`; с `--all` — все).
Отладочная сборка `typl` использует библиотеку в `target/debug/` репозитория, где она была собрана. Чтобы
использовать библиотеку, лежащую в другом месте, укажите её каталог через `--lib-dir` при запуске `typl`
(раздел 3.2). В macOS для компоновки используются Xcode Command Line Tools.

## 2. JIT-компиляция

Превращает уже определённую функцию в машинный код прямо на месте.

```lisp
(defun fib ((n int)) int
  (if (< n 2) n (+ (fib (- n 1)) (fib (- n 2)))))

(compile fib)
(fib 30)           ; с этого момента вызовы выполняют скомпилированный код
```

- `name` не вычисляется. Пишите имя функции как есть (не строкой). Для метода пишите его с именем типа, как
  `(compile point::norm)`.
- Вызываемые функции компилируются вместе с ней.
- **Обобщённые функции компилировать нельзя.** Для каждого типа в каждом месте использования создаётся своя копия.
  Вместо этого компилируйте функцию, которая вызывает её с конкретными типами.
- `trace`, `step`, `disassemble`, `compile`, `compile-file` и `dump` — операции интерпретатора, поэтому функцию,
  которая их вызывает, скомпилировать нельзя. Попытка даёт ошибку с объяснением причины.

Чтобы посмотреть результат компиляции, используйте `disassemble`.

```lisp
(disassemble fib)          ; машинный код хоста
(disassemble fib true)     ; LLVM IR
```

## 3. Сборка исполняемого файла AOT-компиляцией

### 3.1 Написание программы

В качестве точки входа определите **функцию `main` без аргументов**.

```lisp
;; hello.typl
(defun fib ((n int)) int
  (if (< n 2) n (+ (fib (- n 1)) (fib (- n 2)))))

(defun main () ()
  (println "args: ~a" (command-line-args))
  (println "fib(25) = ~a" (fib 25)))

(main)
```

`(main)` в конце файла нужен для того, чтобы `main` вызывалась при запуске `typl hello.typl`. `compile-file`
пропускает этот завершающий `(main)`, так что один и тот же файл работает и в интерпретаторе, и при AOT-компиляции.

### 3.2 Компиляция

В командной строке используйте `typl -c` (`typl --compile` — то же самое).

```sh
$ typl -c hello.typl            # создаёт hello
$ typl -c hello.typl -o fib     # называет исполняемый файл fib
$ ./hello a b
args: #(./hello a b)
fib(25) = 75025
```

Без `-o` исполняемый файл получает имя исходного файла без `.typl` и помещается в тот же каталог, что и исходный файл.
Если имя исходного файла не оканчивается на `.typl`, `-o` обязателен. С `-c` (`--compile`) нельзя указывать
`--image`, `--heap-cells` и `--feature`.

То же самое можно сделать, вызвав `compile-file` из REPL или из программы.

```sh
$ typl
typl> (compile-file "hello.typl" "hello")
typl> :quit
$ ./hello a b
args: #(./hello a b)
fib(25) = 75025
```

Если вы собираете часто, можно поместить эту строку в файл и запускать его командой `typl build.typl`.

```lisp
;; build.typl
(compile-file "hello.typl" "hello")
```

Имена файлов разрешаются относительно **текущего каталога, в котором был запущен `typl`**, а не относительно
местоположения `build.typl`.

Чтобы скомпоновать с `libtypelisp_front.a`, лежащей не там, где её ищет `typl`, укажите её каталог через `--lib-dir`.
Это действует и для `typl -c`, и для `compile-file`.

```sh
$ typl --lib-dir ~/lib/typelisp -c hello.typl
$ typl --lib-dir ~/lib/typelisp build.typl
```

Если в указанном каталоге нет `libtypelisp_front.a`, `typl` останавливается с ошибкой. Файл работает только с тем
`typl`, который был собран вместе с ним. После пересборки `typl` скопируйте его заново.

### 3.3 Что может содержать файл для AOT-компиляции

- Верхний уровень входного файла может содержать только определения (`defun` `defmethod` `defvar`
  `defparameter` `defconstant` `defmacro` `defsignature` `defstruct` `defenum` `deftype` `deftrait`
  `impl` `defffi`, `(unsafe (def-c-struct ...))`), а также `use` и `module`. Выражения верхнего уровня
  вроде `(println ...)` не допускаются, кроме завершающего `(main)`. Размещайте работу внутри `main`.
- Без `main` без аргументов компиляция завершается ошибкой.
- Файлы подключённых через `use` модулей тоже компилируются и объединяются в один исполняемый файл.
- Библиотеки, указанные через `:library` в `defffi`, компонуются автоматически ([FFI для C](ffi.md)).
- Все функции стандартной библиотеки можно использовать при AOT-компиляции. `eval` тоже, но тогда в исполняемый файл
  попадают проверка типов и интерпретатор, отчего он становится больше и медленнее запускается. Программы, не
  вызывающие `eval`, их не содержат.

### 3.4 Поведение исполняемого файла

- `(command-line-args)` возвращает `Vector<string>` одинаковой формы, запускать ли `typl hello.typl a b` или
  `./hello a b`. Первый элемент — имя программы.
- Код завершения задаётся через `(exit n)`. Если `main` возвращается нормально, он равен 0.
- При `panic` программа выводит сообщение и завершается с ненулевым кодом.

## 4. Дампы

Определения текущего сеанса можно сохранить в один файл и в следующий раз начать с него.

```sh
$ typl
typl> (defun sq ((n i32)) i32 (* n n))
typl> (compile sq)
true
typl> (dump "session.typld")
true
typl> :quit
$ typl --image session.typld
typl> (sq 9)
81
```

Это работает и при запуске файла, как `typl --image session.typld prog.typl`.

- Сохраняются **определения**. Выражения, вычисленные в сеансе, не сохраняются.
- Функции, скомпилированные через `compile`, сохраняются в скомпилированном виде.
- Глобальные переменные восстанавливаются **повторным выполнением их инициализаторов**, а не со значениями, которые
  они имели в момент записи дампа.
- Дамп нельзя загрузить `typl` другой версии, чем та, что его записала (это ошибка).

Если вы запускаете файл и делаете из него `(dump ...)`, определения этого файла находятся в модуле, названном по
имени файла. Функция, определённая в `dp.typl`, называется `dp::sq`, и для вызова из другого файла нужен `pub`
([Модули и разбиение на файлы](modules.md)).

## 5. О скомпилированных файлах модулей

Формата наподобие `.fasl` из Common Lisp для записи скомпилированного результата каждого модуля в файл нет.
`compile-file` строит исполняемый файл прямо из исходников. Промежуточных файлов не остаётся.
