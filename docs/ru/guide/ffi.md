# FFI для C (defffi)

Это руководство объясняет, как вызывать функции C из typelisp. Список объявляемых типов и ограничения приведены в
[Справочнике по синтаксису 3.3](../reference/syntax.md#33-defffi--объявление-функций-c-ffi).

## 1. Объявление и вызов функции

`defffi` объявляет имя и типы функции C.

```lisp
(defffi (c-getpid "getpid") () i32)            ; имя в typelisp и имя символа в C
(defffi (c-strlen "strlen") (string) c-ulong)
(defffi (c-cos "cos") (f64) f64 :library "m")  ; искать в libm
```

Вызовы оборачиваются в `(unsafe ...)`.

```lisp
(unsafe (c-getpid))        ; => 12345
(unsafe (c-cos 0.0))       ; => 1.0
```

`unsafe` нужен потому, что компилятор не может проверить, совпадают ли объявленные типы с реальными типами на стороне
C. Написав `unsafe`, вы, автор, берёте ответственность за эту проверку на себя. Если его забыть, будет ошибка с
объяснением.

## 2. Безопасная обёртка

Задуманный способ — ограничить `unsafe` одним местом и показывать наружу обычную функцию.

```lisp
(defun pid () i32 (unsafe (c-getpid)))
(defun str-len ((s string)) int (as int (unsafe (c-strlen s))))

(pid)              ; вызывающему unsafe не нужен
(str-len "hello")  ; => 5
```

## 3. Соответствие типов

| typelisp | C |
|---|---|
| `i8` `i16` `i32` / `u8` `u16` `u32` | Целые той же ширины |
| `f32` / `f64` | `float` / `double` |
| `bool` | `bool` (`_Bool`) |
| `()` | `void` |
| `string` | `const char *` |
| `c-long` / `c-ulong` | `long` / `unsigned long` (а также `size_t`, `int64_t` и т. п.) |
| `ptr` | Любой указатель (`void *`, `FILE *` и т. п.) |
| `(ptr T)` | Указатель на `T` ([раздел 7](#7-структуры-c)) |

### Строки

- Передаваемая `string` копируется в строку C с завершающим NUL, которая освобождается после возврата из вызова. NUL
  в середине строки — ошибка.
- Результат функции, возвращающей `string`, тоже копируется. Память на стороне C не освобождается. Для функций,
  возвращающих строку, которую должен освободить вызывающий (например, `strdup`), принимайте результат как `ptr` и
  вызывайте `free` сами.
- Если функция, объявленная как возвращающая `string`, возвращает NULL, это ошибка. Результат функций, которые могут
  вернуть NULL (например, `getenv`), принимайте как `ptr`.

### `c-long` / `c-ulong` / `ptr`

Эти типы существуют только для передачи значений через границу с C и **не поддерживают арифметику**. Чтобы
использовать такое значение как целое typelisp, преобразуйте его через `as`.

```lisp
(as int (unsafe (c-strlen s)))      ; int не теряет ничего из 64-битного значения
(try-as i32 (unsafe (c-strlen s)))  ; none, если не помещается в i32
(unsafe (c-malloc 16))              ; целочисленные литералы можно передавать как есть
```

`ptr` — значение, которое передаётся обратно функциям C. Прочитать, на что он указывает, со стороны typelisp нельзя.

```lisp
(defffi (c-malloc "malloc") (c-ulong) ptr)
(defffi (c-free "free") (ptr) ())

(unsafe (let ((p (c-malloc 16)))
          (c-free p)
          ()))
```

Эти типы могут встречаться только как аргументы функций, результаты и локальные переменные. Они не могут быть полями
структур, глобальными переменными или аргументами типа `Vector` и подобных.

## 4. Указание библиотеки

Без `:library` символ ищется в том, что уже скомпоновано с процессом (libc и т. п.). Функциям из других библиотек
нужен `:library`.

```lisp
(defffi (sqlite-version "sqlite3_libversion") () string :library "sqlite3")
```

- Короткое имя вроде `"sqlite3"` ищется как `libsqlite3.dylib`, затем как `libsqlite3.so`.
- Имя, содержащее `/`, считается путём.
- Если объявленный символ не найден, ошибка называет его.

## 5. AOT-компиляция

Программы, использующие `defffi`, можно как есть превратить в исполняемые файлы через
[`compile-file`](compile.md#3-сборка-исполняемого-файла-aot-компиляцией). Библиотеки, указанные через `:library`,
добавляются при компоновке автоматически, поэтому `compile-file` не нужны дополнительные аргументы.

## 6. Обратные вызовы

Функцию typelisp можно передать функции C, чтобы та её вызвала. Напишите тип функции среди типов аргументов
`defffi`, а при вызове поставьте в эту позицию имя функции или выражение `lambda`.

```lisp
(defffi (c-free "free") (ptr) ())
(defffi (c-strdup "strdup") (string) ptr)
(defffi (c-strncmp "strncmp") (ptr ptr c-ulong) i32)
(defffi (text-of "strstr") (ptr string) string)          ; strstr(p, "") возвращает p
(defffi (c-qsort "qsort") (ptr c-ulong c-ulong (fn (ptr ptr) i32)) ())

(defun sort-chars ((s string)) string
  (unsafe
    (let ((buf (c-strdup s)))
      (c-qsort buf (as c-ulong (length s)) 1
               (lambda ((a ptr) (b ptr)) i32 (c-strncmp a b 1)))
      (let ((r (text-of buf ""))) (c-free buf) r))))

(sort-chars "cadb")    ; => "abcd"
```

- Передавать можно только функции **без свободных переменных**. Функции верхнего уровня, `lambda` и локальные
  функции `labels` работают, но обращение к локальной переменной объемлющей области — ошибка при проверке типов. C
  передаёт только объявленные аргументы, так что доставить захваченные переменные невозможно. Для хранения состояния
  используйте глобальные переменные.
- Переменную, содержащую функцию, передать нельзя. Пишите на её месте имя функции или выражение `lambda`.
- `panic` или `throw` внутри обратного вызова доходит до вызывающего после возврата функции C.
- Обратный вызов можно вызывать только пока выполняется функция C, вызванная из typelisp. Использовать его из
  `atexit`, обработчиков сигналов и т. п. нельзя.

## 7. Структуры C

Чтобы передать функции C что-то вроде массива структур, объявите через `def-c-struct` структуру с той же раскладкой,
что и в C, и выделите её внутри `unsafe`.

```lisp
(unsafe (def-c-struct item (key i32) (tag u8)))    ; объявляется внутри unsafe верхнего уровня

(defffi (c-qsort "qsort") (ptr c-ulong c-ulong (fn ((ptr item) (ptr item)) i32)) ())

(defun put ((xs (ptr item)) (i int) (k i32)) i32
  (unsafe (let ((p (c-ref xs i))) (setf p::key k))))

(defun key-at ((xs (ptr item)) (i int)) int
  (unsafe (let ((p (c-ref xs i))) (as int p::key))))

(defun sorted-keys () int
  (unsafe
    (let ((xs (c-alloc item 4)))                    ; четыре элемента, все нули
      (put xs 0 3) (put xs 1 1) (put xs 2 4) (put xs 3 2)
      (c-qsort (as ptr xs) 4 8
               (lambda ((a (ptr item)) (b (ptr item))) i32 (- a::key b::key)))
      (+ (* 1000 (key-at xs 0)) (* 100 (key-at xs 1))
         (* 10 (key-at xs 2)) (key-at xs 3)))))

(sorted-keys)    ; => 1234
```

- `(c-alloc T n)` выделяет `n` значений `T` и возвращает `(ptr T)`. `(c-ref p i)` — указатель на `i`-й элемент,
  `p::field` — поле, а `(c-deref p)` — то, на что указывает указатель на скаляр вроде `i32`. Всё это можно записывать
  через `setf`.
- `(as ptr p)` превращает его в нетипизированный `ptr` для передачи функциям C, принимающим `void *`.
- Размер `item` (здесь 8) и положение каждого поля определяются по тем же правилам, что и в C.

### Время жизни выделенной памяти

Выделенная память освобождается, когда управление покидает самый внешний `unsafe` в этой функции. То же происходит
при выходе через `panic` или `throw`. Поэтому значение `(ptr T)` нельзя вынести за пределы `unsafe`. Сделать его
значением `unsafe`, захватить в замыкании, передать в `task` или бросить через `throw` — всё это ошибки типа.
Значения, которые нужны снаружи, скопируйте внутри `unsafe` в числа или в `defstruct`.

При выделении памяти внутри `lambda` или функции `labels` пишите `unsafe` внутри этой функции.

### Память, выделенная C

Указатель, полученный от C как `(ptr T)` (результат `defffi`, аргумент обратного вызова и т. п.), — ошибка, если он не
указывает внутрь памяти, выделенной через `c-alloc`. Функции, получающие память, выделенную C через `malloc`, или
NULL, объявляйте с нетипизированным `ptr`.

## 8. Чего сделать нельзя

- **Функции с переменным числом аргументов** (`printf` и подобные) объявить нельзя. Переменная часть передаётся по
  иным правилам, чем фиксированные аргументы. Объявите отдельное имя для каждого используемого числа аргументов.
- **Передача или возврат структур по значению** невозможны. Используйте функции, передающие указатели.
- **Обобщённые объявления** невозможны.
- **То же имя, что у встроенной функции**, использовать нельзя.
- **Их нельзя передавать как функциональные значения.** Передать такую функцию, как в `(map xs c-abs)`, нельзя;
  оберните её в `lambda`.

  ```lisp
  (unsafe (lambda ((n i32)) i32 (c-abs n)))
  ```
