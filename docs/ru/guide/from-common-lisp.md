# Для программистов на Common Lisp

typelisp наследует синтаксис Common Lisp (CL) и многие имена его функций, но это язык со статической типизацией.
Поэтому код на CL не всегда работает в том виде, как написан. Это руководство собирает места, где привыкшие к CL
обычно спотыкаются, вместе со способами переписать код.

## 1. Нет `nil` и `t`

Логические значения — `true` и `false`. `nil` и `t` не определены.

```lisp
(if (> x 0) "pos" "non-pos")
(defvar (debug bool) false)
```

- **Условием может быть только `bool`.** Запись `0` или пустого списка в условии — ошибка типа. Правила «всё, кроме
  nil, истинно» нет.
- **Ветвь «иначе» у `if` опустить нельзя.** `(if c x)` — ошибка. Когда ветвь «иначе» не нужна, используйте `when` /
  `unless`.
- **«Нет значения» выражается через `Option<T>`.** Функция, которая в CL возвращала nil в смысле «не найдено», здесь
  возвращает `(some x)` или `none`.

  ```lisp
  (match (position 3 (iter v))
    ((some i) (println "found at ~a" i))
    ((none) (println "not found")))
  ```

- Пустой список `()` в зависимости от контекста — это либо значение типа Unit (результат функции, которая ничего не
  возвращает), либо пустой список данных S-выражений. Это значение, отличное от `false`.

## 2. Запись типов

Аргументы и результаты функций должны иметь типы.

```lisp
(defun area ((w i32) (h i32)) i32
  (* w h))

(defun first-or<T> ((v Vector<T>) (default T)) T      ; обобщённая функция
  (unwrap-or (first (iter v)) default))
```

- Определение без типов, такое как `(defun f (x) x)`, написать нельзя.
- Глобальным переменным, как в `defvar`, тоже нужен тип: `(defvar (count int) 0)`.
- `the` — не проверка во время выполнения, а аннотация для проверки типов.
- **Способа исследовать типы во время выполнения нет.** Нет ни `typep`, ни `type-of`, потому что тип каждого значения
  фиксируется при компиляции. Чтобы принимать один из нескольких типов, создайте тип-сумму через `defenum` или
  используйте трейт.
- `deftype` определяет псевдоним типа. Тип, описывающий диапазон значений, как `(deftype small () '(integer 0 9))`,
  создать нельзя.

Целый тип по умолчанию `int` имеет произвольную точность; как и integer в CL, верхнего предела у его размера нет.
Существуют также типы фиксированной ширины от `i8` до `i32` и от `u8` до `u32`. Целого типа фиксированной ширины в
64 бита нет.

## 3. Функции как значения

typelisp не разделяет пространства имён функций и переменных. Имя функции можно передать как значение как есть. Нет
ни `#'`, ни `funcall`.

```lisp
(defun twice ((x int)) int (* 2 x))
(defun apply-to ((f (fn (int) int)) (x int)) int
  (f x))                                  ; вызывать напрямую, не через funcall

(apply-to twice 5)                        ; twice, а не #'twice
```

- Встроенные функции вроде `+` и `1+` тоже можно передавать как значения как есть, когда тип аргумента фиксирован,
  как в `(fn (int) int)`. При передаче такой функции обобщённой функции вроде `foldl` или `map` неизвестно, `+` какого
  типа имеется в виду, поэтому оберните её в `lambda`.

  ```lisp
  (apply-to 1+ 5)                                          ; => 6
  (foldl (iter v) (lambda ((acc int) (x int)) int (+ acc x)) 0)
  ```

- Функции последовательностей принимают **сначала коллекцию, затем функцию**: `(map it f)`, `(filter it f)`,
  `(foldl it f init)`. Это обратно `(mapcar f list)` из CL.
- `lambda` не может использовать `&optional` и `&key` (`&rest` можно).
- **Функцию нельзя вызвать до её определения.** В CL можно вызвать функцию, определённую позже, а здесь это даёт
  `no such function`. Для взаимно рекурсивных функций сначала объявите одну из них через `defsignature`.

  ```lisp
  (defsignature odd2 (i32) bool)
  (defun even2 ((n i32)) bool (if (= n 0) true (odd2 (- n 1))))
  (defun odd2 ((n i32)) bool (if (= n 0) false (even2 (- n 1))))
  ```

## 4. Списки и Vector

Соответствие списку CL — **данные S-выражений**, тип которых `Option<Sexpr>` (пустой список — `none`).
`(list 1 2 3)` и `'(a b c)` имеют этот тип. С данными S-выражений работают макросы и `read`; как обычный контейнер
данных используйте **`Vector<T>`**.

| Что нужно | CL | typelisp |
|---|---|---|
| Голова и хвост S-выражения | `(car xs)` `(cdr xs)` | `(sexpr-car xs)` `(sexpr-cdr xs)` |
| Обход списка S-выражений | `(dolist (x xs) ...)` | То же |
| Последовательность элементов одного типа | Список или вектор | `Vector<T>` |
| Пара | `(cons a b)` | `(cons a b)` (её тип — `cons-cell<A,B>`) |
| Отображение | `(mapcar f xs)` | `(map (iter v) f)` |

`car` / `cdr` — это аксессоры пары `cons-cell<A,B>`, созданной через `cons`. К спискам S-выражений их применять
нельзя.

`Vector` записывается через `#(..)`, как вектор в CL, и печатается тоже как `#(..)`:

```lisp
(let ((v #(1 2)))
  (push v 3)
  (map (iter v) (lambda ((x int)) int (* x 10))))   ; => #(10 20 30)
```

От CL есть три отличия. Все элементы должны быть одного типа (`#(1 "a")` — ошибка типа). Каждое
вычисление создаёт новый вектор, поэтому его изменение не влияет на следующее вычисление (в CL
результат изменения литерала не определён). Пустому `#()` нужен тип, как в `(the Vector<int> #())`.
Многомерный массив записывается как `#2A((1 2) (3 4))`, как в CL.

Функции последовательностей вроде `map`, `filter`, `sort` и `find` работают со значениями, реализующими трейт `Iter`.
Передавайте `Vector`, превратив его в итератор через `(iter v)`.

## 5. Нет множественных значений

Нет ни `values`, ни `multiple-value-bind`. Функции, которые в CL возвращают несколько значений, здесь возвращают
пару или структуру.

| CL | typelisp |
|---|---|
| `(floor 7 2)` → 3, 1 | `(floor-div 7 2)` → `cons-cell` с `car` 3 и `cdr` 1 |
| `(decode-universal-time t)` → 9 значений | Структура `decoded-time` |
| `(read-from-string s)` → значение, позиция | `(read-from-string s)` возвращает `cons-cell` из значения и позиции внутри `Result`. Только значение — `(read s)` |

## 6. Нет специальных переменных (динамического связывания)

`let` всегда связывает лексически. Если перепривязать переменную, определённую через `defvar`, с помощью `let`,
вызываемые оттуда функции всё равно видят исходное значение.

```lisp
(defvar (*depth* int) 1)
(defun show () () (println "~a" *depth*))
(let ((*depth* 2)) (show))       ; в CL 2, в typelisp 1
```

Чтобы временно изменить управляющую переменную вроде `*print-base*`, используйте `dlet`. Он присваивает значение и
восстанавливает исходное, как бы ни было покинуто тело.

```lisp
(dlet ((*print-base* 16))
  (format false "~a" 255))       ; => "ff"
```

`dlet` перезаписывает саму глобальную переменную, так что это не привязка на уровне потока.

## 7. Система условий не перенята

Нет `define-condition`, `handler-case`, `handler-bind`, `restart-case`, `error` и `signal`. Они плохо сочетаются со
статической типизацией. Вместо них для разных целей используются два механизма:

- **Восстановимые неудачи возвращают `Result<T,E>`.** Вызывающий разделяет `ok` / `err` через `match`. Сокращения
  вроде `?` из Rust нет.

  ```lisp
  (match (parse-int "42x")
    ((ok n) n)
    ((err e) (progn (println "bad input: ~a" (message e)) 0)))
  ```

- **Невосстановимые неудачи (ошибки в программе) — это `panic`.** `(panic "message")`, передача `none` в `unwrap`,
  деление на 0 и индекс вне диапазона относятся к этому виду, и программа останавливается. Перед остановкой
  выполняется очистка `unwind-protect`.

Типы ошибок объединены трейтом `Error`, и `(message e)` даёт сообщение. Как создать свой тип ошибки, описано в
[Option, Result и типах ошибок](../reference/functions/option-result.md#3-типы-ошибок-и-трейт-error). `assert` и
`warn` можно использовать как в CL.

`catch` / `throw` / `unwind-protect` есть. Однако метка `catch` ограничена невычисляемым литеральным символом
(`'done`), а значения, бросаемые с одной меткой, имеют один тип.

## 8. Нет CLOS

Нет `defclass`, `defgeneric` и комбинации методов.

- Типы данных определяются через `defstruct` (структуры) и `defenum` (типы-суммы).
- `defmethod` определяет методы, цель которых определяется только **статическим типом первого аргумента**.
  Множественной диспетчеризации нет.
- Чтобы дать разным типам общие операции, используйте трейты (`deftrait` / `impl`). Для значений, конкретный тип
  которых определяется во время выполнения, используйте тип `:dyn Trait`
  ([Справочник по синтаксису 3.9](../reference/syntax.md#39-deftrait--impl--трейты)).

Чем отличается `defstruct`:

- Конструктор — `ИмяТипа::new`: `(point::new 1 2)`. Если нужно имя вроде `make-point`, его создаёт опция
  `(:constructor make-point)`.
- Помимо `(x p)` аксессор можно записать как `p::x`. Изменяется через `(setf p::x 5)`.
- Предикат (`point-p`) не создаётся. Нет `:conc-name`, `:type` и `:named`.
- `:include` наследует только слоты; тип не становится подтипом родителя.

## 9. Модули вместо пакетов

Пакетов нет. Пространства имён — это модули, и файл сам по себе является модулем. Вместо `pkg:symbol` пишите
`module::name`, а имена подключайте через `use` ([Модули и разбиение на файлы](modules.md)).

Ключевые слова `:foo` существуют и являются символами, вычисляющимися в себя. Поскольку пакетов нет, двоеточие —
часть имени: `(symbol->string :foo)` возвращает `":foo"`.

## 10. Отличия в чтении и синтаксисе

- Верхний и нижний регистр не различаются (символы при чтении переводятся в нижний регистр). Как в CL.
- Нет `#'` (раздел 3). Литералы комплексных чисел `#c(...)` прочитать нельзя; комплексные числа создавайте через
  `(complex 1.0 2.0)`.
- Предложения расширенного `loop` пишутся ключевыми словами: `(loop :for i :from 1 :to 3 :collect i)`. `loop`,
  начинающийся не с ключевого слова, — простой бесконечный цикл, из которого выходят через `(break)` или
  `(return значение)`. `return` выходит из самого внутреннего цикла (чтобы выйти из функции, используйте
  `return-from`).
- Назначение `format` — `false` (вернуть строку), `true` (стандартный вывод) или поток. Директивы формата те же, что в
  CL.
- Чтение из строки — `(read "...")`, чтение из потока — `(read-sexpr s)`. Оба возвращают `Result`.
- `eval` проверяет типы переданного выражения до вычисления и возвращает `Result`. Опережающие ссылки невозможны, как
  и в исходном коде.
- `eval-when` нет.
- В именах функций не используются суффиксы `?` и `!`. Предикаты называются с `-p` / `p`, как в CL (`zerop`,
  `sexpr-null`), или с `is-` впереди (`is-some`).

## 11. Основные функции с другими именами

| CL | typelisp |
|---|---|
| `string-upcase` / `string-downcase` | `upcase` / `downcase` |
| `read` (из потока) | `read-sexpr` |
| `pathname` | `to-pathname` |
| Двухаргументные версии `floor` и подобных | `floor-div` `ceiling-div` `round-div` `truncate-div` |
| `mapcar` | `map` (порядок аргументов обратный; раздел 4) |
| `length` (вектора) | `len` |
| `hash-table-count` | `count` / `size` |

Список функций приведён во [Встроенных функциях](../reference/functions/README.md).

## 12. Чего ещё нет

- `progv`, `symbol-function`, `symbol-value`
- `*readtable*` и `copy-readtable`, `readtable-case` (сами макросы чтения можно определить через
  `set-macro-character`)
- Логические пути и пути с шаблонами
- `input-stream-p` / `output-stream-p` (направление потока определяется его типом)
