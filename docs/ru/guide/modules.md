# Модули и разбиение на файлы

Это руководство объясняет, как собрать программу из нескольких файлов. Подробные правила — в разделах 3.10–3.13
[Справочника по синтаксису](../reference/syntax.md#310-module--use--пространства-имён).

## 1. Один файл — один модуль

В typelisp **файл сам по себе является модулем**. Путь файла относительно корня исходников — это путь модуля.

| Файл | Модуль |
|---|---|
| `<root>/geometry.typl` | `geometry` |
| `<root>/geo/shapes.typl` | `geo::shapes` |
| `<root>/net/http/client.typl` | `net::http::client` |

Писать объявление модуля в начале файла не нужно.

## 2. Настройка проекта

Положите в корень проекта файл с именем `typelisp.toml`. Он может быть пустым.

```
myapp/
├── typelisp.toml
├── main.typl
└── geometry.typl
```

Чтобы держать исходники в `src/`, напишите в `typelisp.toml` одну строку:

```toml
src = "src"
```

`typl` ищет `typelisp.toml`, начиная с каталога запускаемого файла и поднимаясь вверх, и использует найденное место
как корень исходников. Если файл не найден, корнем считается каталог запускаемого файла (в REPL — текущий каталог).

## 3. Публикация определений и их использование

`geometry.typl`:

```lisp
(pub defstruct point
  (pub x i32)
  (pub y i32)
  (tag string))                        ; поле без pub нельзя прочитать снаружи

(defun square ((n i32)) i32 (* n n))   ; функцию без pub тоже нельзя вызвать снаружи

(pub defun dist2 ((a point) (b point)) i32
  (+ (square (- a::x b::x)) (square (- a::y b::y))))

(pub defmethod origin (point) point (point::new 0 0 "o"))
```

`main.typl`:

```lisp
(use geometry)

(let ((a (geometry::point::origin))
      (b (geometry::point::new 3 4 "b")))
  (println "~a" (geometry::dist2 a b)))
```

```sh
typl main.typl        # => 25
```

`geometry.typl` загружается в том месте, где написан `(use geometry)`. Загружать его заранее не нужно.

### Что делается публичным

- Функции, структуры, перечисления, глобальные переменные, макросы и методы видны из других модулей, только если у
  них есть `pub`. Ставьте `pub` прямо перед определением, как в `(pub defun ...)`.
- Для структур **публичность типа и публичность полей — разные вещи**. `(pub defstruct point ...)` делает видимым
  тип, а читать и писать снаружи можно только поля, записанные как `(pub x i32)`.
- Использование снаружи непубличного имени даёт ошибку «не удаётся разрешить», например
  `unresolved path: geometry::square`. Это то же сообщение, что и для имени с опечаткой, так что если написание
  верное, а имя всё равно не разрешается, подозревайте отсутствующий `pub`.

Список определений, к которым применим `pub`, приведён в
[Справочнике по синтаксису 3.13](../reference/syntax.md#313-pub--видимость).

## 4. Как писать `use`

```lisp
(use geometry)              ; подключить модуль; чтобы использовать, писать geometry::dist2
(use geometry::dist2)       ; подключить функцию; использовать по голому имени dist2
(use geometry::point)       ; подключить тип; писать point::new, point::origin и point в аннотациях типов
(use a::f b::g)             ; можно писать несколько сразу
```

- **`use` действует только на формы после него.** Ставьте его в начало файла. Запись `geometry::dist2` выше `use`
  даёт `unresolved path`.
- Полный путь `geometry::dist2` без подключения модуля через `use` тоже не разрешается. Загрузку файла вызывает только
  `use`.
- Подключение через `use` имени, голая форма которого уже занята, даёт предупреждение. Если вы всё же хотите его
  подключить, используйте `shadowing-import`.
- Модуль внутри каталога пишется как `(use geo::shapes)`, а дальше к нему обращаются по последней части
  (`shapes::...`).

### Вызов методов трейтов

Методы, реализованные в `impl`, **принадлежат типу**, а не функциям модуля, поэтому их вызывают без имени модуля.

```lisp
(use shapes::core)
(println "~a" (area (core::square::new 4)))    ; area, а не core::area
```

Методы внутри `impl` всегда публичны, даже без `pub`.

Сам трейт нельзя сделать публичным для других модулей. Держите определение трейта, его `impl` и код, использующий его
через `:dyn`, в одном модуле.

## 5. Разделение пространств имён внутри файла

Чтобы дополнительно разделить пространство имён внутри одного файла, используйте `module`. Он вкладывается в
собственный модуль файла.

```lisp
;; внутри main.typl
(module util
  (pub defun clamp ((x i32) (lo i32) (hi i32)) i32
    (if (< x lo) lo (if (> x hi) hi x))))

(println "~a" (util::clamp 15 0 10))    ; main::util::clamp
```

Чтобы поместить весь остаток файла в одно пространство имён, вместо обёртывания в скобки можно написать
`(in-module util)`.

## 6. Ограничения на зависимости

- **Циклы не допускаются.** Если `a.typl` делает `(use b)`, а `b.typl` делает `(use a)`, получится ошибка
  `circular module dependency: a -> b -> a`. Перенесите определения, нужные обоим, в третий модуль.
- **Ни на типы, ни на функции нельзя ссылаться до их определения**, даже в одном файле. Для взаимно рекурсивных
  функций сначала объявите одну из них через `defsignature`
  ([Справочник по синтаксису 3.2](../reference/syntax.md#32-defsignature--опережающие-объявления)).

## 7. Порядок выполнения

Запуск `typl main.typl` проходит в таком порядке:

1. `main.typl` и все файлы, подключённые из него через `use`, читаются и проверяются по типам. **Если где-либо есть
   ошибка типа, ничего не выполняется.**
2. Выражения верхнего уровня подключённых модулей выполняются раньше выражений подключающих их модулей.
3. Выражения верхнего уровня `main.typl` выполняются сверху вниз.

Если собрать точку входа программы в функцию `main` и вызвать `(main)` в конце файла, тот же файл можно использовать и
для [AOT-компиляции](compile.md#3-сборка-исполняемого-файла-aot-компиляцией).

## 8. Чем это отличается от `load`

`(load "path")`, как и `load` в Common Lisp, читает содержимое файла **как есть в текущее пространство имён**. Он не
оборачивает его в модуль, и `pub` не играет роли. Используйте его, например, чтобы прочитать файл настроек или
перезагрузить локальный файл в REPL. Чтобы разбить программу на части, используйте `use`.
