# REPL

Если запустить `typl` без аргументов, откроется REPL (интерактивный режим). В этом документе
описано, что умеет REPL помимо вычисления выражений: его команды, помощь при вводе, обращение к
предыдущим результатам, остановка вычисления и разбор после ошибки.

## Запуск и выход

```
$ typl
typl> (+ 1 2)
3
typl> :quit
```

Выход — `:quit` (коротко `:q`) или `Ctrl+D`. История ввода сохраняется в `~/.typl_history`, и при
следующем запуске её можно вызвать с помощью `Ctrl+P` / `Ctrl+N` или `Ctrl+R` (поиск по истории).

При запуске, до первого приглашения, по порядку выполняется следующее. Ни один из этих шагов не
выводит получившиеся значения.

1. Содержимое `~/.typlrc`, если файл есть. С `--no-init` он не читается.
2. `--eval FORM` и `--load FILE` из командной строки в том порядке, в каком они записаны. Оба можно
   указывать сколько угодно раз.

```
$ typl --load util.typl --eval '(println "ready")'
ready
typl>
```

`--eval`, `--load` и `--no-init` предназначены только для запуска REPL. Указать их при запуске
файла — ошибка.

REPL начинает работу в модуле `user`. Если перейти в другой модуль с помощью `(in-module foo)`,
приглашение показывает этот модуль.

```
typl> (in-module foo)
typl user::foo>
```

## Команды REPL

`:имя`, записанное в начале строки, — это команда REPL. `:help` выводит их список. `:имя`, которого
нет в списке, командой не является и вычисляется как обычное ключевое слово.

| Команда | Значение |
|---|---|
| `:help` (`:h`, `:?`) | вывести список команд |
| `:type FORM` (`:t`) | вывести тип FORM, не вычисляя его |
| `:describe NAME` (`:d`) | вывести вид определения, его тип, поля или варианты, методы, реализуемые трейты, место определения и строку документации |
| `:apropos TEXT` | найти во всех модулях определения, имя которых содержит TEXT (регистр не учитывается) |
| `:src NAME` | вывести исходный текст определения |
| `:who-calls NAME` | вывести функции и методы, которые вызывают функцию или метод NAME |
| `:inspect FORM` (`:i`) | вычислить FORM и раскрыть значение согласно его типу |
| `:backtrace` (`:bt`) | вывести вызовы, которые выполнялись, когда предыдущая строка завершилась ошибкой, начиная с самого внутреннего |
| `:locals [N]` | вывести аргументы вызова N из `:backtrace` (вызова 0, если N не указан) |
| `:cd [DIR]` | сменить текущую папку на DIR (на домашнюю, если DIR не указана) |
| `:pwd` | вывести текущую папку |
| `:quit` (`:exit`, `:q`) | выйти из REPL |

NAME может быть именем вроде `inner` или путём вроде `std::seq::reverse` или `Option::unwrap`.

```
typl> (defun inner ((x int) (s string)) int "Прибавляет 1 к x." (+ x 1))
typl> :describe inner
user::inner is a function
  type: (fn (int string) int)
  parameters: x s
  defined at <stdin>:1:1

Прибавляет 1 к x.
typl> :src inner
(defun inner ((x int) (s string)) int "Прибавляет 1 к x." (+ x 1))
```

`:src` показывает определение, загруженное из файла, по этому файлу, а определение, введённое в
REPL, — по введённому тексту. Для определений стандартной библиотеки место в исходном тексте не
записано, поэтому их исходный текст показать нельзя.

`:who-calls` просматривает тела функций текущего сеанса. Для обобщённой функции находятся только
использования, конкретизированные конкретными типами.

`:cd` меняет папку, в которой ищет `(load ...)`, но `use` по-прежнему ищет файлы в папке, где был
запущен REPL.

## Раскрытие значения (`:inspect`)

`:inspect` раскрывает значение согласно его типу. Структура раскрывается в свои поля, перечисление
(включая `Option`) — в поля своего варианта, `Vector` — в элементы, `HashTable` — в ключи и
значения. Число переходит в эту часть, `u` возвращает на уровень вверх, `q` завершает.

```
typl> (defstruct point (x int) (y Option<int>))
typl> :inspect (make-instance 'point :x 1 :y (Some 2))
(make-instance 'point :x 1 :y (Some 2)) = #<point x: 1 y: (Some 2)>
  type: point
  0. x = 1
  1. y = (Some 2)
inspect> 1
y = (Some 2)
  type: Option<int>
  0. Some 0 = 2
inspect> q
```

Списки и `Sexpr` не раскрываются, а выводятся как есть.

## Помощь при вводе

При вводе в терминале доступно следующее.

- `Tab` дополняет имена (определения и синтаксис вроде `if` и `defun`), пути с `::`, команды REPL в
  начале строки, а внутри строкового литерала — имена файлов.
- Если после имени функции ввести пробел, в конце строки бледным цветом показывается тип этой
  функции.
- Скобка, парная к скобке рядом с курсором, подсвечивается.
- Если нажать Enter до завершения формы, следующая строка начинается с отступом по числу открытых
  скобок.

## Предыдущие результаты (`:*`, `:**`, `:***`)

В REPL `:*` — последнее выведенное значение, `:**` — предыдущее, `:***` — ещё на одно раньше.
Каждое имеет тип своего значения.

```
typl> 1
1
typl> "a"
"a"
typl> 2
2
typl> (+ :*** :*)
3
```

- Ввод, который не вывел значения (например, определение) или завершился ошибкой, не сдвигает
  результаты.
- Написать `:**` или `:***`, пока столько результатов ещё нет, — ошибка.
- Процитированное `':*` — обычное ключевое слово.
- `:*`, записанное в теле функции, продолжает указывать на результат на момент определения функции.
  `*` в Common Lisp читает значение в момент вызова, а typelisp фиксирует его при определении,
  чтобы у него был тип.
- Вне REPL (при запуске файла, а также в `~/.typlrc`, `--load` и `--eval`) `:*` — обычное ключевое
  слово.

## Остановка вычисления (`Ctrl+C`)

Нажатие `Ctrl+C` во время вычисления останавливает его и возвращает к приглашению. Всё, что было
определено раньше, сохраняется. Это работает и для цикла в интерпретаторе, и для цикла в
скомпилированном коде, и во время ожидания в `sleep` или `wait`. Очистка в выполняющихся
`unwind-protect` выполняется.

```
typl> (loop)
^Cerror: interrupted
typl>
```

`Ctrl+C`, нажатое во время ввода, только отбрасывает вводимую строку.

## Разбор после ошибки (`:backtrace`, `:locals`)

После того как вычисление остановилось с ошибкой, `:backtrace` (`:bt`) выводит вызовы функций,
выполнявшиеся в тот момент, начиная с самого внутреннего. `:locals N` выводит аргументы вызова N
согласно их объявленным типам.

```
typl> (defun inner ((x int)) int (if (= x 0) (panic "boom") x))
typl> (defun outer ((n int)) int (* 2 (inner n)))
typl> (outer 0)
error: <stdin>:1:40: panic: boom
typl> :bt
  0: (user::inner 0)  called at <stdin>:1:33
  1: (user::outer 0)  called at <stdin>:1:1
typl> :locals 1
  n = 0
```

- Для вызова из последнего выражения функции (хвостового вызова) вызывающая функция не
  показывается. Благодаря этому цикл с хвостовой рекурсией занимает место одного вызова, сколько
  бы раз он ни повторялся.
- Вызовы внутри скомпилированных функций и анонимные функции (`lambda`) не показываются.
- `:locals` показывает только аргументы, но не переменные, связанные через `let`.
- При вычислении следующей строки запись о предыдущей ошибке удаляется.
