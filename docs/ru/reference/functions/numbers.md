# Числа

Операции над целыми, числами с плавающей точкой, рациональными, комплексными числами и логическими значениями, а
также другие функции, связанные с числами. Как читать формы вызова, см. во [Встроенных функциях](README.md).

## 1. Целые фиксированной ширины

Целых типов семь: **`int`** (`integer` из CL: произвольная точность и тип по умолчанию для целочисленных литералов
без аннотации; глава 3) и типы фиксированной ширины `i8` `i16` `i32` `u8` `u16` `u32`. Для какого из них
разрешается операция, решает тип первого аргумента (они независимы друг от друга, неявных преобразований нет).
**64-битного целого типа нет.** Значение во время выполнения — одно слово, младшие биты которого — метка, поэтому на
непосредственное целое остаётся только 63 бита, и тип, претендующий на 64 бита, где-то должен был бы терять старший
бит. `int` становится bignum, превысив эти 63 бита, так что если ширина не важна, используйте `int`. Таблица ниже — для
шести типов фиксированной ширины (таблица для `int` — в главе 3).

| Имя | Форма | Тип | Описание |
|---|---|---|---|
| `+` `-` `*` `/` | `(op a b)` | `(T,T)→T` | Четыре арифметических действия. `/` усекает к нулю, при делении на ноль — panic |
| `mod` | `(mod a b)` | `(T,T)→T` | Остаток (`mod` из CL, **деление с округлением вниз**: знак следует за делителем. `(mod -7 3)`→`2`). При делении на ноль — panic |
| `rem` | `(rem a b)` | `(T,T)→T` | Остаток (`rem` из CL, **деление с усечением**: знак следует за делимым. `(rem -7 3)`→`-1`). При делении на ноль — panic |
| `floor-div` `ceiling-div` `round-div` `truncate-div` | `(op a b)` | `(T,T)→cons-cell<T,T>` | Соответствуют двухаргументным `floor`/`ceiling`/`round`/`truncate` из CL (`(floor 7 2)`→частное 3, остаток 1). Вместо множественных значений возвращают частное и остаток в `cons-cell` (`car`=частное, `cdr`=остаток). `round-div` округляет половины к чётному, как CL |
| `abs` | `(abs x)` | `T→T` | Модуль |
| `signum` | `(signum x)` | `T→T` | Знак (`1`/`-1`/`0`) |
| `gcd` | `(gcd a b)` | `(T,T)→T` | Наибольший общий делитель |
| `lcm` | `(lcm a b)` | `(T,T)→T` | Наименьшее общее кратное (0, если один из них 0) |
| `max` `min` | `(op a b)` | `(T,T)→T` | Большее / меньшее (три и более аргументов раскрываются сахаром для переменного числа аргументов из главы 8) |
| `1+` `1-` | `(op x)` | `T→T` | `x±1` |
| `<` `<=` `>` `>=` `=` `/=` | `(op a b)` | `(T,T)→bool` | Сравнение |
| `eq` `eql` `equal` `equalp` | `(op a b)` | `(T,T)→bool` | Все то же, что `=` (для чисел одного типа разницы нет) |
| `int->float` | `(int->float x)` | `T→f64` | Расширяющее преобразование в `f64` |
| `int->int` | `(int->int x)` | `T→int` | Расширяющее преобразование в `int` (всегда точное). То, что делает `(as int x)` |
| `int->ratio` | `(int->ratio x)` | `T→ratio` | Расширяющее преобразование в `ratio` (всегда точное) |
| `int->char` | `(int->char x)` | `T→char` | Трактует значение как скалярное значение Unicode. На недопустимом значении — panic |
| `try-int->char` | `(try-int->char x)` | `T→Option<char>` | Версия `int->char`, возвращающая `None` при неудаче |
| `int->i8` `int->i16` `int->i32` `int->u8` `int->u16` `int->u32` | `(int->W x)` | `T→W` | Преобразование ширины. Не помещающиеся значения усекаются (как `as` в Rust) |
| `try-int->i8` … `try-int->u32` | `(try-int->W x)` | `T→Option<W>` | То же преобразование в виде вопроса. `None`, если значение не помещается в эту ширину |

Эти преобразования — также то, что делают специальные формы `(as Type x)`/`(try-as Type x)`
([Справочник по синтаксису](../syntax.md#7-прочие-специальные-формы)). Битовые операции (`logand`/`ash`/`ldb` и т. д.)
и предикаты (`zerop`/`evenp` и т. д.) имеют одинаковую форму для всех типов, поэтому собраны в главах 11 и 9.

У `i8` `i16` `u8` `u16` `u32` ровно таблица этой главы, а у `f32` — ровно таблица `f64` из главы 4.

**Имя типа означает его ширину и знаковость, и больше ничего.** `i32` означает «трактовать 32 бита как знаковые», а
`u32` — «трактовать 32 бита как беззнаковые». `(+ (the u8 200) (the u8 100))` — это `44`, `(+ 2147483647 1)` (как
`i32`) — это `-2147483648`, а `(lognot (the u32 0))` — это `4294967295`. С `f32` то же самое: настоящий binary32.
`(/ (the f32 1.0) (the f32 3.0))` печатается как `0.33333334` — значение, отличное от результата `f64`
`0.3333333333333333`.

Производный каталог CL (`abs`/`signum`/`gcd`/`lcm`/`isqrt`/`expt` и предикаты главы 9) существует для
`int`/`i32`/`f64`/`ratio`. Если он нужен для другой ширины, переходите через `(as int x)` / `(as i32 x)`
(преобразования ширины есть для каждой пары).

## 2. Сырые слова на границе с C (`ptr` / `c-long` / `c-ulong`)

Три типа, используемые только для передачи значений функциям C, объявленным через
[`defffi`](../syntax.md#33-defffi--объявление-функций-c-ffi), и получения от них. `ptr` — непрозрачный указатель, а
`c-long` / `c-ulong` — `long` / `unsigned long` из C. Чтобы сделать такое значение, нужно находиться внутри
`(unsafe ...)`.

**Арифметики нет.** Ничего из таблицы главы 1 не применимо: ни `(+ p 1)`, ни `(< n m)` написать нельзя. Это слова,
которые передаются в C, а не типы для вычислений; для вычислений переходите к типу с шириной. У `c-long` / `c-ulong`
есть только преобразования:

| Имя | Форма | Тип | Описание |
|---|---|---|---|
| `int->i8` … `int->u32` | `(int->W x)` | `T→W` | Те же преобразования ширины, что и в главе 1. Не помещающиеся значения усекаются |
| `try-int->i8` … `try-int->u32` | `(try-int->W x)` | `T→Option<W>` | То же преобразование в виде вопроса |
| `int->c-long` `int->c-ulong` | `(int->W x)` | `T→W` | Путь внутрь — от другого сырого слова и от целых типов главы 1 |
| `try-int->c-long` `try-int->c-ulong` | `(try-int->W x)` | `T→Option<W>` | То же |
| `int->int` | `(int->int x)` | `T→int` | **Всегда точное**. Честный способ прочитать `size_t`, не помещающийся в `i32` |

`(as i32 x)` / `(try-as i32 x)` / `(as int x)` / `(as c-ulong n)` делают именно это, и преобразования есть для каждой
пары с целыми типами главы 1. У `ptr` нет даже этой таблицы: способа прочитать указатель как число не
предусмотрено. Это значение, которое только передают, получают и передают дальше другой функции C.

**Печатать их тоже нельзя.** `(println "~a" x)` не принимает сырое слово (у него нет представления `Sexpr`), поэтому
сначала переходите к типу с шириной, как в `(println "~a" (as int n))`.

«64-битного целого типа нет» из начала главы 1 верно и для этих трёх. Это верно **потому, что их нельзя хранить**: они
не могут быть полем `defstruct`, `defvar`, находиться внутри аргумента типа или внутри `Sexpr`, так что это слова,
которые лишь проходят через функцию как аргументы, результаты и локальные переменные. Подробности — в
[Справочнике по синтаксису](../syntax.md#ptr--c-long--c-ulong--сырые-машинные-слова).

## 3. Целые произвольной точности `int`

`integer` из CL и **целое** этого языка: целочисленные литералы без аннотации имеют этот тип, и встроенные функции,
возвращающие число, например `length` и `char->int`, возвращают этот тип. Значение хранится как 63-битное
непосредственное значение (fixnum), пока помещается, автоматически повышается до bignum, когда результат операции
перестаёт помещаться, и снова становится непосредственным значением, когда помещается опять. `eq` в диапазоне
fixnum всегда означает идентичность значений, а `eql`/`=` — числовое равенство во всём диапазоне. Это тип, отличный от
целых типов фиксированной ширины (глава 1), без неявного преобразования: `(as int x)` — точное расширение от
фиксированной ширины, а `(as i32 n)` / `(try-as i32 n)` — усечение / проверка от `int` (тот же смысл, что у
`int->W` / `try-int->W` в главе 1).

Целочисленный вариант `Sexpr` — тоже просто `int` (`(int n)` принимает и fixnum, и bignum).

Встроенные функции, принимающие индекс или количество (`substring`, `get` у `Vector`, величина сдвига `ash` и т. д.),
принимают `int`, но передача значения, не помещающегося в fixnum, — ошибка времени выполнения («an integer argument
does not fit a fixnum»).

| Имя | Форма | Тип | Описание |
|---|---|---|---|
| `+` `-` `*` | `(op a b)` | `(int,int)→int` | Никогда не переполняются (повышают) |
| `/` | `(/ a b)` | `(int,int)→int` | Усекает к нулю. При делении на ноль — panic |
| `mod` | `(mod a b)` | `(int,int)→int` | Остаток деления с округлением вниз (знак следует за делителем) |
| `max` `min` | `(op a b)` | `(int,int)→int` | |
| `<` `<=` `>` `>=` `=` `/=` | `(op a b)` | `(int,int)→bool` | |
| `eq` `eql` `equal` `equalp` | `(op a b)` | `(int,int)→bool` | Все — `=` |
| `logand` `logior` `logxor` `lognot` `logtest` `logcount` `integer-length` `logbitp` `ash` | | | То же, что в главе 11 (дополнительный код с бесконечным числом битов) |
| `int->float` `int->ratio` `int->char` `try-int->char` | | | То же, что в главе 1 |
| `int->W` `try-int->W` | `(int->W x)` | `int→W` | Усечение / проверка. `W` — одна из шести ширин или `c-long`/`c-ulong` |
| `int->int` | | `int→int` | Тождество (со стороны фиксированных ширин и слов C `int->int` расширяет; глава 1) |
| `abs` `signum` `rem` `gcd` `lcm` `expt` `1+` `1-` | | | Та же форма, что в главе 1. `expt` принимает только неотрицательные показатели |

## 4. Числа с плавающей точкой (`f64` / `f32`)

У `f32` та же таблица.

| Имя | Форма | Тип | Описание |
|---|---|---|---|
| `+` `-` `*` `/` | `(op a b)` | `(f64,f64)→f64` | IEEE 754. Деление на ноль panic не вызывает; оно даёт `inf`/`NaN` |
| `mod` | `(mod a b)` | `(f64,f64)→f64` | Остаток деления с округлением вниз (как в CL; знак следует за делителем. `a - b*floor(a/b)`) |
| `rem` | `(rem a b)` | `(f64,f64)→f64` | Остаток деления с усечением (как в CL; знак следует за делимым. `a - b*truncate(a/b)`) |
| `<` `<=` `>` `>=` `=` `/=` | `(op a b)` | `(f64,f64)→bool` | Сравнение |
| `eq` `eql` `equal` `equalp` | `(op a b)` | `(f64,f64)→bool` | Все то же, что `=` |
| `expt` | `(expt a b)` | `(f64,f64)→f64` | Степень |
| `abs` | `(abs x)` | `f64→f64` | Модуль |
| `signum` | `(signum x)` | `f64→f64` | Знак (`1.0`/`-1.0`; `±0.0`/`NaN` возвращаются как есть. Как в CL, в отличие от `signum` в Rust) |
| `max` `min` | `(op a b)` | `(f64,f64)→f64` | Большее / меньшее (три и более аргументов раскрываются сахаром для переменного числа аргументов из главы 8) |
| `1+` `1-` | `(op x)` | `f64→f64` | `x±1.0` |
| `sqrt` `floor` `ceiling` `round` `truncate` | `(op x)` | `f64→f64` | Унарные операции |
| `exp` `log` `sin` `cos` `tan` `asin` `acos` `atan` `sinh` `cosh` `tanh` `asinh` `acosh` `atanh` | `(op x)` | `f64→f64` | Трансцендентные функции. `log` — натуральный логарифм |
| `log` (два аргумента) | `(log x base)` | `(f64,f64)→f64` | Логарифм по заданному основанию. Раскрывается в `(/ (log x) (log base))` (глава 8) |
| `floor-div` `ceiling-div` `round-div` `truncate-div` | `(op a b)` | `(f64,f64)→cons-cell<f64,f64>` | Соответствуют двухаргументным версиям из CL (`(floor 7.0 2.0)`→частное 3, остаток 1). То же устройство, что у одноимённых функций главы 1 (`car`=частное, `cdr`=остаток) |
| `float->int` | `(float->int x)` | `f64→int` | Преобразует в `int` с усечением к нулю (`truncate` из CL; точно для конечных значений любой величины). На бесконечности и NaN — panic. Для фиксированной ширины используйте `(as i32 x)` |
| `float->ratio` | `(float->ratio x)` | `f64→ratio` | Преобразует в `ratio` как точное двоичное рациональное число (`rational` из CL) |
| `float->f32` `float->f64` | `(op x)` | `f64→f32` / `f64→f64` | Преобразует между ширинами с плавающей точкой. `float->f32` округляет к ближайшему, `float->f64` всегда точно. То, что делает `(as f32 x)` |
| `try-float->f32` `try-float->f64` | `(op x)` | `f64→Option<f32>` / `→Option<f64>` | То же преобразование в виде вопроса. `none`, если округление меняет значение (расширение до `f64` всегда `some`). То, что делает `(try-as f32 x)` |
| `ffloor` `fceiling` `fround` `ftruncate` | `(op x)` | `f64→f64` | Одноимённые функции CL. Псевдонимы `floor`/`ceiling`/`round`/`truncate` выше: в CL версии без префикса возвращают целые, поэтому версии с префиксом `f` соответствуют поведению этого языка |
| `float-radix` `float-digits` `float-precision` | `(op x)` | `f64→int` | Соответственно 2 / 53 / 53 (только точность `0.0` равна 0). `f64` — всегда binary64 IEEE 754, поэтому это константы |
| `float-sign` | `(float-sign x)` | `f64→f64` | `1.0` или `-1.0` |
| `scale-float` | `(scale-float x n)` | `(f64,int)→f64` | `x * 2^n` |
| `decode-float` | `(decode-float x)` | `f64→cons-cell<f64,int>` | Мантисса (в `[1/2,1)`, без знака) и порядок. CL возвращает три значения, но множественных значений нет, поэтому знак оставлен `float-sign` |
| `integer-decode-float` | `(integer-decode-float x)` | `f64→cons-cell<int,int>` | То же разложение с точной 53-битной целой мантиссой. `mantissa * 2^exponent` — ровно исходное значение |
| `rationalize` | `(rationalize x)` | `f64→ratio` | **Простейшее рациональное число, которое читается обратно как это число с плавающей точкой** (`(rationalize 0.1)` — это `1/10`). Для точного двоичного значения используйте `float->ratio` |

**Отличие от CL: как округляет `round`.** `round` (а значит, и `fround`/`round-div`) округляет **от нуля**
(`(round 2.5)` = `3.0`). CL округляет **к чётному**, давая `2`.

## 5. Рациональные числа `ratio`

Совместимые с CL рациональные числа произвольной точности. Всегда хранятся несократимыми с положительным
знаменателем и размещаются в куче. Неявного преобразования с целыми типами или `f64` нет (используйте явный метод
преобразования или `as`/`try-as`). О синтаксисе дробных литералов см.
[Справочник по синтаксису](../syntax.md#1-лексические-элементы).

| Имя | Форма | Тип | Описание |
|---|---|---|---|
| `+` `-` `*` `/` | `(op a b)` | `(ratio,ratio)→ratio` | Четыре действия (результаты всегда несократимы). `/` при делении на ноль — panic |
| `mod` | `(mod a b)` | `(ratio,ratio)→ratio` | Остаток деления с округлением вниз (как в CL; знак следует за делителем) |
| `rem` | `(rem a b)` | `(ratio,ratio)→ratio` | Остаток деления с усечением (как в CL; знак следует за делимым) |
| `abs` | `(abs x)` | `ratio→ratio` | Модуль |
| `signum` | `(signum x)` | `ratio→ratio` | Знак (возвращает `1`/`-1`/`0` как `ratio`) |
| `expt` | `(expt a b)` | `(ratio,ratio)→ratio` | Степень. Показатель должен быть `ratio` с целым значением (иначе panic). Отрицательный показатель даёт обратное число |
| `max` `min` | `(op a b)` | `(ratio,ratio)→ratio` | Большее / меньшее |
| `1+` `1-` | `(op x)` | `ratio→ratio` | `x±1`. У `ratio` нет битовых операций (в CL они только для целых) |
| `<` `<=` `>` `>=` `=` `/=` | `(op a b)` | `(ratio,ratio)→bool` | Сравнение |
| `eq` `eql` `equal` `equalp` | `(op a b)` | `(ratio,ratio)→bool` | Все то же, что `=` |
| `numerator` | `(numerator x)` | `ratio→int` | Числитель несократимой дроби (то же имя, что в CL) |
| `denominator` | `(denominator x)` | `ratio→int` | Знаменатель несократимой дроби (всегда положителен) |
| `ratio->int` | `(ratio->int x)` | `ratio→int` | Целая часть (усечённая к нулю) |
| `ratio->float` | `(ratio->float x)` | `ratio→f64` | Преобразует в `f64` |

Пути внутрь от целых фиксированной ширины и `f64` — это `int->int`/`int->ratio` (глава 1) и
`float->int`/`float->ratio` (глава 4). `int`/`ratio` — отдельные типы, независимые от `i32` и прочих, и смешанная
арифметика требует явных преобразований.

## 6. Комплексные числа `complex`

Структура (`defstruct`) из стандартной библиотеки.

**Два отличия от CL** (оба следуют из статической типизации):

1. **Компоненты всегда `f64`.** Комплексное число в CL может содержать и рациональные числа, и `(complex 1 2)` и
   `(complex 1.0 2.0)` — разные типы. Статический тип должен выбрать один, а трансцендентные функции возвращают
   вариант с плавающей точкой.
2. **`(sqrt -1.0)` — вещественный `sqrt` (NaN).** В CL `sqrt` может вернуть комплексное число из вещественного, но
   `sqrt` для `f64` должен возвращать `f64`. Комплексный результат получается из комплексного аргумента:
   `(sqrt (complex -1.0 0.0))` — это `i`.

| Имя | Форма | Тип | Описание |
|---|---|---|---|
| `complex` / `complex::new` | `(complex re im)` | `(f64,f64)→complex` | Построение. Компоненты можно читать напрямую как `z::re`/`z::im` |
| `realpart` `imagpart` | `(op z)` | `complex→f64` | Вещественная и мнимая части. **Работают и для вещественных чисел** (`(realpart 3.0)`→`3.0`, `(imagpart 3.0)`→`0.0`), как в CL |
| `conjugate` | `(conjugate z)` | `complex→complex` | Сопряжённое (работает и для вещественных) |
| `phase` | `(phase z)` | `complex→f64` | Аргумент в (-pi,pi] (работает и для вещественных) |
| `cis` | `(cis theta)` | `f64→complex` | `e^(i*theta)` |
| `abs` | `(abs z)` | `complex→f64` | Модуль. **Единственный `abs`, который не возвращает тип получателя** (как в CL, модуль комплексного числа вещественный) |
| `+` `-` `*` `/` | `(op z w)` | `(complex,complex)→complex` | Комплексная арифметика |
| `=` `/=` | `(op z w)` | `(complex,complex)→bool` | Покомпонентное равенство. `Eq` тоже реализован (`Ord` нет: у комплексных чисел нет порядка, и `<` в CL их тоже отвергает) |
| `zerop` | `(zerop z)` | `complex→bool` | Равны ли обе компоненты 0 |
| `exp` `log` `sqrt` | `(op z)` | `complex→complex` | `log`/`sqrt` дают главные значения |
| `expt` | `(expt z w)` | `(complex,complex)→complex` | `exp(w log z)`. `(expt 0 0)`=1 |
| `atan2` | `(atan2 y x)` | `(f64,f64)→f64` | Угол вектора `(x,y)`. **Двухаргументный `(atan y x)` из CL — сахар для этого** (он ветвится по числу аргументов, как двухаргументный `log`) |

Оно реализует `print-object`, поэтому `~a`/`~s` печатают его как `#C(re im)`, как CL (у читателя этого языка нет
синтаксиса `#C`, чтобы прочитать его обратно).

|---|---|---|---|
| `not` | `(not b)` | `bool→bool` | Отрицание |
| `eq` `eql` `equal` `equalp` | `(op a b)` | `(bool,bool)→bool` | Все сравнивают значения на равенство |

## 8. Числовые вспомогательные функции и сахар вызова

`abs`/`signum` (все числовые типы), `gcd`/`lcm` (только целые типы), `rem` (все вещественные типы, включая `f64`) и
`expt` (`int`/`f64`/`ratio`) определены как методы каждого числового типа (разрешаются по типу получателя: `(abs x)`
— метод для типа `x`). Подробности для каждого типа — в главах 1, 3, 4 и 5. У целых фиксированной ширины нет `expt`
(у них нет повышения, и они переполнялись бы; переходите к `int` через `(as int x)` и используйте его `expt`).

### 8.1 Формы с переменным числом аргументов и с 0/1 аргументом

Арифметика и сравнение в CL принимают переменное число аргументов, но методы разрешаются только по типу получателя, а
не по числу аргументов. Поэтому **проверка раскрывает следующие формы в двухаргументные вызовы**.

| Что можно написать | Раскрытие | Применяется к |
|---|---|---|
| `(op a b c ...)` | Левая свёртка `(op (op a b) c)` | `+` `-` `*` `/` `max` `min` `logand` `logior` `logxor` `gcd` `lcm` |
| `(cmp a b c ...)` | `(and (cmp a b) (cmp b c) ...)`, где каждый член связан с временной переменной | `<` `<=` `>` `>=` `=` `/=` |
| `(op)` | `(+)`=0 / `(*)`=1 / `(logior)`=`(logxor)`=0 / `(logand)`=-1 / `(gcd)`=0 / `(lcm)`=1 | Те из перечисленных, у которых есть нейтральный элемент |
| `(op x)` | Для `+ * max min logand logior logxor` — сам `x`. `(- x)` меняет знак, `(/ x)` даёт обратное, `(gcd x)`/`(lcm x)` дают `(abs x)` (как в CL) | То же |
| `(cmp x)` | Вычисляет `x` и даёт `true` | `<` `<=` `>` `>=` `=` `/=` |
| `(log x base)` | `(/ (log x) (log base))` | `f64` |

Каждый член вычисляется ровно один раз, слева направо (поэтому сравнения с переменным числом аргументов идут через
временные переменные). Форма `/=` с переменным числом аргументов сравнивает **соседние пары**, в отличие от CL, где
проверяется, различаются ли все пары.

### 8.2 `isqrt` и целочисленный `expt`

| Имя | Форма | Тип | Описание |
|---|---|---|---|
| `isqrt` | `(isqrt n)` | `T→T` | Наибольшее целое, не превосходящее квадратного корня. На отрицательном значении — panic |
| `expt` | `(expt n e)` | `(T,T)→T` | Степень (возведением в квадрат). CL для отрицательного показателя возвращает рациональное число, но целый тип не может его представить, поэтому panic; сначала преобразуйте в `ratio` |

## 11. Битовые операции

Определены на дополнительном коде с бесконечным числом битов (CL 12.10). Реализованы для целых типов фиксированной
ширины и `int`, но не для `ratio` (в CL битовые операции тоже только для целых).

| Имя | Форма | Тип | Описание |
|---|---|---|---|
| `logand` `logior` `logxor` | `(op a b)` | `(T,T)→T` | Побитовые И, ИЛИ, исключающее ИЛИ (версии с переменным числом аргументов и без аргументов — в 8.1) |
| `lognot` | `(lognot x)` | `T→T` | Побитовое дополнение |
| `ash` | `(ash x count)` | `(T,int)→T` | Арифметический сдвиг. Влево, если `count` положителен, вправо, если отрицателен |
| `logbitp` | `(logbitp x index)` | `(T,int)→bool` | Установлен ли бит `index` (**порядок аргументов обратный CL**; см. ниже) |
| `logtest` | `(logtest a b)` | `(T,T)→bool` | `(/= (logand a b) 0)` |
| `logcount` | `(logcount x)` | `T→T` | Число установленных битов (для отрицательного числа — число нулевых битов) |
| `integer-length` | `(integer-length x)` | `T→T` | Число битов, нужных для представления, не считая знака |
| `logeqv` `lognand` `lognor` `logandc1` `logandc2` `logorc1` `logorc2` | `(op a b)` | `(T,T)→T` | Остальные семь, составленные из предыдущих |

**Только второй аргумент `ash` имеет тип `int`, а не `T`.** Это **расстояние** в битах, а не значение типа получателя,
поэтому ширина и знаковость получателя ничего не говорят о расстоянии (по той же причине, по которой `count` в
`(ash integer count)` из CL — любое целое). Сдвиг беззнакового значения вправо — логический
(`(ash (the u8 200) -3)` = `25`), а знакового — арифметический с округлением к минус бесконечности
(`(ash (the i32 -100) -4)` = `-7`). `index` у `logbitp` имеет тип `int` по той же причине.

**Спецификаторы байтов.** Вместо непрозрачного объекта, который возвращает `byte` в CL, используется
`cons-cell<int,int>` (`car`=размер, `cdr`=позиция). И размер, и позиция — количества битов, поэтому они `int`
независимо от ширины разбираемого целого.

**Целое — первый аргумент, в порядке, отличном от CL.** CL пишет `(ldb bytespec integer)`, но этот язык выбирает метод
по типу получателя (первого аргумента), и при спецификаторе на первом месте выбрать по типу целого было бы нельзя.
Все остальные битовые операции имеют форму `(op integer ...)` (`(logand a b)`, `(ash x count)`, `(lognot x)`), и
только семейство `ldb` и `logbitp` были наоборот, поэтому их выровняли. Остальные аргументы сохраняют относительный
порядок CL, так что `(dpb newbyte spec n)` становится `(dpb n newbyte spec)`.

| Имя | Форма | Тип | Описание |
|---|---|---|---|
| `byte` | `(byte size position)` | `(int,int)→cons-cell<int,int>` | Создаёт спецификатор байта |
| `byte-size` / `byte-position` | `(byte-size b)` | `cons-cell<int,int>→int` | Извлекает компонент |
| `ldb` | `(ldb x b)` | `(T,cons-cell<int,int>)→T` | Извлекает из `x` указанный байт, выровненный вправо |
| `ldb-test` | `(ldb-test x b)` | `(T,cons-cell<int,int>)→bool` | Установлен ли какой-либо бит в указанном байте |
| `mask-field` | `(mask-field x b)` | `(T,cons-cell<int,int>)→T` | Обнуляет всё вне указанного байта (сохраняя позиции) |
| `dpb` | `(dpb x newbyte b)` | `(T,T,cons-cell<int,int>)→T` | Помещает выровненный вправо `newbyte` в указанный байт `x` |
| `deposit-field` | `(deposit-field x newbyte b)` | `(T,T,cons-cell<int,int>)→T` | Версия `dpb`, сохраняющая позиции |
| `boole` | `(boole op a b)` | `(int,T,T)→T` | Одна из 16 двухоперандных логических операций, выбираемая `op` (константа `boole-*` из главы 10) |

`T` — тип, реализующий трейт `Bits`, то есть `i8`/`i16`/`i32`/`u8`/`u16`/`u32`/`int`. Только `boole` оставляет `op`
первым, так как менять там порядок CL нет причины.

## 12. Случайные числа

| Имя | Форма | Тип | Описание |
|---|---|---|---|
| `random` | `(random n [state])` | `int &optional random-state → int` | Случайное число от `0` включительно до `n` исключительно. Если состояние опущено, берёт из `*random-state*` и продвигает его |
| `make-random-state` | `(make-random-state [state])` | `&optional random-state → random-state` | Без аргумента — новое состояние; с аргументом — его копия (копия повторяет ту же последовательность) |
| `random-state-p` | `(random-state-p x)` | `random-state→bool` | Всегда `true` (статический тип уже исключает другие типы; существует только для соответствия CL) |
| `*random-state*` | — | `random-state` | Состояние `random` по умолчанию. Глобальная переменная, которой можно присваивать (замените через `setf`) |
| `seed-random-state` | `(seed-random-state n)` | `int→random-state` | Состояние, которое задаёт целое. Одно и то же зерно всегда повторяет одну и ту же последовательность |

Генератор — xorshift64, и он возвращает одну и ту же последовательность при интерпретации и при компиляции.

Новое состояние из `make-random-state` инициализируется по часам, поэтому от запуска к запуску его не воспроизвести.
Для воспроизведения используйте `seed-random-state`:

```lisp
(let ((s (seed-random-state 12345)))
  (println "~a ~a ~a" (random 100 s) (random 100 s) (random 100 s)))
;; при каждом запуске выводит одни и те же три числа
```

**В CL нет переносимого способа задать зерно** (`make-random-state` принимает только `nil`/`t`/состояние), поэтому это
имя следует `sb-ext:seed-random-state` из SBCL, а не CL.

Разные зёрна дают разные последовательности. `(seed-random-state 0)` и `(seed-random-state 1)` дают разные
последовательности, как и `-7` и `7`.
