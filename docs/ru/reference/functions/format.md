# Директивы формата

Директивы, которые пишутся в управляющих строках `print`/`println`/`format`. Они покрывают почти все директивы
`format` из CL. Сами функции описаны в [Печати](printing.md#1-print--println--format).

## 1. Как записываются директивы

Каждая директива состоит по порядку из `~`, необязательных **префиксных параметров** (через запятую: целое / `'c`
(символ) / `v` (берётся из следующего аргумента) / `#` (число оставшихся аргументов)), необязательных
**модификаторов** `:` и `@` и символа директивы. Символы директив нечувствительны к регистру.

Управляющая строка должна быть литералом ([Печать](printing.md#1-print--println--format)). Сверх того, при проверке
контролируется следующее.

- **Число и типы аргументов.** Для каждой директивы, потребляющей аргумент: остался ли аргумент и допустим ли его тип
  (пометки «аргумент» в таблицах ниже). Где путь зависит от значений во время выполнения — перемещение через `~*`,
  выбор предложения `~[`, срабатывание `~^` или число повторений `~@{`, — проверяется **каждый путь**. Лишние
  аргументы допустимы (как в CL).
- **Параметры и модификаторы.** Недопустимый модификатор, слишком много параметров и значения вне диапазона
  (отрицательная ширина, основание вне 2–36, целое там, где ожидается символ, и т. д.) — ошибки. Они никогда молча не
  игнорируются и не округляются.

**Элементы** аргумента-списка (`~{`, `~:{`, `~<...~:>`) — это `Sexpr`, и ни их число, ни тип каждого элемента из
типов не выводятся. Требования к элементам (целое для `~d` и т. д.) и недостающие элементы проверяются при поступлении
значений и являются ошибками времени выполнения (переключения на другое представление вместо этого не происходит).

Снисходительные правила CL не перенимаются. Передача нецелого в `~d` с выводом как через `~a` или трактовка `~:[`
любого значения как логического так не переосмысливаются; это ошибки типа.

## 2. Вывод (потребляет один аргумент)

| Директива | Параметры / модификаторы | Смысл |
|---|---|---|
| `~a` | `~mincol,colinc,minpad,padchar` / `@`=выравнивание вправо | Эстетический (`princ` из CL; строки без кавычек). Аргумент может быть любого типа |
| `~s` | То же | Стандартный (`prin1` из CL; форма, которую можно прочитать обратно). Аргумент может быть любого типа |
| `~w` | — | `write` из CL. Красивая печать, если `*print-pretty*` истинно, иначе то же, что `~s` |
| `~d` `~b` `~o` `~x` | `~mincol,padchar,commachar,interval` / `:`=группы цифр, `@`=всегда знак | Десятичные/двоичные/восьмеричные/шестнадцатеричные целые. Аргумент — целое |
| `~r` | `~radix,mincol,padchar,commachar,interval` (с основанием) или ничего | С основанием — в этом основании (2–36). Без него: `~r`=английское количественное, `~:r`=английское порядковое, `~@r`=римские цифры, `~:@r`=старые римские цифры. Аргумент — целое |
| `~p` | `:`=на один назад, `@`=y/ies | Множественное число (`~p`→"s", `~@p`→"y"/"ies"). Аргумент — целое |
| `~c` | `:`=имя, `@`=синтаксис `#\` | Символ. Аргумент — `char` |
| `~f` | `~w,d,k,overflowchar,padchar` / `@`=знак | Фиксированная точка. Аргумент — число |
| `~e` | `~w,d,,,,padchar,exptchar` / `@`=знак | Экспоненциальная запись. Аргумент — число. Параметры CL для цифр порядка, масштаба и overflowchar не поддерживаются (их указание — ошибка) |
| `~g` | `@`=знак | Общая запись с плавающей точкой. Аргумент — число. Параметров не принимает |
| `~$` | `~d,n,w,padchar` / `:`,`@` | Денежная запись. Аргумент — число |

## 3. Вывод (не потребляет аргументов)

| Директива | Смысл |
|---|---|
| `~%` | Перевод строки (`~n%` — n штук) |
| `~&` | fresh-line (перевод строки, если не в начале строки; `~n&`) |
| `~\|` | Перевод страницы (form feed) |
| `~~` | Литеральный `~` (`~n~` — n штук) |
| `~t` | Табуляция (`~colnum,colincT`. Если уже на столбце colnum или дальше, сдвигается на кратное colinc; при colinc, равном 0, не сдвигается. `@`=относительная. `:`=табуляция относительно начала логического блока, работает только при красивой печати) |
| `~_` | Условный перевод строки (pretty; простой=`:linear` / `~:_`=`:fill` / `~@_`=`:miser` / `~:@_`=`:mandatory`) |
| `~i` | Отступ (pretty; `~ni`=начало блока + n / `~n:i`=текущий столбец + n) |
| `~<newline>` | Игнорирует перевод строки (`:`=сохранить пробелы, `@`=сохранить перевод строки) |

Как и в CL, директивы красивой печати (`~_` `~i` `~:t` `~<...~:>` и путь красивой печати `~a`/`~s`/`~w`) ничего не
делают, когда `*print-pretty*` ложно. По умолчанию оно ложно.

## 4. Управляющие структуры

| Директива | Смысл |
|---|---|
| `~(...~)` | Преобразование регистра (`~(` строчные, `~:(` заглавная в каждом слове, `~@(` заглавная только в первом слове, `~:@(` всё заглавными) |
| `~[...~;...~]` | Условный выбор (ветвится по целому аргументу. С `~n[`, `~v[` или `~#[` ветвится по этому значению и не берёт аргумент. `~:;`=предложение по умолчанию, только последним). `~:[false~;true~]` ветвится по аргументу `bool` и имеет ровно два предложения |
| `~{...~}` | Итерация (обходит аргумент-список. `~:{`=по подспискам, `~@{`=по оставшимся аргументам, `~:@{`=по каждому списку среди оставшихся аргументов, `~^`=выход, `~:}`=выполнить один раз, даже если пусто). Тело, которое за итерацию не потребляет ни одного аргумента, — ошибка (оно никогда бы не завершилось) |
| `~<...~;...~>` | Выравнивание (распределяет сегменты по `~mincol` столбцам. `:`/`@`=заполнение по краям) |
| `~<...~;...~:>` | **Логический блок** (закрывается `~:>`; это не то же, что выравнивание выше). Первый сегмент — префикс, последний — суффикс (оба только литеральные строки). С разделителем `~@;` префикс становится **префиксом каждой строки**. `~:<` делает префикс/суффикс по умолчанию `(`/`)`. Аргумент — один список (`~@<` использует вместо него оставшиеся аргументы) |
| `~*` | Пропуск аргументов (`~n*`=вперёд на n, `~:*`=назад, `~@*`=к абсолютной позиции) |
| `~/name/` | Вызов метода (глава 5. Флаги `:`/`@` передаются методу. Параметров не принимает) |

Следующие директивы CL не поддерживаются (это ошибки при проверке).

- `~?` и `~@?`: они принимают управляющую строку как аргумент времени выполнения, поэтому аргументы, которые
  потребляют её директивы, проверить нельзя. Пишите эти директивы прямо в управляющей строке.
- `~@[...~]`: проверяет, что аргумент не nil, но в этом языке нет nil. Используйте `~:[false~;true~]`, который
  ветвится по `bool`.
- `~{~}` с пустым телом: берёт тело из аргумента времени выполнения. Пишите директивы внутри фигурных скобок.

## 5. `~/name/`

**Одно отличие от CL: имя ищется не как глобальная функция, а как метод собственного типа аргумента.** Метод имеет
форму `((self Self) (colon bool) (at bool)) → string`, и `:`/`@` директивы передаются как есть.

Способ CL — искать глобальную функцию — в этом языке безопасно реализовать нельзя. Даже при литеральной управляющей
строке тип элементов аргумента-списка (внутри `~{`) при проверке неизвестен, и поиск функции только по имени мог бы
вызвать функцию, предназначенную для другого типа. Выбор по типу значения означает, что метод проверен по типам
именно для этого типа, что безопасно (тот же механизм, что и у `print-object`). Это работает и для значений вроде
`string`/`bool`/`char`/`symbol`/списков. Только для целых, ширину которых нельзя определить по значению, это ошибка,
**когда метод с этим именем определён более чем у одного целого типа**.

К какому аргументу он применится, неизвестно, но какие методы он может вызвать — известно. Проверка собирает каждый
`~/name/` из литеральной управляющей строки и отмечает среди типов аргументов в этом месте вызова те, у которых есть
метод указанной формы. Поэтому **если ни у одного из типов аргументов этого метода нет, это ошибка при проверке** (а
не во время выполнения), и это работает и в AOT-программах.

```lisp
(defstruct point (x i32) (y i32))
(defmethod brief ((self point) (colon bool) (at bool)) string
  (if colon (format false "<~a,~a>" self::x self::y) (format false "~a/~a" self::x self::y)))
(println "~a" (format false "~/brief/"  (point::new 3 4)))   ; => 3/4
(println "~a" (format false "~:/brief/" (point::new 3 4)))   ; => <3,4>
```
