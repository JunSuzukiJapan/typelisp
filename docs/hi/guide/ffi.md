# C FFI (defffi)

यह गाइड बताती है कि typelisp से C फ़ंक्शन कैसे कॉल करें। जो टाइप घोषित किए जा सकते हैं उनकी सूची और प्रतिबंध [सिंटैक्स संदर्भ 3.3](../reference/syntax.md#33-defffi--c-फ़ंक्शन-घोषित-करना-ffi) में हैं।

## 1. फ़ंक्शन घोषित करना और कॉल करना

`defffi` C फ़ंक्शन का नाम और टाइप घोषित करता है।

```lisp
(defffi (c-getpid "getpid") () i32)            ; typelisp का नाम और C सिंबल का नाम
(defffi (c-strlen "strlen") (string) c-ulong)
(defffi (c-cos "cos") (f64) f64 :library "m")  ; इसे libm में खोजें
```

कॉल `(unsafe ...)` में लपेटे जाते हैं।

```lisp
(unsafe (c-getpid))        ; => 12345
(unsafe (c-cos 0.0))       ; => 1.0
```

`unsafe` इसलिए चाहिए कि कंपाइलर यह जाँच नहीं कर सकता कि घोषित टाइप C की ओर के वास्तविक टाइप से मेल खाते हैं। `unsafe` लिखने का अर्थ है कि उस जाँच की ज़िम्मेदारी आप, लिखने वाले, लेते हैं। उसे भूलने पर इसे समझाने वाली त्रुटि मिलती है।

## 2. सुरक्षित रैपर लिखना

इच्छित उपयोग यह है कि `unsafe` को एक जगह तक सीमित रखा जाए और बाहर के लिए सामान्य फ़ंक्शन प्रस्तुत किया जाए।

```lisp
(defun pid () i32 (unsafe (c-getpid)))
(defun str-len ((s string)) int (as int (unsafe (c-strlen s))))

(pid)              ; कॉल करने वाले को unsafe की ज़रूरत नहीं
(str-len "hello")  ; => 5
```

## 3. टाइप कैसे मेल खाते हैं

| typelisp | C |
|---|---|
| `i8` `i16` `i32` / `u8` `u16` `u32` | समान चौड़ाई के पूर्णांक |
| `f32` / `f64` | `float` / `double` |
| `bool` | `bool` (`_Bool`) |
| `()` | `void` |
| `string` | `const char *` |
| `c-long` / `c-ulong` | `long` / `unsigned long` (`size_t`, `int64_t` आदि भी) |
| `ptr` | कोई भी पॉइंटर (`void *`, `FILE *` आदि) |
| `(ptr T)` | `T` की ओर पॉइंटर ([खंड 7](#7-c-struct)) |

### स्ट्रिंग

- आपके द्वारा पास की गई `string` NUL-समाप्त C स्ट्रिंग में कॉपी होती है, जो कॉल लौटने के बाद मुक्त की जाती है। स्ट्रिंग के बीच में NUL होना त्रुटि है।
- `string` लौटाने वाले फ़ंक्शन का परिणाम भी कॉपी होता है। C की ओर की मेमोरी मुक्त नहीं की जाती। जो फ़ंक्शन ऐसी स्ट्रिंग लौटाते हैं जिसे कॉल करने वाले को मुक्त करना होता है (जैसे `strdup`), उनका परिणाम `ptr` के रूप में लें और `free` स्वयं करें।
- यदि `string` लौटाने के लिए घोषित फ़ंक्शन NULL लौटाता है, तो यह त्रुटि है। जो फ़ंक्शन NULL लौटा सकते हैं (जैसे `getenv`) उनका परिणाम `ptr` के रूप में लें।

### `c-long` / `c-ulong` / `ptr`

ये टाइप केवल C के साथ सीमा पार मान पास करने के लिए हैं, और **कोई अंकगणित सपोर्ट नहीं करते**। किसी को typelisp के पूर्णांक के रूप में उपयोग करने के लिए उसे `as` से बदलें।

```lisp
(as int (unsafe (c-strlen s)))      ; int 64-बिट मान का कुछ भी नहीं खोता
(try-as i32 (unsafe (c-strlen s)))  ; यदि i32 में न समाए तो none
(unsafe (c-malloc 16))              ; पूर्णांक लिटरल जस के तस पास किए जा सकते हैं
```

`ptr` ऐसा मान है जिसे वापस C फ़ंक्शन को सौंपा जाना है। typelisp की ओर से यह पढ़ने का कोई तरीका नहीं है कि वह किस ओर इंगित करता है।

```lisp
(defffi (c-malloc "malloc") (c-ulong) ptr)
(defffi (c-free "free") (ptr) ())

(unsafe (let ((p (c-malloc 16)))
          (c-free p)
          ()))
```

ये टाइप केवल फ़ंक्शन आर्ग्युमेंट, रिटर्न मान और लोकल वेरिएबल में आ सकते हैं। वे struct फ़ील्ड, ग्लोबल वेरिएबल, या `Vector` जैसे टाइप के टाइप आर्ग्युमेंट नहीं हो सकते।

## 4. लाइब्रेरी का नाम देना

`:library` के बिना, सिंबल को उसमें खोजा जाता है जो पहले से प्रोसेस में लिंक है (libc आदि)। दूसरी लाइब्रेरी के फ़ंक्शन के लिए `:library` चाहिए।

```lisp
(defffi (sqlite-version "sqlite3_libversion") () string :library "sqlite3")
```

- `"sqlite3"` जैसे छोटे नाम को पहले `libsqlite3.dylib`, फिर `libsqlite3.so` के रूप में खोजा जाता है।
- `/` वाले नाम को पाथ माना जाता है।
- यदि घोषित सिंबल नहीं मिलता, तो त्रुटि उसका नाम बताती है।

## 5. AOT कंपाइलेशन

`defffi` का उपयोग करने वाले प्रोग्राम [`compile-file`](compile.md#3-aot-कंपाइलेशन-से-एक्ज़ीक्यूटेबल-बनाना) से जस के तस एक्ज़ीक्यूटेबल में बदले जा सकते हैं। `:library` से नामित लाइब्रेरी लिंक के समय अपने-आप जुड़ जाती हैं, इसलिए `compile-file` को किसी अतिरिक्त आर्ग्युमेंट की ज़रूरत नहीं।

## 6. कॉलबैक

आप typelisp फ़ंक्शन को C फ़ंक्शन को पास कर सकते हैं और उसे वापस कॉल करवा सकते हैं। `defffi` के आर्ग्युमेंट टाइप में फ़ंक्शन टाइप लिखें, और कॉल पर उस स्थान पर फ़ंक्शन का नाम या `lambda` एक्सप्रेशन रखें।

```lisp
(defffi (c-free "free") (ptr) ())
(defffi (c-strdup "strdup") (string) ptr)
(defffi (c-strncmp "strncmp") (ptr ptr c-ulong) i32)
(defffi (text-of "strstr") (ptr string) string)          ; strstr(p, "") p लौटाता है
(defffi (c-qsort "qsort") (ptr c-ulong c-ulong (fn (ptr ptr) i32)) ())

(defun sort-chars ((s string)) string
  (unsafe
    (let ((buf (c-strdup s)))
      (c-qsort buf (as c-ulong (length s)) 1
               (lambda ((a ptr) (b ptr)) i32 (c-strncmp a b 1)))
      (let ((r (text-of buf ""))) (c-free buf) r))))

(sort-chars "cadb")    ; => "abcd"
```

- केवल **बिना मुक्त वेरिएबल वाले** फ़ंक्शन ही पास किए जा सकते हैं। टॉप-लेवल फ़ंक्शन, `lambda` और लोकल `labels` फ़ंक्शन सब काम करते हैं, लेकिन घेरने वाले स्कोप के लोकल वेरिएबल का संदर्भ लेना टाइप जाँच के समय त्रुटि है। C केवल घोषित आर्ग्युमेंट पास करता है, इसलिए कैप्चर किए गए वेरिएबल पहुँचाने का कोई तरीका नहीं है। स्टेट रखने के लिए ग्लोबल वेरिएबल का उपयोग करें।
- फ़ंक्शन रखने वाला वेरिएबल पास नहीं किया जा सकता। उसकी जगह फ़ंक्शन का नाम या `lambda` एक्सप्रेशन लिखें।
- कॉलबैक के भीतर का `panic` या `throw` C फ़ंक्शन के लौटने के बाद कॉल करने वाले तक पहुँचता है।
- कॉलबैक को केवल तब कॉल किया जा सकता है जब वह C फ़ंक्शन चल रहा हो जिसे typelisp ने कॉल किया था। इसे `atexit` या सिग्नल हैंडलर जैसी चीज़ों से उपयोग नहीं किया जा सकता।

## 7. C struct

C फ़ंक्शन को structs का ऐरे जैसी कोई चीज़ पास करने के लिए, `def-c-struct` से C जैसे ही लेआउट वाला struct घोषित करें, और उसे `unsafe` के भीतर आवंटित करें।

```lisp
(unsafe (def-c-struct item (key i32) (tag u8)))    ; टॉप-लेवल unsafe के भीतर घोषित

(defffi (c-qsort "qsort") (ptr c-ulong c-ulong (fn ((ptr item) (ptr item)) i32)) ())

(defun put ((xs (ptr item)) (i int) (k i32)) i32
  (unsafe (let ((p (c-ref xs i))) (setf p::key k))))

(defun key-at ((xs (ptr item)) (i int)) int
  (unsafe (let ((p (c-ref xs i))) (as int p::key))))

(defun sorted-keys () int
  (unsafe
    (let ((xs (c-alloc item 4)))                    ; चार item, सब शून्य
      (put xs 0 3) (put xs 1 1) (put xs 2 4) (put xs 3 2)
      (c-qsort (as ptr xs) 4 8
               (lambda ((a (ptr item)) (b (ptr item))) i32 (- a::key b::key)))
      (+ (* 1000 (key-at xs 0)) (* 100 (key-at xs 1))
         (* 10 (key-at xs 2)) (key-at xs 3)))))

(sorted-keys)    ; => 1234
```

- `(c-alloc T n)` `T` के `n` मान आवंटित करता है और `(ptr T)` लौटाता है। `(c-ref p i)` `i`वें की ओर पॉइंटर है, `p::field` एक फ़ील्ड है, और `(c-deref p)` वह है जिसकी ओर `i32` जैसे स्केलर का पॉइंटर इंगित करता है। इन सभी को `setf` के साथ लिखा जा सकता है।
- `(as ptr p)` उसे बिना टाइप वाले `ptr` में बदल देता है ताकि `void *` लेने वाले C फ़ंक्शन को पास किया जा सके।
- `item` का आकार (यहाँ 8) और हर फ़ील्ड की स्थिति C जैसे ही नियमों से तय होती है।

### आवंटित मेमोरी का जीवनकाल

आवंटित मेमोरी तब मुक्त होती है जब उस फ़ंक्शन में नियंत्रण सबसे बाहरी `unsafe` को छोड़ता है। `panic` या `throw` से छोड़े जाने पर भी यही होता है। इसी कारण, `(ptr T)` मान को `unsafe` के बाहर नहीं ले जाया जा सकता। उसे `unsafe` का मान बनाना, क्लोज़र में कैप्चर करना, `task` को पास करना और `throw` से फेंकना सभी टाइप त्रुटियाँ हैं। जिन मानों को आप बाहर उपयोग करना चाहते हैं उन्हें `unsafe` के भीतर संख्याओं या `defstruct` में कॉपी करें।

`lambda` या `labels` फ़ंक्शन के भीतर आवंटन करते समय, उस फ़ंक्शन के भीतर `unsafe` लिखें।

### C द्वारा आवंटित मेमोरी

C से `(ptr T)` के रूप में प्राप्त पॉइंटर (`defffi` का रिटर्न मान, कॉलबैक आर्ग्युमेंट आदि) त्रुटि है, जब तक कि वह `c-alloc` से आवंटित मेमोरी के भीतर इंगित न करे। जो फ़ंक्शन C द्वारा `malloc` से आवंटित मेमोरी, या NULL, प्राप्त करते हैं उन्हें बिना टाइप वाले `ptr` से घोषित करें।

## 8. जो नहीं किया जा सकता

- **वेरिएडिक फ़ंक्शन** (`printf` और ऐसे) घोषित नहीं किए जा सकते। वेरिएडिक हिस्सा निश्चित आर्ग्युमेंट से भिन्न नियमों से पास होता है। आप जितने आर्ग्युमेंट संख्याओं का उपयोग करते हैं, उनमें से हर एक के लिए अलग नाम घोषित करें।
- **struct को मान द्वारा पास करना या लौटाना** संभव नहीं है। पॉइंटर पास करने वाले फ़ंक्शन का उपयोग करें।
- **जेनेरिक घोषणाएँ** संभव नहीं हैं।
- **बिल्ट-इन फ़ंक्शन जैसा ही नाम** उपयोग नहीं किया जा सकता।
- **उन्हें फ़ंक्शन मान के रूप में पास नहीं किया जा सकता।** आप `(map xs c-abs)` की तरह पास नहीं कर सकते; उसे `lambda` में लपेटें।

  ```lisp
  (unsafe (lambda ((n i32)) i32 (c-abs n)))
  ```
