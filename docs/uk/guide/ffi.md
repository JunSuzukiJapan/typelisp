# FFI для C (defffi)

Цей посібник пояснює, як викликати функції C із typelisp. Перелік типів, які можна оголошувати, і
обмеження наведено в [Довіднику із синтаксису 3.3](../reference/syntax.md#33-defffi--оголошення-функцій-c-ffi).

## 1. Оголошення та виклик функції

`defffi` оголошує назву й типи функції C.

```lisp
(defffi (c-getpid "getpid") () i32)            ; the typelisp name and the C symbol name
(defffi (c-strlen "strlen") (string) c-ulong)
(defffi (c-cos "cos") (f64) f64 :library "m")  ; look it up in libm
```

Виклики обгортаються в `(unsafe ...)`.

```lisp
(unsafe (c-getpid))        ; => 12345
(unsafe (c-cos 0.0))       ; => 1.0
```

`unsafe` потрібен, бо компілятор не може перевірити, що оголошені типи збігаються зі справжніми типами
на боці C. Запис `unsafe` означає, що ви, автор коду, берете відповідальність за цю перевірку. Якщо його
забути, виникає помилка з поясненням цього.

## 2. Написання безпечної обгортки

Задум у тому, щоб обмежити `unsafe` одним місцем і показувати назовні звичайну функцію.

```lisp
(defun pid () i32 (unsafe (c-getpid)))
(defun str-len ((s string)) int (as int (unsafe (c-strlen s))))

(pid)              ; the caller needs no unsafe
(str-len "hello")  ; => 5
```

## 3. Як відповідають типи

| typelisp | C |
|---|---|
| `i8` `i16` `i32` / `u8` `u16` `u32` | Цілі числа тієї самої ширини |
| `f32` / `f64` | `float` / `double` |
| `bool` | `bool` (`_Bool`) |
| `()` | `void` |
| `string` | `const char *` |
| `c-long` / `c-ulong` | `long` / `unsigned long` (також `size_t`, `int64_t` тощо) |
| `ptr` | Будь-який вказівник (`void *`, `FILE *` тощо) |
| `(ptr T)` | Вказівник на `T` ([розділ 7](#7-структури-c)) |

### Рядки

- Переданий `string` копіюється в C-рядок із завершальним NUL, який звільняється після повернення
  виклику. NUL посеред рядка — це помилка.
- Результат функції, що повертає `string`, теж копіюється. Пам'ять на боці C не звільняється.
  Для функцій, що повертають рядок, який викликач має звільнити (як-от `strdup`), візьміть результат як
  `ptr` і звільніть його самостійно через `free`.
- Якщо функція, оголошена як така, що повертає `string`, повертає NULL, це помилка. Результат функцій,
  що можуть повернути NULL (як-от `getenv`), беріть як `ptr`.

### `c-long` / `c-ulong` / `ptr`

Ці типи існують лише для передавання значень через межу з C і **не підтримують арифметики**. Щоб
використати одне з них як ціле число typelisp, перетворіть його через `as`.

```lisp
(as int (unsafe (c-strlen s)))      ; int does not lose any of the 64-bit value
(try-as i32 (unsafe (c-strlen s)))  ; none if it does not fit in an i32
(unsafe (c-malloc 16))              ; integer literals can be passed as they are
```

`ptr` — це значення, яке слід віддавати назад функціям C. З боку typelisp прочитати, на що воно
вказує, не можна.

```lisp
(defffi (c-malloc "malloc") (c-ulong) ptr)
(defffi (c-free "free") (ptr) ())

(unsafe (let ((p (c-malloc 16)))
          (c-free p)
          ()))
```

Ці типи можуть траплятися лише як аргументи функцій, значення, що повертаються, і локальні змінні. Вони
не можуть бути полями структур, глобальними змінними чи аргументами типу для `Vector` тощо.

## 4. Указання бібліотеки

Без `:library` символ шукається серед того, що вже скомпоновано в процес (libc тощо). Функціям з інших
бібліотек потрібен `:library`.

```lisp
(defffi (sqlite-version "sqlite3_libversion") () string :library "sqlite3")
```

- Коротка назва на кшталт `"sqlite3"` шукається як `libsqlite3.dylib`, потім `libsqlite3.so`.
- Назва, що містить `/`, трактується як шлях.
- Якщо оголошений символ не знайдено, помилка називає його.

## 5. AOT-компіляція

Програми з `defffi` можна перетворювати на виконувані файли через
[`compile-file`](compile.md#3-збирання-виконуваного-файлу-aot-компіляцією) як є. Бібліотеки, названі
через `:library`, додаються під час компонування автоматично, тож `compile-file` не потребує додаткових
аргументів.

## 6. Зворотні виклики

Можна передати функцію typelisp функції C і дозволити їй викликати її назад. Запишіть тип функції серед
типів аргументів `defffi`, а під час виклику поставте на це місце назву функції або вираз `lambda`.

```lisp
(defffi (c-free "free") (ptr) ())
(defffi (c-strdup "strdup") (string) ptr)
(defffi (c-strncmp "strncmp") (ptr ptr c-ulong) i32)
(defffi (text-of "strstr") (ptr string) string)          ; strstr(p, "") returns p
(defffi (c-qsort "qsort") (ptr c-ulong c-ulong (fn (ptr ptr) i32)) ())

(defun sort-chars ((s string)) string
  (unsafe
    (let ((buf (c-strdup s)))
      (c-qsort buf (as c-ulong (length s)) 1
               (lambda ((a ptr) (b ptr)) i32 (c-strncmp a b 1)))
      (let ((r (text-of buf ""))) (c-free buf) r))))

(sort-chars "cadb")    ; => "abcd"
```

- Передати можна лише функції **без вільних змінних**. Функції верхнього рівня, `lambda` і локальні
  функції `labels` — усе працює, але посилання на локальну змінну охоплювальної області — це помилка під
  час перевірки типів. C передає лише оголошені аргументи, тож доставити захоплені змінні неможливо.
  Щоб зберігати стан, використовуйте глобальні змінні.
- Змінну, що містить функцію, передати не можна. Пишіть на місці назву функції або вираз `lambda`.
- `panic` або `throw` усередині зворотного виклику сягає викликача після повернення функції C.
- Зворотний виклик можна викликати лише поки виконується функція C, яку викликав typelisp. Його не можна
  використовувати з таких речей, як `atexit` чи обробники сигналів.

## 7. Структури C

Щоб передати функції C щось на кшталт масиву структур, оголосіть структуру з такою самою розкладкою, як
у C, через `def-c-struct` і виділіть її всередині `unsafe`.

```lisp
(unsafe (def-c-struct item (key i32) (tag u8)))    ; declared inside a top-level unsafe

(defffi (c-qsort "qsort") (ptr c-ulong c-ulong (fn ((ptr item) (ptr item)) i32)) ())

(defun put ((xs (ptr item)) (i int) (k i32)) i32
  (unsafe (let ((p (c-ref xs i))) (setf p::key k))))

(defun key-at ((xs (ptr item)) (i int)) int
  (unsafe (let ((p (c-ref xs i))) (as int p::key))))

(defun sorted-keys () int
  (unsafe
    (let ((xs (c-alloc item 4)))                    ; four items, all zero
      (put xs 0 3) (put xs 1 1) (put xs 2 4) (put xs 3 2)
      (c-qsort (as ptr xs) 4 8
               (lambda ((a (ptr item)) (b (ptr item))) i32 (- a::key b::key)))
      (+ (* 1000 (key-at xs 0)) (* 100 (key-at xs 1))
         (* 10 (key-at xs 2)) (key-at xs 3)))))

(sorted-keys)    ; => 1234
```

- `(c-alloc T n)` виділяє `n` значень типу `T` і повертає `(ptr T)`. `(c-ref p i)` — це вказівник на
  `i`-те з них, `p::field` — поле, а `(c-deref p)` — те, на що вказує вказівник на скаляр, як-от `i32`.
  Усе це можна писати з `setf`.
- `(as ptr p)` перетворює його на нетипізований `ptr` для передачі функціям C, що приймають `void *`.
- Розмір `item` (тут 8) і позиція кожного поля визначаються тими самими правилами, що й у C.

### Час життя виділеної пам'яті

Виділена пам'ять звільняється, коли керування залишає крайній зовнішній `unsafe` у цій функції. Те саме
відбувається, коли його залишають через `panic` або `throw`. Через це значення `(ptr T)` не можна
винести за межі `unsafe`. Зробити його значенням `unsafe`, захопити в замикання, передати в `task` і
кинути через `throw` — усе це помилки типів. Копіюйте значення, які хочете використати ззовні, у числа
або `defstruct` усередині `unsafe`.

Виділяючи пам'ять усередині `lambda` або функції `labels`, пишіть `unsafe` усередині цієї функції.

### Пам'ять, виділена C

Вказівник, отриманий від C як `(ptr T)` (значення, що повертає `defffi`, аргумент зворотного виклику
тощо), — це помилка, якщо він не вказує всередину пам'яті, виділеної через `c-alloc`. Функції, що
отримують пам'ять, виділену C через `malloc`, або NULL, оголошуйте з нетипізованим `ptr`.

## 8. Чого не можна робити

- **Функції зі змінною кількістю аргументів** (`printf` та подібні) оголосити не можна. Змінна частина
  передається за іншими правилами, ніж фіксовані аргументи. Оголошуйте окрему назву для кожної кількості
  аргументів, яку використовуєте.
- **Передавати чи повертати структури за значенням** неможливо. Використовуйте функції, що передають
  вказівники.
- **Узагальнені оголошення** неможливі.
- **Ту саму назву, що й у вбудованої функції,** використовувати не можна.
- **Їх не можна передавати як значення-функції.** Передати одну як у `(map xs c-abs)` не можна;
  загорніть її в `lambda`.

  ```lisp
  (unsafe (lambda ((n i32)) i32 (c-abs n)))
  ```
