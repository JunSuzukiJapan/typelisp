# Модулі та розкладання по файлах

Цей посібник пояснює, як скласти програму з кількох файлів. Докладні правила наведено в розділах 3.10–3.13
[Довідника із синтаксису](../reference/syntax.md#310-module--use--простори-імен).

## 1. Один файл — один модуль

У typelisp **файл сам по собі є модулем**. Шлях файлу відносно кореня вихідного коду — це шлях
модуля.

| Файл | Модуль |
|---|---|
| `<root>/geometry.typl` | `geometry` |
| `<root>/geo/shapes.typl` | `geo::shapes` |
| `<root>/net/http/client.typl` | `net::http::client` |

Писати оголошення модуля на початку файлу не потрібно.

## 2. Налаштування проєкту

Покладіть у корінь проєкту файл з іменем `typelisp.toml`. Він може бути порожнім.

```
myapp/
├── typelisp.toml
├── main.typl
└── geometry.typl
```

Щоб тримати вихідний код у `src/`, напишіть у `typelisp.toml` цей один рядок:

```toml
src = "src"
```

`typl` шукає `typelisp.toml`, починаючи з каталогу файлу, який запускає, і рухаючись угору, а місце, де
його знайдено, використовує як корінь вихідного коду. Якщо нічого не знайдено, коренем є каталог
файлу, що запускається (в REPL — поточний каталог).

## 3. Як зробити визначення публічними та використовувати їх

`geometry.typl`:

```lisp
(pub defstruct point
  (pub x i32)
  (pub y i32)
  (tag string))                        ; a field without pub cannot be read from outside

(defun square ((n i32)) i32 (* n n))   ; a function without pub cannot be called from outside either

(pub defun dist2 ((a point) (b point)) i32
  (+ (square (- a::x b::x)) (square (- a::y b::y))))

(pub defmethod origin (point) point (point::new 0 0 "o"))
```

`main.typl`:

```lisp
(use geometry)

(let ((a (geometry::point::origin))
      (b (geometry::point::new 3 4 "b")))
  (println "~a" (geometry::dist2 a b)))
```

```sh
typl main.typl        # => 25
```

`geometry.typl` завантажується в тому місці, де записано `(use geometry)`. Завантажувати його заздалегідь
не потрібно.

### Що стає публічним

- Функції, структури, переліки, глобальні змінні, макроси та методи видимі з інших модулів лише тоді,
  коли мають `pub`. Ставте `pub` одразу перед визначенням, як-от `(pub defun ...)`.
- Для структур **публічність типу й публічність полів — окремі речі**.
  `(pub defstruct point ...)` робить тип видимим, а читати й записувати ззовні можна лише поля, записані
  як `(pub x i32)`.
- Використання непублічної назви ззовні дає помилку «не вдається розв'язати», як-от
  `unresolved path: geometry::square`. Це те саме повідомлення, що й для назви з помилкою в написанні,
  тож якщо написання правильне, а назва все одно не розв'язується, підозрюйте пропущений `pub`.

Перелік визначень, що можуть мати `pub`, наведено в
[Довіднику із синтаксису 3.13](../reference/syntax.md#313-pub--видимість).

## 4. Як писати `use`

```lisp
(use geometry)              ; bring in a module; write geometry::dist2 to use it
(use geometry::dist2)       ; bring in a function; use it by the bare name dist2
(use geometry::point)       ; bring in a type; write point::new, point::origin, and point in type annotations
(use a::f b::g)             ; several can be written together
```

- **`use` діє лише на форми після нього.** Ставте його на початку файлу. Запис `geometry::dist2` вище
  за `use` дає `unresolved path`.
- Запис повного шляху `geometry::dist2` без `use` модуля теж не розв'язується. Лише `use`
  спричиняє завантаження файлу.
- `use` для назви, чия гола форма вже зайнята, дає попередження. Коли ви все одно хочете її
  підключити, використовуйте `shadowing-import`.
- Модуль у каталозі записується як `(use geo::shapes)`, а далі до нього звертаються за останньою
  частиною (`shapes::...`).

### Виклик методів трейтів

Методи, реалізовані в `impl`, **належать типові**, а не функціям модуля, тож їх викликають без назви
модуля.

```lisp
(use shapes::core)
(println "~a" (area (core::square::new 4)))    ; area, not core::area
```

Методи всередині `impl` завжди публічні, навіть без `pub`.

Сам трейт не можна зробити публічним для інших модулів. Тримайте визначення трейта, його `impl` і код, що
використовує його через `:dyn`, в одному модулі.

## 5. Поділ просторів імен усередині файлу

Щоб поділити простір імен далі в межах одного файлу, використовуйте `module`. Він вкладається у власний
модуль файлу.

```lisp
;; inside main.typl
(module util
  (pub defun clamp ((x i32) (lo i32) (hi i32)) i32
    (if (< x lo) lo (if (> x hi) hi x))))

(println "~a" (util::clamp 15 0 10))    ; main::util::clamp
```

Щоб помістити весь решту файлу в один простір імен, можна написати `(in-module util)` замість
обгортання дужками.

## 6. Обмеження залежностей

- **Цикли заборонені.** Якщо `a.typl` робить `(use b)`, а `b.typl` робить `(use a)`, результатом
  є помилка `circular module dependency: a -> b -> a`. Перенесіть визначення, потрібні обом, у третій
  модуль.
- **Ні на типи, ні на функції не можна посилатися до їх визначення**, навіть у межах одного файлу.
  Для взаємно рекурсивних функцій спершу оголосіть одну з них через `defsignature`
  ([Довідник із синтаксису 3.2](../reference/syntax.md#32-defsignature--випереджальні-оголошення)).

## 7. Порядок виконання

Запуск `typl main.typl` проходить у такому порядку:

1. `main.typl` і кожен файл, підключений з нього через `use`, читаються й перевіряються за типами. **Якщо
   де-небудь є помилка типів, нічого не виконується.**
2. Вирази верхнього рівня підключених через `use` модулів виконуються раніше за вирази модулів, що їх
   використовують.
3. Вирази верхнього рівня `main.typl` виконуються згори донизу.

Якщо зібрати точку входу програми у функцію `main` і викликати `(main)` наприкінці файлу, той самий
файл можна використати й для
[AOT-компіляції](compile.md#3-збирання-виконуваного-файлу-aot-компіляцією).

## 8. Чим це відрізняється від `load`

`(load "path")`, як і `load` у Common Lisp, читає вміст файлу **у поточний простір імен як є**. Він не
обгортає його в модуль, і `pub` не відіграє ролі. Використовуйте його для таких речей, як читання
файлу налаштувань чи перезавантаження локального файлу в REPL. Щоб розділити програму на частини,
використовуйте `use`.
