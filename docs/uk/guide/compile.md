# Компіляція

Якщо ви нічого більше не робите, програми typelisp виконуються в інтерпретаторі. Крім того, є два
способи компіляції в нативний код і один спосіб збереження середовища. Подробиці специфікації наведено в
[Довіднику із синтаксису, розділ 10](../reference/syntax.md#10-компіляція).

| Спосіб | Як | Результат |
|---|---|---|
| JIT-компіляція | `(compile name)` | Функція в поточному сеансі замінюється нативним кодом |
| AOT-компіляція | `typl -c src.typl` або `(compile-file "src.typl" "out")` | Самодостатній виконуваний файл |
| Дамп | `(dump "file.typld")` | Зберігає визначення; `typl --image` знову запускається з того самого середовища |

## 1. Підготовка

Компіляція використовує LLVM 22. Якщо ви зібрали `typl` за [README.md](../../../README.md), додаткова
підготовка не потрібна.

Виконувані файли, створені AOT-компіляцією, зв'язуються зі статичною бібліотекою `libtypelisp_front.a`.
Релізна збірка `typl` (зокрема встановлена через `cargo install`) несе цю бібліотеку в собі, тож
підготовка не потрібна. Під час першої компіляції вона записує бібліотеку в
`~/.typelisp/lib/<build ID>/` (або в `$TYPELISP_HOME/lib/<build ID>/`, якщо задано змінну середовища
`TYPELISP_HOME`) і відтоді використовує цю копію. `typl --remove-lib` видаляє її (з `--others` — ті,
що записані іншими версіями `typl`; з `--all` — усі). Налагоджувальна збірка `typl` використовує
бібліотеку з `target/debug/` репозиторію, у якому її зібрано. Щоб використати бібліотеку, розташовану
деінде, вкажіть її каталог через `--lib-dir` під час запуску `typl` (розділ 3.2).
У macOS для компонування використовуються Xcode Command Line Tools.

## 2. JIT-компіляція

Це перетворює вже визначену функцію на нативний код на місці.

```lisp
(defun fib ((n int)) int
  (if (< n 2) n (+ (fib (- n 1)) (fib (- n 2)))))

(compile fib)
(fib 30)           ; from here on, calls run the compiled code
```

- `name` не обчислюється. Пишіть назву функції як є (не як рядок). Для методу пишіть її з назвою типу,
  як-от `(compile point::norm)`.
- Функції, які вона викликає, компілюються разом із нею.
- **Узагальнені функції скомпілювати не можна.** Копія для кожного типу створюється в кожному місці
  використання. Натомість компілюйте функцію, що викликає її з конкретними типами.
- `trace`, `step`, `disassemble`, `compile`, `compile-file` і `dump` — це операції інтерпретатора, тож
  функцію, яка їх викликає, скомпілювати не можна. Спроба скомпілювати її дає помилку з поясненням
  причини.

Щоб подивитися на результат компіляції, використовуйте `disassemble`.

```lisp
(disassemble fib)          ; the host machine code
(disassemble fib true)     ; LLVM IR
```

## 3. Збирання виконуваного файлу AOT-компіляцією

### 3.1 Написання програми

Як точку входу визначте **функцію `main` без аргументів**.

```lisp
;; hello.typl
(defun fib ((n int)) int
  (if (< n 2) n (+ (fib (- n 1)) (fib (- n 2)))))

(defun main () ()
  (println "args: ~a" (command-line-args))
  (println "fib(25) = ~a" (fib 25)))

(main)
```

`(main)` наприкінці файлу потрібен, щоб `main` викликалася, коли ви запускаєте `typl hello.typl`.
`compile-file` пропускає цей завершальний `(main)`, тож той самий файл працює і в інтерпретаторі, і з
AOT-компіляцією.

### 3.2 Компіляція

З командного рядка використовуйте `typl -c` (`typl --compile` — те саме).

```sh
$ typl -c hello.typl            # makes hello
$ typl -c hello.typl -o fib     # names the executable fib
$ ./hello a b
args: #<vector<string> ./hello a b>
fib(25) = 75025
```

Без `-o` виконуваний файл називається за вихідним файлом без `.typl` і розміщується в тому самому каталозі,
що й вихідний файл. Якщо ім'я вихідного файлу не закінчується на `.typl`, `-o` обов'язковий. З `-c`
(`--compile`) не можна вказувати `--image`, `--heap-cells` і `--feature`.

Те саме можна зробити, викликавши `compile-file` з REPL або з програми.

```sh
$ typl
typl> (compile-file "hello.typl" "hello")
typl> :quit
$ ./hello a b
args: #<vector<string> ./hello a b>
fib(25) = 75025
```

Якщо ви збираєте неодноразово, можна покласти цей один рядок у файл і запускати його через
`typl build.typl`.

```lisp
;; build.typl
(compile-file "hello.typl" "hello")
```

Імена файлів розв'язуються від **поточного каталогу, у якому запущено `typl`**, а не від розташування
`build.typl`.

Щоб зв'язати `libtypelisp_front.a`, розташовану не там, де її шукає `typl`, вкажіть її каталог через
`--lib-dir`. Це діє і для `typl -c`, і для `compile-file`.

```sh
$ typl --lib-dir ~/lib/typelisp -c hello.typl
$ typl --lib-dir ~/lib/typelisp build.typl
```

Якщо в указаному каталозі немає `libtypelisp_front.a`, `typl` зупиняється з помилкою. Файл працює лише з
тим `typl`, що зібраний разом із ним. Після перебудови `typl` скопіюйте його знову.

### 3.3 Що може містити AOT-скомпільований файл

- Верхній рівень вхідного файлу може містити лише визначення (`defun` `defmethod` `defvar`
  `defparameter` `defconstant` `defmacro` `defsignature` `defstruct` `defenum` `deftype` `deftrait`
  `impl` `defffi`, `(unsafe (def-c-struct ...))`) та `use` `module`. Вирази верхнього рівня на кшталт
  `(println ...)` не дозволені, за винятком завершального `(main)`. Робіть роботу всередині `main`.
- Без `main` без аргументів компіляція завершується помилкою.
- Файли підключених через `use` модулів теж компілюються й об'єднуються в один виконуваний файл.
- Бібліотеки, названі через `:library` у `defffi`, зв'язуються автоматично ([FFI для C](ffi.md)).
- Кожну функцію стандартної бібліотеки можна використовувати з AOT-компіляцією. `eval` теж можна
  використовувати, але тоді перевіряльник типів та інтерпретатор потрапляють у виконуваний файл, що
  робить його більшим і повільнішим у запуску. Програми, які не викликають `eval`, їх не містять.

### 3.4 Як поводиться виконуваний файл

- `(command-line-args)` повертає `Vector<string>` тієї самої форми, чи запущено як
  `typl hello.typl a b`, чи як `./hello a b`. Перший елемент — назва програми.
- Код завершення задається через `(exit n)`. Якщо `main` повертається нормально, він дорівнює 0.
- У разі `panic` програма друкує повідомлення й завершується з ненульовим кодом.

## 4. Дампи

Визначення поточного сеансу можна зберегти в один файл і наступного разу запустити з нього.

```sh
$ typl
typl> (defun sq ((n i32)) i32 (* n n))
typl> (compile sq)
true
typl> (dump "session.typld")
true
typl> :quit
$ typl --image session.typld
typl> (sq 9)
81
```

Це працює й для запуску файлу, як-от `typl --image session.typld prog.typl`.

- Зберігаються **визначення**. Вирази, обчислені в сеансі, не зберігаються.
- Функції, які ви `compile`-нули, зберігаються в скомпільованому вигляді.
- Глобальні змінні відновлюються **повторним запуском їхніх ініціалізаторів**, а не зі значеннями, які
  вони мали під час запису дампу.
- Дамп не можна завантажити через `typl` іншої версії, ніж та, що його записала (це помилка).

Якщо ви запускаєте файл і з нього робите `(dump ...)`, визначення цього файлу лежать у модулі з назвою
файлу. Функція, визначена в `dp.typl`, називається `dp::sq`, а щоб викликати її з іншого файлу, потрібен
`pub` ([Модулі та розкладання по файлах](modules.md)).

## 5. Про скомпільовані файли модулів

Формату на кшталт `.fasl` у Common Lisp, що записує скомпільований результат кожного модуля у файл,
немає. `compile-file` збирає виконуваний файл безпосередньо з вихідного коду. Жодних проміжних
файлів не залишається.
