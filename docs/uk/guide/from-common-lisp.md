# Для програмістів на Common Lisp

typelisp успадковує синтаксис Common Lisp (CL) і багато назв його функцій, але це мова зі статичною
типізацією. Через це код CL не завжди працює як є. Цей посібник збирає місця, де звиклі до CL люди
схильні спотикатися, разом зі способами переписати код.

## 1. Немає `nil` і `t`

Булеві значення — `true` і `false`. `nil` і `t` не визначені.

```lisp
(if (> x 0) "pos" "non-pos")
(defvar (debug bool) false)
```

- **Умовою може бути лише `bool`.** Запис `0` або порожнього списку як умови — це помилка типів. Правила
  «усе, крім nil, — істина» немає.
- **Гілку else в `if` пропустити не можна.** `(if c x)` — це помилка. Коли гілка else не потрібна,
  використовуйте `when` / `unless`.
- **«Немає значення» виражається через `Option<T>`.** Функція, яка в CL повертала nil на означення «не
  знайдено», тут повертає `(some x)` або `none`.

  ```lisp
  (match (position 3 (iter v))
    ((some i) (println "found at ~a" i))
    ((none) (println "not found")))
  ```

- Порожній список `()` залежно від контексту — це або значення типу Unit (значення, що повертає функція,
  яка нічого не повертає), або порожній список даних у вигляді S-виразів. Це інше значення, ніж `false`.

## 2. Запис типів

Аргументи й результати функцій мусять мати типи.

```lisp
(defun area ((w i32) (h i32)) i32
  (* w h))

(defun first-or<T> ((v Vector<T>) (default T)) T      ; a generic function
  (unwrap-or (first (iter v)) default))
```

- Визначення без типів, як-от `(defun f (x) x)`, написати не можна.
- Глобальні змінні, як-от `defvar`, теж потребують типу: `(defvar (count int) 0)`.
- `the` — це не перевірка під час виконання, а анотація для перевіряльника типів.
- **Досліджувати типи під час виконання не можна.** Немає `typep` чи `type-of`, бо тип кожного значення
  фіксується під час компіляції. Щоб прийняти один із кількох типів, створіть тип-суму через
  `defenum` або використайте трейт.
- `deftype` визначає псевдонім типу. Тип, що описує діапазон значень, як-от
  `(deftype small () '(integer 0 9))`, створити не можна.

Типовий цілий тип `int` має довільну точність; як і ціле в CL, не має верхньої межі розміру. Типи
фіксованої ширини `i8`–`i32` і `u8`–`u32` теж існують. 64-бітного цілого типу фіксованої ширини немає.

## 3. Функції як значення

typelisp не розділяє простори імен функцій і змінних. Назву функції можна передати як значення як є.
Немає `#'` і немає `funcall`.

```lisp
(defun twice ((x int)) int (* 2 x))
(defun apply-to ((f (fn (int) int)) (x int)) int
  (f x))                                  ; call it directly, not with funcall

(apply-to twice 5)                        ; twice, not #'twice
```

- Вбудовані функції, як-от `+` і `1+`, теж можна передавати як значення як є там, де тип аргументу
  зафіксовано, як-от `(fn (int) int)`. Коли ви передаєте одну з них в узагальнену функцію на кшталт
  `foldl` чи `map`, невідомо, `+` якого типу мається на увазі, тож загорніть її в `lambda`.

  ```lisp
  (apply-to 1+ 5)                                          ; => 6
  (foldl (iter v) (lambda ((acc int) (x int)) int (+ acc x)) 0)
  ```

- Функції над послідовностями приймають **спочатку колекцію, потім функцію**: `(map it f)`,
  `(filter it f)`, `(foldl it f init)`. Це навпаки до `(mapcar f list)` у CL.
- `lambda` не може використовувати `&optional` чи `&key` (`&rest` використовувати можна).
- **Функцію не можна викликати до її визначення.** У CL можна викликати функцію, яку визначите пізніше,
  але тут це дає `no such function`. Для взаємно рекурсивних функцій спершу оголосіть одну з них через
  `defsignature`.

  ```lisp
  (defsignature odd2 (i32) bool)
  (defun even2 ((n i32)) bool (if (= n 0) true (odd2 (- n 1))))
  (defun odd2 ((n i32)) bool (if (= n 0) false (even2 (- n 1))))
  ```

## 4. Списки та Vector

Те, що відповідає списку CL, — це **дані у вигляді S-виразів**, тип яких — `Option<Sexpr>` (порожній
список — це `none`). `(list 1 2 3)` і `'(a b c)` мають цей тип. Дані у вигляді S-виразів — це те, з чим
працюють макроси та `read`; для звичайного контейнера даних використовуйте **`Vector<T>`**.

| Що вам потрібно | CL | typelisp |
|---|---|---|
| Голова та решта S-виразу | `(car xs)` `(cdr xs)` | `(sexpr-car xs)` `(sexpr-cdr xs)` |
| Обхід списку S-виразів | `(dolist (x xs) ...)` | Те саме |
| Послідовність елементів одного типу | Список або вектор | `Vector<T>` |
| Пара | `(cons a b)` | `(cons a b)` (її тип — `cons-cell<A,B>`) |
| Відображення | `(mapcar f xs)` | `(map (iter v) f)` |

`car` / `cdr` — це засоби доступу до пари `cons-cell<A,B>`, створеної через `cons`. Їх не можна
застосовувати до списків S-виразів.

`Vector` записується через `#(..)`, як вектор у CL, і друкується теж як `#(..)`:

```lisp
(let ((v #(1 2)))
  (push v 3)
  (map (iter v) (lambda ((x int)) int (* x 10))))   ; => #(10 20 30)
```

Від CL є три відмінності. Усі елементи мають бути одного типу (`#(1 "a")` — помилка типу). Кожне
обчислення створює новий вектор, тож його зміна не впливає на наступне обчислення (у CL результат
зміни літерала не визначений). Порожньому `#()` потрібен тип, як у `(the Vector<int> #())`.
Багатовимірний масив записується як `#2A((1 2) (3 4))`, як у CL.

Функції над послідовностями, як-от `map`, `filter`, `sort` і `find`, працюють зі значеннями, що
реалізують трейт `Iter`. Передавайте `Vector`, перетворивши його на ітератор через `(iter v)`.

## 5. Немає множинних значень

Немає `values` і `multiple-value-bind`. Функції, що в CL повертають кілька значень, повертають пару або
структуру.

| CL | typelisp |
|---|---|
| `(floor 7 2)` → 3, 1 | `(floor-div 7 2)` → `cons-cell`, у якої `car` дорівнює 3, а `cdr` — 1 |
| `(decode-universal-time t)` → 9 значень | Структура `decoded-time` |
| `(read-from-string s)` → значення, позиція | `(read-from-string s)` повертає `cons-cell` зі значення й позиції всередині `Result`. Лише для значення — `(read s)` |

## 6. Немає спеціальних змінних (динамічного зв'язування)

`let` завжди зв'язує лексично. Якщо ви перез'єднаєте змінну, визначену через `defvar`, за допомогою
`let`, функції, які викликаються звідти, усе одно бачать початкове значення.

```lisp
(defvar (*depth* int) 1)
(defun show () () (println "~a" *depth*))
(let ((*depth* 2)) (show))       ; 2 in CL, 1 in typelisp
```

Щоб тимчасово змінити керівну змінну, як-от `*print-base*`, використовуйте `dlet`. Він присвоює
значення і відновлює початкове, як би не залишили тіло.

```lisp
(dlet ((*print-base* 16))
  (format false "~a" 255))       ; => "ff"
```

`dlet` переписує саму глобальну змінну, тож це не зв'язування на рівні потоку.

## 7. Систему умов не прийнято

Немає `define-condition`, `handler-case`, `handler-bind`, `restart-case`, `error` і `signal`.
Вони погано поєднуються зі статичною типізацією. Натомість для різних цілей використовуються ці два
засоби:

- **Відновлювані збої повертають `Result<T,E>`.** Викликач розділяє `ok` / `err` через `match`.
  Скорочення на кшталт `?` з Rust немає.

  ```lisp
  (match (parse-int "42x")
    ((ok n) n)
    ((err e) (progn (println "bad input: ~a" (message e)) 0)))
  ```

- **Невідновлювані збої (помилки в коді) — це `panic`.** До цього виду належать `(panic "message")`,
  передача `none` в `unwrap`, ділення на 0 та індекс поза межами, і програма зупиняється. Очищення
  `unwind-protect` виконується перед зупинкою.

Типи помилок уніфіковано трейтом `Error`, а `(message e)` дає повідомлення. Як створити власний тип
помилки, описано в розділі
[Option, Result і типи помилок](../reference/functions/option-result.md#3-типи-помилок-і-трейт-error).
`assert` і `warn` можна використовувати як у CL.

`catch` / `throw` / `unwind-protect` існують. Однак тег `catch` обмежено необчислюваним літеральним
символом (`'done`), а значення, кинуті з одним тегом, мають один тип.

## 8. Немає CLOS

Немає `defclass`, `defgeneric` чи комбінування методів.

- Типи даних визначаються через `defstruct` (структури) і `defenum` (типи-суми).
- `defmethod` визначає методи, чия ціль вибирається лише за **статичним типом першого аргументу**.
  Множинної диспетчеризації немає.
- Щоб дати типам спільні операції, використовуйте трейти (`deftrait` / `impl`). Для значень, конкретний
  тип яких вирішується під час виконання, використовуйте тип `:dyn Trait`
  ([Довідник із синтаксису 3.9](../reference/syntax.md#39-deftrait--impl--трейти)).

Чим відрізняється `defstruct`:

- Конструктор — це `TypeName::new`: `(point::new 1 2)`. Якщо вам потрібна назва на кшталт `make-point`,
  її створює опція `(:constructor make-point)`.
- Крім `(x p)`, засіб доступу можна записати як `p::x`. Змінюйте через `(setf p::x 5)`.
- Предикат (`point-p`) не створюється. `:conc-name`, `:type` і `:named` немає.
- `:include` лише успадковує слоти; тип не стає підтипом батьківського.

## 9. Модулі замість пакетів

Пакетів немає. Простори імен — це модулі, а файл сам по собі є модулем. Замість `pkg:symbol` пишіть
`module::name`, а імена підключайте через `use`
([Модулі та розкладання по файлах](modules.md)).

Ключові слова `:foo` існують і є символами, що обчислюються самі в себе. Оскільки пакетів немає,
двокрапка є частиною імені: `(symbol->string :foo)` повертає `":foo"`.

## 10. Відмінності у читанні та синтаксисі

- Регістр літер не розрізняється (символи під час читання стають малими літерами). Це так само, як у CL.
- `#'` немає (розділ 3). Літерали комплексних чисел `#c(...)` прочитати не можна; створюйте комплексні
  числа через `(complex 1.0 2.0)`.
- Клаузи розширеного `loop` записуються ключовими словами: `(loop :for i :from 1 :to 3 :collect i)`.
  `loop`, що починається не з ключового слова, — це простий нескінченний цикл, який залишають через
  `(break)` або `(return value)`. `return` залишає найглибший цикл (щоб вийти з функції, використовуйте
  `return-from`).
- Призначення `format` — це `false` (повернути рядок), `true` (стандартний вивід) або потік. Директиви
  формату такі самі, як у CL.
- Читання з рядка — `(read "...")`, а читання з потоку — `(read-sexpr s)`. Обидва повертають `Result`.
- `eval` перевіряє типи заданого виразу перед обчисленням і повертає `Result`. Посилання вперед
  неможливі, як і у вихідному коді.
- `eval-when` немає.
- Назви функцій не використовують суфіксів `?` чи `!`. Предикати називаються з `-p` / `p`, як у CL
  (`zerop`, `sexpr-null`), або з `is-` попереду (`is-some`).

## 11. Основні функції з іншими назвами

| CL | typelisp |
|---|---|
| `string-upcase` / `string-downcase` | `upcase` / `downcase` |
| `read` (з потоку) | `read-sexpr` |
| `pathname` | `to-pathname` |
| Версії `floor` та подібних із двома аргументами | `floor-div` `ceiling-div` `round-div` `truncate-div` |
| `mapcar` | `map` (порядок аргументів зворотний; розділ 4) |
| `length` (вектора) | `len` |
| `hash-table-count` | `count` / `size` |

Перелік функцій наведено в розділі [Вбудовані функції](../reference/functions/README.md).
