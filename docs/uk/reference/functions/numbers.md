# Числа

Операції над цілими числами, числами з рухомою комою, раціональними, комплексними числами та булевими
значеннями, а також інші функції, пов'язані з числами. Як читати форми викликів, див. у розділі
[Вбудовані функції](README.md).

## 1. Цілі числа фіксованої ширини

Є сім цілих типів: **`int`** (`integer` з CL: довільна точність і типовий тип цілих літералів без
анотацій; розділ 3) і типи фіксованої ширини `i8` `i16` `i32` `u8` `u16` `u32`. Для якого типу
розв'язується операція, визначає тип першого аргументу (вони незалежні один від одного, неявних
перетворень немає). **64-бітного цілого типу немає.** Значення під час виконання — це одне слово, чиї
молодші біти є міткою, тож для безпосереднього цілого лишається лише 63 біти, а тип, що претендує на 64
біти, десь мав би втрачати старший біт. `int` стає bignum, коли виходить за ці 63 біти, тож якщо ширина
не важлива, використовуйте `int`. Таблиця нижче — для шести типів фіксованої ширини (таблиця для `int` —
у розділі 3).

| Назва | Форма | Тип | Опис |
|---|---|---|---|
| `+` `-` `*` `/` | `(op a b)` | `(T,T)→T` | Чотири арифметичні операції. `/` відкидає в бік нуля й завершується через panic при діленні на нуль |
| `mod` | `(mod a b)` | `(T,T)→T` | Остача (`mod` з CL, **ділення з округленням униз**: знак слідує за дільником. `(mod -7 3)`→`2`). Panic при діленні на нуль |
| `rem` | `(rem a b)` | `(T,T)→T` | Остача (`rem` з CL, **ділення з відкиданням**: знак слідує за діленим. `(rem -7 3)`→`-1`). Panic при діленні на нуль |
| `floor-div` `ceiling-div` `round-div` `truncate-div` | `(op a b)` | `(T,T)→cons-cell<T,T>` | Відповідають версіям `floor`/`ceiling`/`round`/`truncate` з CL з двома аргументами (`(floor 7 2)`→частка 3, остача 1). Замість множинних значень повертають частку й остачу в `cons-cell` (`car`=частка, `cdr`=остача). `round-div` округлює половини до парного, як CL |
| `abs` | `(abs x)` | `T→T` | Абсолютне значення |
| `signum` | `(signum x)` | `T→T` | Знак (`1`/`-1`/`0`) |
| `gcd` | `(gcd a b)` | `(T,T)→T` | Найбільший спільний дільник |
| `lcm` | `(lcm a b)` | `(T,T)→T` | Найменше спільне кратне (0, якщо будь-яке з них 0) |
| `max` `min` | `(op a b)` | `(T,T)→T` | Більше / менше (три й більше аргументів розгортаються цукром зі змінною кількістю аргументів з розділу 8) |
| `1+` `1-` | `(op x)` | `T→T` | `x±1` |
| `<` `<=` `>` `>=` `=` `/=` | `(op a b)` | `(T,T)→bool` | Порівняння |
| `eq` `eql` `equal` `equalp` | `(op a b)` | `(T,T)→bool` | Усі те саме, що `=` (для чисел одного типу різниці немає) |
| `int->float` | `(int->float x)` | `T→f64` | Розширювальне перетворення на `f64` |
| `int->int` | `(int->int x)` | `T→int` | Розширювальне перетворення на `int` (завжди точне). Те, що робить `(as int x)` |
| `int->ratio` | `(int->ratio x)` | `T→ratio` | Розширювальне перетворення на `ratio` (завжди точне) |
| `int->char` | `(int->char x)` | `T→char` | Інтерпретує значення як скалярне значення Unicode. Panic на некоректному значенні |
| `try-int->char` | `(try-int->char x)` | `T→Option<char>` | Версія `int->char`, що повертає `None` у разі невдачі |
| `int->i8` `int->i16` `int->i32` `int->u8` `int->u16` `int->u32` | `(int->W x)` | `T→W` | Перетворення ширини. Значення, що не вміщуються, обрізаються (як `as` у Rust) |
| `try-int->i8` … `try-int->u32` | `(try-int->W x)` | `T→Option<W>` | Те саме перетворення у вигляді запитання. `None`, якщо значення не вміщується в цю ширину |

Ці перетворення — це також те, що роблять спеціальні форми `(as Type x)`/`(try-as Type x)`
([Довідник із синтаксису](../syntax.md#7-інші-спеціальні-форми)). Бітові операції (`logand`/`ash`/`ldb` тощо)
і предикати (`zerop`/`evenp` тощо) мають однакову форму для всіх типів, тож зібрані в розділах 11 і 9.

`i8` `i16` `u8` `u16` `u32` мають точно таблицю цього розділу, а `f32` має точно таблицю `f64` з розділу
4.

**Назва типу означає його ширину та знаковість, не більше.** `i32` означає «трактувати 32 біти як
знакові», а `u32` — «трактувати 32 біти як беззнакові». `(+ (the u8 200) (the u8 100))` дорівнює `44`,
`(+ 2147483647 1)` (як `i32`) дорівнює `-2147483648`, а `(lognot (the u32 0))` дорівнює `4294967295`.
`f32` те саме: справжній binary32. `(/ (the f32 1.0) (the f32 3.0))` друкується як `0.33333334`, що є іншим
значенням, ніж результат `f64`, `0.3333333333333333`.

Похідний каталог CL (`abs`/`signum`/`gcd`/`lcm`/`isqrt`/`expt` і предикати з розділу 9) існує для
`int`/`i32`/`f64`/`ratio`. Якщо він потрібен для іншої ширини, перейдіть через `(as int x)` /
`(as i32 x)` (перетворення ширини існують для кожної пари).

## 2. Сирі слова на межі з C (`ptr` / `c-long` / `c-ulong`)

Три типи, що використовуються лише для передавання значень до функцій C, оголошених через
[`defffi`](../syntax.md#33-defffi--оголошення-функцій-c-ffi), і з них. `ptr` — це непрозорий вказівник, а
`c-long` / `c-ulong` — це `long` / `unsigned long` з C. Зробити одне з них значенням можна лише всередині
`(unsafe ...)`.

**Арифметики немає.** Нічого з таблиці розділу 1 не застосовується: не можна написати ні `(+ p 1)`, ні
`(< n m)`. Це слова, які передають у C, а не типи, з якими обчислюють, тож для обчислень перейдіть до
типу з шириною. `c-long` / `c-ulong` мають лише перетворення:

| Назва | Форма | Тип | Опис |
|---|---|---|---|
| `int->i8` … `int->u32` | `(int->W x)` | `T→W` | Ті самі перетворення ширини, що й у розділі 1. Значення, що не вміщуються, обрізаються |
| `try-int->i8` … `try-int->u32` | `(try-int->W x)` | `T→Option<W>` | Те саме перетворення у вигляді запитання |
| `int->c-long` `int->c-ulong` | `(int->W x)` | `T→W` | Шлях усередину, від іншого сирого слова та від цілих типів з розділу 1 |
| `try-int->c-long` `try-int->c-ulong` | `(try-int->W x)` | `T→Option<W>` | Так само |
| `int->int` | `(int->int x)` | `T→int` | **Завжди точне**. Чесний спосіб прочитати `size_t`, що не вміщується в `i32` |

`(as i32 x)` / `(try-as i32 x)` / `(as int x)` / `(as c-ulong n)` — це те, що вони роблять, а
перетворення існують для кожної пари з цілими типами з розділу 1. `ptr` не має навіть цієї таблиці:
способу прочитати вказівник як число не передбачено. Це значення, яке лише передається, приймається й
віддається далі іншій функції C.

**Їх також не можна друкувати.** `(println "~a" x)` не приймає сирого слова (воно не має представлення
`Sexpr`), тож спершу перейдіть до типу з шириною, як-от `(println "~a" (as int n))`.

«64-бітного цілого типу немає» з початку розділу 1 стосується й цих трьох. Це так, **бо їх не можна
зберігати**: вони не можуть бути полем `defstruct`, `defvar`, усередині аргументу типу чи `Sexpr`, тож це
слова, що лише проходять через функцію як аргументи, значення, що повертаються, і локальні змінні.
Подробиці див. у
[Довіднику із синтаксису](../syntax.md#ptr--c-long--c-ulong--сирі-машинні-слова).

## 3. Цілі числа довільної точності `int`

`integer` з CL і **ціле число** цієї мови: цілі літерали без анотацій мають цей тип, а вбудовані функції,
що повертають число, як-от `length` і `char->int`, повертають цей тип. Значення зберігається як 63-бітне
безпосереднє значення (fixnum), поки вміщується, автоматично підвищується до bignum, коли результат
операції більше не вміщується, і повертається до безпосереднього значення, коли знову вміщується. `eq` —
це завжди тотожність значень у межах діапазону fixnum, а `eql`/`=` — числова тотожність у всьому
діапазоні. Це інший тип, ніж цілі типи фіксованої ширини (розділ 1), без неявного перетворення:
`(as int x)` — це точне розширення від фіксованої ширини, а `(as i32 n)` / `(try-as i32 n)` — це
обрізання / перевірка від `int` (те саме значення, що й `int->W` / `try-int->W` у розділі 1).

Цілочисельний варіант `Sexpr` — це теж просто `int` (`(int n)` приймає і fixnum, і bignum).

Вбудовані функції, що приймають індекс або кількість (`substring`, `get` для `Vector`, кількість зсуву
для `ash` тощо), приймають `int`, але передача значення, що не вміщується в fixnum, — це помилка під час
виконання («an integer argument does not fit a fixnum»).

| Назва | Форма | Тип | Опис |
|---|---|---|---|
| `+` `-` `*` | `(op a b)` | `(int,int)→int` | Ніколи не переповнюються (підвищуються) |
| `/` | `(/ a b)` | `(int,int)→int` | Відкидає в бік нуля. Panic при діленні на нуль |
| `mod` | `(mod a b)` | `(int,int)→int` | Остача від ділення з округленням униз (знак слідує за дільником) |
| `max` `min` | `(op a b)` | `(int,int)→int` | |
| `<` `<=` `>` `>=` `=` `/=` | `(op a b)` | `(int,int)→bool` | |
| `eq` `eql` `equal` `equalp` | `(op a b)` | `(int,int)→bool` | Усі `=` |
| `logand` `logior` `logxor` `lognot` `logtest` `logcount` `integer-length` `logbitp` `ash` | | | Те саме, що в розділі 11 (доповняльний код з нескінченною кількістю бітів) |
| `int->float` `int->ratio` `int->char` `try-int->char` | | | Те саме, що в розділі 1 |
| `int->W` `try-int->W` | `(int->W x)` | `int→W` | Обрізання / перевірка. `W` — одна із шести ширин або `c-long`/`c-ulong` |
| `int->int` | | `int→int` | Тотожність (на боці фіксованої ширини та слів C `int->int` розширює; розділ 1) |
| `abs` `signum` `rem` `gcd` `lcm` `expt` `1+` `1-` | | | Та сама форма, що й у розділі 1. `expt` приймає лише невід'ємні показники |

## 4. Числа з рухомою комою (`f64` / `f32`)

`f32` має ту саму таблицю.

| Назва | Форма | Тип | Опис |
|---|---|---|---|
| `+` `-` `*` `/` | `(op a b)` | `(f64,f64)→f64` | IEEE-754. Ділення на нуль не спричиняє panic; воно дає `inf`/`NaN` |
| `mod` | `(mod a b)` | `(f64,f64)→f64` | Остача від ділення з округленням униз (як у CL; знак слідує за дільником. `a - b*floor(a/b)`) |
| `rem` | `(rem a b)` | `(f64,f64)→f64` | Остача від ділення з відкиданням (як у CL; знак слідує за діленим. `a - b*truncate(a/b)`) |
| `<` `<=` `>` `>=` `=` `/=` | `(op a b)` | `(f64,f64)→bool` | Порівняння |
| `eq` `eql` `equal` `equalp` | `(op a b)` | `(f64,f64)→bool` | Усі те саме, що `=` |
| `expt` | `(expt a b)` | `(f64,f64)→f64` | Степінь |
| `abs` | `(abs x)` | `f64→f64` | Абсолютне значення |
| `signum` | `(signum x)` | `f64→f64` | Знак (`1.0`/`-1.0`; `±0.0`/`NaN` повертаються як є. Як у CL, на відміну від `signum` у Rust) |
| `max` `min` | `(op a b)` | `(f64,f64)→f64` | Більше / менше (три й більше аргументів розгортаються цукром зі змінною кількістю аргументів з розділу 8) |
| `1+` `1-` | `(op x)` | `f64→f64` | `x±1.0` |
| `sqrt` `floor` `ceiling` `round` `truncate` | `(op x)` | `f64→f64` | Унарні операції |
| `exp` `log` `sin` `cos` `tan` `asin` `acos` `atan` `sinh` `cosh` `tanh` `asinh` `acosh` `atanh` | `(op x)` | `f64→f64` | Трансцендентні функції. `log` — натуральний логарифм |
| `log` (два аргументи) | `(log x base)` | `(f64,f64)→f64` | Логарифм за заданою основою. Розгортається в `(/ (log x) (log base))` (розділ 8) |
| `floor-div` `ceiling-div` `round-div` `truncate-div` | `(op a b)` | `(f64,f64)→cons-cell<f64,f64>` | Відповідають версіям CL з двома аргументами (`(floor 7.0 2.0)`→частка 3, остача 1). Той самий задум, що й у функцій з тими самими назвами в розділі 1 (`car`=частка, `cdr`=остача) |
| `float->int` | `(float->int x)` | `f64→int` | Перетворює на `int`, відкидаючи в бік нуля (`truncate` з CL; точно для скінченних значень будь-якого розміру). Panic на нескінченності та NaN. Для фіксованої ширини використовуйте `(as i32 x)` |
| `float->ratio` | `(float->ratio x)` | `f64→ratio` | Перетворює на `ratio` як точне двійкове раціональне число (`rational` з CL) |
| `float->f32` `float->f64` | `(op x)` | `f64→f32` / `f64→f64` | Перетворює між ширинами чисел з рухомою комою. `float->f32` округлює до найближчого, `float->f64` завжди точне. Те, що робить `(as f32 x)` |
| `try-float->f32` `try-float->f64` | `(op x)` | `f64→Option<f32>` / `→Option<f64>` | Те саме перетворення у вигляді запитання. `none`, якщо округлення змінює значення (розширення до `f64` — завжди `some`). Те, що робить `(try-as f32 x)` |
| `ffloor` `fceiling` `fround` `ftruncate` | `(op x)` | `f64→f64` | Функції з тими самими назвами з CL. Псевдоніми наведених вище `floor`/`ceiling`/`round`/`truncate`: у CL ті, що без префікса, повертають цілі числа, тож ті, що з префіксом `f`, відповідають поведінці цієї мови |
| `float-radix` `float-digits` `float-precision` | `(op x)` | `f64→int` | 2 / 53 / 53 відповідно (лише точність `0.0` дорівнює 0). `f64` — завжди IEEE-754 binary64, тож це константи |
| `float-sign` | `(float-sign x)` | `f64→f64` | `1.0` або `-1.0` |
| `scale-float` | `(scale-float x n)` | `(f64,int)→f64` | `x * 2^n` |
| `decode-float` | `(decode-float x)` | `f64→cons-cell<f64,int>` | Мантиса (у `[1/2,1)`, без знака) і показник. CL повертає три значення, але множинних значень немає, тож знак залишено `float-sign` |
| `integer-decode-float` | `(integer-decode-float x)` | `f64→cons-cell<int,int>` | Те саме розкладання з точною 53-бітною цілою мантисою. `mantissa * 2^exponent` — це точно початкове значення |
| `rationalize` | `(rationalize x)` | `f64→ratio` | **Найпростіше раціональне число, що читається назад як це число з рухомою комою** (`(rationalize 0.1)` — це `1/10`). Для точного двійкового значення використовуйте `float->ratio` |

**Відмінність від CL: як округлює `round`.** `round` (а отже, `fround`/`round-div`) округлює **від нуля**
(`(round 2.5)` = `3.0`). CL округлює **до парного**, даючи `2`.

## 5. Раціональні числа `ratio`

Раціональні числа довільної точності, сумісні з CL. Вони завжди зберігаються в нескоротному вигляді з
додатним знаменником і виділяються в купі. Неявного перетворення з цілими типами чи `f64` немає
(використовуйте явний метод перетворення або `as`/`try-as`). Про синтаксис літерала ratio див.
[Довідник із синтаксису](../syntax.md#1-лексичні-елементи).

| Назва | Форма | Тип | Опис |
|---|---|---|---|
| `+` `-` `*` `/` | `(op a b)` | `(ratio,ratio)→ratio` | Чотири операції (результати завжди в нескоротному вигляді). `/` завершується через panic при діленні на нуль |
| `mod` | `(mod a b)` | `(ratio,ratio)→ratio` | Остача від ділення з округленням униз (як у CL; знак слідує за дільником) |
| `rem` | `(rem a b)` | `(ratio,ratio)→ratio` | Остача від ділення з відкиданням (як у CL; знак слідує за діленим) |
| `abs` | `(abs x)` | `ratio→ratio` | Абсолютне значення |
| `signum` | `(signum x)` | `ratio→ratio` | Знак (повертає `1`/`-1`/`0` як `ratio`) |
| `expt` | `(expt a b)` | `(ratio,ratio)→ratio` | Степінь. Показник має бути `ratio` з цілим значенням (інакше panic). Від'ємний показник дає обернене |
| `max` `min` | `(op a b)` | `(ratio,ratio)→ratio` | Більше / менше |
| `1+` `1-` | `(op x)` | `ratio→ratio` | `x±1`. `ratio` не має бітових операцій (у CL вони лише для цілих) |
| `<` `<=` `>` `>=` `=` `/=` | `(op a b)` | `(ratio,ratio)→bool` | Порівняння |
| `eq` `eql` `equal` `equalp` | `(op a b)` | `(ratio,ratio)→bool` | Усі те саме, що `=` |
| `numerator` | `(numerator x)` | `ratio→int` | Чисельник у нескоротному вигляді (та сама назва, що й у CL) |
| `denominator` | `(denominator x)` | `ratio→int` | Знаменник у нескоротному вигляді (завжди додатний) |
| `ratio->int` | `(ratio->int x)` | `ratio→int` | Цілa частина (відкидання в бік нуля) |
| `ratio->float` | `(ratio->float x)` | `ratio→f64` | Перетворює на `f64` |

Шляхи від цілих чисел фіксованої ширини та `f64` — це `int->int`/`int->ratio` (розділ 1) і
`float->int`/`float->ratio` (розділ 4). `int`/`ratio` — окремі типи, незалежні від `i32` та інших, а
змішана арифметика потребує явних перетворень.

## 6. Комплексні числа `complex`

Структура (`defstruct`) у стандартній бібліотеці.

**Дві відмінності від CL** (обидві випливають зі статичної типізації):

1. **Компоненти — завжди `f64`.** Комплексне число CL може містити й раціональні числа, а `(complex 1 2)` і
   `(complex 1.0 2.0)` — різні типи. Статичний тип мусить вибрати один, а трансцендентні функції
   повертають вид із рухомою комою.
2. **`(sqrt -1.0)` — це дійсний `sqrt` (NaN).** У CL `sqrt` може повернути комплексне число від
   дійсного, але `sqrt` для `f64` мусить повертати `f64`. Комплексний результат дає комплексний
   аргумент: `(sqrt (complex -1.0 0.0))` — це `i`.

| Назва | Форма | Тип | Опис |
|---|---|---|---|
| `complex` / `complex::new` | `(complex re im)` | `(f64,f64)→complex` | Побудова. Компоненти можна читати напряму як `z::re`/`z::im` |
| `realpart` `imagpart` | `(op z)` | `complex→f64` | Дійсна й уявна частини. **Працюють також для дійсних чисел** (`(realpart 3.0)`→`3.0`, `(imagpart 3.0)`→`0.0`), як у CL |
| `conjugate` | `(conjugate z)` | `complex→complex` | Спряжене (працює й для дійсних чисел) |
| `phase` | `(phase z)` | `complex→f64` | Аргумент у (-pi,pi] (працює й для дійсних чисел) |
| `cis` | `(cis theta)` | `f64→complex` | `e^(i*theta)` |
| `abs` | `(abs z)` | `complex→f64` | Абсолютне значення. **Єдиний `abs`, що не повертає тип одержувача** (як у CL, абсолютне значення комплексного числа дійсне) |
| `+` `-` `*` `/` | `(op z w)` | `(complex,complex)→complex` | Комплексна арифметика |
| `=` `/=` | `(op z w)` | `(complex,complex)→bool` | Покомпонентна рівність. `Eq` теж реалізовано (`Ord` немає: комплексні числа не мають порядку, і `<` з CL їх теж відхиляє) |
| `zerop` | `(zerop z)` | `complex→bool` | Чи обидва компоненти дорівнюють 0 |
| `exp` `log` `sqrt` | `(op z)` | `complex→complex` | `log`/`sqrt` дають головні значення |
| `expt` | `(expt z w)` | `(complex,complex)→complex` | `exp(w log z)`. `(expt 0 0)`=1 |
| `atan2` | `(atan2 y x)` | `(f64,f64)→f64` | Кут вектора `(x,y)`. **`(atan y x)` з CL із двома аргументами — це цукор для цього** (розгалужується за кількістю аргументів, як `log` із двома аргументами) |

Він реалізує `print-object`, тож `~a`/`~s` друкують його як `#C(re im)`, як і CL (читач цієї мови не має
синтаксису `#C`, щоб прочитати його назад).

## 8. Числові допоміжні засоби та цукор викликів

`abs`/`signum` (усі числові типи), `gcd`/`lcm` (лише цілі типи), `rem` (усі дійсні типи, включно з `f64`)
і `expt` (`int`/`f64`/`ratio`) визначені як методи кожного числового типу (розв'язуються за типом
одержувача: `(abs x)` — це метод для типу `x`). Подробиці для кожного типу наведено в розділах 1, 3, 4 і
5. Цілі числа фіксованої ширини не мають `expt` (вони не підвищуються й переповнювалися б; перейдіть до
`int` через `(as int x)` і використайте його `expt`).

### 8.1 Форми зі змінною кількістю аргументів і з 0/1 аргументом

Арифметика та порівняння в CL приймають змінну кількість аргументів, але методи розв'язуються лише за
типом одержувача, а не за кількістю аргументів. Тому **перевіряльник розгортає такі форми у виклики з
двома аргументами**.

| Форма, яку можна писати | Розгортання | Застосовується до |
|---|---|---|
| `(op a b c ...)` | Лівий згортальний вираз `(op (op a b) c)` | `+` `-` `*` `/` `max` `min` `logand` `logior` `logxor` `gcd` `lcm` |
| `(cmp a b c ...)` | `(and (cmp a b) (cmp b c) ...)`, де кожен доданок прив'язано до тимчасової змінної | `<` `<=` `>` `>=` `=` `/=` |
| `(op)` | `(+)`=0 / `(*)`=1 / `(logior)`=`(logxor)`=0 / `(logand)`=-1 / `(gcd)`=0 / `(lcm)`=1 | Ті з наведених вище, що мають нейтральний елемент |
| `(op x)` | Для `+ * max min logand logior logxor` — сам `x`. `(- x)` змінює знак, `(/ x)` дає обернене, `(gcd x)`/`(lcm x)` дають `(abs x)` (як у CL) | Те саме |
| `(cmp x)` | Обчислює `x` і дає `true` | `<` `<=` `>` `>=` `=` `/=` |
| `(log x base)` | `(/ (log x) (log base))` | `f64` |

Кожен доданок обчислюється рівно один раз, зліва направо (саме тому порівняння зі змінною кількістю
аргументів ідуть через тимчасові змінні). Форма `/=` зі змінною кількістю аргументів порівнює **сусідні
пари**, на відміну від CL, що питає, чи всі пари відрізняються.

### 8.2 `isqrt` і цілочисельний `expt`

| Назва | Форма | Тип | Опис |
|---|---|---|---|
| `isqrt` | `(isqrt n)` | `T→T` | Найбільше ціле, що не перевищує квадратний корінь. Panic на від'ємному значенні |
| `expt` | `(expt n e)` | `(T,T)→T` | Степінь (піднесенням до квадрата). CL повертає раціональне число для від'ємного показника, але цілий тип його не може представити, тож виникає panic; спершу перетворіть на `ratio` |

## 11. Бітові операції

Визначені на доповняльному коді з нескінченною кількістю бітів (CL 12.10). Вони реалізовані для цілих
типів фіксованої ширини та `int`, а не для `ratio` (у CL бітові операції теж лише для цілих).

| Назва | Форма | Тип | Опис |
|---|---|---|---|
| `logand` `logior` `logxor` | `(op a b)` | `(T,T)→T` | Порозрядні «і», «або», виключне «або» (версії зі змінною кількістю та нуль аргументів — у 8.1) |
| `lognot` | `(lognot x)` | `T→T` | Порозрядне доповнення |
| `ash` | `(ash x count)` | `(T,int)→T` | Арифметичний зсув. Уліво, якщо `count` додатний, управо, якщо від'ємний |
| `logbitp` | `(logbitp x index)` | `(T,int)→bool` | Чи встановлено біт `index` (**порядок аргументів зворотний до CL**; див. нижче) |
| `logtest` | `(logtest a b)` | `(T,T)→bool` | `(/= (logand a b) 0)` |
| `logcount` | `(logcount x)` | `T→T` | Кількість встановлених бітів (для від'ємного числа — кількість нульових бітів) |
| `integer-length` | `(integer-length x)` | `T→T` | Кількість бітів, потрібних для представлення, без урахування знака |
| `logeqv` `lognand` `lognor` `logandc1` `logandc2` `logorc1` `logorc2` | `(op a b)` | `(T,T)→T` | Решта сім, складені з наведених вище |

**Лише другий аргумент `ash` має тип `int`, а не `T`.** Це **відстань** у бітах, а не значення типу
одержувача, тож ширина й знаковість одержувача нічого не кажуть про відстань (з тієї ж причини, що й
`count` у `(ash integer count)` з CL — будь-яке ціле). Зсув беззнакового значення вправо — логічний
(`(ash (the u8 200) -3)` = `25`), а знакового — арифметичний з округленням до від'ємної нескінченності
(`(ash (the i32 -100) -4)` = `-7`). `index` у `logbitp` має тип `int` з тієї самої причини.

**Специфікатори байтів.** Замість непрозорого об'єкта, який повертає `byte` у CL, використовується
`cons-cell<int,int>` (`car`=розмір, `cdr`=позиція). І розмір, і позиція — це кількості бітів, тож вони
мають тип `int` незалежно від ширини цілого, що розбирається.

**Ціле число — перший аргумент, в іншому порядку, ніж у CL.** CL пише `(ldb bytespec integer)`, але ця
мова вибирає метод за типом одержувача (першого аргументу), а зі специфікатором першим вибрати за типом
цілого було б неможливо. Усі інші бітові операції мають форму `(op integer ...)` (`(logand a b)`,
`(ash x count)`, `(lognot x)`), і лише родина `ldb` та `logbitp` були навпаки, тож їх приведено до
єдиного вигляду. Решта аргументів зберігає відносний порядок CL, тож `(dpb newbyte spec n)` стає
`(dpb n newbyte spec)`.

| Назва | Форма | Тип | Опис |
|---|---|---|---|
| `byte` | `(byte size position)` | `(int,int)→cons-cell<int,int>` | Створює специфікатор байта |
| `byte-size` / `byte-position` | `(byte-size b)` | `cons-cell<int,int>→int` | Виймає компонент |
| `ldb` | `(ldb x b)` | `(T,cons-cell<int,int>)→T` | Виймає із `x` указаний байт, вирівняний праворуч |
| `ldb-test` | `(ldb-test x b)` | `(T,cons-cell<int,int>)→bool` | Чи встановлено будь-який біт в указаному байті |
| `mask-field` | `(mask-field x b)` | `(T,cons-cell<int,int>)→T` | Очищає все поза указаним байтом (зберігаючи позиції) |
| `dpb` | `(dpb x newbyte b)` | `(T,T,cons-cell<int,int>)→T` | Вкладає вирівняний праворуч `newbyte` в указаний байт `x` |
| `deposit-field` | `(deposit-field x newbyte b)` | `(T,T,cons-cell<int,int>)→T` | Версія `dpb`, що зберігає позицію |
| `boole` | `(boole op a b)` | `(int,T,T)→T` | Одна з 16 логічних операцій з двома операндами, обрана через `op` (константа `boole-*` з розділу 10) |

`T` — це тип, що реалізує трейт `Bits`, а саме `i8`/`i16`/`i32`/`u8`/`u16`/`u32`/`int`. Лише `boole`
тримає `op` першим, бо причини міняти порядок CL там немає.

## 12. Випадкові числа

| Назва | Форма | Тип | Опис |
|---|---|---|---|
| `random` | `(random n [state])` | `int &optional random-state → int` | Випадкове число від `0` до `n` не включно. Якщо стан пропущено, бере з `*random-state*` і просуває його |
| `make-random-state` | `(make-random-state [state])` | `&optional random-state → random-state` | Без аргументу — новий стан; із аргументом — його копія (копія відтворює ту саму послідовність) |
| `random-state-p` | `(random-state-p x)` | `random-state→bool` | Завжди `true` (статичний тип уже виключає інші типи; існує лише для відповідності CL) |
| `*random-state*` | — | `random-state` | Типовий стан `random`. Глобальна змінна, якій можна присвоювати (замініть через `setf`) |
| `seed-random-state` | `(seed-random-state n)` | `int→random-state` | Стан, який називає ціле число. Те саме зерно завжди відтворює ту саму послідовність |

Генератор — xorshift64, і він повертає ту саму послідовність, інтерпретований чи скомпільований.

Новий стан від `make-random-state` ініціалізується з настінного годинника, тож його не можна відтворити
між запусками. Щоб відтворювати, використовуйте `seed-random-state`:

```lisp
(let ((s (seed-random-state 12345)))
  (println "~a ~a ~a" (random 100 s) (random 100 s) (random 100 s)))
;; prints the same three numbers on every run
```

**У CL немає переносного способу задати зерно** (`make-random-state` приймає лише `nil`/`t`/стан), тож ця
назва слідує `sb-ext:seed-random-state` з SBCL, а не CL.

Різні зерна дають різні послідовності. `(seed-random-state 0)` і `(seed-random-state 1)` дають різні
послідовності, так само як `-7` і `7`.
