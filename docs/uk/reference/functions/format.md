# Директиви формату

Директиви, що записуються в керівних рядках `print`/`println`/`format`. Вони охоплюють майже всі директиви
`format` з CL. Самі функції описано в розділі [Друк](printing.md#1-print--println--format).

## 1. Як записувати директиви

Кожна директива — це `~`, потім необов'язкові **параметри-префікси** (через кому: ціле число / `'c`
(знак) / `v` (береться з наступного аргументу) / `#` (кількість аргументів, що залишилися)), потім
необов'язкові **модифікатори** `:` і `@`, потім символ директиви, у такому порядку. Символи директив
нечутливі до регістру.

Керівний рядок має бути літералом ([Друк](printing.md#1-print--println--format)). Крім того, під час
перевірки перевіряється таке.

- **Кількість і типи аргументів.** Для кожної директиви, що споживає аргумент: чи лишився аргумент і чи
  приймається його тип (примітки про «аргумент» у таблицях нижче). Там, де шлях залежить від значень під
  час виконання, як-от переміщення через `~*`, яку клаузу `~[` обрано, чи спрацьовує `~^` або скільки
  разів повторюється `~@{`, перевіряється **кожен шлях**. Зайві аргументи припустимі (як у CL).
- **Параметри та модифікатори.** Неприйнятний модифікатор, забагато параметрів і значення поза діапазоном
  (від'ємна ширина, основа, відмінна від 2–36, ціле число там, де очікується знак тощо) — це помилки. Їх
  ніколи не ігнорують мовчки й не округлюють.

**Елементи** аргументу-списку (`~{`, `~:{`, `~<...~:>`) — це `Sexpr`, і ні їхню кількість, ні тип
кожного елемента не можна дізнатися з типів. Вимоги до елементів (ціле число для `~d` тощо) і відсутні
елементи перевіряються, коли значення надходять, і є помилками часу виконання (він ніколи не перемикається
натомість на інше представлення).

М'які правила CL не прийнято. Передача нецілого числа в `~d` з друком його як `~a` або трактування
`~:[` будь-якого значення як булевого не перетлумачуються так; це помилки типів.

## 2. Вивід (споживає один аргумент)

| Директива | Параметри / модифікатори | Значення |
|---|---|---|
| `~a` | `~mincol,colinc,minpad,padchar` / `@`=вирівнювання праворуч | Естетичний (`princ` з CL; рядки без лапок). Аргумент може мати будь-який тип |
| `~s` | Так само | Стандартний (`prin1` з CL; форма, яку можна прочитати назад). Аргумент може мати будь-який тип |
| `~w` | — | `write` з CL. Друкує красиво, якщо `*print-pretty*` істинна, інакше те саме, що `~s` |
| `~d` `~b` `~o` `~x` | `~mincol,padchar,commachar,interval` / `:`=групи цифр, `@`=завжди знак | Десяткові/двійкові/вісімкові/шістнадцяткові цілі числа. Аргумент — ціле число |
| `~r` | `~radix,mincol,padchar,commachar,interval` (з основою) або без | З основою — ця основа (2–36). Без неї: `~r`=англійський кількісний числівник, `~:r`=англійський порядковий числівник, `~@r`=римські цифри, `~:@r`=старі римські цифри. Аргумент — ціле число |
| `~p` | `:`=назад на один, `@`=y/ies | Множина (`~p`→"s", `~@p`→"y"/"ies"). Аргумент — ціле число |
| `~c` | `:`=назва, `@`=синтаксис `#\` | Знак. Аргумент — `char` |
| `~f` | `~w,d,k,overflowchar,padchar` / `@`=знак | З фіксованою комою. Аргумент — число |
| `~e` | `~w,d,,,,padchar,exptchar` / `@`=знак | Експоненціальний запис. Аргумент — число. Параметри CL exponent-digits, scale і overflowchar не підтримуються (їх указання — помилка) |
| `~g` | `@`=знак | Загальний запис чисел з рухомою комою. Аргумент — число. Параметрів не приймає |
| `~$` | `~d,n,w,padchar` / `:`,`@` | Грошовий запис. Аргумент — число |

## 3. Вивід (не споживає аргументів)

| Директива | Значення |
|---|---|
| `~%` | Новий рядок (`~n%` для n штук) |
| `~&` | fresh-line (новий рядок, якщо не на початку рядка; `~n&`) |
| `~\|` | Розрив сторінки (form feed) |
| `~~` | Літеральний `~` (`~n~` для n штук) |
| `~t` | Табуляція (`~colnum,colincT`. Якщо вже в стовпці colnum або далі, рухається далі на кратне colinc; не рухається, якщо colinc дорівнює 0. `@`=відносно. `:`=табуляція відносно початку логічного блоку, що працює лише при красивому друці) |
| `~_` | Умовний новий рядок (красивий друк; звичайний=`:linear` / `~:_`=`:fill` / `~@_`=`:miser` / `~:@_`=`:mandatory`) |
| `~i` | Відступ (красивий друк; `~ni`=початок блоку + n / `~n:i`=поточний стовпець + n) |
| `~<newline>` | Ігнорує новий рядок (`:`=зберегти пробіли, `@`=зберегти новий рядок) |

Як і в CL, директиви красивого друку (`~_` `~i` `~:t` `~<...~:>` і шлях красивого друку в
`~a`/`~s`/`~w`) нічого не роблять, коли `*print-pretty*` хибна. Типово вона хибна.

## 4. Керівні структури

| Директива | Значення |
|---|---|
| `~(...~)` | Перетворення регістру (`~(` малі літери, `~:(` кожне слово з великої, `~@(` з великої лише перше слово, `~:@(` усе великими) |
| `~[...~;...~]` | Умовний вибір (розгалужується за цілим аргументом. З `~n[`, `~v[` або `~#[` розгалужується за цим значенням і не бере аргументу. `~:;`=клауза за замовчуванням, лише як остання клауза). `~:[false~;true~]` розгалужується за аргументом `bool` і має рівно дві клаузи |
| `~{...~}` | Ітерація (обходить аргумент-список. `~:{`=по підсписках, `~@{`=по решті аргументів, `~:@{`=по кожному списку серед решти аргументів, `~^`=вихід, `~:}`=виконати раз, навіть якщо порожньо). Тіло, що за одну ітерацію не споживає аргументу, — це помилка (воно ніколи б не завершилося) |
| `~<...~;...~>` | Вирівнювання (розподіляє сегменти по `~mincol` стовпцях. `:`/`@`=заповнення по краях) |
| `~<...~;...~:>` | **Логічний блок** (закривається через `~:>`; річ, відмінна від наведеного вище вирівнювання). Перший сегмент — префікс, останній — суфікс (обидва лише літеральні рядки). З роздільником `~@;` префікс — це **префікс для кожного рядка**. `~:<` типово задає префікс/суфікс як `(`/`)`. Аргумент — один список (`~@<` використовує натомість решту аргументів) |
| `~*` | Пропуск аргументів (`~n*`=уперед на n, `~:*`=назад, `~@*`=до абсолютної позиції) |
| `~/name/` | Виклик методу (розділ 5. Прапорці `:`/`@` передаються методові. Параметрів не приймає) |

Такі директиви CL не підтримуються (це помилки під час перевірки).

- `~?` і `~@?`: вони беруть керівний рядок як аргумент часу виконання, тож аргументи, які споживають
  його директиви, перевірити не можна. Пишіть ці директиви прямо в керівному рядку.
- `~@[...~]`: він перевіряє, що аргумент не nil, але в цій мові nil немає. Використовуйте
  `~:[false~;true~]`, що розгалужується за `bool`.
- `~{~}` з порожнім тілом: воно бере тіло з аргументу часу виконання. Пишіть директиви всередині
  фігурних дужок.

## 5. `~/name/`

**Одна відмінність від CL: назва шукається не як глобальна функція, а як метод власного типу
аргументу.** Метод має форму `((self Self) (colon bool) (at bool)) → string`, а `:`/`@` директиви
передаються як є.

Спосіб CL із пошуком як глобальної функції не можна безпечно реалізувати в цій мові. Навіть з літеральним
керівним рядком тип елементів аргументу-списку (всередині `~{`) під час перевірки невідомий, а пошук
функції лише за назвою міг би викликати функцію, призначену для іншого типу. Вибір за типом значення
означає, що метод перевіряється за типами саме для цього типу, і це безпечно (той самий механізм, що й
у `print-object`). Він працює також для значень на кшталт `string`/`bool`/`char`/`symbol`/списків. Лише
для цілих чисел, ширину яких за значенням не визначити, це помилка, **коли метод із такою назвою
визначає більше ніж один цілий тип**.

До якого аргументу це застосовується, невідомо, але відомо, які методи можуть бути викликані.
Перевіряльник збирає кожен `~/name/` з літерального керівного рядка й записує з-поміж типів аргументів у
цьому місці виклику ті, що мають метод наведеної форми. Тож **якщо жоден із типів аргументів не має
методу, це помилка під час перевірки** (а не під час виконання), і це працює також у виконуваних файлах
AOT.

```lisp
(defstruct point (x i32) (y i32))
(defmethod brief ((self point) (colon bool) (at bool)) string
  (if colon (format false "<~a,~a>" self::x self::y) (format false "~a/~a" self::x self::y)))
(println "~a" (format false "~/brief/"  (point::new 3 4)))   ; => 3/4
(println "~a" (format false "~:/brief/" (point::new 3 4)))   ; => <3,4>
```
