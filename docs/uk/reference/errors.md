# Повідомлення про помилки

Що означають основні повідомлення про помилки від `typl` і як їх виправити.

## 1. Як читати помилку

Помилки пишуться в стандартний потік помилок у такому вигляді:

```text
error: file:line:column: kind: message
```

`kind` (вид) показує, коли помилку було виявлено.

| Вид | Коли | Значення |
|---|---|---|
| `type error` | До запуску (під час перевірки) | Помилка в типах або іменах. Ця форма не виконується |
| (без виду) | Під час читання або перевірки | Синтаксична помилка, як-от незбалансовані дужки, або ім'я, яке не вдається знайти |
| `panic` | Під час виконання | Невідновлюваний збій. Програма зупиняється після виконання очищення `unwind-protect` |

Рядки, що починаються з `warning:`, — це попередження, обробка триває.

`file:line:column` вказує на вираз із помилкою. Для помилки під час виконання, що трапляється всередині
функції стандартної бібліотеки, воно вказує на місце, де програма викликала цю функцію. Деякі помилки
не мають позиції (як-от `error: panic: ...`).

Приклад:

```text
error: main.typl:1:24: type error: type mismatch: expected `i32`, found `string`
```

Це означає, що вираз у рядку 1, стовпці 24 файлу `main.typl` був `string` там, де очікувався `i32`.

## 2. Помилки під час перевірки

Помилки, виявлені до запуску. Форма не виконується, доки їх не виправлено.

### 2.1 Типи

| Повідомлення | Значення та виправлення |
|---|---|
| ``type mismatch: expected `T`, found `U` `` | Вираз типу `U` стоїть там, де потрібен тип `T`. Неявних перетворень немає; для чисел перетворюйте через `(as T x)`. `int` і `i32` теж різні типи |
| ``integer literal 300 is out of range for u8 (0..=255)`` | Літерал не вміщується в тип. Якщо ви хочете його обрізати, напишіть `(as u8 300)` |
| ``unknown type `foo`: no type of that name is visible here. ...`` | Типу з такою назвою немає. Визначайте тип до першої форми, що його використовує (в типів немає випереджального оголошення). Якщо ви мали на увазі змінну типу, запишіть її на місці оголошення, як-от `<foo>` після назви функції ([Довідник із синтаксису 3.6](syntax.md#36-defstruct--структури-користувацькі-типи)) |
| ``cannot infer type argument `t` for `vector::new` `` | Аргумент типу не вдається визначити. Запишіть тип через `the`, як-от `(the Vector<int> (Vector::new))` |
| ``non-exhaustive match on `color`: 1/2 variants covered`` | `match` не обробляє кожен варіант. Додайте гілки для відсутніх варіантів або гілку `_` |
| ``type `pt` does not implement trait `eq` required by `where` clause on type parameter `a` `` | Функція вимагає трейт, якого не реалізує переданий вами тип. Напишіть `(impl Eq pt ...)` ([Стандартні трейти](functions/traits.md)) |
| ``` `sq` does not implement `shape`, so it cannot be used as `:dyn shape` ``` | Значення типу, що не реалізує трейт, передано туди, де очікується `:dyn`. Напишіть `impl` |
| ``` `error` is a trait, not a type — write `:dyn error` for a trait object ``` | Назву трейта записано там, де має стояти тип. Напишіть `:dyn Error` |
| ``if: (if cond then else)`` | `if` має неправильну форму. `if` вимагає гілки else. Коли вона не потрібна, використовуйте `when` |

### 2.2 Імена

| Повідомлення | Значення та виправлення |
|---|---|
| `no such function: bar` | Функції чи методу з такою назвою немає. Перевірте написання |
| ``no method `upcase` for type `int` (the type of the first argument, which selects the method); `upcase` is a method of `char`, `string` `` | Методи вибираються за типом першого аргументу. Метод із такою назвою існує, але не для типу першого аргументу (тут `int`). Наприкінці повідомлення перелічено типи, що мають цей метод |
| `unbound variable: y` | Змінної з такою назвою немає. Перевірте написання та область дії зв'язування (чи не використано її поза своїм `let`?) |
| ``use: unresolved `nosuch` `` | Модуль, названий у `use`, не знайдено. Як імена файлів відповідають шляхам модулів, див. [Довідник із синтаксису 3.11](syntax.md#311-файли-та-модулі-багатофайлові-проєкти) |
| `unresolved path: c::hidden` | Модуль існує, але імені немає, або воно невидиме, бо не має `pub` |
| `circular module dependency: a -> b -> a` | Модулі підключають один одного через `use`. Винесіть спільну частину в окремий модуль |
| ``return-from: no enclosing block named `nope` `` | Жоден `block` із назвою, переданою в `return-from`, його не охоплює. Блок функції можна використовувати лише всередині цієї функції |

### 2.3 Виклики

| Повідомлення | Значення та виправлення |
|---|---|
| `f: expected 1 argument(s), got 2` | Кількість аргументів не збігається |
| `f: unknown keyword argument :b` | Передано іменований аргумент, якого функція не має |
| `new: expected 1 field(s), got 2` | Кількість значень, переданих конструкторові структури, не збігається з кількістю полів |
| ``setf: cannot assign to constant `k` `` | Присвоєно назві, визначеній через `defconstant`. Якщо її потрібно змінювати, використовуйте `defvar` |
| ``defsignature: `later` has no definition in this file — a declaration promises one`` | Функцію, оголошену через `defsignature`, не визначено |
| ``format: ~/nosuch/ — no argument here has a method `nosuch` of the shape ...`` | Жоден із типів аргументів не має методу, який викликається через `~/name/` ([Директиви формату, розділ 5](functions/format.md#5-name)) |

## 3. Помилки читання

| Повідомлення | Значення та виправлення |
|---|---|
| `unexpected end of input while reading a list` | Бракує закривальної дужки. Позиція вказує на місце, де читання закінчилося (наприклад, кінець файлу), тож шукайте відкривальну дужку |

## 4. Помилки під час виконання (panic)

| Повідомлення | Значення та виправлення |
|---|---|
| `panic: divide by zero` | Ділення на нуль для цілих чи раціональних чисел. Ділення на нуль для чисел з рухомою комою не спричиняє panic; воно дає `inf`/`NaN` |
| `panic: unwrap: called on none` | `unwrap` застосовано до `none`. Обробіть випадок `none` через `match` або `unwrap-or` |
| `panic: Vector: index 5 out of bounds` | Індекс поза межами. Перевірте довжину через `len` або використайте функцію, що повертає `none` поза межами (`nth`, `pop` тощо) |
| `panic: an integer argument does not fit a fixnum` | В аргумент, що приймає індекс або кількість, передано `int`, який не вміщується в 63 біти |
| `throw: no enclosing (catch 'oops) for this throw` | `throw` виконався без охоплювального `catch` із тим самим тегом |
| `panic: <message>` | Програма викликала `(panic "<message>")`. Невдалий `assert` дає `assertion failed: ...` |

`panic` зупиняє весь процес, навіть коли виникає всередині задачі
([Довідник із синтаксису 12.4](syntax.md#124-взаємодія-з-іншими-можливостями)). Збої, від яких ви хочете
відновлюватися, виражайте через `Result` ([Довідник із синтаксису, розділ 9](syntax.md#9-політика-обробки-помилок)).

## 5. Попередження

| Повідомлення | Значення |
|---|---|
| ``warning: redefining function `f` `` | Функцію з такою самою назвою визначено знову. Діє пізніше визначення. Зазвичай з'являється, коли ви виправляєте визначення в REPL |
